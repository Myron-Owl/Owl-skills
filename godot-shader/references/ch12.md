# 第 12 章：2D 顶点动画

### 第 12 章：2D 顶点动画 —— 让 Sprite 形变
**学习目标**：掌握 vertex() 函数中修改 VERTEX 的核心技法，能独立实现旗帜飘动、草丛摇曳和果冻弹性三种经典 2D 顶点形变效果，理解"锚点权重"的概念并用它控制形变在不同区域的不同幅度。

**场景搭建**：本章的三种效果均按如下流程搭建场景：创建一个 Sprite2D 节点，为其指定一张矩形纹理（如旗面贴图或纯色矩形），新建 ShaderMaterial 并创建 canvas_item shader。

**内容要点**：

- vertex() 在 2D 中的执行上下文：VERTEX 是 vec2，代表顶点的局部坐标（不是像素）
- 正弦波基础位移：VERTEX.y += sin(TIME) * amplitude——为什么修改 VERTEX 能让精灵形变
- 旗帜飘动（5 步渐进构建）：纯正弦波 → 加锚点权重 pow(UV.x, 2.0) → 多频叠加波 → 加噪声纹理 → 完整 flag（X 方向拉伸 + varying 传递波值给 fragment 做颜色变化）
- 草丛摇曳：UV.y 作权重（根部=0 不动），与旗帜的 pow(UV.x, 2.0) 形成对照
- 果冻/弹性效果：VERTEX *= 1.0 + sin(TIME) * strength——等比缩放整个形状

---

## 1. 为什么需要 vertex()：从"像素"到"形状"
前 11 章，你写的所有 shader 几乎都活在 fragment() 里。你改颜色、调亮度、混合纹理、做溶解——无论多炫，这些操作都有一个共同前提：**你只修改了颜色，从未修改过形状**。

精灵仍然是一个完美的矩形。四个角仍在四个角。纹理贴在它上面，但轮廓纹丝不动。如果要修改顶点，你需要回顾本书第一章介绍的顶点着色器 vertex()。

vertex() 函数解决了一个问题：**在 GPU 画出任何像素之前，先改变物体的形状**。你可以把精灵的角拉开、压扁、弯曲、抖动——这个操作发生在光栅化之前，所以纹理和颜色会自动"跟着"形变走。

**vertex() 是什么？** 对 2D canvas_item shader 来说，vertex() 在每个**顶点**上执行一次。一个 Sprite2D 有 4 个顶点（四个角），所以 vertex() 会被调用 4 次。在这 4 次调用里修改 VERTEX（顶点的局部坐标），GPU 就得到了一个"变了形"的新四边形——然后才进入 fragment() 给这个四边形里的每个像素上色。

## 2. 正弦波位移：最简单的形变

### 2.1 第一行代码：让精灵"呼吸"
创建一个 canvas_item shader，在 vertex() 中写入：

```
shader_type canvas_item;

void vertex() {
    VERTEX.y += sin(TIME * 3.0) * 20.0;
}
```
你的精灵会上下起伏——整张图像一块硬纸板，四个角同步升降。

**为什么这能工作？** TIME 是 Godot 从游戏启动开始累积的秒数，每秒自动增长。sin(TIME * 3.0) 产生一个在 -1 到 1 之间平滑往返的值。乘以 20.0 后，VERTEX.y 在 -20 到 +20 像素之间往返。由于四个顶点被加上了相同的偏移量，整张图同步移动。

这个效果虽然基础，但它验证了两个关键事实：
1. 在 vertex() 中修改 VERTEX 能改变精灵形状，而且纹理自动跟随
2. TIME 变量在任何 shader 中都能直接使用，不需要声明

### 2.2 为什么要学正弦波形变：波是顶点动画的基础语言
观察游戏中的形变效果：旗帜飘动、草丛摇曳、水面波浪、角色呼吸、技能扩散——它们的本质都可以归约为一种模式：

**"顶点位置 = 原始位置 + 波（时间 + 空间位置）"**

sin() 是最简单的波。真正实用的效果是在这个公式上逐步叠加：
- **权重**：不是所有区域都动一样多
- **多频**：不是只有一个波在动
- **噪声**：不是完全规律的周期运动

下面我们构建一个草丛摇曳的效果。

## 3. 草丛摇曳：同一个工具，不同的权重函数
草丛摆动的效果应该有如下特点：
- 草 **根部固定在土里**（UV.y = 1 处位移应为 0）
- 草 **叶尖自由摆动**（UV.y = 0 处位移最大）
- 草受到的风力是 **推拉侧面**（X 方向位移）
在场景中增加一个Sprite2D节点，并将草丛的图片设置到纹理中，可以将scale进行适当的缩放。然后在其下挂一下shader代码。

### 最简草摆动

```
shader_type canvas_item;

uniform float amplitude = 50.0;
uniform float frequency = 2.0;

void vertex() { 
    float weight = 1.0 - UV.y;
    float sway = sin(TIME * frequency ) * amplitude;
    VERTEX.x += sway * weight;
}
```
关键点：
- **weight = 1.0 - UV.y**：UV.y = 1 是纹理底部（根部），权重 0——完全不动。UV.y = 0 是纹理顶部（叶尖），权重 1——全幅度摆动。中间线性过渡。
- **sin(TIME * frequency)**：用于模拟随时间变化的摇摆位移。
- **位移方向是 VERTEX.x**：风从侧面吹过，推拉草的侧面。你也可以试试 VERTEX.y += sway * weight * 0.3 做一个微弱的上下浮动——风也会把草压弯一点。

### 增加颜色和相位
这个图片是白色的，所以需要增加草绿色。其次，如果场景中有多个草，我们希望它们的摇摆不要完全一致，否则显的很假，因此需要增加相位参数。首先我们将grass节点复制两份，这样场景中有三个不同的草，然后修改shader如下：

```
shader_type canvas_item;

uniform float amplitude = 50.0;
uniform float frequency = 2.0;
uniform float phase_offset = 0.0;

void vertex() { 
    float weight = 1.0 - UV.y;
    float sway = sin(TIME * frequency + phase_offset) * amplitude;
    VERTEX.x += sway * weight;
}

void fragment() {
    float h = UV.y;

    vec3 bottom_color = vec3(0.10, 0.55, 0.15);
    vec3 top_color = vec3(0.05, 0.25, 0.05);

    vec3 col = mix(bottom_color, top_color, smoothstep(0.0, 1.0, h));
    COLOR.rgb = col;
}
```

关键点：
- **phase_offset参数**：放在sin函数中，将时间错开，不同的草会有不同的摇摆响应。你需要手工分别设置这三个草的phase_offset参数
- **增加颜色渐变**：使用fragment函数，定义两种颜色，然后基于UV的y轴高度进行颜色混合，这样底部是偏深绿，顶部是偏浅绿色。
- 

设置这三个草的phase_offset参数时，如果发现三个草的参数仍然完全一样，这是因为它们共享了同一个shader代码资源，你需要将它们的材质设置为make unique即可。然后再修改参数。
完整代码参见 grass.gdshader

## 4. 旗帜飘动：5 步渐进构建
下面我们来构建一个旗帜飘动的效果。在场景中增加一个 Sprite2D，纹理使用icon即可（或纯色矩形），旗杆在左侧。这意味着旗杆侧不应动，旗尾侧应摆幅最大）。在节点下挂如下shader。

### 步骤 1：纯正弦波 —— 整条旗同步摆动

```
shader_type canvas_item;

uniform float speed = 2.0;
uniform float frequency = 4.0;

void vertex() {
    float wave = sin(TIME * speed + UV.x * frequency);
    VERTEX.y += wave * 8.0;
}
```

你会发现整个图形会有摆动的效果，但是边缘部分是一起移动的，感觉很僵硬。原因并不在 Shader 本身，而在于物体拥有多少个顶点。Sprite2D只有四个顶点，因此，一个 Sprite2D 的 vertex() 函数一共只会执行 4 次。矩形只是简单形变成了一个平行四边形。如果希望物体能够产生更加细腻的形变，就需要增加顶点数量。这正是 MeshInstance2D 的作用。

在场景节点中点右键，选择change type，将节点修改成 MeshInstance2D ，然后mesh选项中选择QuadMesh，size设置为128，这对应了128像素。将subdivide的长和宽都设置为20。这样会增加其顶点数量。完成后可以看到旗帜的边缘会变得有柔软的感觉。但是纹理出现上下颠倒，这是因为MeshInstance2D的坐标系统是用的3D的，将其size.y设置为-128即可修复。

目前的效果：整张旗面上下浮动，边缘呈正弦波摆动，但左侧和右侧的位移幅度**完全一样**——这不像一面被风吹的旗，倒像一块硬纸板在水面上上下浮动。

**为什么不像旗？** 因为缺少一个物理直觉：旗杆侧被固定住（位移应为 0），旗尾侧自由摆动（位移应最大）。UV.x 在 sin() 内部只控制了"波在当前柱子上的相位"——即不同垂直列的波到达波峰的时间不同，产生了一个从左到右的"波纹推进"感——但它没有控制"幅度"。

UV.x * frequency 控制的是**波峰出现的位置**：当 UV.x = 0 时正弦值是 sin(TIME * speed)；当 UV.x = 0.5 时是 sin(TIME * speed + 2.0)——波峰向右偏移了。这给了旗帜一个从左到右的"传播"视觉，但**振幅是均匀的**。

### 步骤 2：加锚点权重 —— 旗杆不动，旗尾飞起
解决振幅均匀问题的关键，是给每个顶点加上**位移权重**。旗杆在 UV.x = 0，旗尾在 UV.x = 1。我们希望权重在 UV.x = 0 时为 0（不动），在 UV.x = 1 时为 1（全幅度摆动）。最简单的权重函数是 UV.x 本身——线性渐变。

但线性渐变感觉生硬。pow(UV.x, 2.0)（二次方）让靠近旗杆的区域更"粘"——UV.x = 0.3 时的权重是 0.09（远小于 0.3），使旗面靠近旗杆的大片区域几乎不动，而尾部的加速更明显。这更接近现实旗帜的受力形态。

```
void vertex() {
    float weight = pow(UV.x, 2.0);
    float wave = sin(TIME * speed + UV.x * frequency);
    VERTEX.y += wave * 20.0 * weight;
}
```

你会发现

此时的效果已接近一面飘动的旗：左侧几乎不动（旗杆固定感），右侧大幅摆动（自由端感）。sin() 内部的 UV.x * frequency 仍负责"波从左到右传播"的视觉——你可以调节 frequency 来控制旗面上同时出现几个波峰。

### 步骤 3：多频叠加 —— 旗面不再单调正弦
一面真正的旗在风中不是完美的正弦波。观察任何旗杆上的旗帜——你会看到**一个大波（低频）上还叠着小碎波（高频）**。这种"大波浪上挂着小波纹"的感觉，是单频正弦波做不到的。

解决方案：**再加一个波**——不同的速度、不同的频率、不同的振幅。

```
void vertex() {
    float weight = pow(UV.x, 2.0);

    float wave = sin(TIME * speed + UV.x * frequency);
    float secondary = sin(TIME * speed * 2.0 + UV.x * frequency * 3.0);

    VERTEX.y += (wave * 8.0 + secondary * 2.0) * weight *2.0;
}
```
关键点：
- secondary 的 TIME 系数是主波的 2 倍——它变化更快（高频振动感）
- secondary 的 UV.x 系数是主波的 3 倍——它在旗面上有更密集的波峰
- secondary 的振幅（2.0）远小于主波（8.0）——它只是"大波浪上的小涟漪"

现在旗面的运动变得丰富了：一个大的起伏（主波）上面叠着细碎的抖动（次波）。继续添加更多波，可以让运动越来越自然——这就是 **FBM（Fractal Brownian Motion，分形布朗运动）** 的思想：多层不同频率、不同振幅的噪声/波叠加。

### 步骤 4：加入噪声纹理 —— 打破规律性
即使有两个正弦波叠加，运动仍然是完全规律的——每过一个周期，旗面会精确地回到完全相同的位置。真正的风吹旗帜有随机性：一阵强一阵弱、风向微微变化、空气湍流。

**噪声纹理解决的问题：** 给波动叠加不可预测的"扰动"。你需要一个看起来像"云雾"或"大理石花纹"的纹理——它不是真实的云，而是一张记录了伪随机值的图（每个像素的亮度在 0 到 1 之间随机分布，但相邻像素值接近）。

**如何获得噪声纹理？** 最简单的方式是使用 Godot 内置的 NoiseTexture2D 资源（见第 7 章）。在 Inspector 中创建一个 NoiseTexture2D，设置其 noise 属性为 FastNoiseLite，调整参数后将此纹理拖入 shader 的 uniform。或者你也可以使用任何一张自带"随机感"的纹理（如石头表面、云雾贴图）。

声明噪声纹理的 uniform：

```
uniform sampler2D noise_tex : repeat_enable;
```
repeat_enable 是一个纹理 hint，告诉 Godot 当 UV 坐标超出 (0,0)→(1,1) 范围时让纹理重复平铺而不是钳位——因为我们要让噪声纹理随时间滚动，坐标会不断变大。

在 vertex() 中使用噪声：

```
void vertex() {
    float weight = pow(UV.x, 2.0);

    float wave = sin(TIME * speed + UV.x * frequency);
    float secondary = sin(TIME * speed * 2.0 + UV.x * frequency * 3.0);

    vec2 noise_uv = UV - vec2(TIME * 0.2, 0.0);
    float noise = texture(noise_tex, noise_uv).r - 0.5;

    VERTEX.y += (wave * 8.0 + secondary * 2.0 + noise * 4.0) * weight * 2.0;
}
```
逐行解析噪声部分：
1. **noise_uv = UV - vec2(TIME * 0.2, 0.0)**：让噪声纹理随时间向左滚动（UV.x 被减去一个不断增长的值）。只改变 .x 而不改变 .y——噪声像"风带"一样水平流过旗面。如果同时改变 .y，会产生斜向滚动——可以试试。
2. **texture(noise_tex, noise_uv).r**：采样噪声纹理的红色通道。噪声纹理是灰度的，所以 R、G、B 三个通道的值相同——取哪个都行。.r 是通用写法（不用 .x 是因为采样纹理返回的是颜色 vec4，取第一个分量用 .r 比 .x 更语义化）。
3. **- 0.5**：噪声纹理的值范围是 0.0 到 1.0。减去 0.5 后变成 -0.5 到 0.5——这样噪声能向两个方向推拉顶点，而不是只往一个方向推。
4. **noise * 4.0**：调节噪声的影响力。太大画面抖动太激烈，太小看不出效果。

此时的效果已经不规律了：旗帜在大波动中夹杂着不可预测的微幅抖动——这就是有机运动的关键。

### 步骤 5：完整 flag —— X 方向拉伸 + 颜色联动
一面真正的旗不仅上下飘动（Y 轴），还会在水平方向上有轻微的伸缩变化：旗尾被风吹出时微微拉宽，收回时微微收窄。同时，波动的隆起处会略微"迎着光"变亮——这是 fragment 阶段可以做的。

把 X 方向拉伸和波值传递（varying）加入，得到完整旗面 shader：

```
shader_type canvas_item;

uniform sampler2D noise_tex : repeat_enable;

uniform float speed : hint_range(0.0, 10.0, 1.0) = 2.0;
uniform float frequency : hint_range(0.0, 10.0, 1.0) = 4.0;
varying float wave;

void vertex() {
    float weight = pow(UV.x, 2.0);

    wave = sin(TIME * speed + UV.x * frequency);

    float secondary =
        sin(TIME * speed * 2.0 + UV.x * frequency * 3.0);

    vec2 noise_uv = UV - vec2(TIME * 0.2, 0.0);
    float noise = texture(noise_tex, noise_uv).r - 0.5;

    VERTEX.y +=
        (wave * 8.0 +
         secondary * 2.0 +
         noise * 4.0) * weight*2.0;

    VERTEX.x += wave * 3.0 * weight;
}

void fragment() {
    vec4 tex = texture(TEXTURE, UV);
    tex.rgb *= 1.0 + wave * 0.2;
    COLOR = tex;
}
```
新增内容详解：

- **varying float wave**：将 vertex() 中计算的主波值传递给 fragment()。GPU 会在四个顶点的波值之间做双线性插值——旗面中间像素的 wave 值自动获得平滑过渡。没有 varying，fragment() 无法知道顶点阶段的计算结果。
- **VERTEX.x += wave * 3.0 * weight**：水平方向的拉伸。振幅只有 3.0（远小于 Y 方向的 8.0）——旗面的水平伸缩是微妙的效果，不是主运动。同样乘以 weight 使旗杆侧不被拉伸。
- **tex.rgb *= 1.0 + wave * 0.2**：在 fragment() 中，利用 varying 传来的波值微调颜色亮度。波峰处 wave > 0，亮度增加 1.0 + 正数 使其微微变亮；波谷处 wave < 0 使其微微变暗。这模拟了旗帜波动时的受光变化——布面凸起处迎着光，凹陷处背着光

## 5. 果冻/弹性效果：等比缩放形状
旗帜和草丛都是"部分区域动、部分区域不动"——通过权重函数实现了非均匀形变。还有一种更简单但视觉效果强烈的形变：**整张图均匀地膨胀和收缩**——就像一块果冻被轻轻拍了一下。

```
shader_type canvas_item;

uniform float strength = 0.15;
uniform float speed = 6.0;

void vertex() {
    float pulse = sin(TIME * speed) * strength;
    VERTEX *= 1.0 + pulse;
}
```
**它是什么？** VERTEX *= 1.0 + sin(TIME * speed) * strength 将四个顶点的 X 和 Y 坐标同时乘以一个在 1.0 - strength 到 1.0 + strength 之间变化的因子。当 pulse > 0 时顶点向外推（膨胀），pulse < 0 时顶点向内拉（收缩）。因为所有顶点都相对于原点（精灵的中心）缩放，效果是整张图从中心向外膨胀和收缩。

**为什么用乘法而非加法？** 旗帜用的是 VERTEX.y += ...（加法），果冻用的是 VERTEX *= ...（乘法）。加法是"移动"顶点——让一整片区域朝一个方向偏。乘法是"缩放"顶点——让顶点相对于原点拉近或推远。两者产生完全不同质感的运动：
- 加法形变 → 弯曲、拉伸、偏摆（适合旗帜、草）
- 乘法形变 → 膨胀、收缩、脉冲（适合果冻、心跳动画）

### 5.1 变体：增加颜色变化
你也可以增加一个颜色变化，在膨胀时让颜色更亮。这里需要使用一个varying变量，让pulse可以从vertex传递到fragment阶段。

```
varying float pulse;

void vertex() {
    pulse = sin(TIME * speed) * strength;
    VERTEX *= 1.0 + pulse;
}

void fragment() {
    vec4 tex = texture(TEXTURE, UV);
    tex.rgb *= 1.0 + pulse * 0.8;
    COLOR = tex;
}
```

### 5.2 变体：XY 方向不对称的果冻
真正的果冻被拍打后，可能在水平方向膨胀更多、垂直方向膨胀更少。你可以让 X 和 Y 的缩放系数不同：

```
void vertex() {
    float pulse = sin(TIME * speed) * strength;
    VERTEX.x *= 1.0 + pulse * 1.5;
    VERTEX.y *= 1.0 + pulse * 0.5;
}
```
X 方向放大 1.5 倍，Y 方向只放大 0.5 倍——精灵被横向压扁和拉宽。这是"弹性形变"的全新维度。

### 5.3 应用场景
果冻效果的应用远不止"果冻"本身：
- **角色受击反馈**：被击中的瞬间，角色精灵快速膨胀 strength = 0.1 再缩回——GDScript 中用一个 tween 控制 strength uniform 从 0.1 衰减到 0
- **UI 按钮弹性**：按钮被按下时微微缩一下 strength = -0.05，松手时弹回
- **技能蓄力**：蓄力光圈持续脉动 VERTEX *= 1.0 + sin(TIME * 4.0) * 0.08
- **爆炸冲击波视觉**：冲击波圆环在最外层用果冻式膨胀（配合 fragment 中的 alpha 衰减）

## 本章小结
本章是第一次让你走出 fragment()——走进 vertex()。整套 2D 顶点动画可以归纳为一道公式：

**VERTEX = 原始位置 + 权重 × 时间驱动 × 强度**

四个案例的差异，全部落在"权重函数怎么选"上：

| 案例 | 形变类型 | 权重函数 | 时间驱动 |
| 草丛摇曳 | 单方向位移 | pow(UV.x, 2.0)（根部不动、顶部大动） | sin(TIME * speed) |
| 旗帜飘动 | 单方向位移 | UV.y（旗杆到旗尾线性增加） | sin(...) * 噪声 复合 |
| 果冻/弹性 | 整图缩放 | 1.0（均匀） | sin(TIME * speed) * strength |

带走两个心法：

- **形变的位置由"权重 × 时间项"决定**——只要你能给物体每个位置写出一个"动得多厉害"的权重，就能造出该动的部分动、不该动的部分不动的效果。
- **vertex() 的代价远低于 fragment()**——它只跑顶点数那么多次（四顶点的精灵只跑 4 次！），因此适合做大尺度的形状动画；但要警惕：**4 个顶点的精灵做不出"波纹形变"**，只会整体晃——想做曲面形变必须先增加 mesh 细分。
下一章（ch13）会暂时回到 fragment()，进入颜色处理领域——但你在本章学到的"把顶点当成变量"的思维，会在 ch18（3D vertex）中以更大的尺度卷土重来。
