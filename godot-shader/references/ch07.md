# 第 7 章：噪声

### 第 7 章：噪声 —— 打破重复感的钥匙
**学习目标**：理解随机（random）与噪声（noise）的本质区别——随机是一盘散沙，噪声是连绵的山丘；能用 hash 函数构建值噪声、用 FBM 在 shader 中生成有空间连续性的程序化纹理；能分辨值噪声和梯度噪声的视觉特征。

**场景搭建**：本章需要2D 场景：添加 Sprite2D 节点，挂载 ShaderMaterial → 新建 canvas_item 类型 shader，用于观察噪声纹理和草地效果。

**内容要点**：
- 伪随机 hash 函数的工作原理
- 值噪声（value noise）：hash 四角 → 双线性混合 → 平滑连续
- 梯度噪声（gradient noise / Perlin noise）：随机方向向量 × 距离的点积 → 更自然的过渡
- Godot 内置 NoiseTexture2D 用法：设置参数 → 传 uniform sampler2D → 简单路径快速出效果
- FBM（Fractal Brownian Motion）：FBM 视觉对照：从模糊到丰富的细节叠加过程
- 实战 2D：草地颜色变化（噪声驱动 mix(green, yellow_green, noise_value)）

### 7.1 随机数是一盘散沙，噪声是连绵的山丘
在第 5 章和第 6 章中，我们用 sin(TIME) 和 smoothstep 做出了周期运动和圆环效果。它们的共同特点是**规律的、可预测的**。但真实世界不是这样的——草地不是均匀的绿，木头纹理不是等间距的条纹，烟雾不是标准正弦波。真实世界的视觉特征中，大量存在一种"有结构的不规则性"。

直接生成"真实感的不规则"有一个直觉解法：给每个像素一个随机数。试一试再说。

```
shader_type canvas_item;

float hash(vec2 p) {
    return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

void fragment() {
    float r = hash(UV * 10.0);
    COLOR = vec4(vec3(r), 1.0);
}
```
运行这 10 行代码，你会看到满屏的**白噪声**——像老电视没信号时的雪花点。每个像素独立随机，相邻像素之间没有任何关系。这在信号处理中叫"白噪声"（white noise），所有频率等量存在。

白噪声在 shader 中有用——比如在复古 CRT 效果中模拟噪点。但如果你想用"随机"来画木头纹理、云朵、地形，白噪声完全帮不上忙。因为木头纹理的特点是**相邻位置的亮度相似，但变化又有一定的不可预测性**。

这就是**噪声（noise）** 要解决的问题：**在随机性和连续性之间取得平衡**。好的噪声函数输出的值，在空间上相邻的位置是相似的（有连续性），但又不是简单的周期重复（有随机性）。

**随机 vs 噪声的核心区别**：随机数函数——同一个输入两次，返回不同的值（依赖内部状态）；hash 函数——同一个输入永远返回同一个值（纯函数）；噪声函数——相近的输入返回相近的值（hash + 插值）。

### 7.2 第 1 步：hash —— 噪声的"原子"
噪声函数的起点是一个叫 **hash**（哈希）的函数。它的输入是一个空间坐标（vec2 或 vec3），输出是一个 0 到 1 之间的浮点数。对同一个输入，它永远返回同一个输出——这就满足了 GPU"无记忆"的约束：不需要记住任何状态，只要拿坐标去算就行。

下面是经常会见到的标准 hash 函数：

```
float hash(vec2 p) {
    return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}
```
这行代码看起来像一个魔法咒语。拆开来看每一步在做什么：

- **dot(p, vec2(127.1, 311.7))**：把二维坐标 p 变成一个标量。127.1 和 311.7 是经验选择的扰动参数。它们没有特殊数学意义，作用是让 dot() 的结果在坐标空间中分布得更加均匀，避免出现明显重复模式。
- **sin(...)**：将上一步的标量映射到 [-1, 1]。正弦函数在这里起到的作用不是"做周期动画"，而是"把大数折叠到小区间"——sin(12345.67) 和 sin(12345.68) 的值没有肉眼可见的相关性，但它们又是确定性的。
- *** 43758.5453**：放大。sin 的值在 [-1, 1]，乘以一个大常数后，小数部分的分布更加均匀。
- **fract(...)**：截取小数部分，得到 [0, 1) 之间的输出。
**为什么要用这套复杂的操作？** 因为 GPU 上没有"随机数种子表"。hash 函数必须在纯数学中模拟出"确定性的混乱"——同一个输入永远同一个输出、不同输入看起来毫无关联。sin + dot + fract 的组合是 shader 社区经过十几年验证的经典方案。

```
void fragment() {
    float r = hash(UV * 10.0);
    COLOR = vec4(vec3(r), 1.0);
}
```

UV * 10.0 中的 10.0 是一个缩放因子（scale）——它把 UV 从 [0,1] 范围放大到 [0,10]。如果不想要连续的白噪声，而是想要**离散的棋盘格**——每个格子里颜色一致，格子之间随机变化——用 floor() 把坐标量化成整数网格即可。将上面的白噪声代码中的 UV * 10.0 改为 floor(UV * 10.0)，你会看到**随机棋盘格**——每个 10×10 的格子内颜色相同，格子之间颜色随机。这就是 hash 在网格上的直接应用：

```
float r = hash(floor(UV * 10.0));
```
[IMAGE: 随机棋盘格](../ch07-diagrams/grid.webp)

**这一小节你只需要记住**：hash = 空间随机函数，同一输入永远返回同一输出。噪声的"随机性"从这里来。

### 7.3 第 2 步：一维值噪声 —— 在两点之间架桥
hash 让每个整数格点有了一个固定的随机值。但两个格点之间的区域——比如坐标 (0.3, 0) 和 (0.4, 0) 的中间位置 (0.35, 0)——该输出什么值？

如果直接输出 hash(0.3) 或 hash(0.4)，你会得到**阶梯状**的不连续变化：颜色在格点处突然跳变。这显然不是我们想要的"连绵山丘"。

解决方案是**插值（interpolation）**：在两个相邻格点的 hash 值之间做平滑过渡。先从简单的一维开始理解这个原理。

一维噪声的流程：输入 x → floor(x) 得整数坐标 i → fract(x) 得小数部分 f → hash(i) 和 hash(i+1) → 用 f 在两值间插值 → 输出连续噪声。

```
float noise_1d(float x) {
    float i = floor(x);
    float f = fract(x);
    float a = hash(vec2(i, 0.0));
    float b = hash(vec2(i + 1.0, 0.0));
    return mix(a, b, f);
}

void fragment() {
    float n = noise_1d(UV.x * 10.0);
    COLOR = vec4(vec3(n), 1.0);
}
```
但有时候你会发现不正常的颜色“跳变”——在整数边界处（如 x=7.0），噪声值突然从一个颜色跳到另一个。

[IMAGE: 随机棋盘格](../ch07-diagrams/error.webp)

其原因在于：当前这个hash 函数对精度极度敏感，导致有时候 GPU 实际算出来的 hash值 不可靠，从而破坏了连续性。如果你需要更高的稳定性（避免 sin 函数在极端输入下的精度衰减），可以使用纯整数 hash 替代：

```
float hash(vec2 p) {

    // 1. 把浮点坐标强制转成整数网格坐标
    //    这样保证每个像素格/整数格对应唯一输入
    ivec2 i = ivec2(p);

    // 2. 基础空间扰动（大质数混合）
    //    作用：把 x/y 坐标打散成一个初始整数种子
    int n = i.x * 73856093 ^ i.y * 19349663;

    // 3. 线性同余混合（LCG step）
    //    作用：进一步扩散比特分布，让结果更“随机”
    //    1664525 / 1013904223 是经典 LCG 参数
    n = n * 1664525 + 1013904223;

    // 4. 位扰动（bit scramble）
    //    作用：把高位信息折叠到低位，减少周期性结构
    n = n ^ (n >> 16);

    // 5. 归一化到 [0,1]
    //    2147483647 = int32 最大值（去掉符号位）
    return float(n) * (1.0 / 2147483647.0);
}
```
**两种 hash 的选择**：fract(sin(dot(...))*) 版本只有 1 行，适合教学和快速原型，但可能存在精度问题；整数版本约 10 行，适合正式项目。你可以视情况选择。

### 7.4 第 3 步：二维值噪声 —— 四角混合
一维噪声沿一条线在两点之间插值。二维噪声需要在一个矩形格子的**四个角**之间做双线性插值——先沿 X 方向在上下两行各做一次 mix，再沿 Y 方向在这两个结果之间做一次 mix。

步骤分解：
1. floor(coord) 得到当前格子的整数坐标 i
2. fract(coord) 得到格子内的小数偏移 f
3. 取四个角的 hash 值：a = hash(i)、b = hash(i + (1,0))、c = hash(i + (0,1))、d = hash(i + (1,1))
4. 对 f 做 Hermite 平滑：f = f*f*(3.0 - 2.0*f)
5. X 方向两次 mix：top = mix(a, b, f.x)、bottom = mix(c, d, f.x)
6. Y 方向一次 mix：result = mix(top, bottom, f.y)

写成代码：

```
vec2 smooth_curve(vec2 t) { 
    return t * t * (3.0 - 2.0 * t); 
    }

float noise_2d(vec2 coord) {
    vec2 i = floor(coord);
    vec2 f = fract(coord);
    f = smooth_curve(f);

    float a = hash(i);
    float b = hash(i + vec2(1.0, 0.0));
    float c = hash(i + vec2(0.0, 1.0));
    float d = hash(i + vec2(1.0, 1.0));

    return mix(mix(a, b, f.x), mix(c, d, f.x), f.y);
}
```
smooth_curve函数把线性变化变得更平滑，也就是缓慢开始 → 快速变化 → 再缓慢结束。 3f² - 2f³就是我们在第六章学习过的 smoothstep()数学等价的多项式。

把 noise_2d(UV * scale) 的输出直接赋给 COLOR.rgb，你会看到灰度的云团——明亮区域和阴暗区域之间的过渡是柔和的，没有棋盘格那样的锐利边缘，也没有明显的重复感。**这就是值噪声（value noise）**——噪声家族中最简单直观的一种。它的名字来源于"直接对格点的值进行插值"。但是它看起来还是不那么自然，这需要继续下一步工作。

#### 7.5 第 4 步：FBM —— 在粗糙之上叠加精细
单独的噪声是一个频率的产物——无论你把 scale 调多大，它产生的纹理细节是均匀的：大团块和小团块的尺寸是同级别的。但真实世界的地形、云朵、火焰有一个特点——**大起伏上叠着小起伏，小起伏上又有更小的细节**。这就是分形（fractal）自相似性。

**FBM（Fractal Brownian Motion，分形布朗运动）** 用简单的循环实现了这种多层细节叠加：

```
第 1 层：低频大振幅 → 画出大轮廓（大山、大洋流）
第 2 层：频率翻倍、振幅减半 → 画出中等起伏（山坡、波浪）
第 3 层：频率再翻倍、振幅再减半 → 画出小细节（碎石、浪花）
... 继续叠加 ...
```
FBM 本质上是在叠加不同频率的噪声，这是一种称为**频率分层（Frequency Decomposition）**的程序化生成核心思想。**低频**决定整体结构（山在哪、云团在哪），**中频**决定形状变化（山的坡度、云团边缘），**高频**决定表面细节（碎石纹理、云的丝状边缘）。后续章节的水面、地形、云层、火焰都在复现这个三层结构。

翻译成代码就是以下循环模板：

```
uniform float lacunarity = 2.0;
uniform float gain = 0.5;

float fbm(vec2 p) {
    float value = 0.0;
    float amplitude = 0.5;
    float frequency = 1.0;

    for (int i = 0; i < 6; i++) {
        value += amplitude * noise_2d(p * frequency);
        frequency *= lacunarity;
        amplitude *= gain;
    }
    return value;
}
```
**为什么这样设计参数？**

- **lacunarity（空隙度）**：控制每层频率翻几倍。值越大，高频层采样越密，纹理显得越"碎"。默认 2.0 是平衡点。调到 3.0 以上会让细节看起来紊乱。
- **gain（增益）**：控制每层振幅缩几倍。值越接近 1.0，高频层贡献越大，纹理看起来越"粗糙"。调到 0.3 以下则高频细节几乎消失，噪声音调回到平滑状态。你可以试试：gain = 0.8 和 gain = 0.3 有什么区别？（直觉：lacunarity = "细节变密的速度"，gain = "细节保留程度"）
- **octaves（叠加层数）**：循环次数。6 层是实践中常用的上限——超过 6 层，肉眼几乎分辨不出增加了什么细节，但计算量翻倍。
- **起始 amplitude 通常设为 0.5**：6 层叠加的最终值约在 0 到 1 之间（等比数列求和），不需要额外 normalize。如果起始 amplitude = 1.0，最终值会超过 1.0，需要在末尾 clamp。
下面是同一个噪声函数在 1 层、3 层、6 层 FBM 下的对比：

[IMAGE: 三种不同fbm对比](../ch07-diagrams/fbm_3.webp)

- **1 层**：就是原始的二维值噪声——大团块，没有细节
- **3 层**：中间频率加入——团块边缘出现中等起伏
- **6 层**：高频细节充分展开——纹理丰富，接近真实地形
关键洞察：FBM 的本质不是"创造复杂纹理"，而是**把复杂度拆成频率从低到高的多个层，每个层只负责一个频率范围**。这是真正的"分而治之"。

**这一小节你只需要记住**：FBM = 多频噪声叠加。低频定结构，中频定形状，高频定细节。lacunarity = "细节变密的速度"，gain = "细节保留程度"。

#### 7.6 噪声全景：从值噪声到 Perlin 噪声
值噪声虽然平滑，但有一个视觉缺陷——它倾向于产生**块状的、有点方**的纹理。这是因为四角的值是纯标量，插值过程在每个格子中产生的是四个角的线性混合。

**梯度噪声（gradient noise）** 解决了这个问题。它不在格点上存标量值，而是给每个格点分配一个**随机的二维方向向量**。对于格子内任意位置，计算它到四个格点的方向向量与各格点随机向量的**点积**，然后对这四个点积进行双线性插值。

**简化梯度噪声（angle-based gradient noise）**——它的原理与经典的 Perlin 噪声相同（格点存方向、做点积），但在梯度向量的生成方式上做了简化。经典 Perlin 使用预定义的12个方向向量查表，而我们这里用随机角度生成——更短、更容易理解，视觉结果几乎一致。下面是**完整的实现**：

```
float hash21(vec2 p) {
    return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

float perlin_2d(vec2 p) {
    vec2 i = floor(p);
    vec2 f = fract(p);
    f = f * f * (3.0 - 2.0 * f);  // Hermite 平滑

    // 四个角的随机梯度向量（每个角从 hash 值映射到一个随机方向角）
    float a = hash21(i) * 6.28318;
    float b = hash21(i + vec2(1.0, 0.0)) * 6.28318;
    float c = hash21(i + vec2(0.0, 1.0)) * 6.28318;
    float d = hash21(i + vec2(1.0, 1.0)) * 6.28318;

    // 计算距离向量与梯度向量的点积
    float va = dot(vec2(cos(a), sin(a)), f - vec2(0.0, 0.0));
    float vb = dot(vec2(cos(b), sin(b)), f - vec2(1.0, 0.0));
    float vc = dot(vec2(cos(c), sin(c)), f - vec2(0.0, 1.0));
    float vd = dot(vec2(cos(d), sin(d)), f - vec2(1.0, 1.0));

    // 双线性混合（与值噪声相同的插值方式）
    return mix(mix(va, vb, f.x), mix(vc, vd, f.x), f.y);
}
```
**代码逐段解析：**

- 
**随机梯度向量生成**（第 8-11 行）：用 hash21() 给每个格点一个随机值 → 乘以 2π 映射为一个方向角 → cos/sin 拆分为单位向量。这样每个格点的"随机方向"就确定了——不像值噪声存标量，这里是存方向。

- 
**点积计算**（第 13-16 行）：对格子内任意位置，计算它到四个格点角的偏移向量（f - vec2(0,0) 等），与对应角的梯度向量做点积。点积的几何含义是"该位置在梯度方向上的投影长度"——在梯度方向上走多远。这个值域为 [-1, 1]。

- 
**平滑插值**（第 19 行）：对四个点积值进行双线性 mix，和 7.4 节值噪声的插值方式完全一致。最终输出范围 [-1, 1]，使用时需要 * 0.5 + 0.5 映射到 [0, 1]。

**值噪声 vs Perlin 噪声的关键差异：**

- **输出值域**：值噪声输出 [0, 1]；Perlin 噪声输出 [-1, 1]，需 * 0.5 + 0.5 映射
- **格点处行为**：值噪声在格点处 = 格点的随机标量值（不确定）；Perlin 噪声在格点处 = 0.0（因为偏移向量为 0，点积为 0，插值后也是 0，映射后为 0.5 中灰）
- **视觉质感**：值噪声产生"圆润团块"感；Perlin 噪声产生"有方向性的山丘起伏"感

**噪声家谱：各类噪声的关系**

噪声不是一个算法，而是一个家族。它们的共同目标都是：根据输入坐标 (x, y)，生成一个看起来随机、但实际上可重复计算的数值。不同噪声之间的主要区别在于：

- 格点上存储什么信息？
- 如何进行插值？
- 如何生成随机性？
- 最终产生什么视觉风格？
可以把它们的关系理解为下面这棵“家谱树”：

```
Hash（伪随机原子）
 │
 ├─ Value Noise（值噪声）
 │    └─ FBM（多层叠加）
 │          └─ Domain Warp（域扭曲）
 │
 ├─ Gradient Noise（梯度噪声）
 │    └─ Perlin Noise
 │          └─ Simplex Noise
 │
 └─ White Noise（白噪声）

Voronoi（距离场）
 └─ Cellular Noise
```

- **Value Noise**：格点存随机标量，平滑混合。圆润团块感。本书主力噪声，最容易理解，实现简单。
- **Gradient Noise（Perlin）**：格点存随机方向，点积运算。山丘起伏感，过渡更自然。上面的 perlin_2d() 即其完整实现。还有Simplex Noise，它是Perline的改进，高维效率更高
- **Cellular Noise（Voronoi）**：计算像素到最近格点的距离。产生类似细胞壁、蜂巢、长颈鹿斑纹的图案。
- **Godot NoiseTexture2D 对应**：在 FastNoiseLite 的 Noise Type 下拉中，Perlin 对应上面的 perlin_2d() 实现，Simplex 是其计算量更低的变体，Cellular 对应 Voronoi 距离场类型。搭配 Fractal 开关即可实现对应噪声的 FBM 版本。
本书后续实战主要使用 Value Noise + FBM 组合——因为实现更短、理解更容易，且 FBM 叠加后值噪声和梯度噪声的视觉差异进一步缩小。Perlin/Simplex 作为进阶选项，在你需要更自然的过渡质感时切换。

**三种核心范式的公式压缩**：
- Value Noise = hash + interpolation
- FBM = 多频 Value Noise 叠加（value += amp * noise(p * freq)）
- Gradient Noise = gradient + dot + interpolation — 存方向而非存值

**这一小节你只需要记住**：Value Noise = hash + interpolation（存随机值，团块感）。Gradient Noise = gradient + dot + interpolation（存随机方向，山丘感）。日常用 Value Noise + FBM 就够。

### 7.7 Godot 内置方式：NoiseTexture2D —— 最快出效果的路径
写一个完整的噪声函数（hash + 插值 + FBM）大约 30 行代码。但 Godot 提供了一个内置的捷径：**NoiseTexture2D**。它本质上是一个封装好的噪声生成器，你把参数调好，它生成一张噪声纹理，你像用普通贴图一样在 shader 里 texture() 采样。

#### 实操对比：代码实现 vs NoiseTexture2D
在 7.5 节中用 noise_2d() 函数写出了值噪声。现在用 NoiseTexture2D 复现同样的效果：创建一个 Sprite2D，挂 canvas_item shader，用 texture(my_noise, UV) 采样并直接输出到 COLOR。和 7.5 节的自写代码版本对比——视觉上几乎相同。

**操作流程：**

- 在 FileSystem 面板右键 → New Resource → 搜索 **NoiseTexture2D**
- 在 Inspector 中设置参数：
- **Noise**：内嵌的 FastNoiseLite 对象，点击展开
- **Noise Type**：尝试选择不同的噪声种类
- **Frequency**：控制噪声频率，越大细节越密。起点用 0.05
- **Fractal**：开启 Fractal 开关后，**Octaves**（叠加层数）、**Lacunarity**（频率倍增因子）、**Gain**（振幅衰减因子）三个参数——这就是内置的 FBM
- **Lacunarity**：默认 2.0，每层频率翻倍
- **Gain**：默认 0.5，每层振幅减半
- **Width / Height**：纹理分辨率，一般 256×256 或 512×512 就够
- 勾选 **Seamless**：如果噪声要做循环滚动（不做可不用）
- 保存为 noise_texture.tres
- 在 shader 中声明 uniform sampler2D my_noise : repeat_enable（加上 repeat_enable 使得 UV 超出 [0,1] 时纹理循环），然后在 ShaderMaterial 的 Shader Parameters 面板中将 my_noise 赋值为刚才创建的 NoiseTexture2D
**shader 代码示例：**

```
shader_type canvas_item;

uniform sampler2D my_noise : repeat_enable;

void fragment() {
    float n = texture(my_noise, UV).r;  //噪声是灰度图，取red通道即可
    COLOR = vec4(vec3(n), 1.0);
}
```

[IMAGE: 三种不同fbm对比](../ch07-diagrams/use_noisetexture.webp)

**代码实现 vs NoiseTexture2D 怎么选？**

********************
|  | 代码实现（hash+noise+FBM） | NoiseTexture2D |
| 上手难度 | 🔴 需要理解 hash / 插值 / FBM 原理 | 🟢 调参数即可 |
| 代码实现 | 灵活、可动画、可定制。多像素重计算，移动端需留意开销 | 计算便宜（一次纹理采样）、调试方便。受限于FastNoiseLite参数范围 |
| 性能 | 6层FBM在fragment中每像素都跑hash/noise/mix循环，开销不低。 | 预生成的NoiseTexture2D只需一次纹理采样 |
| 调试能力 | 🔴 出错时定位困难 | 🟢 在编辑器中可以预览噪声纹理 |
| 适合场景 | 学习原理 / 需要定制噪声逻辑 | 快速出效果 / 多个 shader 共用噪声 |

本书的建议：学习阶段用代码实现理解原理；项目开发中用 NoiseTexture2D 快速出效果；一些高级的特殊需求回到代码实现。

### 7.8 实战 2D：草地颜色变化
理论收工，开始实战。第一个案例是 2D 草地的颜色变化——用噪声打破纯绿色的均匀感。

场景：在 Sprite2D或ColorRect 上挂 canvas_item shader。

**第 1 步（最简版）：纯色草地**

```
shader_type canvas_item;

void fragment() {
    vec3 green = vec3(0.2, 0.6, 0.1);
    COLOR = vec4(green, 1.0);
}
```
一片均匀的绿。没有任何变化。

**第 2 步：加入 hash + 噪声**

```
shader_type canvas_item;

uniform float noise_scale = 10.0;

float hash(vec2 p) {
    ivec2 i = ivec2(p);
    int n = i.x * 73856093 ^ i.y * 19349663;
    n = n * 1664525 + 1013904223;
    n = n ^ (n >> 16);
    return float(n) * (1.0 / 2147483647.0);
}

float noise_2d(vec2 coord) {
    vec2 i = floor(coord);
    vec2 f = fract(coord);
    f = f * f * (3.0 - 2.0 * f);
    float a = hash(i);
    float b = hash(i + vec2(1.0, 0.0));
    float c = hash(i + vec2(0.0, 1.0));
    float d = hash(i + vec2(1.0, 1.0));
    return mix(mix(a, b, f.x), mix(c, d, f.x), f.y);
}

void fragment() {
    vec3 green = vec3(0.2, 0.6, 0.1);
    float n = noise_2d(UV * noise_scale);
    COLOR = vec4(green * (0.7 + 0.3 * n), 1.0);
}
```
现在的绿色有了明暗变化——但变化范围只有 ±15%，且因为是单层噪声，纹理细节不够丰富。

**第 3 步：用 mix 在两种绿色间切换 + FBM**

把单层噪声升级为 FBM，同时用噪声值在深绿和浅绿之间插值：

```
shader_type canvas_item;

uniform float noise_scale = 5.0;
uniform float contrast = 1.0;

// ... hash + noise_2d（同上） ...

float fbm(vec2 p) {
    float value = 0.0;
    float amplitude = 0.5;
    float frequency = 1.0;

    for (int i = 0; i < 4; i++) {
        value += amplitude * noise_2d(p * frequency);
        frequency *= 2.0;
        amplitude *= 0.5;
    }

    return value;
}

void fragment() {
    vec3 dark_green  = vec3(0.15, 0.45, 0.05);
    vec3 light_green = vec3(0.35, 0.75, 0.15);
    vec3 yellow_green = vec3(0.45, 0.70, 0.10);

    float n = fbm(UV * noise_scale);

    // 噪声值在 [0, 1] 范围内 → 映射到深绿到浅绿
    vec3 grass = mix(dark_green, light_green, n);
    // 噪声值接近 0.7 以上的区域加入黄色倾向
    grass = mix(grass, yellow_green, smoothstep(0.65, 0.85, n) * 0.5);

    COLOR = vec4(grass, 1.0);
}
```
**第 4 步：加微调——给噪声加个流动动画**

随着时间推移，噪声纹理缓慢移动，于是草地表面的亮暗区域不断变化。视觉上，它更像是云层在天空中缓慢移动，导致投射到草地上的阴影不断漂移

```
void fragment() {
    vec3 dark_green   = vec3(0.15, 0.45, 0.05);
    vec3 light_green  = vec3(0.35, 0.75, 0.15);
    vec3 yellow_green = vec3(0.45, 0.70, 0.10);

    vec2 uv = UV * noise_scale + vec2(TIME * flow_speed, TIME * flow_speed * 0.7);
    float n = fbm(uv);

    vec3 grass = mix(dark_green, light_green, n);
    grass = mix(grass, yellow_green, smoothstep(0.65, 0.85, n) * 0.5);

    COLOR = vec4(grass, 1.0);
}
```
**注意**：本节使用 UV 平移来演示噪声的动画效果——视觉上更接近"地面在流动"。真实游戏中草地的摆动通常通过顶点位移（vertex displacement，即 VERTEX.y += noise(...)）来实现，这将在第 12 章和第 18 章详细讲解。

到此，草地的颜色不再是一片均匀的绿。它有了明暗变化、冷暖偏向，而且这些变化是空间上连续的——不会出现某个像素突然跳变成灰色。这就是噪声解决的核心问题。

#### 用 NoiseTexture2D 替代代码噪声
如果你不想在 shader 里嵌入 hash/noise/fbm 三个函数，可以完全用 NoiseTexture2D 替代：创建一张 NoiseTexture2D 资源，参数设为 Perlin、Fractal 开、3 Octaves，然后在 shader 里用 texture(noise_tex, UV * 5.0).r 替代 fbm(UV * 5.0)。两种方式的最终草地效果几乎相同。本书在实战案例中展示代码版本，是为了让你在深入定制（如 ch18 地形位移、ch21 水体 FBM 调制）时有完整可控的工具——当你不需要定制时，NoiseTexture2D 完全够用。

**完整代码见** grass.gdshader

### 本章小结
本章从零构建了 shader 中最重要的程序化纹理工具——噪声。三个核心概念贯穿全章：

- **hash** 是确定性随机源：同一输入永远同一输出，满足 GPU 无状态约束
- **插值** 是连续性的来源：在离散格点之间架桥，让随机变成噪声。Hermite 平滑（3f²-2f³）消除导数不连续
- **FBM** 是复杂度生成器：把单层噪声按频率分层叠加——低频定结构，中频定形状，高频定细节
从工程角度，你有两条路径：手写代码实现（灵活、可定制、理解原理）和 NoiseTexture2D（快速、调参、调试方便）。
