# 第 21 章：3D 水体

### 第 21 章：3D 水体 —— 从低成本到工程级
**学习目标**：掌握三种不同复杂度的 3D 水体实现——从仅靠法线贴图 + 噪声顶点位移的低成本方案，到卡通风格的 toon 水体，再到具备 Gerstner 波、折射、深度着色、Fresnel 和泡沫的写实工程级水体。读者可以根据自己项目的性能预算和风格需求选择适合的层级。

**场景搭建**：创建一个 3D 场景，根节点为 Node3D，添加 DirectionalLight3D + WorldEnvironment（配天空环境光），一个高细分 PlaneMesh（Subdivide Width/Depth ≥ 100）的 MeshInstance3D 挂在本章的 shader 上，以及若干 MeshInstance3D 物体（立方体、球体、胶囊体）放置在水中和岸边，以便观察深度着色和泡沫效果。所有 shader 类型为 spatial。

---

## 0. 三种方案，三种场景
打开网上的"工程级水体 shader"——你可能会看到 400+ 行代码、8 组 Gerstner 波、三平面映射、Snell 窗口、距离衰减、泡沫系统……。初学者面对这样的代码，最常见的反应是关掉编辑器。

**但大多数项目不需要 400 行的水体。**

本章提供三种方案，分别对应不同的性能和风格需求：

```
方案 A（≈60 行）  低成本水体：噪声顶点位移 + 法线贴图 + Blinn-Phong specular
       ↓
方案 B（≈70 行）  Toon 水体：噪声位移 + 深度边缘 + caustic + 屏幕颜色
       ↓
方案 C（≈270 行） 写实水体：Gerstner 波 + 折射 + 深度着色 + Fresnel + 泡沫
```
如果你是移动端项目或者场景中有大片水面——选方案 A。如果你在做风格化/卡通项目——选方案 B。只有当你需要真正的写实水体、并且场景允许使用 SCREEN_TEXTURE 和 DEPTH_TEXTURE（需要 Forward+ 或 Mobile 渲染器）——才需要方案 C。

## 1. 方案 A：低成本水体
完整代码见 water_basic.gdshader。

### 1.1 顶点动画：用噪声纹理驱动波浪
方案 A 不使用 Gerstner 波——它用**噪声纹理**来驱动顶点位移。两张噪声纹理以不同速度和方向滚动、混合，产生的起伏比单一的 sin() 自然得多，但计算成本远低于 Gerstner 波。

```
shader_type spatial;
render_mode blend_mix, cull_disabled, depth_draw_always;

uniform sampler2D noise_map : repeat_enable;
uniform sampler2D normal_map : hint_normal, repeat_enable;
uniform float height_scale = 0.3;
uniform vec2 scroll_speed = vec2(0.1, 0.15);
uniform vec2 plane_size;

void vertex() {
    vec2 uv1 = UV * 5.0 + TIME * scroll_speed;
    vec2 uv2 = UV * 3.0 + TIME * scroll_speed * 1.7 + vec2(3.0, 1.0);

    float n1 = texture(noise_map, uv1).r;
    float n2 = texture(noise_map, uv2).r;
    float height = 0.5 * (n1 + n2);

    VERTEX.y += height * height_scale;
}
```
几个关键设计：

- **两组 UV 不同频率、不同速度**：uv1 频率 5.0 + 基础速度，uv2 频率 3.0 + 1.7 倍速度 + 固定偏移。两组噪声相加后的起伏不会单调重复。
- **height_scale 作为振幅控制**：不需要改 shader 代码，调 uniform 就能改变波浪大小。
**为什么不直接用 sin(VERTEX.x * freq + TIME)？** 因为 sin 波只有一个方向、一个频率，看起来像"抖动"而不是"水面"。两张噪声纹理的叠加即使不用 Gerstner 的水平挤压，也能产生足够自然的视觉起伏。

### 1.2 法线贴图：让平面看起来有细节
顶点位移产生的是**大尺度**的波浪——你的 PlaneMesh 细分再高，也不可能在顶点层面表现毫米级的水面纹路。**法线贴图（normal map）正好填补这个空缺**：它不改顶点位置，只改光照计算时用的法线方向，让平面在像素级别看起来凹凸不平。

在 fragment 中做双法线滚动混合：

```
uniform float normal_scale = 1.0;

void fragment() {
    vec2 uv1 = UV * 5.0 + TIME * scroll_speed;
    vec2 uv2 = UV * 3.0 + TIME * scroll_speed * 1.7 + vec2(3.0, 1.0);

    vec3 n1 = texture(normal_map, uv1).rgb;
    vec3 n2 = texture(normal_map, uv2).rgb;
    vec3 normal = normalize(n1 + n2);

    NORMAL_MAP = normal;
    NORMAL_MAP_DEPTH = normal_scale;
```
**注意**：这里采样法线贴图时用的是 texture(normal_map, uv).rgb 而没有手动做 * 2.0 - 1.0 解码——这是因为 NORMAL_MAP 内置变量在 Godot 中期望的就是 [0, 1] 编码值，Godot 会自动解码。

NORMAL_MAP_DEPTH 控制法线扰动的强度（类似法线贴图的"深度"），与 NORMAL_MAP 配合使用。

### 1.3 Fresnel：近处透明，远处不透明
Fresnel（菲涅尔）效应是水面最核心的光学特性：低头看脚下的水——透明，能看到水底；抬头看远处的湖面——反光，看不到水下。

在 shader 中：

```
uniform vec4 shallow : source_color = vec4(0.2, 0.5, 0.8, 0.6);
uniform vec4 deep    : source_color = vec4(0.02, 0.05, 0.2, 0.9);

    float fresnel = 1.0 - abs(dot(normalize(NORMAL), normalize(VIEW)));
    fresnel = pow(fresnel, 3.0);

    ALBEDO = mix(shallow.rgb, deep.rgb, fresnel);
    ALPHA = mix(shallow.a, deep.a, fresnel);
    ROUGHNESS = 0.2;
}
```

- dot(NORMAL, VIEW) = 1.0 → 视线垂直 → fresnel = 0 → 浅水色（透明）
- dot(NORMAL, VIEW) = 0.0 → 视线平行 → fresnel = 1 → 深水色（不透明）
- pow(fresnel, 3.0) 控制过渡斜率：指数越大，中间过渡越窄
这里的 shallow 和 deep 同时控制颜色（rgb）和透明度（a）。注意这里用的是 NORMAL（已经被 NORMAL_MAP 扰动过的法线），所以 Fresnel 过渡也会跟随法线贴图的凹凸而微妙变化。

**方案 A 完成。** 你有一个会起伏、有水面纹理细节、从某些角度看透明、有闪烁高光的水面了。它不依赖 SCREEN_TEXTURE、不依赖 DEPTH_TEXTURE、不需要 Gerstner 波——兼容所有渲染器，性能开销极低。

## 2. 方案 B：卡通风格水体
完整代码见 water_toon.gdshader。

方案 A 的 Fresnel 驱动 alpha 混合是一种"软"过渡。卡通风格需要的是"硬"过渡 + 明亮的色彩 + 风格化的边缘效果。方案 B 展示了如何在 Godot 中构建一个 toon 水体——它同样用噪声驱动顶点位移，但后续处理完全不同。

### 2.1 顶点：噪声位移 + 梯度法线重建
方案 B 在 vertex 中做了两件事：位移顶点位置、重建法线方向。我们先看代码，再逐层拆解每行背后的原因。

```
shader_type spatial;

uniform sampler2D main_noise_sampler : repeat_enable;
uniform sampler2D tiny_noise_sampler : repeat_enable;
uniform sampler2D caustic_sampler : filter_linear, repeat_enable;

uniform sampler2D DEPTH_TEXTURE : hint_depth_texture, filter_linear_mipmap;
uniform sampler2D SCREEN_TEXTURE : hint_screen_texture, filter_linear_mipmap;

varying vec2 base_offset;

float get_noise(vec2 offset) {
    return texture(main_noise_sampler, offset).x;
}

void vertex() {
    base_offset = UV + TIME * 0.01;
    float h = get_noise(base_offset) * 0.3;
    VERTEX.y += h;

    float eps = 0.02;
    float hL = get_noise(base_offset - vec2(eps, 0.0));
    float hR = get_noise(base_offset + vec2(eps, 0.0));
    float hD = get_noise(base_offset - vec2(0.0, eps));
    float hU = get_noise(base_offset + vec2(0.0, eps));

    float dx = (hR - hL) / (2.0 * eps);
    float dz = (hU - hD) / (2.0 * eps);
    float strength = 0.03;
    vec3 normal = normalize(vec3(-dx * strength, 1.0, -dz * strength));
    NORMAL = normal;
}
```

#### 为什么要重建法线？
当你执行 VERTEX.y += h 把平面顶起来以后，表面形状变了——但 Godot 内置的 NORMAL **并不会自动更新**。PlaneMesh 的原始 NORMAL 始终是 (0, 1, 0)（竖直向上）。这意味着光照计算会用错误的法线，水面看起来仍像一块平板——只是高度在变。

所以你必须在 VERTEX 位移之后，手动把 NORMAL 更新为波浪面真正的法线。

#### 为什么不用 NORMAL_MAP（方案 A 的做法）？
方案 A 在 fragment 中用 NORMAL_MAP 写入了法线贴图，Godot 会自动把它从切线空间变换到世界空间。但方案 B 的 toon 水体需要法线参与更多的计算——不只是光照，还有 fresnel(NORMAL, VIEW, ...) 的视觉判断（近透远反）。在 vertex 中直接算出世界空间法线、直接写入 NORMAL，更简单、更可控，后续所有计算一步到位。

#### 中心差分法：从高度场到梯度
平面位移后变成了一个高度场 y = h(x, z)。要找到表面法线，需要知道曲面在 X 方向和 Z 方向的**斜率**（即偏导数 ∂h/∂x 和 ∂h/∂z）。

这里用的方法是**中心差分**：在目标点周围，沿 X 轴向左 (-eps, 0) 和向右 (+eps, 0) 各采样一次高度，用两侧高度差除以间距来近似斜率：

```
dx = (hR - hL) / (2*eps)   →   ∂h/∂x 的近似
dz = (hU - hD) / (2*eps)   →   ∂h/∂z 的近似
```
eps = 0.02 是采样偏移量：太小 → 噪声纹理相邻点高度差异不够，梯度接近零；太大 → 采样点跑到太远的位置，梯度不再反映本地的斜率。

**为什么叫"中心差分"？** 因为它在目标点的两侧等距采样（左-右、下-上），相减后除以两倍间距。它比"前向差分"（只采右侧点，除以 eps）精度高一阶。

#### 法线公式：(-dx*strength, 1.0, -dz*strength) 是怎么来的？
高度场 h(x, z) 的表面可以视为参数曲面。两条切向量分别是：

```
T_x = (1,  ∂h/∂x,  0) = (1,  dx,  0)
T_z = (0,  ∂h/∂z,  1) = (0,  dz,  1)
```
法线 = 两条切向量的叉积（右手系，cross(T_z, T_x)）：

```
N = T_z × T_x = (-dx, 1, -dz)
```
归一化后就是 normalize(-dx, 1, -dz)。负号来自叉积的方向——它保证法线朝上（y 分量始终为正，因为 1.0 是唯一正分量）。

**strength = 0.03 是风格化参数**，不是物理推导。乘以 strength 实际上是在缩小平面的凹凸感：法线扰动变小 → 光照更"平滑" → 更接近卡通风格。如果把 strength 调到 1.0，法线会完全跟随噪声纹理的形状，光照变化剧烈——那是写实风格的做法。对于 toon 水体，你需要**比物理更弱的法线**，所以用 0.03 压低扰动。

**关键总结**：方案 A 用 NORMAL_MAP（切线空间法线，Godot 自动 TBN 变换）来添加像素级表面细节；方案 B 直接在 vertex 中用中心差分法从高度场推导世界空间法线，一步到位覆盖光照、Fresnel 等所有后续计算。

### 2.2 深度纹理：GPU 知道水下物体的距离
Toon 风格的一个标志性效果是**水与物体交界处的白色边缘**——类似描边，但由深度决定。要实现这个效果，需要先理解 DEPTH_TEXTURE 和"视图空间深度"这两个概念。

#### 2.2.1 DEPTH_TEXTURE 是什么？
Godot 在渲染每一帧时，为屏幕上所有不透明物体生成一张**深度纹理**，存储在 DEPTH_TEXTURE 中（需要 hint_depth_texture 标记才能绑定）。渲染画面时，这张纹理已经写好了：纹理中每个像素存储的是"那个像素位置场景物体的深度"。

你可以把 DEPTH_TEXTURE 想象类似于整个屏幕大小的一张灰度图：黑色 = 离相机近，白色 = 离相机远。

但这里有一个坑：**这张纹理中存储的值不是物理距离，而是经过投影变换后的非线性深度**。为什么是"非线性"的？因为 GPU 做了一个透视除法——离相机近的物体，深度精度高；离相机远的物体，深度精度低。DEPTH_TEXTURE 中存储的就是这个经过压缩的值。

如果把 DEPTH_TEXTURE 的值直接当成距离来用，会出现"远处物体的深度变化一丁点，对应实际距离却差很远"的问题。必须把非线性深度**反投影回线性距离**才能做有意义的比较。

#### 2.2.2 从非线性深度到视图空间深度

```
void fragment() {
    float depth_tex = textureLod(DEPTH_TEXTURE, SCREEN_UV, 0.0).r;
    vec4 world_pos = INV_PROJECTION_MATRIX * vec4(SCREEN_UV * 2.0 - 1.0, depth_tex, 1.0);
    world_pos.xyz /= world_pos.w;
```
这段代码把深度纹理中的一个点从"屏幕上的像素"反算回"3D 空间中相机前方的一个位置"。逐行拆解：

**第 1 行：读取深度纹理。**

```
depth_tex = textureLod(DEPTH_TEXTURE, SCREEN_UV, 0.0).r;
```
SCREEN_UV 是当前水面片元在屏幕上的位置（[0, 1] 范围）。textureLod 的 LOD=0 表示用最高精度采样。返回的 .r 通道是 Godot  中 [0, 1] 的非线性深度值（0 = 近平面，1 = 远平面）。

**第 2 行：构造四维坐标。**

```
vec4(SCREEN_UV * 2.0 - 1.0, depth_tex, 1.0)
```
这一步把三个独立的值打包成一个 vec4，准备做矩阵乘法：

- **.xy**：SCREEN_UV * 2.0 - 1.0 把 [0, 1] 的屏幕 UV 映射到 [-1, 1] 的**归一化设备坐标（NDC）**。例如屏幕正中间的像素 (0.5, 0.5) → NDC (0, 0)。
- **.z**：depth_tex，NDC 深度（Godot 4 中已经是 [0, 1] 范围，对应 near→far）。
- **.w**：1.0，齐次坐标的 w 分量（暂时为 1，一会儿会被矩阵变换改写）。
现在 vec4(ndc_xy, depth_tex, 1.0) 就是一个"在 NDC 空间 + 齐次坐标系中描述的点"。

**第 3 行：乘以逆投影矩阵。**

```
INV_PROJECTION_MATRIX * vec4(...)
```
PROJECTION_MATRIX 把 3D 空间中的点映射到屏幕。INV_PROJECTION_MATRIX 是它的逆操作——把屏幕上的点**反推回 3D 空间**。它得到的结果是在视图空间中的坐标，就是以摄像机为原点的3D空间坐标。

数学上：投影矩阵 P 把"视图空间中的一个点 (x,y,z,1)"映射到"裁剪空间 (a,b,c,w)"。逆矩阵 P⁻¹ 则反向：把 NDC 坐标 (a,b,c,1) 变回视图空间。乘法结果会得到一个在视图空间中的四维齐次坐标。

**第 4 行：透视除法。**

```
world_pos.xyz /= world_pos.w;
```
矩阵乘法后 world_pos.w 不再是 1——它包含了透视投影的距离信息。除以 w（透视除法）后，world_pos.xyz 恢复为真正的三维坐标。

此时 world_pos.z 就是**屏幕中当前像素在视图空间中的 Z 坐标**（沿相机视线方向的距离）。这就是我们需要的"线性距离"。

**注意**：变量名叫 world_pos 但在 Godot 的 spatial shader 中，VERTEX 如果是在vertex()中使用，它是在局部空间中，如果是在fragment()中使用，它已经在视图空间了，所以 INV_PROJECTION_MATRIX 反解出来的也是视图空间坐标。VERTEX.z 和 world_pos.z 在同一个坐标系中，可以直接比较。

**视图空间 Z vs 世界空间 Y**：这里比较的是视图空间的 Z 分量——沿相机视线方向的斜距。当相机俯视水面时，视线方向 ≈ 垂直向下，Z 差 ≈ 真实的垂直水深，近似成立。但当相机斜看（掠射角）时，Z 差测量的是斜距而非垂直距离：同一个浅滩，正视和斜视时边缘检测的阈值会不同，水岸交界处的白色边缘会随相机角度漂移。更严格的做法是用 INV_VIEW_MATRIX 将水面点和场景点都转回世界空间，用 .y 分量（世界空间的垂直高度）做比较——这才是物理正确的"水深"，不受相机角度影响。方案 C 的高级水体直接采用了这个做法。

#### 2.2.3 比较两个深度：水多深？
拿到屏蔽中场景的视图空间深度 world_pos.z 后，和水面自身的视图空间深度 VERTEX.z 比较：

```
两者深度差 = VERTEX.z - world_pos.z
```

- **差值很小**（水面深度 ≈ 场景深度）→ 水面就在物体上方一点点 → **水很浅** → 边缘
- **差值很大**（水面深度 ≫ 场景深度）→ 水面离物体很远 → **水很深**
toon 水体的边缘检测正是利用这个差值：

```
    float water_edge = world_pos.z + 0.05;
    float water_edge_mask = clamp(
        1.0 - smoothstep(water_edge, water_edge + (caustic_1 * 0.5), VERTEX.z),
        0.0, 1.0
    );
```
smoothstep 在这里的作用：当 VERTEX.z（水面深度）接近 water_edge（场景深度 + 0.05）时，输出从 0 平滑过渡到 1。1.0 - smoothstep(...) 翻转方向：水浅 → mask 接近 1.0（白色边缘），水深 → mask 接近 0.0（不显示边缘）。

caustic_1 * 0.5 让 smoothstep 的过渡范围随 caustic 纹理的采样值波动——边缘不是均匀的直线，而是跟随水波纹理变成不规则的波浪形。这是 toon 风格中"不完美边缘"的关键，避免过于机械的描边效果。

### 2.3 屏幕颜色混合 + 深度着色

```
    float water_depth_mask = clamp(
        1.0 - smoothstep(world_pos.z, world_pos.z + 3.0, VERTEX.z),
        0.0, 1.0
    );

    vec3 screen_texture = texture(SCREEN_TEXTURE, SCREEN_UV, 2.0).rgb;
    vec3 final_water_color = mix(water_color, screen_texture * water_depth_color, water_depth_mask * 0.75);
```
这里有两个不同的 mask：

- **water_edge_mask**：小阈值（0.05）——检测岸边（极浅水）→ 白色边缘
- **water_depth_mask**：大阈值（3.0）——检测整体水深 → 控制屏幕色 vs 水色的混合比例
texture(SCREEN_TEXTURE, SCREEN_UV, 2.0) 第三个参数是 LOD 级别：深水处用 LOD 2.0 模糊采样屏幕颜色，模拟"深水看不清水底"。

### 2.4 Caustic 纹理叠加

```
    vec2 noise_offset = texture(tiny_noise_sampler, UV).rg;
    noise_offset = (noise_offset * 2.0 - 1.0);

    float caustic_1 = texture(caustic_sampler,
        UV * 5.0 + TIME * 0.05 + noise_offset * 0.1
    ).x;

    float final_caustic = caustic_1 * (1.0 - fresnel(NORMAL, VIEW, 1.0)) * 0.8;
```
几个关键设计：

- **噪声偏移 caustic UV**：tiny_noise_sampler 给 caustic 纹理的 UV 添加微小的随机偏移（* 0.1），让 caustic 图案看起来不那么"完美对齐"。
- **Fresnel 权重**：(1.0 - fresnel(NORMAL, VIEW, 1.0))——近处（视线垂直）Fresnel 小 → caustic 强；远处（视线平行）Fresnel 大 → caustic 弱。水面远处反光强，caustic 就应该淡。

### 2.5 最终输出：风格化的明亮水体


### 3.1 步骤 1：Gerstner 波 + 正确法线

#### Gerstner 波是什么？
最直觉的水面动画是用 sin(x + t) 把顶点上下推——但这是"抖动的布"，不是"浪"。

真正的海浪有一个关键特征：**波峰尖锐、波谷平坦**。这不是视觉效果，而是物理事实——海面上的水分子在做近似圆周运动：波峰处水向前推，波谷处水向后拉。这就叫"余摆线波"（trochoidal wave），1802 年由 Franz Gerstner 首次描述，2001 年由 Jerry Tessendorf 引入计算机图形学，从此成为实时水体渲染的标配。

数学上，Gerstner 波不只改 y，还改 x 和 z。想象平面上每个顶点都是一个水分子：波浪经过时，水分子不是在原地上下抖动，而是**沿一个圆轨迹运动**——这个圆叫"轨道圆"。波峰处分子运动方向和波浪传播方向一致（"向前推"），波谷处方向相反（"向后拉"）。Gerstner 波的公式就是描述这个轨道圆上的位置：

```
// 对平面上 (x,z) 处的一个点，波沿着方向 dir 传播：
phase = f * dot(dir, (x, z)) + speed * time + phase_offset  // 当前位置/时间的相位

x' = x + steepness * amplitude * dir.x * cos(phase)   // 水平位移（沿传播方向）
y' =     amplitude * sin(phase)                        // 垂直位移（与波高直接相等）
z' = z + steepness * amplitude * dir.z * cos(phase)   // 水平位移（沿传播方向）
```
几个要点：

- **phase 里的每一项**：f * dot(dir, xz) 是空间相位——dir 方向的点相位不同，垂直 dir 方向的点相位相同（形成平行的波峰线）；speed * time 让这些波峰线随时间移动；phase_offset 是初始偏移——三条波用不同偏移可以避免波峰在原点重合。
- **amplitude = 波高**：y' 里直接用 amplitude * sin(phase)，不除以频率。修改 amplitude uniform 就能直观地改变波高。
- **steepness 控制水平挤压**：它介于 0 到 1 之间。steepness = 0 时退化为纯垂直 sin 波；steepness 越大，波峰越尖锐、波谷越平缓。注意 steepness × amplitude × frequency 过大会导致波面自相交（"打卷"）——保持在每个波的水平位移不超过 1 个波长即安全。
- **与 sin 波的关键区别**：sin 波的 y' 和 x',z' 是独立的；Gerstner 波的垂直位移和水平位移**来自同一个 phase**——水分子沿一个相位锁定的圆运动，这才做出了"推拉感"。

#### 代码化：6 个参数，一条波
每条 Gerstner 波都有 6 个参数。在步骤 1 中我们把它封装进一个函数，直接在 vertex 中叠加多条波：

```
shader_type spatial;
render_mode blend_mix, depth_draw_always, cull_disabled, specular_schlick_ggx, diffuse_burley;

uniform float time_scale : hint_range(0.0, 2.0) = 1.0;

uniform vec3 wave_direction_deg = vec3(45.0, -15.0, 120.0);
uniform vec3 wave_frequency  = vec3(0.3, 0.6, 1.2);
uniform vec3 wave_amplitude  = vec3(0.08, 0.05, 0.01);
uniform vec3 wave_steepness  = vec3(0.5, 0.4, 0.3);
uniform vec3 wave_speed      = vec3(1.2, 1.5, 2.0);
uniform vec3 wave_phase_deg  = vec3(0.0, 90.0, 45.0);

void add_gerstner_wave(vec2 xz, float t, float dir_deg, float freq,
                       float amp, float steep, float spd, float phase_deg,
                       inout vec3 displacement,
                       inout vec3 tangent_x, inout vec3 tangent_z) {
    vec2 dir = vec2(sin(dir_deg * PI / 180.0), cos(dir_deg * PI / 180.0));
    float f = TAU * freq;
    float p = phase_deg * PI / 180.0;
    float d = dot(f * dir, xz) + spd * t + p;
    float cos_d = cos(d);
    float sin_d = sin(d);

    displacement.x += steep * amp * dir.x * cos_d;
    displacement.y += amp * sin_d;
    displacement.z += steep * amp * dir.y * cos_d;

    float neg_sin_common = -steep * amp * f * sin_d;
    float cos_common     =  amp * f * cos_d;
    tangent_x.x += neg_sin_common * dir.x * dir.x;
    tangent_x.y += cos_common       * dir.x;
    tangent_x.z += neg_sin_common * dir.y * dir.x;
    tangent_z.x += neg_sin_common * dir.x * dir.y;
    tangent_z.y += cos_common       * dir.y;
    tangent_z.z += neg_sin_common * dir.y * dir.y;
}
```
这个函数同时做两件事：
1. **位移累加**：标准 Gerstner 公式，steep * amp * dir * cos_d 做水平挤压，amp * sin_d 做垂直起伏
2. **偏导累加**：计算位移对 X 和 Z 的偏导数（tangent_x 和 tangent_z），用于在 vertex 末尾通过叉积重建法线

关于偏导的数学细节不需要死记——只需要理解：位移函数知道了，偏导就是它的空间导数。add_gerstner_wave 把偏导也一并累加，省去在 vertex 中做中心差分采样的额外纹理查询。

在 vertex 中叠加三条波并重建法线：

```
varying float wave_height;
varying float wave_slope;

void vertex() {
    float t = TIME * time_scale;
    vec3 displacement = vec3(0.0);
    vec3 tangent_x = vec3(1.0, 0.0, 0.0);
    vec3 tangent_z = vec3(0.0, 0.0, 1.0);

    add_gerstner_wave(VERTEX.xz, t,
        wave_direction_deg.x, wave_frequency.x,
        wave_amplitude.x, wave_steepness.x,
        wave_speed.x, wave_phase_deg.x,
        displacement, tangent_x, tangent_z);

    add_gerstner_wave(VERTEX.xz, t,
        wave_direction_deg.y, wave_frequency.y,
        wave_amplitude.y, wave_steepness.y,
        wave_speed.y, wave_phase_deg.y,
        displacement, tangent_x, tangent_z);

    add_gerstner_wave(VERTEX.xz, t,
        wave_direction_deg.z, wave_frequency.z,
        wave_amplitude.z, wave_steepness.z,
        wave_speed.z, wave_phase_deg.z,
        displacement, tangent_x, tangent_z);

    VERTEX += displacement;
    NORMAL = normalize(cross(tangent_z, tangent_x));

    wave_height = displacement.y;
    wave_slope = 1.0 - NORMAL.y;
}
```
**关键细节**：

- **三条波必须有不同的方向角**——如果方向相同，叠加出来仍是"一条波"。
- **NORMAL = normalize(cross(tangent_z, tangent_x))**：从累加的偏导重建法线。这是物理上正确的做法——法线垂直于波面，而波面的切向量就是偏导方向。
- **wave_height 和 wave_slope 作为 varying 传入 fragment**：wave_height 用于后续的波峰颜色渐变和泡沫，wave_slope（1.0 - NORMAL.y）用于波峰泡沫检测——坡面越陡，wave_slope 越大。
**步骤 1 结果**：一个会起伏的水面，法线跟随波浪方向正确变化。如果在这里就配上光照，你会看到高光在波峰和波谷之间移动——比方案 A 的噪声位移更"像海面"。

### 3.2 步骤 2：法线贴图微细节叠加
Gerstner 波给出了大尺度的波浪形状，但缺少小尺度的表面纹理。法线贴图正好填补这个空缺——用两张法线贴图不同方向滚动，混合后叠加到 Gerstner 法线上。

```
group_uniforms normal;
uniform sampler2D normal_map1 : hint_normal, repeat_enable;
uniform sampler2D normal_map2 : hint_normal, repeat_enable;
uniform float normal_map_strength : hint_range(0.0, 2.0) = 0.8;
uniform float normal_map_scale = 5.0;
uniform vec2 normal_scroll1 = vec2(0.05, 0.1);
uniform vec2 normal_scroll2 = vec2(-0.08, 0.06);
group_uniforms;

void fragment() {
    float t = TIME * time_scale;

    vec2 nm1_uv = UV * normal_map_scale + t * normal_scroll1;
    vec2 nm2_uv = UV * normal_map_scale + t * normal_scroll2;
    vec3 nm1 = texture(normal_map1, nm1_uv).rgb;
    vec3 nm2 = texture(normal_map2, nm2_uv).rgb;
    vec3 nm_blended = normalize(vec3(nm1.xy + nm2.xy, nm1.z + nm2.z));
    vec3 enhanced_normal = normalize(NORMAL + vec3(nm_blended.xy * normal_map_strength * 0.3, 0.0));
    NORMAL = enhanced_normal;
```
关键技巧：**不替换，只叠加**。NORMAL + vec3(nm_blended.xy * strength * 0.3, 0.0) 把法线贴图的 XY 分量作为微扰加到 Gerstner 法线上——Z 分量补 0.0，不让贴图改变整体法线朝向；系数 0.3 手动压低，防止微扰盖过 Gerstner 波的大方向。两张贴图反方向滚动（normal_scroll1 vs normal_scroll2），混合后不会产生明显的重复模式。

**步骤 2 结果**：水面在 Gerstner 大波浪之上，多了细碎的表面纹理。近处能看到法线贴图带来的微小凹凸，远处 Gerstner 波主导视觉。

### 3.3 步骤 3：折射 —— SCREEN_TEXTURE 偏移
折射的本质不是"透明"，而是**光在水面处改变方向，导致水下物体看起来位置偏移**。在实时渲染中模拟这一点，不需要光线追踪——只需要偏移 SCREEN_UV，然后用偏移后的 UV 采样 SCREEN_TEXTURE。

```
group_uniforms screen;
uniform sampler2D screen_texture : hint_screen_texture, filter_linear_mipmap;
uniform sampler2D depth_texture : hint_depth_texture, filter_nearest;
group_uniforms;

group_uniforms refraction;
uniform sampler2D refraction_noise : repeat_enable;
uniform float refraction_strength : hint_range(0.0, 0.1) = 0.02;
uniform float noise_scale = 10.0;
uniform float noise_scroll_speed = 0.3;
group_uniforms;

    // 在 fragment() 中：
    vec2 noise_uv = UV * noise_scale + t * noise_scroll_speed;
    vec2 noise_offset = (texture(refraction_noise, noise_uv).rg * 2.0 - 1.0) * refraction_strength * 0.3;
    vec2 refract_offset = enhanced_normal.xy * refraction_strength + noise_offset;
    vec2 refracted_uv = SCREEN_UV + refract_offset;
```
折射偏移有两个来源：

- **法线方向**（主导）：enhanced_normal.xy * refraction_strength——水面法线越倾斜，折射偏移越大。这是物理上合理的：平的表面折射轻微，倾斜的表面折射显著。
- **噪声扰动**（辅助）：noise_offset 用一张噪声纹理添加微小的随机扰动（乘以 0.3 压低权重），让折射不完全由法线决定，增加自然感。
**为什么不用纯法线？** 法线贴图的方向在 UV 空间是规律的——在片元着色器中 enhanced_normal.xy 取决于法线贴图采样的位置。如果只用纯法线，折射的"扭曲感"会完全跟随法线贴图的模式，看起来像"透过有规律的毛玻璃看东西"而不是"水下扭曲"。噪声注入打破这种规律性。

**先埋个伏笔**：这一步的折射是"最直觉"的实现——偏移 UV、直接采样。它隐藏着一个 bug：偏移后的 UV 可能落在错误的物体上。我们先带着它继续，步骤 5 在拥有深度工具之后专门解决它。

### 3.4 步骤 4：深度重建与水下判定
有了深度纹理，我们就能回答两个问题：**"这个像素所在的物体离水面多远？"**（决定水的颜色深浅）和**"那个物体到底在水下还是水上？"**（决定要不要给它叠水色、做折射）。第二个问题看似简单，却是屏幕空间水体最容易翻车的地方。

首先把深度重建封装成函数：

```
// 从深度纹理重建指定屏幕 UV 处的场景几何。
// 返回值：视空间深度（沿视线轴，越大越远）
// out scene_world：场景点的世界坐标
// out depth_raw  ：原始深度值（≈1.0 表示该像素在深度快照时未被任何不透明物体写入，初始值 = 远平面距离）
float reconstruct_scene(vec2 screen_uv, mat4 inv_proj, mat4 inv_view,
                        out vec3 scene_world, out float depth_raw) {
    depth_raw = textureLod(depth_texture, screen_uv, 0.0).r;
    vec3 ndc = vec3(screen_uv * 2.0 - 1.0, depth_raw);
    vec4 view_pos = inv_proj * vec4(ndc, 1.0);
    view_pos.xyz /= view_pos.w;
    scene_world = (inv_view * vec4(view_pos.xyz, 1.0)).xyz;
    return -view_pos.z;
}
```

- 重建过程与方案 B 的 2.2.2 节完全相同：NDC → 逆投影 → 透视除法，得到视空间坐标。
- 多了两步：用 INV_VIEW_MATRIX 把视空间坐标再转回**世界空间**（马上就会用到），以及把原始深度值 depth_raw 一并带出（折射校验会用 depth_raw来识别"采样点后方有没有真实物体"。）。
- out 参数与步骤 1 的 inout 类似，用于从函数里带出多个返回值。

#### 水下判定：直觉做法为什么有问题
第2小节用的方法是**比较视空间深度 Z**：场景深度 > 水面深度 → 场景在水面后方 → 判为水下。

但是比较空间深度回答的是"谁在谁前面"，而水下判定需要回答的是"谁在谁**下面**"——这是两个不同的问题。无歧义的判据是**世界空间高度**：

```
    vec3 scene_world;
    float depth_raw;
    float scene_depth = reconstruct_scene(SCREEN_UV, INV_PROJECTION_MATRIX, INV_VIEW_MATRIX,
                                          scene_world, depth_raw);
    vec3 water_world = (INV_VIEW_MATRIX * vec4(VERTEX, 1.0)).xyz;
    float water_depth = -VERTEX.z;

    float height_diff = scene_world.y - water_world.y;
    // 如果height_diff > 0 → 场景点比水面点高 → 在水面之上，与遮挡关系无关
    float is_underwater = 1.0 - smoothstep(-0.05, 0.05, height_diff);
```

- 悬浮的立方体：场景点（立方体表面）比水面点（波峰）**高** → height_diff > 0 → is_underwater = 0 → 不叠水色。
- 真正浸在水中的物体：场景点比水面点**低** → 判为水下。
- 水线交界处：height_diff ≈ 0，smoothstep 提供 ±5cm 的软过渡带，避免硬切换闪烁。
- 在开阔水域处：远平面的世界 Y 远低于水面 → height_diff 为巨大负值 → smoothstep 直接输出 1.0。

#### 深度着色：浅水蓝，深水暗
判定对了，就可以做颜色。光在水中的吸收遵循 Beer-Lambert 指数衰减定律——水层越厚，透过的光越少、颜色越深：

```
group_uniforms depth;
uniform vec4 color_shallow : source_color = vec4(0.2, 0.6, 0.9, 0.6);
uniform vec4 color_deep    : source_color = vec4(0.02, 0.05, 0.2, 0.9);
uniform float depth_absorption : hint_range(0.5, 5.0) = 2.0;
uniform float depth_offset : hint_range(-2.0, 1.0) = -0.75;
group_uniforms;

    // 视线方向水层厚度：仅用于颜色深浅估计，不用于水下判定
    float water_column = max(scene_depth - water_depth, 0.0);
    float depth_blend = exp((-water_column - depth_offset) * depth_absorption);
    depth_blend = clamp(1.0 - depth_blend, 0.0, 1.0);
    vec3 depth_color = mix(color_shallow.rgb, color_deep.rgb, depth_blend);
```
注意这里**两个深度的分工**：判定"是否水下"用世界 Y（height_diff），估计"水有多深"仍用视空间 Z 差（water_column）。前者必须无歧义；后者只是颜色深浅的估计量，斜距近似足够用。depth_offset 为负值（-0.75）让浅水区扩大，防止整片水面看起来都是深蓝色。

**步骤 4 结果**：水中物体有了正确的深浅渐变，岸边水浅偏亮、远处水深偏暗；悬浮在水面上方的物体不再被错误地染上水色。

### 3.5 步骤 5：折射采样校验
步骤 4 修正了水下判定，但还存在潜在问题。**偏移后的 UV 可能落在水附近的物体上**。修复方法是对 refracted_uv 做一次深度复查——采样点如果比水面更靠近摄像机，就放弃这次折射偏移：

```
    // 对折射后的 UV 做深度复查
    vec3 refr_scene_world;
    float refr_depth_raw;
    float refr_scene_depth = reconstruct_scene(refracted_uv, INV_PROJECTION_MATRIX, INV_VIEW_MATRIX,
                                               refr_scene_world, refr_depth_raw);
    bool refr_hit_foreground = (refr_depth_raw <= 0.999)
                             && (refr_scene_depth < water_depth - 0.05);
    vec2 safe_refracted_uv = refr_hit_foreground ? SCREEN_UV : refracted_uv;
```

- refr_depth_raw <= 0.99999：采样点代表存在真实物体（不是远平面）。
- refr_scene_depth < water_depth - 0.05：且它比水面更靠近相机 → 它是前景物体，不该被"拖进"水里。
- 两个条件同时满足 → 退回未偏移的 SCREEN_UV。
所以，屏幕空间效果的正确性取决于两点：**决策用的数据是对的，采样用的数据也是对的**——两者独立，都要校验。

### 3.6 步骤 6：Fresnel + 组装 + 波峰颜色
Fresnel 与方案 A 相同：视线越平行于水面，反光越强。

```
group_uniforms Fresnel;
uniform float fresnel_power : hint_range(1.0, 10.0) = 3.0;
uniform float fresnel_intensity : hint_range(0.0, 1.0) = 0.6;
uniform vec4 fresnel_color : source_color = vec4(0.3, 0.5, 0.8, 1.0);
group_uniforms;

    float fresnel = 1.0 - abs(dot(normalize(enhanced_normal), normalize(VIEW)));
    fresnel = pow(fresnel, fresnel_power);
```
fresnel_color 是天空反射的近似色——在没有真正的环境反射（SSR、反射探针）的情况下，用这个纯色来做"水面反光的颜色"。fresnel_intensity 控制 Fresnel 效应的强度。

现在把屏幕色、深度色、Fresnel 组装起来：

```
group_uniforms specular;
uniform float specular_amount : hint_range(0.0, 1.0) = 0.8;
uniform float roughness_amount : hint_range(0.0, 1.0) = 0.2;
uniform float metallic_amount : hint_range(0.0, 1.0) = 0.0;
group_uniforms;

    // 屏幕颜色采样：水下用校验过的折射 UV，水上用原始 UV
    float screen_lod = min(depth_blend * is_underwater * 1.2, 1.5);
    vec2 final_screen_uv = mix(SCREEN_UV, safe_refracted_uv, is_underwater);
    vec3 screen_color = textureLod(screen_texture, final_screen_uv, screen_lod).rgb;

    // 颜色混合（两层：透射 + 反射）
    // 第一层 透射：光穿过水层到达眼睛。screen_color 是折射后的水下画面，
    //   depth_color 是水柱自身的吸收色，color_shallow.a 控制水的透明度。
    vec3 water_color = mix(screen_color, depth_color, color_shallow.a * is_underwater);
    // 第二层 反射：光在水面反弹。fresnel 越大 → 视线越平 → 反射越强，
    //   fresnel_color 越占主导。与水下内容完全无关，只与观察角度有关。
    water_color = mix(water_color, fresnel_color.rgb, fresnel * fresnel_intensity * is_underwater);
```
重要设计：

- **两层 mix 对应两个独立的光学通路**：透射（光穿过水面，看到水下）与反射（光在水面弹回，看到天空倒影）。写成两步不是开销，是可读性——每一步对应一个物理方程，单独调任何一个参数都不会破坏另一个。
- **final_screen_uv = mix(SCREEN_UV, safe_refracted_uv, is_underwater)**：水下区域用校验过的折射 UV，露出水面的区域用原始 UV（那里没有水，不需要折射）。
- **screen_lod = min(depth_blend * is_underwater * 1.2, 1.5)**：深水处用更高的 LOD（模糊），模拟"深水看不清水底"。乘以 is_underwater 让非水下像素保持清晰；上限钳到 1.5，防止远距离整片水面糊掉。
- **is_underwater 门控**：深度颜色、Fresnel、折射都只在水下区域生效。露出水面的物体不受水体颜色影响。
最后加一个便宜但有视觉效果的技巧：波峰处让水面微微变浅蓝。

```
uniform vec4 crest_color : source_color = vec4(0.6, 0.85, 0.95, 1.0);
uniform float crest_blend : hint_range(0.0, 1.0) = 0.3;

    float crest_weight = smoothstep(0.0, 0.3, wave_height) * crest_blend;
    water_color = mix(water_color, crest_color.rgb, crest_weight);

    ALBEDO = water_color;
    ROUGHNESS = roughness_amount;
    METALLIC = metallic_amount;
    SPECULAR = specular_amount;
```
wave_height 来自 vertex 阶段记录的 Gerstner 波位移量的 Y 分量。smoothstep(0.0, 0.3, wave_height)：波高在 0 到 0.3 之间做平滑过渡，波峰高度超过 0.3 时完全变为峰色。crest_blend = 0.3 保证峰色只做微妙的亮色叠加——不需要泡沫就有一定的视觉层次。

**步骤 6 结果**：低头看水透明、抬头看远反光，波峰处微微发亮——水面已经有了完整的光学表现。

### 3.7 步骤 7：泡沫系统 —— 岸边缘 + 波峰
泡沫是水体写实的最后一块拼图。方案 C 实现两类泡沫：

**岸边缘泡沫**：smoothstep 在水很浅的位置产生白色泡沫 mask，用泡沫纹理的 alpha 通道打破均匀色块。

**波峰泡沫**：用法线坡度（wave_slope = 1.0 - NORMAL.y）而不是波高来检测——波面越陡，泡沫越多。

```
uniform sampler2D foam_texture : source_color, repeat_enable;
uniform float foam_scale : hint_range(1.0, 50.0) = 15.0;
uniform vec2 foam_scroll = vec2(0.05, 0.08);
uniform float shore_start : hint_range(0.0, 2.0) = 0.2;
uniform float shore_end : hint_range(0.0, 2.0) = 0.05;
uniform float crest_threshold : hint_range(0.0, 0.5) = 0.15;

    // 岸边缘泡沫：水层越薄泡沫越多
    float shore_alpha = is_underwater * (1.0 - smoothstep(shore_end, shore_start, water_column));

    // 波峰泡沫：法线坡度越大（坡面越陡），泡沫越多
    float crest_foam = smoothstep(crest_threshold * 0.5, crest_threshold, wave_slope);

    float foam_mask = max(shore_alpha, crest_foam);

    vec2 foam_uv = UV * foam_scale + t * foam_scroll;
    vec4 foam_tex = texture(foam_texture, foam_uv);

    EMISSION = foam_tex.rgb * foam_mask * foam_tex.a;
    ALBEDO = mix(ALBEDO, foam_tex.rgb, foam_mask * foam_tex.a);
```
细节解析：

- **shore_alpha**：water_column 很小 → smoothstep 接近 0 → 1.0 - ... 接近 1.0 → 有泡沫。乘以 is_underwater 防止露出水面的物体边缘也产生泡沫。
- **crest_foam**：wave_slope 是 1.0 - NORMAL.y——平坦表面 NORMAL = (0, 1, 0) → slope = 0 → 无泡沫；陡坡 NORMAL.y 小 → slope 大 → 有泡沫。crest_threshold = 0.15 意味着法线偏离垂直方向约 8.6 度就开始出现泡沫。
- **max(shore_alpha, crest_foam)**：两种泡沫取最大值——不会互相抵消。
- **foam_tex.a**：泡沫纹理的 alpha 通道作为透明度 mask。foam_mask * foam_tex.a 意味着：在泡沫应该出现的地方（泡沫 mask=1），纹理 alpha 决定泡沫的可见度——产生"斑驳泡沫"而不是"整块白色"。
- **EMISSION + ALBEDO 双写**：EMISSION 让泡沫在逆光/暗光下依然可见（泡沫是白色的，自发光），ALBEDO 让泡沫接受场景光照。两者结合比只用一种更自然。
**步骤 7 完成。** 你现在有了一个完整的写实水体：Gerstner 波提供自然波浪 → 法线贴图提供微细节 → 折射扭曲水下世界 → 深度着色区分浅水深水 → Fresnel 实现近透远反 → 波峰颜色增加层次 → 泡沫系统连接水与岸边、展示浪花。

### 3.8 完整 shader 回顾
方案 C 的完整 shader 约 270 行，结构如下：

| 模块 | uniform 组 | 核心函数 |
| Wave | wave_* (vec3) | add_gerstner_wave() |
| Screen | screen_texture, depth_texture | reconstruct_scene() |
| Refraction | refraction_noise, refraction_strength | 折射 UV 深度复查 |
| Normal | normal_map1/2, normal_scroll1/2 | 法线贴图解包混合 |
| Depth | color_shallow/deep, depth_absorption, depth_offset | 世界 Y 水下判定 |
| Fresnel | fresnel_power, fresnel_intensity, fresnel_color | — |
| Specular | specular_amount, roughness_amount | — |
| Foam | foam_texture, shore_start/end, crest_threshold | — |

**render_mode 配置**：

```
render_mode blend_mix, depth_draw_always, cull_disabled, specular_schlick_ggx, diffuse_burley;
```

- blend_mix：透明混合模式——水面是半透明的
- depth_draw_always：强制写入深度缓冲——否则水下物体会渲染到水面上方
- cull_disabled：禁用背面剔除——水面是平面，从下方看时也需要渲染（水下视角）
- specular_schlick_ggx + diffuse_burley：指定高光和漫反射的 BRDF 模型
**性能注意事项**：
- 方案 C 需要 Forward+ 或 Mobile 渲染器（hint_screen_texture 和 hint_depth_texture 不兼容 Compatibility）
- 泡沫纹理采样和法线贴图采样是 fragment 中最大的开销——如果性能紧张，优先降低法线贴图分辨率或减少滚动层数
- vertex 阶段的 add_gerstner_wave 有较多三角函数计算——如果水体不需要近景写实，降回方案 A 或方案 B

## 4. 本章小结
本章介绍了三种不同复杂度的 3D 水体实现：

********************************
|  | 方案 A（低成本） | 方案 B（Toon） | 方案 C（写实） |
| 行数 | ≈60 | ≈70 | ≈270 |
| 波浪 | 噪声纹理位移 | 噪声纹理位移 + 梯度法线 | Gerstner 波 + 偏导法线 |
| 表面细节 | 双法线滚动 | 梯度法线（轻量） | 双法线叠加 Gerstner 法线 |
| 折射 | 无 | SCREEN_TEXTURE | SCREEN_TEXTURE（法线+噪声偏移） |
| 深度着色 | Fresnel 模拟 | DEPTH_TEXTURE 边缘 | Beer-Lambert 吸收 |
| 泡沫 | 无 | 深度边缘白线 | 岸边缘 + 波峰泡沫 |
| 光照 | 自定义 light() Blinn-Phong | 默认 PBR（高粗糙度） | 默认 PBR + 增强 SPECULAR |
| 需渲染器 | 任意 | Forward+ / Mobile | Forward+ / Mobile |

选择建议：
- **移动端 / 大量水体**：方案 A。噪声位移 + 法线贴图已经足以让水面"看起来在动"。
- **卡通 / 风格化项目**：方案 B。深度边缘白线 + caustic 纹理 + 高粗糙度 PBR = 干净的卡通水面。
- **写实项目 / 近景水体**：方案 C。Gerstner 波 + 折射 + 深度 + Fresnel + 泡沫 = 完整的水面表现。

如果你需要一个"只比方案 A 多一点点"的中间态：在方案 A 的基础上加入 SCREEN_TEXTURE 折射（步骤 3.3）和 DEPTH_TEXTURE 深度着色（步骤 3.4）——这就是约 100 行的"中间态水体"，性能开销可控，视觉质量大幅提升。
