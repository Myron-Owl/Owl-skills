# 第 5 章：基础数学函数

### 第 5 章：基础数学函数 —— 让画面动起来
**学习目标**：熟用 sin() / cos() / fract() / mod() / abs() / pow() / floor() / ceil() 八个核心数学函数，能独立实现周期动画和循环效果——让第四章的静止画面拥有节奏与脉搏。

**场景搭建**：在场景中新建一个 Sprite2D 节点（拖入任意贴图），为其新建 ShaderMaterial，再新建一个 canvas_item 类型的 shader 文件。以下所有代码片段直接替换该 shader 内容即可。不需要额外的 GDScript 脚本。

**内容要点**：

- sin() 与 cos()：周期运动的发动机。从裸 sin(TIME) 出发，5 步渐进构建呼吸发光
- 通用公式 sin(TIME × ω) × A + B：频率、振幅、偏置的直觉理解
- fract()：永不减速的循环引擎。fract() vs sin() 的视觉对照——前者线性复位，后者正弦减速
- mod()：取余制造空间重复——mod(UV.x, 0.2) 在画布上产生竖条纹
- abs() / pow() / floor() / ceil()：塑形函数速览，附视觉对照表
- 多频叠加：sin(t) + sin(t × 2.1) × 0.5 + sin(t × 5.2) × 0.25 ——从单一机械波动走向有机自然节奏
- 实战：呼吸发光特效 ——多频脉冲驱动 COLOR 亮度，让 Sprite2D 像呼吸一样明暗起伏

## 1. 为什么是数学：从静止到运动的跃迁
第 4 章给了你一个完整的 shader 骨架。你能让 Sprite2D 变成紫色、绿色、半透明——但它是静止的。无论你在编辑器里等多久，紫色永远是紫色。

问题在哪？COLOR = vec4(1.0, 0.0, 1.0, 1.0) 是一个常量。GPU 忠实地为每个像素执行这个赋值，40,000 次执行，每次结果完全相同。**要让画面动起来，我们需要一个变量——一个随时间不断变化的值。**

你在 ch4 的内置变量表中见过它：TIME。

TIME 是 Godot 自动注入的全局浮点数，记录引擎启动以来的秒数。它是一个不断增长的值——启动后第 1 秒 TIME = 1.0，第 60 秒 TIME = 60.0，第 3600 秒 TIME = 3600.0。但裸 TIME 本身没有节奏感——它只是一条单调上升的直线。把它直接放进 COLOR：

```
shader_type canvas_item;

void fragment() {
    COLOR = vec4(vec3(TIME), 1.0);
    // TIME=1.0 → 白色（溢出）；TIME>1.0 → 始终白色
}
```
结果：纯白。因为颜色通道的上限是 1.0，而 TIME 在 1 秒后就过去了。

我们需要的东西是——**把一个无限增长的数字，塑造成有节奏、有边界、有循环的波形**。这就是本章八个数学函数要做的事。它们是 shader 世界里最基础的"节奏工具箱"。可以把 TIME 想象成水龙头里流出的水——源源不断，没有形状。sin()、fract()、mod() 这些函数就是管道和阀门：它们改变水流的形状、速度和方向。本章的目标就是让你熟练使用这些"管道"。

## 2. sin() 与 cos()：shader 的心跳

### 2.1 sin 解决了一个问题：如何产生持续、平滑的往复运动
游戏里最常见的动态效果是什么？呼吸发光、标志闪烁、物品悬浮——它们的共同点：一个值在某个范围内来回摆动，不越界、不停滞。

sin(x) 恰好天然具备这种能力：
- 输入 x 从 0 到 2π（约 6.283），输出从 0 升到 1、降到 -1、再回到 0——刚好一个完整周期
- 输入 x 继续增长，输出循环重复——无限延续
- 波形是**平滑的**（sin 在任何一点都可导）：没有突变，没有锯齿

这就是为什么 sin 是 shader 里"动态"一词的第一个代数具象。

**为什么不用 GDScript 控制？** 在 GDScript 中你可以用 _process(delta) 逐帧改变一个属性——但那是 CPU 逐帧跑逻辑、再通过 uniform 传进 shader。如果你有 100 个 Sprite，每个都需要独立的呼吸节奏，意味着 CPU 每帧要计算 100 次波形、更新 100 个 uniform。而 sin 写在 shader 里，每个像素独立计算，GPU 的并行特性让 100 个呼吸和 1 个呼吸的代价几乎一样。

### 2.2 5 步渐进构建呼吸发光
我们不一次性把最终代码贴出来再回头解释——每一步只加一样东西，每一步你能看到效果变化。

#### 第 1 步：裸 sin(TIME) —— 认识波形

```
shader_type canvas_item;

void fragment() {
    float wave = sin(TIME);
    COLOR = vec4(vec3(wave), 1.0);
}
```
保存。你的 Sprite2D 动了——以约 6.28 秒为周期，颜色从灰白渐变到黑色、再从黑色渐变回灰白。

但你实际看到的是什么？并不是平滑的亮→暗→亮，而是亮→黑→黑→黑→半亮→亮——闪烁中间有一段死寂的纯黑。

**为什么会这样？** sin(TIME) 的输出范围是 [-1.0, 1.0]。当输出为负值时，vec3(wave) 的三个分量全为负——颜色通道不能表示负值，GPU 将其钳制为 0.0（纯黑）。你在屏幕上看到的亮度轨迹是：……白 → 黑 → 黑 → 黑 → 半白 → 白 → ……——波形被"削底"了。

#### 第 2 步：控制频率 —— 让变化快起来
一个周期 6.28 秒太慢了。你想要一秒两次的呼吸节奏。把 TIME 乘以一个系数：

```
float wave = sin(TIME * 2.0);
```
TIME * 2.0 的效果：1 秒内 TIME 从 0 增到 1，TIME * 2.0 从 0 增到 2。sin 的输入变化速度加倍，输出周期缩短为一半。我们说"频率为 2"。

但底削的问题还在——输出的负半周依然被截断为黑色。

#### 第 3 步：加振幅 —— 控制摆动的幅度

```
float wave = sin(TIME * 2.0) * 0.5;
```
现在 wave 的范围从 [-1.0, 1.0] 缩小到 [-0.5, 0.5]。乘以 0.5 就是**振幅**（amplitude）的作用：不改变频率，但压缩或拉大波形的峰值高度。

问题是幅度小了，但负数依然在——颜色仍然有一半时间是黑的。我们真正想要的是一个在 [0, 1] 之间光滑摆动的值。

#### 第 4 步：加偏置 —— 把波形抬到正值区

```
float wave = sin(TIME * 2.0) * 0.5 + 0.5;
```
+ 0.5 是**偏置**（offset / bias）。它将整个波形垂直平移 0.5 个单位。变换过程：

```
sin(TIME * 2.0)           → [-1.0, 1.0]      ← 原始正弦
* 0.5                     → [-0.5, 0.5]      ← 施加振幅
+ 0.5                     → [ 0.0, 1.0]      ← 施加偏置
```
现在 wave 的范围是精确定义的 [0.0, 1.0]——不越界、不截断、不断黑。你的 Sprite2D 平滑地在黑白之间渐变，整整一个周期全是可见的。

这一刻你已经引出了 shader 动画的通用公式：

```
通用周期公式：sin(TIME × ω) × A + B
```

| 参数 | 角色 | 取值范围 | 如果你增大它…… |
| ω（omega） | 频率 —— 决定变化快慢 | 任何正值 | 波形加速，周期缩短 |
| A（amplitude） | 振幅 —— 决定摆动幅度 | 任何非负值 | 波形"拉高拉低"，亮暗对比加大 |
| B（bias） | 偏置 —— 决定波形的中心位置 | 任何值 | 整体向亮（+B）或暗（-B）平移 |

#### 第 5 步：驱动 Sprite 的亮度 —— 真正的"呼吸"
现在 wave 已经是一个完美的 0→1 脉冲信号。接下来把它接上画面的颜色输出。我们不直接输出灰度——我们要让 Sprite 自身的纹理参与进来，用 wave 控制它的亮度：

```
shader_type canvas_item;

void fragment() {
    float pulse = sin(TIME * 2.0) * 0.5 + 0.5;
    vec4 tex = texture(TEXTURE, UV);
    COLOR = vec4(tex.rgb * pulse, tex.a);
}
```
分解这 3 行：
- float pulse：这是我们刚才花了 4 步锻造出的 0→1 脉冲信号
- vec4 tex = texture(TEXTURE, UV)：这行代码是你在全书第一次调用 texture() 函数，值得放慢看。

**texture() 是 shader 里的"查色"函数**——给定一张贴图和一个 UV 坐标，它返回贴图上对应位置的颜色值。它有两个参数：第一个是"查哪张贴图"（TEXTURE，当前 Sprite2D 绑定的纹理），第二个是"查贴图的哪个位置"（UV，当前像素的纹理坐标）。GPU 自动把 Sprite2D 的图标纹理和四个顶点的 UV 坐标对接好，你不需要手动做任何绑定——写 texture(TEXTURE, UV) 就完成了"取当前像素的贴图颜色"这一整步。

**那 TEXTURE 和 UV 是从哪来的？** 它们都是内置变量，不需要你声明。TEXTURE 的类型是 sampler2D（一个"纹理句柄"，指向 Sprite2D 节点上挂载的贴图资源），UV 是 vec2，代表当前片元对应的纹理坐标。ch4 的变量表中提过它们，但现在是第一次实际使用——你不需要给它们赋值，只需要把它们喂给 texture()。

**返回值是一个 vec4**——RGBA 四个分量，代表贴图在这个像素上的颜色和透明度。所以 tex.rgb 是颜色的红绿蓝三个通道，tex.a 是 Alpha 透明度。后面的 tex.rgb * pulse 只改变颜色的亮度（RGB），不动透明度。

- COLOR = vec4(tex.rgb * pulse, tex.a)：将贴图的 RGB 通道乘以 pulse。pulse=1.0 时贴图原色输出（最亮），pulse=0.0 时贴图全黑（最暗），中间值线性过渡。Alpha 通道保持不变——我们不改变透明度，只改变亮度
保存。你的 Sprite2D 像在呼吸——亮起、暗下、亮起、暗下。你刚刚完成了人生中第一个 shader 动画。

### 2.3 cos()：sin 的兄弟函数
cos(x) 与 sin(x) 的波形完全相同——只是水平偏移了 π/2（约 1.57 个单位）。cos(0) = 1.0（从峰值开始），而 sin(0) = 0.0（从零点开始）。

在 shader 里用 sin 还是 cos，99% 的情况下没有本质区别——你是在用它们的**波形形状**，而不是绝对相位。不过有一个惯例：
- 需要从 0 开始变化的：用 sin
- 需要从峰值开始变化的：用 cos

在你刚完成的呼吸发光里，把 sin 换成 cos——效果几乎一样，只是起始亮度不同。试试看。

## 3. fract()：永不减速的循环引擎

### 3.1 fract 解决了一个问题：如何制造不停滞的线性循环
sin() 有一个视觉特征：波形在波峰和波谷处**减速**——变化率接近零，给人"停顿"的感觉。这对于呼吸、悬浮等有机运动恰好是优点；但如果你想要一个进度条、一个持续滚动的 UV、一个永不减速的节奏——sin 的"峰谷减速"就成了阻碍。

一个关键的认知锚点：sin 改变的是'速度本身'——速度在变化（峰谷处慢、中间快），所以波形有平滑的曲率；fract 改变的是'位置'——速度始终不变，只是在区间边界处瞬间复位。sin 是'呼吸'，fract 是'秒表'。

fract(x) 是"取小数部分"：

```
fract(1.3) = 0.3
fract(2.7) = 0.7
fract(3.0) = 0.0   ← 恰好整数，归零
fract(3.1) = 0.1
```

定义：fract(x) = x - floor(x)，即"削掉整数部分，只留小数"。它把任何输入值折叠进 [0.0, 1.0) 区间。

**为什么不用整数做循环？** 如果你有一个从 0 到 1 的变量，一旦到 1 它就不会自动回到 0——你需要写一个 if 判断。但在 GPU 上 if 分支成本高。fract() 用一次纯数学运算完成"归零-重来"——没有分支。

### 3.2 sin vs fract：视觉对照
下面两张"图"不是贴图——是你 shader 输出的颜色。试着分别跑这两个版本，对比 Sprite2D 的亮度变化节奏：

```
// 版本 A：sin 周期（平滑，峰谷减速）
void fragment() {
    float sin_pulse = sin(TIME * 2.0) * 0.5 + 0.5;
    COLOR = vec4(vec3(sin_pulse), 1.0);
}
```

```
// 版本 B：fract 循环（线性，瞬间复位）
void fragment() {
    float fract_loop = fract(TIME * 0.5);
    COLOR = vec4(vec3(fract_loop), 1.0);
}
```
运行版本 B：Sprite2D 的亮度匀速从黑涨到白，到顶后**瞬间跳回黑色**再开始下一轮。"匀速"是因为 TIME * 0.5 匀速增长，fract() 保留的小数部分也是匀速的——没有 sin 的曲率。"瞬间归零"发生在 TIME 恰好经过 2.0、4.0、6.0……等 TIME * 0.5 恰好为整数的时刻。

**选型指南**：
- 呼吸、悬浮、水波 → sin（有机、平滑、减速感天然符合物理直觉）
- 进度条、滚动 UV、计时指示器 → fract（匀速、永不减速、切换干脆）
- 如果你不确定：让 Sprite2D 跑两个版本各 10 秒，眼睛会告诉你答案

### 3.3 fract 的经典应用场景
fract() 最典型的用途是让某个值在 0→1 之间无限循环，同时保持恒定速度。比如 ch13 会讲的彩虹流光：

```
float hue_shift = fract(TIME * 0.1);  // 每 10 秒完成一圈色相循环
```
ch16 的 CRT 扫描线也依赖 fract(UV.y * line_count + TIME * scroll_speed) 来实现无限滚动的横线。fract 是 shader 里"无限滚动"这个词的代数等价物。

## 4. mod()：在空间上制造重复

### 4.1 mod 解决了一个问题：如何把一段有限范围无限重复
mod(a, b) 返回 a 除以 b 的**余数**。与 fract() 的关系：fract(x) 本质就是 mod(x, 1.0)——取除以 1.0 的余数。

但 mod() 的除数是**可定制的**：

```
mod(3.7, 2.0) = 1.7    ← 3.7 ÷ 2.0 = 1 余 1.7
mod(0.3, 0.2) = 0.1    ← 0.3 ÷ 0.2 = 1 余 0.1
mod(0.75, 0.2) = 0.15  ← 0.75 ÷ 0.2 = 3 余 0.15
```

fract() 只能把值折叠进 [0, 1)；mod() 能把值折叠进任意区间 [0, divisor)。

在继续之前，先建立 fract 和 mod 的统一认知：**它们的本质是同一个操作——把无限线性增长的值折叠进有限区间。** 它们的区别仅在于折叠区间的跨度：fract() 固定折叠进 [0, 1)——适合时间循环；mod() 的折叠区间由第二个参数指定——既可以做时间循环，也可以做空间重复。理解了这个统一模型，fract 和 mod 就不再是'两个函数'，而是'同一个工具的两个变体'。

### 4.2 从时间循环到空间重复
上一节你用 fract(TIME * 0.5) 在**时间维度**上制造了循环。现在用 mod() 在**空间维度**上制造重复——用 UV 坐标：

```
shader_type canvas_item;

void fragment() {
    float stripes = mod(UV.x, 0.2);
    COLOR = vec4(vec3(stripes), 1.0);
}
```
发生了什么：UV.x 从 0 到 1 贯穿 Sprite 的水平方向。mod(UV.x, 0.2) 把这条线切成了 5 段——每 0.2 个单位复位一次。效果是 5 条从左到右由黑到白的渐变条纹，每一条都是上一段的精确复制。

**为什么会有图案？** 因为 mod 的输出在每段内从 0 到 0.2 线性增长，到了 0.2 的倍数就跳回 0。这个"线性增长→瞬间归零"就是 fract() 在时间维度做的事——现在用 mod() 搬到了空间维度。颜色由 mod 值控制：0 是黑，0.2 是灰白——每段独立重复。

加上一步让条纹变成**纯色块**而不是渐变：

```
float stripes = step(0.1, mod(UV.x, 0.2));
```
step(0.1, x) 返回：x ≥ 0.1 时为 1.0，否则为 0.0。现在你得到的是 5 组黑白条纹——第 6 章的 step() / smoothstep() 会详细展开这一技巧。

### 4.3 mod 的另一个用途：限制范围
mod() 也常用于把一个值钳制在某个区间内——比如把角度限制在 [0, 2π) 或 [-π, π) 范围。目前阶段，你只需要记住：mod() 是"无限重复"的数学工具，既可重复时间（与 fract 同族），也可重复空间（与 UV 配合）。

## 5. abs / pow / floor / ceil：塑形函数速览
这四个函数的使用频率不如 sin/fract/mod，但在特定场景中它们是不可替代的工具。下面用一张表对照它们的输入-输出形状——你不需要背诵，只需要在脑中建立"这个函数会让波形变成什么形状"的视觉印象。

| 函数 | 输入范围 | 输出特点 | 在 shader 中的典型用途 | 视觉形状 |
| abs(x) | 任何值 | 负值翻转为正值。abs(-0.5) = 0.5 | 制造 V 形对称图案；做"SDF 距离"（距离不能为负） | \_/ |
| pow(x, n) | x > 0 最常用 | n>1 压缩暗部、0<n<1 提亮暗部。pow(0.5, 2) = 0.25 | Gamma 校正（pow(color, 2.2)）；自定义衰减曲线 | J 形，n>1 越弯 |
| floor(x) | 任何值 | 向下取整。floor(2.7) = 2.0 | 像素化（floor(UV * res) / res）；瓷砖贴图索引 | 阶梯（左开右闭） |
| ceil(x) | 任何值 | 向上取整。ceil(2.3) = 3.0 | 配合 floor 做像素对齐；性能场景中的"保证不小于" | 阶梯（左闭右开） |

### 5.1 逐函数一张图：输出长什么样
以下每个片段你都可以直接粘贴进 fragment() 里跑一次——哪个 Sprite 颜色在上下文中最直观就用哪个。对照着"视觉形状"那一栏的文字描述，看屏幕上的实际渐变方向。

**abs()**：在 Sprite 上观察到从 UV=0.5 为中心向两侧对称的 V 形渐变。因为 abs 把 0.5 左侧的负值"折叠"到了正值一侧：

```
float v = abs(UV.x - 0.5);
COLOR = vec4(vec3(v * 2.0), 1.0);
// 中间 UV.x=0.5 → abs(0)=0 → 黑
// 两侧 → abs(±0.5)=0.5 → ×2=1.0 → 白
```
**pow()**：n=2（平方）让中间调变暗；n=0.5（开方）让暗部提前变亮：

```
float v = pow(UV.x, 2.0);   // 试试 2.0 → 0.5 → 4.0
COLOR = vec4(vec3(v), 1.0);
// pow(0.5, 2) = 0.25 ← 暗部被压缩
// pow(0.5, 0.5) = 0.71 ← 暗部被提亮
```
**floor()**：在 Sprite 上看到几道等宽的纯色台阶：

```
float steps = 5.0;
float v = floor(UV.x * steps) / steps;
COLOR = vec4(vec3(v), 1.0);
// floor(UV.x*5) 输出 0,1,2,3,4 五个台阶 → ÷5 缩回 [0,1]
```
**ceil()**：与 floor 类似，但每级台阶的"起跳点"不同：

```
float steps = 5.0;
float v = ceil(UV.x * steps) / steps;
COLOR = vec4(vec3(v), 1.0);
// ceil(0.01*5) = ceil(0.05) = 1.0 → 台阶从接近 0 处就起跳
```
**此时不必深挖每个函数的所有用法**。本章的目的是让你在看到 pow、floor、abs 时不再陌生——你知道它们大致会把一个数值"捏"成什么形状。真正需要精确调用时，把上面的代码重新跑一次，看着屏幕调参数，10 秒就能找回手感。

---

### 为什么 GPU 喜欢这些函数：无状态 + 可并行的优势
这些数学函数的真正价值不在于它们的数学定义，而在于一个 GPU 硬件层面的事实：**每一个片元着色器调用执行 sin(x) 或 fract(x) 时，既不需要读取任何外部内存（无状态），也不需要参考相邻像素的结果（无依赖）。** 这意味着几万个像素的波形计算可以完全并行执行——没有等待、没有锁、没有内存争用。这是为什么 shader 能用纯数学运算实现成千上万独立动画的核心原因。相比之下，在 CPU 上用 GDScript 驱动同样的效果，你需要为每个对象维护状态变量、逐帧更新、通过 uniform 传入 shader——而直接把 sin 写在 fragment 里，成本趋近于零。

## 6. 多频叠加：从机械到有机

### 6.1 单频的局限
你现在的呼吸脉冲是 sin(TIME * 2.0) * 0.5 + 0.5——一个完美的正弦波。但"完美"在视觉上意味着**可预测、单调、机械**。真正的呼吸不是等速等幅的正弦波：吸气和呼气的节奏不对称，偶尔会有微小的不均匀。

你需要的不只是一个波——是**多个波的叠加**。

### 6.2 为什么是"S"形：多频叠加的直观效果
看下面两组脉冲——你把它们分别跑在 Sprite 上，感受差异：

```
// 单频：规整，但像节拍器
float pulse_a = sin(TIME * 2.0) * 0.5 + 0.5;
```

```
// 多频：有机物感——像真实的呼吸或烛火
float pulse_b = sin(TIME * 2.0) * 0.6
              + sin(TIME * 4.1) * 0.3
              + sin(TIME * 9.3) * 0.1;
pulse_b = pulse_b * 0.45 + 0.5; // 归一化到 [0.05, 0.95]
```
单频（pulse_a）你会看到一个均匀、对称、完全可预测的呼吸——每一拍和前一拍一模一样。多频（pulse_b）则不同：起伏有了"重音"，某些周期比其他周期略强或略弱，浅层节奏上叠加了更细碎的微动。

### 6.3 通用多频模板
多频叠加有三条设计规则：

**规则 1：高频的振幅必须递减。** 如果三个波振幅相同（都是 1.0），叠加结果会超出 3.0——波形被硬钳制，细节丢失。递减系数没有固定值：0.6 + 0.3 + 0.1 是一个安全的经验起始点（大致按 1/n 衰减）。

**规则 2：频率不要用整数倍。** 整数倍频率 = 强同步，节奏感强，但更机械（波形周期存在公共最小公倍数，整体周期性打不破）；非整数倍频率（如 4.1、9.3）= 去同步，频率之间不会形成固定的相位锁定关系，波形更像自然现象。这个技巧在 ch7 的 FBM 噪声中会以更系统的方式重现。

**规则 3：不要超过 3-4 层。** 在 canvas_item fragment 中，每多加一个 sin() 运算对性能的影响微乎其微——但 4 层以上的叠加在视觉上已经很难区隔，属于浪费。

将上述规则提炼为一个可直接套用的模板：

```
float multi_wave = sin(TIME * f1) * a1    // 主频：最大振幅
                 + sin(TIME * f2) * a2    // 次频：中等振幅
                 + sin(TIME * f3) * a3;   // 高频：最小振幅
// f1 < f2 < f3；a1 > a2 > a3；所有 f 为非整数倍关系
float pulse = multi_wave * 0.5 + 0.5;     // 映射到 [0, 1]
```
以后你在任何 shader 里需要"有机的、活生生的波动"时，调出这个模板，改三个频率三个振幅——10 秒就能替代一个生硬的单频正弦。

## 7. 本章实战：呼吸发光特效
现在把前六节学到的东西熔为一炉。下面的代码就是本章交付的 pulse.gdshader——也是你人生中第二个完整的 shader（第一个是 ch4 的紫色精灵）。

```
shader_type canvas_item;

void fragment() {
    // 多频叠加脉冲：三个不同频率的正弦波叠加
    float pulse = sin(TIME * 2.0) * 0.6
                + sin(TIME * 4.1) * 0.3
                + sin(TIME * 9.3) * 0.1;

    // 归一化：从 [-1.0, 1.0] 映射到 [0.05, 0.95]
    // 最低亮度 0.05 而非 0——永远不会完全暗灭
    pulse = pulse * 0.45 + 0.5;

    // 获取原始贴图颜色
    vec4 tex = texture(TEXTURE, UV);

    // 用脉冲值驱动亮度：暗时 ×0.05 → 亮时 ×0.95
    float brightness = 0.05 + pulse * 0.95;
    COLOR = vec4(tex.rgb * brightness, tex.a);
}
```
逐行解释：

| 行 | 代码逻辑 | 对应的章节知识 |
| 第 5–7 行 | 三个频率的 sin 叠加：f1=2.0、f2=4.1、f3=9.3，振幅递减 0.6→0.3→0.1 | 第 6.3 节（多频叠加） |
| 第 10 行 | pulse * 0.45 + 0.5：振幅 0.45，偏置 0.5，输出范围 [0.05, 0.95] | 第 2.2 节（通用公式） |
| 第 13 行 | texture(TEXTURE, UV)：获取 Sprite 的原始贴图 | ch4 内置变量表 |
| 第 16 行 | tex.rgb * brightness：亮度调制——不改变色相，不改变 Alpha | 第 2.2 节第 5 步 |

**为什么最低亮度是 0.05 而非 0.0？** 完全熄灭到 0.0 在视觉上像是 Sprite"消失了一瞬间"——对于呼吸发光而言过于剧烈。0.05 保留了一线可见度，过渡更柔和。你可以把 0.05 改成 uniform float min_brightness 让它在编辑器中可调。

如果你想让这个呼吸光效在游戏中有开关控制——比如角色受伤时才呼吸红光——加一行 uniform：

```
uniform float intensity : hint_range(0.0, 1.0) = 1.0;
```
然后把 brightness 的计算改为：

```
float brightness = mix(1.0, 0.05 + pulse * 0.95, intensity);
```
mix(a, b, t)：t=0 时取 a，t=1 时取 b，中间线性过渡。当 intensity = 0.0 时，Sprite 原色输出（无呼吸）；当 intensity = 1.0 时，全呼吸效果。GDScript 中用一句 tween 从 0 驱动到 1 就能实现"受到伤害 → 开始呼吸红光"的过渡。

## 本章小结
本章以 TIME 为起点，沿着两个轴线构建了 shader 动画的基础函数体系：

- **时间轴工具（驱动动画）**：sin（平滑往复）、cos（同族偏移）、fract（线性循环）——它们接受 TIME 作为输入，输出随时间变化的波形。
- **空间轴工具（塑造图形）**：mod（空间重复）、abs（对称折叠）、pow（伽马塑形）、floor/ceil（量化分级）——它们操作 UV 坐标，在画布上生成图案。
核心公式 sin(TIME × ω) × A + B 是本章的最大收获——它让你能从零开始构造任何周期性动画。多频叠加是从"机械"走向"有机"的关键技巧：高频低振幅的去同步波叠加，打破单频的可预测性。所有这些函数共享 GPU 最喜欢的特质：无状态、无依赖、可完全并行——这就是为什么把波形计算直接写在 fragment 里比 CPU 驱动高效得多。
