# lmeeting

面向游戏项目的会议 Skill，用于筹备、主持和整理创意探索、玩法与系统评审、美术选型、技术方案、排期协作、试玩与缺陷评审、里程碑验收及复盘。

## 核心方法

```text
明确会议目的与结束条件
  → 核对共同材料、客观事实与项目约束
  → 从意见和分歧中定位可验证的问题
  → 分析原因，寻找解决方法
  → 作出决定或设计最小验证
  → 明确负责人、期限和验收条件
```

有候选方案时，先按客观因素筛选。主观意见用于发现遗漏的问题；能在项目约束内解决的问题可以保留或调整，原因和办法尚未证实时进入验证，无法解决或代价超界时再排除。

## 支持的会议

- 创意探索
- 玩法、系统、关卡、叙事与 UI 评审
- 美术风格选型
- 技术方案讨论
- 排期与范围会议
- 进度和跨部门协调
- 试玩与缺陷评审
- 里程碑验收
- 项目复盘

技能会按会议目的选择流程。创意会先形成备选方案，协调会处理阻塞与交接，验收会核对既定标准，复盘会还原事实并落实改进。

## 美术风格选型

美术会议保留专用流程：

1. 按技术可实现性、平台适配、游戏设定和其他制作因素逐轮筛选。
2. 从参会人的排除意见中寻找客观原因，并讨论解决方法。
3. 确定保底参考、追赶目标、平级局部参考。
4. 将三个参考组合成一种可执行的项目风格。
5. 通过目标引擎、镜头和设备中的代表性小样验证。

## 调用示例

```text
使用 $lmeeting 帮我准备一次战斗系统评审会，列出会前材料、45 分钟议程、主持问题和会后记录模板。
```

```text
使用 $lmeeting 整理这份试玩会记录，区分玩家观察、体验反馈、原因假设、已定结论和验证任务。
```

```text
使用 $lmeeting 筹备美术风格会议，从候选游戏中筛选三个参考并形成小样验收计划。
```

## 安装

使用 Owl-skills 根目录的安装脚本，可同时安装到 Claude Code 与 Codex 的技能目录。也可将整个 `lmeeting` 目录复制到：

```text
~/.codex/skills/lmeeting/
```

重新打开任务后，使用 `$lmeeting` 调用。
