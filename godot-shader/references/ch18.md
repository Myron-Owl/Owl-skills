# 第 18 章：3D 顶点动画与形变

### 第 18 章：3D 顶点动画与形变 —— 让模型"活"起来
**学习目标**：掌握 spatial shader 的 vertex() 处理器中修改 VERTEX 的核心技法，能独立实现地形顶点位移、3D 冲击波、植被风动和 Billboard（广告牌）四种 3D 顶点动画效果，理解模型空间与世界空间的坐标转换在顶点形变中的角色，并能判断何时用 Vertex Shader、何时用 Fragment Shader。

**场景搭建**：地形位移效果：MeshInstance3D + PlaneMesh（将 Subdivisions 设为 32×32 以上以确保有足够的顶点可供变形），挂载 ShaderMaterial。冲击波效果：MeshInstance3D + PlaneMesh挂载 ShaderMaterial。植被风动效果：MeshInstance3D + 导入 .glb 树模型，挂载 ShaderMaterial。Billboard 效果：MeshInstance3D + QuadMesh 。所有效果均使用 spatial 类型 shader。

**内容要点**：

- 3D VERTEX 是 vec3，在模型空间（Model Space）。回顾 ch3 的 3D 空间变换链：Model → World → View → Clip → NDC → Screen
- 地形顶点位移：噪声高度图驱动 VERTEX.y += height，用 varying vec2 将采样坐标从 vertex 传到 fragment，实现 Z+（高度）位移与材质的联动
- 3D 冲击波：世界空间计算距离 → smoothstep 构造环形波 → VERTEX += NORMAL * ring_amplitude，与 GDScript 协作驱动 shockwave_percentage
- 植被风动：分步构建——全局摆动 → 空间差异化 → 根固定 → 噪声驱动自然摆动
- Billboard（始终朝向摄像机）：render_mode skip_vertex_transform 跳过自动变换管线，从 INV_VIEW_MATRIX 提取相机方向，手动重建世界坐标并写入 POSITION。这是本章唯一一个**不修改 VERTEX、而是直接计算 POSITION** 的案例，难度明显更高

## 1. 从 2D 到 3D：vertex() 的升级
第 12 章你在 canvas_item 的 vertex() 里修改 VERTEX——一个 vec2，代表精灵四个角的局部坐标。2D 的形变是平面的：你只能在一个扁平的矩形上做 Y 方向升降和 X 方向拉伸。进入 3D，一切都不一样了：

|  | 2D canvas_item | 3D spatial |
| VERTEX 类型 | vec2 | vec3 |
| 顶点数量 | 4（Sprite2D 的四角） | 数百~数万（取决于模型面数） |
| 形变维度 | X/Y 平面内 | X/Y/Z 三轴任意方向 |
| 空间参考 | 局部坐标，pixel 单位 | 模型空间（Model Space），米制单位 |
| 额外可用变量 | UV, COLOR | UV, COLOR, NORMAL, TANGENT, BINORMAL, MODEL_MATRIX, VIEW_MATRIX, NODE_POSITION_WORLD, CAMERA_POSITION_WORLD |

**3D vertex() 解决的核心问题**：当一个 PlaneMesh 有 33×33 = 1089 个顶点时，vertex() 在每个顶点上执行一次——1089 次并行调用。你写一次形变公式，GPU 把它同时应用到上千个顶点上。这使得"让一块平面变成起伏的山丘"在一行代码内成为可能。

## 2. 坐标空间回顾：VERTEX 在哪里
VERTEX 是模型空间（Model Space）下的坐标。模型空间以物体自身为参照系：原点在物体的 (0,0,0)，平面模型的中心在原点，X 轴向右、Y 轴向上、Z 轴向后。

要让形变"与外部世界交互"（如冲击波从世界中的某个点向外扩散），你需要把 VERTEX 转换到世界空间：

```
vec3 world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz;
```
MODEL_MATRIX 是一个 mat4，它把模型空间的 (x, y, z) 映射到世界空间的 (x', y', z')。乘以 MODEL_MATRIX 后，坐标就"脱离"了物体自身，进入了世界坐标系——你可以用这个坐标与世界空间中的点做距离比较。

**为什么是 vec4(VERTEX, 1.0)？** ch2 讲过：3D 变换（旋转、缩放、平移）在数学上需要 4D 齐次坐标才能统一为一次矩阵乘法。第 4 维 w = 1.0 表示"这是一个位置"，而非方向（方向用 w = 0.0）。

NORMAL 同样是模型空间下的方向向量（w = 0.0）。这意味着如果你沿法线方向推顶点——VERTEX += NORMAL * amount——你是在模型空间的局部法线方向上位移。这对大多数形变（地形隆起、护盾膨胀、布料出平面）是正好的，因为"沿局部表面外推"天然就是模型空间的操作。

## 3. 3D 模型导入与纹理基础
在做植被风动等效果之前，你需要知道如何把外部 3D 模型和纹理导入 Godot。

### 支持的 3D 格式
Godot 原生支持 .glb（glTF Binary）格式，这是推荐格式——它把模型网格、材质、动画打包成一个文件。其他常见格式包括：

- .glb / .gltf：推荐，开源标准，支持 PBR 材质和动画
- .obj：老式文本格式，只存网格和基础材质，不含动画
- .fbx：Autodesk 私有格式，Godot 通过 fbx2gltf 导入为 glTF
将文件直接拖入 FileSystem 面板即可。导入后，Godot 自动生成 .import 文件和一个场景（Scene），双击场景即可在 3D 视口中看到模型。默认情况下场景是只读的，如果要修改模型的材质，需要右键选择继承创建（New Inherited Scene），来创建一个新的3D场景，在这个场景中才可以打开并修改对应mesh节点的material。

### 纹理通道速查
导入模型后，它的材质通常会引用多张纹理。在 shader 中，最常见的纹理类型：

| 纹理 | Shader 变量 | 用途 |
| Albedo / Base Color | ALBEDO | 表面颜色（RGB），透明确度可选（A） |
| Normal Map | NORMAL_MAP | 表面凹凸细节，不改变几何体 |
| Roughness | ROUGHNESS | 表面粗糙度（0 = 镜面，1 = 漫反射） |
| Metallic | METALLIC | 金属度（0 = 非金属，1 = 全金属） |
| Emission | EMISSION | 自发光颜色，不受场景光照影响 |

植被通常使用一张 Albedo 纹理（带 Alpha 通道做叶片镂空）和一张 Normal Map。你可以在 ShaderMaterial 的 Shader Parameters 中把这些纹理拖入对应 uniform slot。

## 4. MeshInstance 中 Material 的位置
在 MeshInstance3D 节点中，有多个地方可以设置材质，它们有不同的优先级：

| 位置 | 说明 | 优先级 |
| Mesh → Surface Material | 在 Mesh 资源内部，针对某个 surface 指定材质 | 最低（被 override 覆盖） |
| GeometryInstance3D → Material Override | 对节点所有 surface 统一覆盖 | 中（覆盖 Mesh 内置材质） |
| GeometryInstance3D → Surface Material Override | 按 surface 序号分别覆盖 | 最高 |

**实用原则**：如果你想临时替换某个 MeshInstance 的材质（比如给所有树统一挂一个风动 shader），用 Material Override。如果想保留模型自带的大部分材质、只替换其中一个 surface，用 Surface Material Override。

在编辑器中，选中 MeshInstance3D 节点，在 Inspector 的 GeometryInstance3D 分类下即可找到这些属性。在 ShaderMaterial 的 Shader Parameters 中，你可以拖放纹理资源到对应的 uniform 槽位、也可以调整数值型参数。

## 5. 地形顶点位移
第 7 章你用噪声纹理在 fragment 里给像素上色，做出类似地形的视觉。但这只是颜色——模型表面本身是平的。vertex() 中的噪声高度图能让模型表面**真的**凸起。

**关键认知**：GPU 实际上并没有增加新的顶点，它只是把已有顶点移动到了新的位置。因此，Mesh 是否足够细分，会直接决定最终效果——一个只有 4 个顶点的 QuadMesh 永远做不出山脉的轮廓。务必在使用前将 PlaneMesh 的 Subdivisions 设为 32 以上。

### 步骤 1：纯数学波 —— 验证 vertex() 工作在 3D
创建 spatial shader，在一个细分的 PlaneMesh 上：

```
shader_type spatial;

void vertex() {
    VERTEX.y += sin(VERTEX.x * 3.0 + TIME * 2.0) * 0.3;
}
```
效果：平面变成了一条条正弦波垄，沿 X 轴推进。这是你的第一行 3D 顶点动画。此处需要将 PlaneMesh 设置为 10m 长宽，然后将 Subdivisions 设为 32。

**VERTEX.y += 意味着什么？** 你在每个顶点的 Y 坐标上叠加一个偏移量。对于平面模型（初始所有顶点 y = 0），这就是"把平面上的点抬起来"。被抬起的顶点之间的三角形面也随之倾斜，光照在这上面产生正确的高光和阴影。

### 步骤 2：从 VERTEX 坐标构造 UV —— 平面投影
上一步只沿 X 轴变化——波是单向的。要做出真正的"地形"，需要在 XZ 平面上采样 2D 噪声。但 VERTEX 是模型空间坐标，范围取决于你的 PlaneMesh 尺寸。一个 4m×4m 的平面，VERTEX.xz 在 -2 到 2 之间。而纹理的 UV 坐标在 0 到 1 之间。

把模型空间坐标映射到纹理 UV：

```
void vertex() {
    vec2 uv = VERTEX.xz / 10.0 + 0.5;  // 将 [-2,2] 映射到 [0,1]
}
```

- VERTEX.xz / 10.0：将 4m 范围缩放到 [-0.5, 0.5]
- + 0.5：平移到 [0, 1]
如果你的平面尺寸不同，把 10.0 换成实际尺寸。更通用的写法：

```
float plane_size = 10.0;
vec2 uv = VERTEX.xz / plane_size + 0.5;
```

### 步骤 3：引入噪声纹理

```
shader_type spatial;

uniform sampler2D noise : repeat_enable;
uniform float height_scale = 0.5;

void vertex() {
    vec2 uv = VERTEX.xz / 4.0 + 0.5;
    float height = texture(noise, uv).r;
    VERTEX.y += height * height_scale;
}
```
现在你的平面有了自然的起伏——不再是完美的正弦波，而是噪声驱动的随机地形。NoiseTexture2D 的 R 通道存储灰度值（0~1），height_scale 控制最大高度（单位：米）。

**噪声纹理从哪里来？** 在 Godot Inspector 中创建 NoiseTexture2D 资源，配置 FastNoiseLite 生成器（选择 Simplex 或 Perlin 噪声类型），指定尺寸为 256×256 且关闭 seamless（地形不需要无缝）。然后在 ShaderMaterial 的 Shader Parameters 中将该资源拖入 noise 槽位。

### 步骤 4：噪声动画 —— 流动的地形
静止的地形还不够。给噪声 UV 加上时间偏移，地形表面就会"流动"起来——像沙丘被风推动，或岩浆表面的缓慢对流：

```
void vertex() {
    vec2 uv = VERTEX.xz / 4.0 + 0.5;
    vec2 flow = vec2(TIME * 0.1, TIME * 0.05);
    float height = texture(noise, uv + flow).r;
    VERTEX.y += height * height_scale;
}
```
flow 的 X 和 Y 分量用不同速度——这比单一方向的滚动更自然。* 0.1 控制流速：值越小越慢（适合大片地形），值越大越快（适合岩浆或水体表面）。

### 步骤 5：完整地形 —— varying 传递坐标 + NORMAL_MAP 法线贴图
当前的地形有一个问题：vertex() 决定了顶点的高度，但 fragment() 里的材质（颜色、法线贴图）并不知道顶点被"挪"到了哪里。

**解决方案**：用 varying vec2 把"被时间偏移后的 UV 坐标"从 vertex() 传给 fragment()：

```
shader_type spatial;

uniform float height_scale : hint_range(0.0, 2.0) = 0.5;
uniform sampler2D noise : repeat_enable;
uniform sampler2D normalmap;
uniform float plane_size = 10.0;
varying vec2 tex_position;

void vertex() {
    vec2 uv = VERTEX.xz / plane_size + 0.5;
    vec2 flow = vec2(TIME * 0.1);
    tex_position = uv + flow;

    float height = texture(noise, tex_position).r;
    VERTEX.y += height * height_scale;
}

void fragment() {
    ALBEDO = vec3(0.1, 0.3, 0.5);
    METALLIC = 0.0;
    ROUGHNESS = 0.01;
    NORMAL_MAP = texture(normalmap, tex_position).rgb;
}
```
**为什么 varying 能解决这个问题？** vertex() 在每个顶点上执行一次，fragment() 在每个像素上执行多次。varying 变量在顶点之间做线性插值——GPU 自动算出每个像素的中间值。当地形的 1089 个顶点各有不同的 tex_position 时，它们中间的每个像素都得到一个平滑过渡的法线贴图坐标。

**为什么这里同时需要 NORMAL_MAP 和 noise？** noise 纹理的 R 值用来在 vertex() 中抬升/降低顶点（改变真实的几何形状）。NORMAL_MAP 纹理则是在 fragment() 中给表面增加"虚假"的凹凸细节——它不改变顶点位置，但通过扭曲每个像素的光照法线方向，让低面数的网格看起来有更多细节。两者的区别：

- NORMAL：顶点自带的原始法线，精度由 Mesh 的面数决定。一个 32×32 的平面只有约 1000 个法线方向，细节有限。
- NORMAL_MAP：从纹理采样得到的逐像素法线。通过将噪声纹理（格式设为 Normal Map）赋值给 NORMAL_MAP 内置变量，每个像素都能获得独立的光照法线方向——视觉上"看起来"比实际几何体丰富得多。
对于这个地形案例，你将同一个噪声纹理分别拖入 noise 和 normalmap 两个 uniform slot（先在 Inspector 中配置好一个 NoiseTexture2D，然后复制到另一个 slot）。这样可以确保 vertex 的位移和 fragment 的法线细节来自同一套噪声模式，整体效果一致——你会看到流动的水面，波谷和波峰的光照变化相互匹配。

完整 shader 文件：terrain.gdshader

## 6. 3D 冲击波
冲击波是游戏中常见的特效：角色重击地面、炸弹爆炸、能量场扩散。在 3D 中实现冲击波，本质是**在世界空间中计算顶点到冲击波源点的距离，将距离映射为位移量**。

### 步骤 1：全局脉冲 —— 所有顶点同时升降

```
shader_type spatial;

uniform float shockwave_strength = 0.25;

void vertex() {
    float pulse = sin(TIME * 5.0) * 0.5 + 0.5;
    VERTEX.y += pulse * shockwave_strength;
}
```
整个平面同步上下起伏。这不是冲击波——冲击波是一个环从中心向外扩散。但它验证了 vertex() 中对 Y 轴的操作可以工作。

### 步骤 2：计算世界空间距离 —— 找到冲击波源
冲击波的本质：距离波源越近的顶点，越早被影响。需要一个可靠的"距离"度量。

```
uniform vec3 shockwave_origin = vec3(0.0, 0.0, 0.0);

void vertex() {
    vec3 world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz;
    vec3 to_origin = world_pos - shockwave_origin;
    float dist = length(to_origin);

    VERTEX.y += exp(dist * 0.5) * shockwave_strength;
}
```
shockwave_origin 是世界空间中的一个点——通常由 GDScript 设为爆炸位置或角色脚下。exp(dist * 0.5) 是一个随距离增大而指数增长的函数——离中心越远，位移越大。world_pos 是当前顶点的局部坐标在矩阵计算转换后得到世界空间中的坐标，它和冲击中心作减法得到两点之间的向量，再经过 length 计算得到距离长度。

**为什么一定要在世界空间计算？** 在模型空间计算距离时，距离参照的是物体的本地原点。如果你在场景中移动 Plane 节点，冲击波的"中心"也会跟着 Plane 走——节点移到哪，冲击波就在哪。而世界空间中的 shockwave_origin 是一个固定的世界坐标点：无论 Plane 放在哪里，冲击波始终从那个世界点向外扩散。这才是你想要的——地面上的爆炸不会因为地面的 Mesh 节点被移动就跟着"漂移"。

到目前为止，你会看到一个类似于山谷的三维效果：当前平面的中心点和世界中心点重合，所以中心仍处于 0 的高度，但是其它顶点离中心点越远，其高度提升越明显。

### 步骤 3：环形波 —— 用 smoothstep 构造"环"
山谷还不是冲击波——冲击波应该是一个**向外扩散的环**，环经过的地方有扰动，环到达之前和之后的地面都是平的。

环形波的数学公式：

```
effect = smoothstep(inner_r, mid_r, dist)      // 上升沿
       * (1.0 - smoothstep(mid_r, outer_r, dist))  // 下降沿
```
两个 smoothstep 相乘，产生一个只在环形区域内为 1 的"窗口函数"：

```
uniform float shockwave_strength = 1.0;
uniform vec3 shockwave_origin = vec3(0.0, 0.0, 0.0);

uniform float shockwave_radius = 4.0;
uniform float shockwave_width = 0.5;

void vertex() {
    vec3 world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz;
    vec3 to_origin = world_pos - shockwave_origin;
    float dist = length(to_origin);

    float ring = smoothstep(
        shockwave_radius - shockwave_width,
        shockwave_radius - shockwave_width * 0.5,
        dist
    );
    ring *= 1.0 - smoothstep(
        shockwave_radius,
        shockwave_radius + shockwave_width * 0.5,
        dist
    );

    VERTEX.y += ring * shockwave_strength;
}
```
现在效果是：平面在距离原点 shockwave_radius 处有一个凸起的环，环内外都是平的。但环是静止的——它不会"扩散"。

### 步骤 4：动画扩散 —— shockwave_percentage 驱动
要让环从中心向外扩散，需要一个从 0 到 1 变化的进度变量。这个变量由 GDScript 每帧更新：

```
uniform float shockwave_percentage : hint_range(0.0, 1.0) = 0.3;

void vertex() {
    vec3 world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz;
    vec3 to_origin = world_pos - shockwave_origin;
    float dist = length(to_origin);

    float max_dist = shockwave_percentage * shockwave_radius;
    float min_dist = max(0.0, max_dist - shockwave_width);

    float effect = smoothstep(min_dist, max_dist - shockwave_width * 0.5, dist);
    effect *= 1.0 - smoothstep(max_dist, max_dist + shockwave_width * 0.5, dist);

    VERTEX.y += effect * shockwave_strength;
}
```
核心逻辑：shockwave_percentage 是一个在 0→1 之间变化的浮点数。随着它从 0 增长到 1，max_dist 从 0 增长到 shockwave_radius——环形波从中心移动到最大半径。

**GDScript 端驱动**（挂载到 MeshInstance3D 节点的脚本）：

```
extends MeshInstance3D

@export var origin: Vector3 = Vector3.ZERO
@export var radius: float = 2.0
@export var width: float = 0.5
@export var strength: float = 0.25
@export var duration: float = 1.5

var _elapsed: float = 0.0
var _active: bool = false

func trigger_shockwave(pos: Vector3) -> void:
    origin = pos
    _elapsed = 0.0
    _active = true
    material_override.set("shader_parameter/shockwave_origin", origin)
    material_override.set("shader_parameter/shockwave_radius", radius)
    material_override.set("shader_parameter/shockwave_width", width)
    material_override.set("shader_parameter/shockwave_strength", strength)

func _process(delta: float) -> void:
    if not _active:
        return
    _elapsed += delta
    var pct = clamp(_elapsed / duration, 0.0, 1.0)
    material_override.set("shader_parameter/shockwave_percentage", pct)
    if pct >= 1.0:
        _active = false
```
shockwave_percentage 从 0 线性增长到 1，shader 中环形波随之外移。

### 步骤 5：沿法线方向位移 + 网格纹理
当前冲击波只沿世界 Y 轴抬升——这在平面上有效，但在球体或倾斜面上看起来不对。改为沿顶点法线方向位移：

```
VERTEX += NORMAL * effect * shockwave_strength;
```
NORMAL 是模型空间下的法线向量。平面 Mesh 的法线全部朝上 (0,1,0)，所以和 VERTEX.y += 的效果一样——但对于球体，每个顶点的法线指向不同的方向，沿法线外推会产生"球面向外膨胀"的效果，这才是冲击波在弯曲表面上的正确表现。

在 fragment 中添加网格纹理（方便观察形变）：

```
void fragment() {
    vec2 uv = UV * 10.0;
    float grid = step(0.95, fract(uv.x)) + step(0.95, fract(uv.y));
    ALBEDO = vec3(grid);
}
```
UV * 10.0 把原本 0→1 的 UV 放大到 0→10，fract() 取小数部分产生 10×10 的重复图案，step(0.95, ...) 在每条线附近（fract 值接近 1.0 时）输出白线。这个技巧来自 ch5 的 fract() 讲解——网格线让你能肉眼观察到每个顶点的移动。

完整的 shader 文件：shockwave3d.gdshader

## 7. 植被摆动
前面的地形和冲击波都是平面 Mesh 的形变。植被风动则是把同样的"顶点位移"思维应用到立体的植物模型上——根部固定、顶部随风摇摆。这一节采用与前面一致的"分步渐进"方式，带你从最简单的全局摆动逐步构建到自然的噪声风动。

建模部分，你可以使用导入的 .glb 树模型（参见第 3 节）。

### 步骤 1：全局同步摆动
最基础的风动：用 sin(TIME) 让所有顶点在 X 方向上同步来回摆动：

```
shader_type spatial;
render_mode cull_disabled;

uniform float sway_strength = 0.1;
uniform float sway_speed = 1.5;

void vertex() {
    float sway = sin(TIME * sway_speed) * sway_strength;
    VERTEX.x += sway;
}
```
所有顶点以相同幅度、相同相位左右摆动。整棵植物像一个刚体在来回平移。

### 步骤 2：空间差异化
如果场景中有多棵植物，它们应该各自有不同的摆动相位，否则会像"队伍齐步走"一样假。利用顶点的世界空间 XZ 坐标来产生相位差：

```
void vertex() {
    vec3 world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz;
    float angle = TIME * sway_speed + world_pos.x * 0.5 + world_pos.z * 0.3;
    float sway = sin(angle) * sway_strength;
    VERTEX.x += sway;
}
```
world_pos.x 和 world_pos.z 作为相位偏移——不同位置的树进入波形的不同阶段。即便两棵树的材质完全相同，它们也会因为空间位置不同而产生不同的摆动状态。* 0.5 和 * 0.3 控制位置差异带来的"波长"——值越大，相邻两棵植物的摆动差异越明显。

### 步骤 3：根部固定
目前整棵植物一体位移，现实中，根部插入地面后是不动的，越到梢部摆动幅度越大：

```
void vertex() {
    vec3 world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz;
    float angle = TIME * sway_speed + world_pos.x * 0.5 + world_pos.z * 0.3;

    float height_factor = world_pos.y / 1.0; //1.0高度，根据实际模型调整
    height_factor = clamp(height_factor, 0.0, 1.0);

    float sway = sin(angle) * sway_strength * height_factor;
    VERTEX.x += sway;
}
```
height_factor 在根部（y ≈ 0）为 0，在树梢处为 1。乘以 sway_strength 后，根完全不摆动，树梢获得最大摆幅。中间的顶点在两者之间线性过渡——植物呈现出"弯曲"的效果。

### 步骤 4：引入噪声 —— 自然风动
真实的风不是完美的正弦波——它有时强有时弱，每棵树的响应也不同。引入噪声让摆动更有机：

```
shader_type spatial;
render_mode cull_disabled;

uniform sampler2D albedo_texture : source_color;
uniform sampler2D emission_texture : source_color;

uniform vec3 emission_color : source_color = vec3(0.1);
uniform float emission_strength = 1.0;

uniform float sway_strength : hint_range(0.0, 2.0) = 0.3;
uniform float sway_speed : hint_range(0.0, 5.0) = 1.5;

void vertex() {
    vec3 world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz;

    float angle = TIME * sway_speed + world_pos.x * 0.5 + world_pos.z * 0.3;

    float height_factor = world_pos.y / 5.0; // 根据实际树高调整
    height_factor = clamp(height_factor, 0.0, 1.0);

    float sway_x = sin(angle) * sway_strength * height_factor;
    float sway_z = cos(angle * 0.8) * sway_strength * height_factor;

    VERTEX.x += sway_x;
    VERTEX.z += sway_z;
}

void fragment() {
    vec4 albedo = texture(albedo_texture, UV);
    vec4 emission = texture(emission_texture, UV);
    ALBEDO = albedo.rgb;
    ALPHA = albedo.a;
    EMISSION = emission.rgb * emission_color * emission_strength;
}
```
与步骤 3 的区别在于：X 方向用 sin、Z 方向用 cos（不同频率 * 0.8）。这让树在两个水平轴上的摆动节奏不同——不是僵硬的单向晃动，而是在水平面上画出不规则的椭圆轨迹。树冠既左右摇也前后摇，幅度各异，产生更自然的"风中摇曳"效果。

**为什么用 cos 而不是第二个 sin？** sin(angle) 和 cos(angle * 0.8) 构成一对正交但频率不一致的振荡。在极坐标中，这对振荡合成的轨迹是一个缓慢旋转的椭圆（Lissajous 曲线）——树的顶端正是在做这种不规则的椭圆运动。

完整 shader 文件：grass.gdshader

## 8. Billboard（广告牌）：直接计算 POSITION
**重要提示**：Billboard 是本章唯一一个**不修改 VERTEX、而是直接计算 POSITION** 的案例。前面的地形、冲击波和植被，本质上都是"在模型空间里移动已有的顶点"。而 Billboard 绕过了 Godot 的整个自动变换管线，手动重建顶点的世界位置和裁剪空间坐标。这不再是"修改"顶点——这是"重写"顶点。难度明显更高，请做好心理准备。

**Billboard 解决的问题**：让一个平面 Quad 始终朝向摄像机——无论摄像机怎么旋转，你看到的总是同一面。典型应用：树木叶子片、粒子替代、远处建筑的 2D 替身、3D UI 浮标。如果你不想用 shader，也可以直接用 Godot 的 Material 设置选项，里面可以打开自动 Billboard 功能。本小节主要为介绍原理和代码。

场景设置时，新建一个 MeshInstance3D，然后创建一个 QuadMesh，在 Geometry 上新建一个 shader 材质。

### 步骤 1：render_mode skip_vertex_transform —— 关闭自动变换

```
shader_type spatial;
render_mode skip_vertex_transform;
```
加上这行 render_mode 后，Godot 不再自动执行 MODEL_MATRIX → VIEW_MATRIX → PROJECTION_MATRIX 的顶点变换链。你现在**必须手动计算并写入 POSITION**——否则模型不会出现在屏幕上。

**POSITION 是什么？** 它是顶点在裁剪空间（Clip Space）中的最终输出。skip_vertex_transform 激活后，vertex() 的唯一职责就是手工计算 POSITION（vec4，齐次裁剪坐标）。如果忘记写 POSITION = ...，模型就不会被渲染。

### 步骤 2：从 INV_VIEW_MATRIX 提取相机方向
ch3 讲过：VIEW_MATRIX 把世界空间转换到摄像机空间；它的逆矩阵 INV_VIEW_MATRIX 把摄像机空间转换回世界空间。INV_VIEW_MATRIX 的前三列（[0], [1], [2]）是摄像机空间中的三个方向坐标轴，也就是摄像机在世界空间中的**右方向、上方向、前方向**。

```
void vertex() {
    vec3 cam_right = normalize(INV_VIEW_MATRIX[0].xyz);
    vec3 cam_up    = normalize(INV_VIEW_MATRIX[1].xyz);
}
```

- INV_VIEW_MATRIX[0].xyz：摄像机 X 轴在世界中的方向——即"在你的屏幕中指向右边"的那个方向
- INV_VIEW_MATRIX[1].xyz：摄像机 Y 轴在世界中的方向——即"在你的屏幕中指向上方"

### 步骤 3：重建顶点世界位置 —— 深入理解"为什么"
Billboard 的核心公式：

```
vec3 world_pos = NODE_POSITION_WORLD
    + cam_right * VERTEX.x
    + cam_up * VERTEX.y;
```
这个公式的含义需要从两个角度理解：

**生活角度**：想象你手里拿着一张海报，想让它始终正对观众。你站在舞台上某个位置（NODE_POSITION_WORLD），把海报展开——但海报的"水平"方向必须和观众的视线平行（而不是世界的水平方向）。所以你把海报的左右两个角，沿着观众眼睛的"右方向"（cam_right）展开，把上下两个角沿着观众的"上方"（cam_up）展开。无论观众走到剧场的哪个角落，海报始终正对他的脸——因为"左右"和"上下"永远以他的视线为准。

**数学角度**：Quad 的四个原始顶点坐标是 (±0.5, ±0.5, 0)——它们存在于 QuadMesh 自身的模型空间中。在普通的 3D 管线里，这些顶点会先经过 MODEL_MATRIX（把 Quad 放到世界中的某个位置和朝向），再经过 VIEW_MATRIX（转换到摄像机视角）。Billboard 的做法是把这个过程"掰开重组"：

- 位置信息由 NODE_POSITION_WORLD 提供（替代 MODEL_MATRIX 的平移部分）
- 朝向信息由 cam_right 和 cam_up 提供（替代 MODEL_MATRIX 的旋转部分——Quad 自身的旋转被丢弃了）
- 顶点的 X/Y 分量被投影到摄像机的右/上方向轴上，而非世界的 X/Y 轴
这样，Quad 本身的旋转被完全忽略——无论节点在场景中被怎么旋转，顶点始终在摄像机面对的平面上展开。

### 步骤 4：手动写入 POSITION
手动构建完整的 MVP 变换链：

```
void vertex() {
    vec3 cam_right = normalize(INV_VIEW_MATRIX[0].xyz);
    vec3 cam_up    = normalize(INV_VIEW_MATRIX[1].xyz);

    vec3 world_pos = NODE_POSITION_WORLD
        + cam_right * VERTEX.x
        + cam_up * VERTEX.y;

    POSITION = PROJECTION_MATRIX * VIEW_MATRIX * vec4(world_pos, 1.0);
}
```
这是管线自己在 skip_vertex_transform 关闭时做的事情——你只是手动重做了一遍。顺序是固定的：世界坐标 → 视图矩阵 → 摄像机空间 → 投影矩阵 → 裁剪空间。

### 步骤 5：添加纹理 + unshaded
最后要记得在编辑器中，将 Godot 的 icon 设置给 texture_albedo。Billboard 通常不需要 PBR 光照——它常用于 2D 替身和 UI，光照反而破坏效果。加 render_mode unshaded 绕开光照计算：

```
shader_type spatial;
render_mode skip_vertex_transform, unshaded;

uniform sampler2D texture_albedo : source_color;

void vertex() {
    vec3 cam_right = normalize(INV_VIEW_MATRIX[0].xyz);
    vec3 cam_up    = normalize(INV_VIEW_MATRIX[1].xyz);

    vec3 world_pos = NODE_POSITION_WORLD
        + cam_right * VERTEX.x
        + cam_up * VERTEX.y;

    POSITION = PROJECTION_MATRIX * VIEW_MATRIX * vec4(world_pos, 1.0);
}

void fragment() {
    vec4 tex = texture(texture_albedo, UV);
    ALBEDO = tex.rgb;
    ALPHA = tex.a;
}
```
第 3 章你第一次见到 INV_VIEW_MATRIX，当时它的角色是"取摄像机在世界中的位置和方向"。本章是你第一次实际用它做效果——把相机的方向向量拆出来，用它重建顶点。ch3 的空间链是理论，Billboard 是这条链在实战中的第一个应用。

完整 shader 文件：billboard.gdshader

## 9. 知识补充：关于Vertex Shader 的限制
在深入使用 Vertex Shader 之前，有一件事必须明确：**Vertex Shader 不能做什么**。这是很多初学者容易产生误解的地方。

**Vertex Shader 能做的**：

- ✅ 修改顶点的位置（VERTEX）
- ✅ 修改顶点的 UV 坐标（UV）
- ✅ 修改顶点的颜色（COLOR）
- ✅ 读取顶点自身的法线、切线等属性
- ✅ 通过 MODEL_MATRIX 访问世界空间
**Vertex Shader 不能做的**：

- ❌ **增加顶点**：你无法在 shader 中凭空创建新顶点。一个 32×32 的平面有 1089 个顶点，shader 只能在这 1089 个位置上运算，不能把 1089 变成 10000。
- ❌ **删除顶点**：你不能隐藏或移除某些顶点（除非通过 POSITION 把它们移到屏幕外）。
- ❌ **获取邻居顶点**：一个顶点在 shader 中只能访问自己的数据（位置、UV、法线等），无法知道相邻顶点的位置或属性。
- ❌ **修改 Mesh 拓扑**：你不能改变顶点之间的三角形连接关系。
**这意味着什么？** 地形顶点位移的效果好坏，直接取决于 Mesh 的细分程度。一个只有 4 个顶点的 QuadMesh，无论你的噪声函数多精细，地形都是平的——因为没有足够的顶点可以被"抬起来"。在开始任何 Vertex Shader 工作前，先检查你的 Mesh 是否有足够的顶点密度。如果 Mesh 不够细，你应该在编辑器中提高 Subdivisions，或者新建细分更高的 Mesh，而不是期望 shader 来弥补。

## 10. 知识补充：何时用 Vertex Shader
这是一个实践中最常见的问题：某个视觉效果，应该放在 vertex() 还是 fragment() 中实现？

**核心判断标准**：是否需要"改变模型的轮廓"。

| 需求 | Vertex Shader | Fragment Shader | 说明 |
| 改变模型轮廓 | ✅ | ❌ | vertex() 移动顶点后，模型的侧影线（Silhouette）会改变。fragment() 无论怎么改颜色，轮廓永远是原始模型的形状。 |
| 改变颜色 | ❌ | ✅ | vertex() 可以改 COLOR，但最终每个像素的着色在 fragment() 中完成——颜色是像素级操作。 |
| UV 扭曲 | △（少见） | ✅ | 在 vertex() 中改变 UV 只会影响每个顶点的 UV 值（中间像素自动插值），精度受顶点数限制。在 fragment() 中扭曲 UV 是逐像素的，效果更精细。 |
| 波浪形变 | ✅ | △（仅视觉） | 如果你想让物体表面真的凸起变形（遮挡后面的东西、影子随之变化），必须用 vertex()。如果只是想"看起来有波动"（像第 7 章的水面），在 fragment() 中扭曲 UV 更省性能。 |
| 光照变化 | ❌ | ✅ | 光照计算（漫反射、高光、阴影）在 fragment() 中基于法线与光线方向进行，vertex() 不参与。 |
| 性能成本 | 低（每个顶点一次） | 高（每个像素一次） | 对于高分辨率屏幕，fragment() 的调用次数远超 vertex()。能用 vertex() 实现的效果尽量在顶点层面解决。 |

**一个实用口诀**：

- 如果你想让物体的**影子**也跟着变化 → 必须用 vertex()
- 如果你只是想改变物体**看起来的样子**（颜色、凹凸感、反光） → 用 fragment()
- 如果物体的面数非常高（数万顶点），而你的目标分辨率不高 → 用 fragment() 可能更快
- 如果物体的面数很低（几百顶点），而你想让整个曲面发生形变 → 用 vertex() 是正确的选择
**举例**：第 7 章的水面效果使用了 fragment() 的 UV 扭曲来制造波纹视觉——模型本身是一块平板，波纹只是"看起来有"，但平板下面的物体不会被遮挡，阴影也不会随波纹变化。本章的地形效果用了 vertex()——顶点被真实地抬起来了，新的地形会遮挡后面的物体，高光也会在山脊处正确聚集。这两种方法各有适用场景，没有绝对的优劣。

## 本章小结
本章把 ch12 学到的 2D 顶点动画"升级"为 3D 版本——核心算式没变（VERTEX = 原始 + 权重 × 时间驱动 × 强度），但坐标系从 vec2 变成了 vec3、可影响的空间维度从 2 个变成 3 个。

四个案例按"代价比"递增排列：

****
| 案例 | 核心算式 | 关键点 |
| 地形位移 | VERTEX.y += noise(world_pos.xz) * height | 用 world_pos.xz 驱动噪声，保证地形不会跟着模型移动漂走 |
| 3D 冲击波 | VERTEX += NORMAL * pulse(width, radius) | 沿模型法线外推 = 任何朝向都正确膨胀 |
| 植被风动 | VERTEX.xz += sin(TIME * speed + world_pos.y/freq) * weight | 高度权重让根部不动、顶部摆；sin 的相位偏移避免整片同步 |
| Billboard | POSITION = PROJECTION * VIEW * vec4(cam_right * size, 0, 1) | 直接写 POSITION 绕过默认变换，把四边形锁向摄像机 |

带走两条工程心法：

- **顶点密度决定形变精度上限**：4 顶点 quad 写不出"水波曲面"，shader 不能凭空产生顶点。任何想要光滑形变的效果，先检查 mesh 细分。
- **判断"vertex vs fragment"的三句话口诀**：影子要跟着变 → vertex；只改颜色不变形状 → fragment；顶点数极多但 resolution 又不高 → 优先 fragment。
下一章（ch19）会从 vertex() 跨到 fragment()，把你已经在 ch4 短暂见过的 PBR 属性（ALBEDO/ROUGHNESS/METALLIC 等）逐一展开——那才是 3D 渲染的"材料"层。
