# 第 9 章：纹理采样与操作

### 第 9 章：纹理采样与操作 —— 让贴图动起来
**学习目标**：掌握 texture() 和 textureLod() 的纹理采样方法，能对 UV 坐标进行平移、缩放、旋转变换，用 mix() 混合多层纹理实现视差滚动背景，并理解法线贴图的解压原理（* 2.0 - 1.0）。章末能独立完成一个 Parallax 星空滚动背景。

**场景搭建**：2D 部分创建 Sprite2D 节点，挂入一张星空纹理（或 NoiseTexture2D），新建 canvas_item 类型的 shader 文件。3D 法线贴图演示部分创建 MeshInstance3D + PlaneMesh，新建 spatial 类型的 shader 文件，挂入法线贴图。

**内容要点**：

- texture()：纹理采样的基础函数——给 UV 坐标、取颜色值
- 纹理参数：repeat_enable（平铺） / filter_linear vs filter_nearest（过滤模式） 
- UV 变换三件套：偏移（UV + vec2）/ 缩放（UV * vec2）/ 旋转（mat2 旋转矩阵）
- 多层纹理混合：不同速度滚动 + mix() 叠加 → Parallax 视差效果
- 法线贴图写入 NORMAL_MAP
- textureLod()：手动指定 mipmap 层级，做模糊/锐化控制
- 实战：Parallax 星空滚动背景

## 1. texture()：GPU 上的"取色笔"

### 1.1 它是什么？
texture() 是 shader 中最基础的纹理采样函数。它接收一个纹理和一个 UV 坐标，返回该坐标处的颜色值：

```
vec4 color = texture(TEXTURE, UV);
```
TEXTURE 是 canvas_item shader 的内置纹理变量——它自动绑定到 Sprite2D 上的纹理，你不需要声明它，也不需要手动传入任何值。在 spatial shader 中，更常见的做法是通过自定义 uniform sampler2D 进行纹理采样，而不是依赖一个统一的 TEXTURE 内置变量。

UV 是一个**标准化的连续坐标系**：UV 原点在左上角，U代表横向，向右递增，V代表纵向， 向下递增（这是 2D canvas_item 约定）。传入的 UV 值是元素为 float的二元数组。它可以由 0.3、0.573、1.823 等任意小数构成。你可以理解它是一个类似经纬度的查询地址。

但纹理是**离散的像素网格**——一张 256×256 的纹理只有 256×256 个"确切有颜色"的位置。当你用 texture(TEXTURE, vec2(0.573, 0.324)) 采样时，GPU 拿到的 UV 坐标 (0.573, 0.324) 并不正好落在某个像素上。texture() 自动做了**双线性插值**：取周围 4 个像素的颜色，按距离加权平均，返回一个平滑的中间值。

这就是纹理采样最基础的机制：**你给连续的坐标，GPU 从离散的像素格子里"推测"出中间值**。filter_linear（默认）就启用这个插值；filter_nearest 关闭它（直接取最近的像素）。理解了这一点，后面所有 UV 操作——偏移、缩放、旋转——都只是"改变去哪格取色"。

### 1.2 为什么需要它？
第 8 章之前，你画的每一个图形都是纯代码生成的——圆、环、矩形，全凭数学公式。但这在游戏开发中只能覆盖少数场景。游戏中绝大多数视觉元素来自**美术资源**：角色贴图、地面纹理、粒子精灵、UI 图标。

texture() 解决的问题是：**如何把一张美术图片“接入”到 shader 的计算流程中**。它把图片变成 vec4——和你在 shader 中操作的任何变量没有区别。拿到这个 vec4 之后，你就可以对它做一切之前学过的事情：调色、混合、遮罩、动画。

### 1.3 怎么用：基础采样与分量提取
最简代码——把 Sprite2D 的纹理原样输出，在Sprite2D节点上设置icon纹理，然后将如下shader挂到其下：

```
shader_type canvas_item;

void fragment() {
    COLOR = texture(TEXTURE, UV);
}
```
保存后画面和没有 shader 时完全一样——这恰好是对的：你向 GPU 说"把纹理上 UV 位置的颜色拿过来，作为最终颜色"，结果当然是原图。

texture() 返回的是 vec4。你可以分别取用各个分量：

```
vec4 tex = texture(TEXTURE, UV);
float red_part   = tex.r;     // 只取红色通道
vec3 rgb_part    = tex.rgb;   // 取 RGB 三色，不要 alpha
float alpha_part = tex.a;     // 只取透明度
```
在 canvas_item 中，纹理的 alpha 通道直接控制精灵的透明度——取 tex.a 就等于拿到了美术在 Photoshop 里画的透明区域。

从纹理取出颜色后，最基础的调整是在 shader 外部控制亮度：

```
uniform float brightness : hint_range(0.0, 2.0) = 1.0;

void fragment() {
    vec4 tex = texture(TEXTURE, UV);
    COLOR = tex * brightness;
}
```
brightness = 1.0 保持原样，0.5 变暗一半，2.0 变亮一倍。这个模式看似简单，但揭示了一个关键设计：**shader 的参数由编辑器控制，你在 Inspector 中拖滑条，shader 立即响应**。你可以尝试其它更复杂的效果参数——饱和度、对比度、色调偏移——都是同样的 uniform + 乘法模式，当然代码会更复杂些。

完整代码见bright.gdshader

## 2. 纹理参数：控制采样行为的开关
上一节我们是使用TEXTURE变量作为texture()函数的纹理参数输入。你也可以使用自定义的uniform sampler2D作为纹理参数输入。下面使用ColorRect作为节点来挂shader。声明 uniform sampler2D my_tex 变量后，你会在编辑器中看到my_tex参数，可以将icon图片拖进去。可以看到，下面的shader代码，只是用my_tex来代替了TEXTURE。基本功能是一样的。

```
shader_type canvas_item;

uniform sampler2D my_tex;

void fragment() {
    COLOR = texture(my_tex, UV);
}
```

### 2.1 repeat_enable：纹理平铺
**问题**：当 UV 坐标超出 [0, 1] 范围时，纹理该如何表现？

纹理的默认行为是 **clamp**（钳位）：UV < 0 的部分取边缘像素，UV > 1 的部分也取边缘像素——纹理只显示一次，四周被拉伸的边缘色填充。可以通过uniform变量的hint参数来控制其改变行为。

在变量后加冒号是增加hint，设置为repeat_enable 将其行为改为 **repeat**重复平铺：UV = 1.5 时等同于 UV = 0.5，纹理像地砖一样会无限重复。

```
uniform sampler2D my_tex : repeat_enable;
```
**为什么需要它？** 当你做 UV 滚动（UV + vec2(TIME * 0.1, 0.0)）时，如果纹理是 clamp 模式，滚动一下画面就停在边缘不动了。repeat_enable 让滚动无限循环——纹理首尾相接，永远滚不完。平铺地面纹理、滚动天空背景、无缝噪声贴图，都依赖它。

验证代码——输出重复 10 次的纹理：

```
shader_type canvas_item;

uniform sampler2D my_tex : repeat_enable;

void fragment() {
    vec2 tiled_uv = UV * 10.0;
    COLOR = texture(my_tex, tiled_uv);
}
```
你会看到纹理重复了 10×10 次。你可以尝试将 repeat_enable修改为repeat_disable，观察效果。

完整代码见repeat.gdshader

### 2.2 filter_linear vs filter_nearest：画面清晰度的选择
**问题**：当纹理被放大或缩小时，像素之间的空隙由什么颜色填充？

filter_linear 是默认模式，使用**双线性插值**——取周围 4 个像素做加权平均。效果是画面柔和、过渡平滑，但放大后会有模糊感。

filter_nearest 使用**最近邻采样**——只取最近的单个像素。效果是画面锐利、保留硬边缘，但放大后会看到明显的像素格子。

```
uniform sampler2D pixel_art : filter_nearest;   // 像素风游戏
uniform sampler2D smooth_tex : filter_linear;   // 写实风格（默认）
```
**为什么需要它？** 像素风游戏必须用 filter_nearest——否则角色放大后面部糊成一团。写实风格用 filter_linear——否则草地缩小后会出现摩尔纹。这不是"好不好看"的偏好问题，而是**纹理内容的视觉意图**决定的。

在 Godot 编辑器中，你可以在 Import 面板（选中纹理资源 → Import 标签）的 Flags → Filter 中为纹理设置全局默认过滤模式。shader 中的 hint 会覆盖这个全局设置。

## 3. UV 变换：偏移、缩放与旋转
有了 texture()，你可以直接从纹理取颜色。但取颜色**之前**还可以做一件事：**变换 UV 坐标**。变换 UV 之后再采样，相当于在"扭曲"纹理——不需要修改纹理原图，零成本实现滚动、缩放、旋转效果。

### 3.1 UV 偏移：让纹理动起来
最基础的 UV 变换：给 UV 加上一个偏移量。

```
vec2 offset = vec2(TIME * 0.1, 0.0);   // 随时间向右偏移
vec2 scrolled_uv = UV + offset;
vec4 color = texture(TEXTURE, scrolled_uv);
```
**直觉**：UV 坐标代表"到哪里取颜色"。你不在原地取色，而是把取色点向右挪了一点——就像透过一个向右移动的窗框看一幅静止的画。画面看起来向左滚动。

这个模式的通用形式是：

```
vec2 scrolled_uv = UV + vec2(speed_x, speed_y) * TIME;
```
speed_x 和 speed_y 控制水平和垂直方向的滚动速度。正值向右/下滚，负值向左/上滚。配合 repeat_enable，偏移可以无限进行——纹理首尾相接，永远不会走到"尽头"。如果你使用的是内置纹理变量，可以在编辑器的Texture选项中设置Repeat为Enabled。

[IMAGE: 滚动效果](../ch09-diagrams/scroll.webp)

完整代码见 scroll.gdshader

### 3.2 UV 缩放：放大与缩小
把 UV 乘以一个系数，纹理就被拉伸或压缩：

```
vec2 scaled_uv = UV * scale;    // scale > 1 → 纹理缩小（重复更多）
                                  // scale < 1 → 纹理放大（只显示一部分）
```
**为什么乘 2 会"缩小"？** 回忆 UV 的范围是 [0, 1]。乘以 2 后范围变成 [0, 2]——原来覆盖整个表面的纹理现在只覆盖左半部分（[0, 0.5]），右半部分取的是 [1, 2] 范围（配合 repeat_enable 显示第二遍）。纹理看起来变小了。

缩放关于点的位置：默认以 (0, 0)（左上角）为缩放原点。要让缩放围绕中心进行，先平移再缩放再平移回来：

```
vec2 uv_centered = UV - vec2(0.5);      // 移到中心
uv_centered *= scale;                     // 缩放
vec2 result_uv = uv_centered + vec2(0.5); // 移回原位
```
完整代码见 scale.gdshader

### 3.3 UV 旋转：二维旋转矩阵
把 UV 坐标绕点 (0.5, 0.5) 旋转角度 angle（弧度）：

```
float angle = TIME * 0.5;                  // 角度随时间变化
float c = cos(angle);
float s = sin(angle);
mat2 rotation = mat2(vec2(c, s),vec2(-s, c));        // 2D 旋转矩阵
vec2 uv_centered = UV - vec2(0.5);         // 移到旋转中心
vec2 rotated_uv = rotation * uv_centered;  // 旋转
vec2 result_uv = rotated_uv + vec2(0.5);  // 移回
```
mat2(c, -s, s, c) 是二维旋转矩阵的标准形式，不用背下来。你只需要理解两件事：
1. **先平移后旋转再平移回来**：因为旋转矩阵绕原点旋转，必须先把中心移到原点
2. **是 UV 在旋转，不是纹理在旋转**：你改变的是"去哪里取色"，不是纹理本身

完整代码见rotate.gdshader

## 4. textureLod() 与 Mipmap：手动控制细节层级

### 4.1 Mipmap 是什么？
Mipmap 是一组**预先缩小的纹理副本**。原始纹理是 "层级 0"（最大最清晰），每向上一级，纹理的宽高各缩小一半：

```
LOD 0: 1024×1024  ← 原始尺寸，最清晰
LOD 1:  512×512
LOD 2:  256×256
LOD 3:  128×128
...
LOD 10:   1×1     ← 整个纹理缩成一像素，最模糊
```
Godot 在导入纹理时**自动生成 mipmap 链**（Import 面板 → Flags → Mipmaps → On）。默认情况下，GPU 根据像素在屏幕上占用的面积自动选择 mipmap 层级——这叫"自动 LOD"。如果你双击icon.svg，可以在编辑器右侧看到有7层 Mipmaps。

Mipmap 存在的目的是减少远距离采样时的闪烁（Aliasing）和纹理缓存（Texture Cache）开销。当远处物体在屏幕上只占据几个像素时，直接用 1024×1024 的原纹理采样会反复跳选离散像素——这就是"远处闪烁"的来源。GPU 自动选择缩小的 mipmap 层级，每个采样覆盖更多原始像素，消除闪烁的同时降低缓存压力。绝大多数情况下你不需要手动使用 textureLod()。

### 4.2 textureLod() 解决什么问题？
texture(TEXTURE, UV) 使用自动 LOD——你无法控制 GPU 选择哪个 mipmap 层级。textureLod(TEXTURE, UV, lod) 让你**手动指定层级**。

**为什么需要手动控制？** 两个场景：

- **模糊效果**：故意用较高 LOD 层级（更模糊的 mipmap）采样，获得柔焦效果
- **调试 mipmap 链**：在开发时可视化各级 mipmap，确认纹理在不同距离下的表现

```
float lod = 3.0;                                  // 选择第 3 级 mipmap（128px）
vec4 blurry = textureLod(TEXTURE, UV, lod);        // 故意用模糊版本
```
lod = 0.0 取最清晰的原纹理，lod = 5.0 取高度模糊的缩小版。另外注意，如果要让textureLod生效，需要在Texture中将filter设置为 Mipmap选项。

**适用范围说明**：textureLod() 在不同平台和渲染阶段的支持可能有限——部分移动平台或特定 shader 阶段（如 vertex shader）中不可用。对大多数初学者场景，直接使用 texture() 即可，textureLod() 属于特殊需求时使用的高级接口。

完整代码参见 blur.gdshader

## 5 在 3D 场景中使用纹理
前面所有示例都基于 canvas_item shader。在 3D 场景中，采样纹理同样依赖 texture()——只是输出目标不同，在3D场景中创建一个MeshInstance3D节点，然后设置为PlaneMesh，在其下挂一个spatial shader。

```
shader_type spatial;

// 自定义纹理
uniform sampler2D albedo_tex : source_color;

void fragment()
{
    vec4 tex = texture(albedo_tex, UV);
    ALBEDO = tex.rgb;
}
```
ALBEDO 是 spatial shader 的基础颜色输出，相当于 canvas_item 中的 COLOR.rgb。ALPHA是透明度设置，在编辑器中设置albedo_tex等于brick_diff.png，你就可以看到一面墙体显示在三维空间中。

到目前为止，我们采样的纹理都是"颜色"。但是 GPU 并不关心一张图片代表什么。同样一张 RGB 图片，可以表示颜色，可以表示高度，也可以表示法线方向。texture() 并不知道图片是什么。是 shader **如何解释** texture() 返回的数据，决定了这张图片的用途。接下来我们看看一种最常见的特殊纹理，法线贴图——Normal Map。

法线贴图是一张 RGB 图片，但它的每个像素存的**不是颜色，而是表面的法线方向**。

- R 通道存法线的 X 分量（左/右偏向）
- G 通道存法线的 Y 分量（上/下偏向）
- B 通道存法线的 Z 分量（指向表面外的程度）
图片的 RGB 值范围是 [0, 1]——这是颜色编码。但法线方向的范围是 [-1, 1]，一般是通过手动在代码中处理转换（*2.0 - 1.0），但是当纹理用于赋值NORMAL_MAP时，godot会自动帮你处理这步转换流程。只需要使用texture函数来读取法线贴图，然后设置为NORMAL_MAP。

```
shader_type spatial;

uniform sampler2D normal_map : hint_normal;  //告诉 Godot 这是一个法线贴图

void fragment()
{
    vec3 normal = texture(normal_map, UV).rgb;   // 从贴图取出法线向量
    NORMAL_MAP = normal;  
    NORMAL_MAP_DEPTH = 2.0; 
}
```
NORMAL_MAP 是 spatial shader 的内置输出变量。你写入法线方向，Godot 引擎自动完成其它的工作。默认的法线深度是1，可以写入NORMAL_MAP_DEPTH来加强这种凹凸感。

**效果**：在 PlaneMesh 上，一张平坦的砖墙会具备凹凸感——砖缝凹陷、石面粗糙。而模型本身的顶点一个都没变。这就是法线贴图的核心价值：用极低的顶点数模拟极高的几何细节。

[IMAGE: 滚动效果](../ch09-diagrams/3d_texture.webp)

法线贴图主要有两种格式：OpenGL（NormalGL）和 DirectX（NormalDX）。它们唯一的区别是 **绿色通道（Y 分量）方向相反**。Godot需要使用 OpenGL（NormalGL）如果在 Godot 中误用了 DirectX 法线贴图，最明显的现象就是**凹凸方向完全相反**，原本应该凹进去的砖缝会看起来凸出来，光照方向也会显得不自然。

完整代码见 texture_3d.gdshader

## 6. 多层纹理混合：mix() 的进阶应用
第 6 章你学会了用 mix(a, b, t) 混合两种颜色。这一节把这个能力扩展到纹理混合——用同一个 mix() 把两层不同的纹理叠加在一起。

### 6.1 两层纹理，不同速度：视差滚动的核心机制
视差滚动（Parallax Scrolling）是一条古老的 2D 游戏技术：远处的背景移动得慢，近处的背景移动得快——用速度差创造深度感。

在 shader 中实现视差滚动，不需要多个节点——只需要对同一个 shader 里的两层纹理分别施加不同的 UV 偏移，然后用 mix() 混合：

```
// 远景层：滚动慢
vec2 uv_far = UV + vec2(TIME * speed_far, 0.0);
vec4 tex_far = texture(tex_stars, uv_far);

// 近景层：滚动快
vec2 uv_near = UV + vec2(TIME * speed_near, 0.0);
vec4 tex_near = texture(tex_stars, uv_near);
```
这里的关键是**相同的纹理、不同的 UV 偏移速度**——两张纹理不是真正的"远方"和"近处"星空，而是同一张星空纹理以不同速度滚动的两个实例。但大脑会把快的那层解读为"更近"，慢的那层解读为"更远"。

### 6.2 混合方式的选择
有了两层纹理的颜色值，如何把它们叠加在一起？三种常用策略：

**策略 A：mix() 平均混合**（适用于纹理之间不重叠或互补的场景）

```
float blend = 0.5;
vec4 result = mix(tex_far, tex_near, blend);
```
当 blend = 0.5 时，两层的可见度各占一半。blend 越接近 0，远景层越明显；越接近 1，近景层越明显。

**策略 B：max() 取亮部**

```
vec4 result = max(tex_far, tex_near);
```
max() 在每个像素上取两层中较亮的那个。如果远景层有一颗星、近景层也有一颗星，结果取两者中更亮的那颗——星星不会被覆盖，而是叠加变多。

**策略 C：+ 加法叠加**

```
vec4 result = tex_far * 0.5 + tex_near * 0.5;
```
各取一半权重相加。比 max 更柔和——当两层在同一位置都有亮像素时，结果会变亮（甚至超过 1.0，需要用 clamp 防过曝）。

## 7. 实战：Parallax 星空滚动背景
这是本章的核心实战——构建一个双层视差星空背景，两层以不同速度滚动，max() 叠加出深度感。全程不依赖外部 GDScript，所有动画在 shader 中完成。

### 第 1 步：单层滚动
最简版本：一张星空纹理，水平滚动。

```
shader_type canvas_item;

uniform sampler2D noise_tex: repeat_enable;
uniform float threshold = 0.9;

void fragment() {;
    vec2 uv = UV + vec2(TIME * 0.02, 0.0);
    float n = texture(noise_tex, uv).r;
    float stars = smoothstep(threshold - 0.01, threshold + 0.01, n);
    COLOR.rgb = vec3(stars);
}
```
给 noise_tex 赋一张 NoiseTexture2D（Seamless 模式），保存后画面向左缓慢滚动——这是整个效果的底线。

repeat_enable 是必需的——如果没有它，UV 滚出 [0, 1] 后画面就停在边缘像素不动了。然后使用smoothstep函数将noise切成一个个的小块，在大于0.9的地方才会保留，并柔和边缘。

### 第 2 步：加第二层，不同速度
在同一个 shader 中添加第二层纹理采样，用更快的滚动速度：

```
void fragment() {;
    vec2 uv_slow = UV + vec2(TIME * 0.02, 0.0);
    float stars_slow = texture(noise_tex, uv_slow).r;
    stars_slow = smoothstep(threshold - 0.01, threshold + 0.01, stars_slow);
    vec2 uv_fast = UV + vec2(TIME * 0.06, 0.0);
    float stars_fast = texture(noise_tex, uv_fast).r;
    stars_fast = smoothstep(threshold - 0.01, threshold + 0.01, stars_fast);
    COLOR.rgb = vec3(stars_slow+stars_fast);
}
```
**效果**：同一张纹理以两个速度滚动，用加法把两层中像素合并，当星星叠在一起时更亮。这样星星明显变多了。快的层（近景）和慢的层（远景）产生速度差，这就是视差滚动的雏形。

### 第 3 步：颜色调制
让远景星星略暗一些、近景星星略亮一些，加深深度感：星星可以是白色，也可以是金色、蓝色、紫色。用乘法给两层星空分别上色：

```
void fragment() {;
    vec2 uv_slow = UV + vec2(TIME * 0.02, 0.0);
    float stars_slow = texture(noise_tex, uv_slow).r;
    stars_slow = smoothstep(threshold - 0.01, threshold + 0.01, stars_slow);
    stars_slow *= 1.2;
    vec3 stars_far = vec3(stars_slow) *  vec3(0.3, 0.4, 0.8);  
    vec2 uv_fast = UV + vec2(TIME * 0.06, 0.0);
    float stars_fast = texture(noise_tex, uv_fast).r;
    stars_fast = smoothstep(threshold - 0.01, threshold + 0.01, stars_fast);
    stars_fast *= 1.5;
    vec3 stars_near = vec3(stars_fast) *  vec3(0.9, 0.85, 0.6); 

    COLOR.rgb = vec3(stars_far+stars_near);
}
```
**效果**：远景是深蓝色调，近景是金色暖调。两层颜色不同，眼睛更容易分辨远近——视差感又进了一步。

### 第 4 步：成品——提升为可调参数
把硬编码的数值全部提取为 uniform，方便在编辑器中实时调试，同时把相同的逻辑抽象成函数。在texture函数进行采样时，增加offset参数，以避免两层星空的噪音模式重复：

```
vec3 star_layer(vec2 uv, float speed, vec2 offset, float intensity, vec3 color) {
    uv += vec2(TIME * speed, 0.0);

    float n = texture(noise_tex, uv + offset).r;

    float s = smoothstep(threshold - softness, threshold + softness, n);
    s *= intensity;
    s = pow(s, 2.0);
    return color * s;
}

void fragment() {
    vec3 far_layer = star_layer(
        UV, slow_speed, vec2(13.1, 7.7), slow_intensity,
        vec3(0.3, 0.4, 0.8)
    );

    vec3 near_layer = star_layer(
        UV, fast_speed, vec2(91.2, 37.4), fast_intensity,
        vec3(0.9, 0.85, 0.6)
    );

    vec3 result = far_layer+near_layer;
    COLOR.rgb = result;
}
```
现在打开 Inspector，你可以：
- 拖动 speed_far 和 speed_near 调整两层滚动速度的比例
- 拖动 brightness_far 和 brightness_near 控制每层的星光明暗
- 更改 color_far 和 color_near 颜色选择器，实时切换远景/近景色调

完整 shader 文件见 stars_parallax.gdshader。

## 本章小结：纹理是 shader 的"输入设备"
这一章你跨越了一个关键门槛：从"一切都是数学"进入"数学 + 美术资源"的混合世界。

- **texture() 是取色笔**：你不需要画像素——你去贴图中拿像素。拿到 vec4 之后，之前学的所有工具（smoothstep、mix、sin、distance）照样能用。
- **UV 是坐标**：UV 不是"固定的"——它是你可以平移、缩放、旋转的变量。你变换的是"去哪里取色"，而不是纹理本身。
- **纹理参数是行为开关**：repeat_enable 让纹理无限平铺；filter_nearest 让像素风锐利；
- **多层混合创造深度**：同一张纹理以不同速度滚动，再用 max()/mix() 叠加——你创造的不是"两层图片"，而是"两个速度移动的天空平面"。大脑把这个解释为深度。
下一章我们将进入屏幕空间——不只是拿自己的纹理，还要读取**已经渲染到屏幕上的画面**，用 SCREEN_TEXTURE 和 SCREEN_UV 做热浪扭曲和水下折射。
