# 第 17 章：2D 水体特效

### 第 17 章：2D 水体特效
**学习目标**：综合运用之前学到的2D shader 技术，完成三个渐进式水体特效案例——从一个简单的 top-down 水面开始，逐步叠加波浪模拟、屏幕反射、程序化云层等技法，最终组合出可直接用于游戏的成品效果。同时总结出一套可复用的"特效设计方法论"，让读者在未来的项目中能独立拆解和实现任意 2D 游戏特效。

**场景搭建**：本章三个案例共用同一套验证环境。创建一个 Node2D 根节点，依次添加：① 一个 ColorRect（挂载 top-down 水面 shader）；② 侧向反射区域——上方放置一个 TextureRect（显示原始景物精灵），紧挨其下方放置另一个 TextureRect（同一纹理，但 flip_v = true 垂直翻转，挂载反射水面 shader）；③ 一个 ColorRect（挂载云层 shader 作为天空），其下方一个 ColorRect（挂载云层反射水面 shader，内部程序化生成云并反射）。所有节点均使用 canvas_item 类型 shader，不使用 BackBufferCopy 或 SCREEN_TEXTURE。

**内容要点**：

- 特效设计方法论：拆运动 → 拆颜色 → 拆形状 → 拆混合 → 定动画来源
- 案例 1：Top-down 流动水面（UV 滚动 + 噪声扰动 + 纹理图案 + 颜色混合）
- 案例 2：侧向视角水面反射（三重波浪 + 噪声扰动 + 镜像精灵反射 + 水深着色 + 波峰高光）
- 案例 3a：程序化卡通云层（多层噪声混合 + smoothstep 密度控制 + 色阶离散化）
- 案例 3b：云层反射水面（将案例 2 的反射系统 + 案例 3a 的云层生成组合到一个 shader 中）

## 0. 特效设计方法论：看到一个效果，你该从哪下手
第 12 章到第 16 章，每一章教会你一个独立的 shader 技术。但在实际项目中，你需要的不是"这个效果用什么技术"，而是**"看到一个效果之后，从哪开始下手"**。

下面这套五步分析法，是本书作者在拆解了几十个游戏特效后总结出的通用流程。本章三个案例都将按这个流程来讲解——你先学会"怎么想"，再学会"怎么做"。

### 五步分析法

```
看到一个游戏特效
    ↓
第一步 · 拆运动：它在怎么动？
    · 有没有旋转？（atan + TIME）
    · 有没有缩放？（UV * scale）
    · 有没有滚动？（UV + direction * TIME * speed）
    · 有没有噪声扰动？（noise texture → offset）
    ↓
第二步 · 拆颜色：颜色在怎么变化？
    · 有没有渐变色？（mix(color_a, color_b, t)）
    · 有没有发光/辉光？（emission = color * glow_factor）
    · 有没有色相/明度/饱和度变化？（rgb ↔ hsv）
    ↓
第三步 · 拆形状：这个效果的基本几何单元是什么？
    · 圆形/圆环？（length(uv), abs(dist - r)）
    · 矩形？（sd_rounded_box）
    · 纯噪声纹理？（直接采样）
    · SDF 复合？（min/max 组合多个形状）
    ↓
第四步 · 拆混合：各层之间怎么叠加？
    · mix(a, b, t) —— 线性混合
    · max(a, b) —— 取亮部（适合叠加发光层）
    · a * b —— 正片叠底（适合阴影/遮罩）
    ↓
第五步 · 定动画来源：谁来驱动这些变化？
    · TIME —— shader 内置时间（适合持续循环动画）
    · 鼠标/玩家坐标 —— GDScript → uniform
    · GDScript tween —— uniform 渐变（适合一次性触发）
    · 物理系统 —— GDScript 读取物理状态 → uniform
    ↓
    组合起来 → 写出 shader
```
这五步的妙处在于：**它把一个视觉上不可分割的整体效果，拆成了数学上可独立实现的小模块**。你不需要一次性在脑中建模整个效果——你只需要问五个问题，逐一回答，然后把答案拼起来。

下面三个案例中，每个案例的第一步都是"用五步分析法拆解这个效果"。在读到第二个案例时，你应该已经有了"先拆再写"的肌肉记忆。

**学习方法提示**：阅读本章时，每看到一个"五步拆解"表格，先不要往下看代码。自己闭上眼想一想：这个效果在画面上是什么样？拆出的每个小模块我大概会用哪个函数？然后再看答案。这是把知识从"认识的"变成"能用的"最有效的方式。

## 1. 案例 1：Top-down 流动水面

### 游戏中的什么地方用
俯视 RPG 的湖泊河流、策略游戏的海洋区域、弹幕射击的水面背景。核心需求：water 面纹理要有流动感，但不是规矩的一个方向滚动——要像真实水流一样有细微的乱流。

### 五步拆解

| 步骤 | 问题 | 答案 | 对应技术 |
| 1. 拆运动 | 水在怎么动？ | 沿固定方向持续流动，同时水面有细微不规则的乱流 | UV 滚动+ 噪声扰动 |
| 2. 拆颜色 | 水是什么颜色？ | 蓝色基底，亮部偏白（模拟水面反光） | mix(water_color, white, pattern) |
| 3. 拆形状 | 水的基本单元是什么？ | 一张重复的水纹图案纹理（pattern texture） | 纹理采样 |
| 4. 拆混合 | 各层怎么叠加？ | 颜色层 × 图案亮度 = 水面颜色 | mix() |
| 5. 定动画 | 谁来驱动？ | TIME 持续驱动流动 | TIME |

拆解完毕。这个效果需要的全部技术是：UV 滚动、噪声采样、颜色混合。下面分步构建。

### 1.1 第一步：最简版本 —— 不动的图案

```
shader_type canvas_item;

uniform sampler2D pattern_tex : repeat_enable;

void fragment() {
    float pattern = texture(pattern_tex, UV).r;
    COLOR.rgb = vec3(pattern);
}
```
效果：一个静止的黑白水面纹理。pattern_tex 是你要赋予的水纹图案——可以是一张四方连续的波纹贴图。.r 取红色通道作为灰度值，因为水纹图案通常是灰度图，任意通道都能代表亮度。

**为什么需要 pattern 纹理？** 纯数学函数（如 sin/cos 叠加）可以模拟规则波纹，但真实水面的光泽变化包含大量不规则的图案——水底深浅、岸边泡沫、水面反光斑块。一张图案纹理能以零计算量提供这些不规则信息。

### 1.2 第二步：让它流起来 —— UV 滚动
水面的第一步永远是"让它动"。UV 滚动就是给 UV 加上一个随时间增长的方向偏移：

```
uniform vec2 flow_direction = vec2(1.0, 0.0);
uniform float wave_flow_speed : hint_range(0.0, 2.0) = 0.15;

vec2 get_flow_uv(vec2 uv) {
    return uv + flow_direction * TIME * wave_flow_speed;
}

void fragment() {
    vec2 flow_uv = get_flow_uv(UV);
    float pattern = texture(pattern_tex, flow_uv).r;
    COLOR.rgb = vec3(pattern);
}
```
flow_direction 控制水流方向（(1.0, 0.0) = 从左到右），wave_flow_speed 控制流速。TIME 随时间增长 → UV 偏移量持续增大 → 纹理"滑动"起来。

现在水面流动了，但看起来像一条传送带——因为每行像素的偏移量完全相同，水纹以绝对规律的方式平移。真实水面不是这样的。

### 1.3 第三步：加噪声 —— 打破规律性
真实水面的"流动"实际上包含两种运动：大尺度的方向性流动（河水往下游走），和小尺度的随机扰动（漩涡、涟漪、局部乱流）。我们需要第二层偏移——噪声——来模拟后者。

噪声在这里解决什么问题？噪声给规律运动加上"有机感"。一条没有噪声的河流看起来像电脑生成的，加上噪声后就像无人机航拍的真实河流。

```
uniform sampler2D noise_texture : repeat_enable;
uniform float noise_scale = 3.0;
uniform float noise_strength : hint_range(0.0, 0.05) = 0.02;
uniform float flow_speed : hint_range(0.0, 2.0) = 0.1;

vec2 get_noise_offset(vec2 uv) {
    vec2 noise_uv = uv * noise_scale + flow_direction * TIME * flow_speed;
    vec2 noise = texture(noise_texture, noise_uv).rg;
    noise = noise * 2.0 - 1.0;
    return noise * noise_strength;
}

void fragment() {
    vec2 noise_offset = get_noise_offset(UV);
    vec2 final_uv = get_flow_uv(UV) + noise_offset;
    float pattern = texture(pattern_tex, final_uv).r;
    COLOR.rgb = vec3(pattern);
}
```
逐行解释 get_noise_offset()：

- uv * noise_scale：放大 UV 坐标。noise_scale = 3.0 意味着噪声纹理在画面上的"颗粒"缩小到 1/3——噪声特征更密集
- + flow_direction * TIME * flow_speed：噪声本身也在流动（和主流同方向但速度不同），防止噪声图案成为"静止的扭曲"
- texture(noise_texture, noise_uv).rg：从噪声纹理取 R 和 G 通道，组成一个 vec2。两个通道的值各自在 [0, 1] 范围内
- * 2.0 - 1.0：把 [0, 1] 映射到 [-1, 1]，让偏移方向可以同时向左和向右
- * noise_strength：缩放偏移量。0.02 意味着每个像素最多偏移 2% 的 UV 范围——这是扰动，不是位移
**两层偏移的关系**：第一步的 get_flow_uv() 提供大尺度的方向流动，第二步的 get_noise_offset() 在此基础上叠加小尺度的随机扰动。两者相加形成最终采样坐标——既有方向感，又不失有机感。

### 1.4 第四步：加颜色 —— 从灰度到水面
目前画面是黑白的图案纹理。水面应该是蓝色的，且图案中的"亮区"应该模拟水面反光（偏白），"暗区"模拟深水（偏蓝）。

```
uniform vec4 water_color : source_color = vec4(0.1, 0.45, 0.7, 0.8);

void fragment() {
    vec2 noise_offset = get_noise_offset(UV);
    vec2 final_uv = get_flow_uv(UV) + noise_offset;
    float pattern = texture(pattern_tex, final_uv).r;
    vec3 reflection = mix(water_color.rgb, vec3(1.0), pattern).rgb;
    COLOR.rgb = reflection;
}
```
pattern 的值在 [0, 1] 之间（图案暗区=0，亮区=1）。mix(water_color, white, pattern)：暗区 → 水蓝色，亮区 → 白色（模拟水面反光）。这就是案例 1 的全部着色逻辑——极简，但足以产生"有光泽的水面"的视觉。

### 1.5 第五步：成品总结
完整 shader 文件：water_topdown.gdshader

**核心技术组合回顾**：

| 技术 | 在本案例中的角色 |
| UV 滚动 (UV + direction * TIME) | 水流的主体运动 |
| 噪声纹理采样 (texture(noise, uv).rg) | 打破 UV 滚动的规律性，增加自然乱流 |
| mix(water_color, white, pattern) | 用纹理图案的亮度控制水面颜色在"深蓝"和"反光白"之间过渡 |

**关键参数调试指南**：

| 参数 | 默认值 | 调高效果 | 调低效果 |
| wave_flow_speed | 0.15 | 水流更急（山涧） | 水流更缓（沼泽） |
| noise_strength | 0.02 | 乱流明显（激流） | 几乎只有方向性流动（平缓水面） |
| noise_scale | 3.0 | 噪声颗粒更细密 | 噪声颗粒更大块（不适合水面） |
| flow_speed | 0.1 | 噪声自身流动更快 | 噪声自身几乎静止 |

把 noise_strength 从 0.02 调到 0.0（关掉噪声），观察只有 UV 滚动的水面——你会看到它像一个滚动的传送带。再把 wave_flow_speed 从 0.15 调到 0.0（关掉流动），只剩噪声——水面变成静止的扭曲图案。两种运动缺一不可：滚动给方向，噪声给有机感。

## 2. 案例 2：侧向视角水面反射

### 游戏中的什么地方用
横版卷轴游戏的水域区域、侧视 RPG 的河面。核心需求：水面不只是自己流动，还要**反射出上方的景物**——天空、建筑、角色——并且反射影像要被波纹打碎。

这比案例 1 多了一个核心挑战：从"水面自己的图案"变成"水面反射外部世界"。

### 场景搭建要点
本案例不需要 BackBufferCopy 或 Viewport，用的是 2D 游戏中一个极简的"伪反射"技巧——**镜像精灵**：

- 将景物的原始精灵（TextureRect/Sprite2D）放置在画面上方（正常显示区域）
- 在原始精灵的正下方放置第二个 TextureRect/Sprite2D，**使用同一张纹理**，但设置 flip_v = true（垂直翻转），并挂载 reflection.gdshader
- 垂直翻转让"倒影"已经出现在正确的位置——画面下方的"镜像"就是未经扭曲的反射
- shader 通过 texture(TEXTURE, uv) 采样的是**节点自身的纹理**（即那张已被垂直翻转的精灵图），然后施加波浪偏移，把"完美的镜像"变成"被打碎的水面倒影"
**为什么用镜像精灵而不是 BackBufferCopy？** 有三个理由：(1) 性能——不需要额外的渲染 pass，零开销；(2) 简单——一个 TextureRect + flip_v = true 就能搞定；(3) 可控——你可以独立调整水面的纹理质量、分辨率、翻转后的位置，不受场景中其他节点的影响。代价是"反射"的内容局限于你手动镜像的那张纹理——但对于 2D 游戏中的静态水面背景，这完全够用。

### 五步拆解

| 步骤 | 问题 | 答案 | 对应技术 |
| 1. 拆运动 | 水面上的反射影像在怎么动？ | 横向波纹摆动——不是单纯的 UV 平移，而是"镜像纹理被波浪扭曲" | 正弦波扰动 UV+ 噪声扰动 |
| 2. 拆颜色 | 反射影像之外还有哪些颜色？ | 水深区域偏暗蓝，波峰有白色高光 | mix(deep, shallow, height) 水深着色+ pow(max(wave, 0), 4) 高光 |
| 3. 拆形状 | 基本单元是什么？ | 精灵纹理的像素——水面通过 texture(TEXTURE, uv) 采样上方景物的镜像 | texture(TEXTURE, uv) |
| 4. 拆混合 | 各层怎么叠加？ | 反射纹理 × 水深着色 + 波峰高光 | * 叠加 + + 加亮 |
| 5. 定动画 | 谁来驱动？ | TIME 驱动波浪和噪声流动 | TIME |

### 2.1 第一步：单波偏移 —— 一条正弦波的扭曲
先不看噪声、不看颜色。反射的核心操作只有一个——用正弦波偏移 UV，让纹理的采样位置沿水平方向波动：

```
shader_type canvas_item;

uniform float wave_amplitude : hint_range(0.0, 0.1) = 0.025;
uniform float wave_frequency : hint_range(1.0, 50.0) = 20.0;
uniform float wave_speed : hint_range(0.0, 5.0) = 1.2;

void fragment() {
    float wave = sin(UV.y * wave_frequency + TIME * wave_speed);
    vec2 offset = vec2(wave * wave_amplitude, 0.0);
    vec4 reflection = texture(TEXTURE, UV + offset);
    COLOR = reflection;
}
```
关键点：
- sin(UV.y * frequency + TIME * speed)：一条沿 Y 轴（画面垂直方向）传播的水平波纹。在任意一帧，屏幕上半部和下半部的 UV 偏移量不同，形成"行交替扭曲"的波浪感
- offset 只加在 X 方向：水平波纹反映在画面上是"水平行被左右拉动"——这正是你站在水边看到的倒影扭曲方向
- wave_amplitude = 0.025：每条波纹把像素左右拉动约 2.5% 的屏幕宽度。值越大扭曲越剧烈

**为什么用 UV.y 而不是 UV.x？** 在侧向视角中，水面占据画面下半部。UV.y 从 0（水面顶部/远岸）变化到 1（水面底部/近岸）。波纹沿 Y 轴传播意味着越靠近观众（UV.y 大），波纹越密集——符合透视直觉。

### 2.2 第二步：三重波浪 —— 多频叠加打破单一节奏
一条正弦波产生的扭曲太规律——所有像素在同一行的偏移量完全相同，倒影看起来像在"均匀地左右摇晃"。真实水面的波纹是多种频率、多种速度的叠加：

```
vec2 get_flow_uv(vec2 uv) {
    return uv + flow_direction * TIME * wave_flow_speed;
}

float get_wave_height(vec2 uv) {
    vec2 flow_uv = get_flow_uv(uv);
    float t = TIME;
    float wave1 = sin(flow_uv.y * wave_frequency + t * wave_speed);
    float wave2 = sin(flow_uv.x * wave_frequency * 0.7 + t * wave_speed * 1.4);
    float wave3 = sin((flow_uv.x + flow_uv.y) * wave_frequency * 0.45 + t * wave_speed * 0.8);
    return (wave1 + wave2 + wave3) / 3.0;
}

vec2 get_wave_offset(float height) {
    return flow_direction * height * wave_amplitude;
}
```
三条波的差异设计：
- **wave1**：沿 Y 轴传播的主波（flow_uv.y * frequency）——基础水平波纹
- **wave2**：沿 X 轴但频率更低（* 0.7）、速度更快（* 1.4）——在水平波纹上叠加微弱的纵向起伏
- **wave3**：沿对角线传播（flow_uv.x + flow_uv.y）、频率最低（* 0.45）——缓慢的大尺度涌浪

三条波取平均：每一点的偏移是三种不同方向和频率的运动的综合结果。规律性被打破了——但你单看画面感觉"就是水在晃"，而不是在"算三条波"。

### 2.3 第三步：加噪声 —— 水面不止是波浪
和案例 1 一样，波浪之外还需要噪声来模拟细碎的涟漪和乱流。这部分代码与案例 1 完全相同：

```
uniform sampler2D noise_texture : repeat_enable;
uniform float noise_scale = 3.0;
uniform float noise_strength : hint_range(0.0, 0.05) = 0.02;
uniform float flow_speed : hint_range(0.0, 2.0) = 0.1;

vec2 get_noise_offset(vec2 uv) {
    vec2 noise_uv = uv * noise_scale + flow_direction * TIME * flow_speed;
    vec2 noise = texture(noise_texture, noise_uv).rg;
    noise = noise * 2.0 - 1.0;
    return noise * noise_strength;
}
```
现在最终的采样 UV 是三层偏移的叠加：

```
float wave_height = get_wave_height(UV);
vec2 wave_offset = get_wave_offset(wave_height);
vec2 noise_offset = get_noise_offset(UV);
vec2 final_offset = wave_offset + noise_offset;
vec4 reflection = texture(TEXTURE, UV + final_offset);
```
**三层偏移的分工**：波浪（正弦波）负责大尺度的倒影扭曲——你看到的"倒影在晃动"；噪声负责小尺度的细碎扰动——你看到的"水面在闪烁"。两者缺一不可：少了波浪，倒影不会扭曲；少了噪声，扭曲过于光滑。

### 2.4 第四步：水深着色 —— 不只是"反射"
只反射纹理的水面会有一个问题——画面中所有区域（远岸、近岸、深水、浅水）看起来都一样。现实中的水体是**靠近岸边浅**、**中央深处暗**，而且波峰处因角度关系反光更强。

我们需要根据波浪高度给水面"染色"：

```
uniform float depth_strength : hint_range(0.0, 1.0) = 0.55;

vec3 get_water_tint(float wave_height) {
    float height = wave_height * 0.5 + 0.5;
    vec3 deep_color = water_color.rgb * (1.0 - depth_strength);
    return mix(deep_color, water_color.rgb, height);
}
```
逐行解释：
1. wave_height * 0.5 + 0.5：把 [-1, 1] 的波高值映射到 [0, 1]，方便当 mix 插值权重
2. water_color.rgb * (1.0 - depth_strength)：深水颜色 = 水体颜色 × 暗度系数。depth_strength = 0.55 意味着深水亮度只有水色的 45%
3. mix(deep_color, water_color, height)：波峰（height 大）→ 水原色（亮），波谷（height 小）→ 深水色（暗）

效果：波浪起伏处，画面自动呈现出"亮暗交替"的立体感。这不是光照计算——只是借波浪高度在"水色"和"深水色"之间做了渐变。

### 2.5 第五步：波峰高光 —— 让水面"闪光"
最后一项：波峰处的白色高光。真实水面在波浪最高点会集中反射光源，形成刺眼的白色光斑：

```
uniform float highlight_strength : hint_range(0.0, 1.0) = 0.25;

// 在 fragment() 中，着色之后：
float highlight = pow(max(wave_height, 0.0), 4.0);
water += highlight * highlight_strength * water_color.rgb;
```
关键操作：
- max(wave_height, 0.0)：只取正波高（波峰），波谷下方忽略
- pow(..., 4.0)：把波高值压成"尖峰"——只有最高的波峰才产生高光。指数越大，高光范围越窄（越集中在最高点）
- 加到 water 上而非乘以 water：高光是"额外叠加"的光，不是调亮现有颜色

### 成品总结
完整 shader 文件：reflection.gdshader

**核心技术组合回顾**：

| 技术 | 在本案例中的角色 |
| sin() 三重波叠加 | 大尺度的倒影扭曲（模拟波浪折射） |
| 噪声纹理采样 | 小尺度的水面闪烁和乱流 |
| texture(TEXTURE, uv + offset) | 采样节点的纹理（垂直翻转的镜像精灵），产生"倒影在水面扭曲"的效果 |
| mix(deep, shallow, wave_height) | 用波高做水深着色（波峰亮、波谷暗） |
| pow(max(wave, 0), 4.0) | 波峰高光——只有最高点才加白色闪光 |

**与案例 1 的技术对比**：

| 对比维度 | 案例 1（top-down） | 案例 2（侧向反射） |
| 核心运动 | UV 滚动 + 噪声 | 正弦波 × 3 + 噪声 |
| 水面内容 | 图案纹理 | 镜像精灵纹理（flip_v = true） |
| 着色逻辑 | mix(water_color, white, pattern) | mix(deep, shallow, wave_height) + 高光 |
| 复杂度 | 简单——适合快速背景水体 | 中等——适合需要反射的场景水体 |

**关键参数调试指南**：

| 参数 | 默认值 | 效果描述 |
| wave_amplitude | 0.025 | 倒影扭曲强度。太大 → 倒影完全不可辨认；太小 → 像镜子 |
| wave_frequency | 20.0 | 波纹密度。值越大波纹越密（模拟微风水面） |
| depth_strength | 0.55 | 水深差异。0.0 → 全水面均匀色；1.0 → 波谷纯黑 |
| highlight_strength | 0.25 | 波峰高光亮度。0.0 → 哑光水面；0.5 → 强反光 |

## 3. 案例 3：云层反射水面

### 游戏中的什么地方用
俯视 RPG 中水体反射天空的云层——水面不只是"蓝色的"，而是能映出天上飘过的白云。也适用于任何需要"水体反射一个不可见物体"的场景——比如水面反射月亮（月亮本身在画面外）。

第三个案例拆成两个部分：先做一个"会飘的云"（天空背景），再做一个"把云反射到水面上"的 shader。

### 为什么需要独立的云 shader
案例 2 的反射依赖镜像精灵——水面上方必须有一张纹理可以镜像。但在 top-down 视角中，天空（包括云层）在画面之外——没办法用简单的 flip_v = true 来镜像。**解决方案**：用 shader 程序化生成云层，然后在水面 shader 中"想象"一个天空，从中采样。

这就是案例 3 的核心思路：**把"反射外部世界"变成"反射程序化生成的世界"**。这个思路的适用范围远超水面——任何需要在 shader 中"凭空产生"反射内容的场景都能用。

---

### 3a. 程序化卡通云层
完整 shader 文件：cloud.gdshader

#### 五步拆解

| 步骤 | 问题 | 答案 | 对应技术 |
| 1. 拆运动 | 云在怎么动？ | 缓慢漂移，不同频率的云层速度不同 | UV + TIME * speed 多频偏移 |
| 2. 拆颜色 | 云是什么颜色？ | 白色高亮，淡蓝灰阴影，蓝天底色 | mix(sky, cloud_color, density) |
| 3. 拆形状 | 云的基本单元是什么？ | 噪声纹理的多层叠加——没有固定形状的"团块" | 噪声纹理采样 |
| 4. 拆混合 | 各层怎么叠加？ | 不同频率的噪声加权相加 + smoothstep 控制密度 | 加权混合 + smoothstep |
| 5. 定动画 | 谁来驱动？ | TIME 驱动各层云以不同速度漂移 | TIME |

#### 第一步：一张噪声的云

```
shader_type canvas_item;

uniform sampler2D noise : repeat_enable;
uniform float time_speed : hint_range(0.0, 1.0) = 0.1;

void fragment() {
    vec2 uv = UV * 2.0;
    vec2 offset = vec2(TIME * time_speed * 0.1, TIME * time_speed * 0.05);
    float cloud = texture(noise, uv + offset).r;
    COLOR.rgb = vec3(cloud);
}
```
效果：一张放大了 2 倍的噪声纹理，在画面上缓慢漂移。这就是云层的基础——一团模糊的、缓慢移动的灰度图案。

#### 第二步：多层噪声混合 —— 让云"有结构"
一张噪声看起来像一团均匀的灰雾。真实云层有"块状感"——大片白云团、小块碎云、云间的蓝天缝隙。不同尺度的结构需要不同频率的噪声：

```
uniform float scale : hint_range(0.1, 10.0) = 2.0;

void fragment() {
    vec2 uv = UV * scale;
    vec2 offset = vec2(TIME * time_speed * 0.1, TIME * time_speed * 0.05);

    float n1 = texture(noise, uv + offset).r;
    float n2 = texture(noise, uv * 2.5 - offset * 0.7).r;
    float n3 = texture(noise, uv * 0.8 + offset * 1.2).r;
    float n4 = texture(noise, uv * 4.0 + offset * 0.3).r;

    float cloud = n1 * 0.5 + n2 * 0.3 + n3 * 0.15 + n4 * 0.05;
    COLOR.rgb = vec3(cloud);
}
```
四条噪声通道的分工：

| 通道 | UV 缩放 | 偏移速度 | 权重 | 作用 |
| n1 | ×1.0（基准） | 基准速度 | 0.5 | 大块云团的主体形状 |
| n2 | ×2.5 | 基准 × 0.7（略慢） | 0.3 | 中等尺寸的云层细节 |
| n3 | ×0.8 | 基准 × 1.2（略快） | 0.15 | 大尺度的缓慢渐变（云团之间的过渡） |
| n4 | ×4.0 | 基准 × 0.3（慢） | 0.05 | 细碎的云朵纹理 |

**为什么各层的偏移方向不同（有的是 + offset，有的是 - offset）？** 如果所有层朝同一个方向以相同的速度漂移，画面看起来像一张图在平移。让不同层朝不同方向（或不同速度）移动，产生的是"云层之间的相对运动"——大云团和小碎云各自独立漂移。

#### 第三步：用 smoothstep 控制密度 —— 让云"有边界"
目前的云是连续的灰度渐变——从白到灰均匀过渡。真实云层有明确的边界——一块云是白的，旁边的天空是蓝的，之间有一个明显的分界：

```
uniform float cloud_density : hint_range(0.0, 1.0) = 0.4;
uniform float softness : hint_range(0.0, 0.5) = 0.15;

// 在混合出 cloud 值之后：
cloud = smoothstep(cloud_density, cloud_density + softness, cloud);
```
smoothstep(0.4, 0.55, cloud) 的效果：噪声值低于 0.4 的区域 → 输出 0（无云/蓝天），高于 0.55 的区域 → 输出 1（白云），0.4–0.55 之间 → 平滑过渡（云的边缘）。cloud_density 控制"有多少天空区域被云覆盖"（调高 = 多云，调低 = 晴空），softness 控制云的边缘柔和度。

#### 第四步：卡通色阶 —— 风格化处理
给云加上卡通/赛璐珞风格：不保留连续灰度，而是离散化为有限几阶：

```
uniform int color_steps : hint_range(2, 8) = 4;

float stepped = floor(cloud * float(color_steps)) / float(color_steps - 1);
stepped = clamp(stepped, 0.0, 1.0);
```
floor(cloud * 4) / 3 的效果：连续的 [0, 1] 云密度被映射为 4 个离散台阶（0.0, 0.33, 0.67, 1.0）。结果：云的阴影部分不再是"渐变的灰"，而是"分层的色块"——类似于塞尔达旷野之息的天空风格。

#### 第五步：上色+混合

```
uniform vec3 sky_color : source_color = vec3(0.3, 0.6, 0.9);

vec3 cloud_color = mix(
    vec3(0.7, 0.75, 0.85),   // 阴影部分（淡蓝灰）
    vec3(1.0, 1.0, 1.0),     // 高亮部分（纯白）
    stepped
);
vec3 final_color = mix(sky_color, cloud_color, stepped);
COLOR = vec4(final_color, 1.0);
```
两层 mix 的逻辑：
1. 在云色内部：stepped 从 0→1，颜色从"阴影蓝灰"渐变到"高亮纯白"——云自己的明暗层次
2. 在天空与云之间：mix(sky_color, cloud_color, stepped)——无云区域（stepped=0）输出蓝天，有云区域（stepped>0）输出云色

**关键参数调试**：

| 参数 | 默认值 | 调高效果 | 调低效果 |
| cloud_density | 0.4 | 晴空万里→多云 | 阴天→少云 |
| softness | 0.15 | 云边缘生硬（剪纸感） | 云边缘柔和（水彩感） |
| color_steps | 4 | 更平滑（接近连续色） | 更卡通（2 阶 = 纯二值，无阴影） |
| time_speed | 0.1 | 云飘得快 | 云几乎静止 |

### 3b. 云层反射水面
完整 shader 文件：water_cloud.gdshader

现在把案例 2 的反射系统和案例 3a 的云层系统组合到一起。核心变化：反射 shader 中的 texture(TEXTURE, uv) 被替换为对**程序化天空函数**的调用。

#### 五步拆解

| 步骤 | 问题 | 答案 | 对应技术 |
| 1. 拆运动 | 水面反射的云在怎么动？ | 波浪扭曲 + 噪声扰动（与案例 2 相同） | 三重 sin 波 + 噪声 |
| 2. 拆颜色 | 反射的是什么颜色？ | 程序化生成的天空（蓝天 + 飘浮白云）+ 水深着色 + 高光 | get_sky_background() 函数 |
| 3. 拆形状 | 反射内容的基本单元？ | 程序化云层（噪声叠加 + smoothstep） | 来自案例 3a 的云层生成逻辑 |
| 4. 拆混合 | 各层怎么叠加？ | 天空色 × 水色 + 波峰高光 | * 叠加 + + 高光 |
| 5. 定动画 | 谁来驱动？ | TIME 驱动波浪 + TIME 驱动云层漂移（两个独立的时间系统） | TIME |

#### 第一步：搬来波浪系统
从案例 2 直接把 get_flow_uv()、get_wave_height()、get_wave_offset()、get_noise_offset() 全部搬过来。不需要改一行代码——水面反射的"扭曲层"完全相同：

```
// 与案例 2 完全相同的波浪系统（略）
uniform float wave_amplitude, wave_frequency, wave_speed;
uniform vec2 flow_direction;
uniform float wave_flow_speed, flow_speed, noise_scale, noise_strength;
uniform sampler2D noise_texture : repeat_enable;

// get_flow_uv() / get_wave_height() / get_wave_offset() / get_noise_offset()
// 全部与案例 2 相同，此处略
```

#### 第二步：移植云层生成函数
把案例 3a 的云层逻辑封装成一个函数，放进水面 shader：

```
uniform sampler2D cloud_texture : repeat_enable;

float get_cloud(vec2 uv, float scale, float time_speed) {
    vec2 offset = vec2(TIME * time_speed * 0.1, TIME * time_speed * 0.05);

    float n1 = texture(cloud_texture, uv * scale + offset).r;
    float n2 = texture(cloud_texture, uv * scale * 2.5 - offset * 0.7).r;
    float n3 = texture(cloud_texture, uv * scale * 0.8 + offset * 1.2).r;

    float cloud = n1 * 0.5 + n2 * 0.3 + n3 * 0.15;
    return smoothstep(0.4, 0.55, cloud);
}
```
这里只保留了案例 3a 的 n1/n2/n3（去掉了 n4 和卡通化步骤），因为水面反射中的云不需要太多细节——波浪扭曲本身就会"打散"云的形状。cloud_texture 和 noise_texture 可以用同一张噪声纹理（不同参数采样即可）。

#### 第三步：组装天空背景

```
uniform vec3 sky_color : source_color = vec3(0.3, 0.6, 0.9);

vec3 get_sky_background(vec2 uv) {
    float cloud_density = get_cloud(uv, 1.0, 0.1);

    vec3 cloud_color = mix(
        vec3(0.7, 0.75, 0.85),
        vec3(1.0, 1.0, 1.0),
        cloud_density
    );

    return mix(sky_color, cloud_color, cloud_density);
}
```
get_sky_background(uv) 的返回值：给定一个 UV 坐标，返回"从这个方向看天空"的颜色——包含蓝天底色和白/灰云层。它就是云 shader 的"精简版"，去掉了卡通色阶（因为反射水面不需要卡通风格），但保留了云团的结构。

#### 第四步：用水面扭曲采样天空
这是和案例 2 的核心差异——**不是采样镜像纹理，而是采样程序化天空**：

```
void fragment() {
    float wave_height = get_wave_height(UV);
    vec2 wave_offset = get_wave_offset(wave_height);
    vec2 noise_offset = get_noise_offset(UV);
    vec2 sample_uv = UV + wave_offset + noise_offset;

    vec3 reflection = get_sky_background(sample_uv);

    vec3 water_tint = get_water_tint(wave_height);
    vec3 water = reflection * water_tint;

    float highlight = pow(max(wave_height, 0.0), 4.0);
    water += highlight * highlight_strength * water_color.rgb;

    COLOR = vec4(water, 1.0);
}
```
把案例 2 的 texture(TEXTURE, uv + offset) 替换为 get_sky_background(uv + offset)——这就是两个案例之间的"接口"。波浪系统和着色逻辑保持不变，只换了"反射内容的来源"。

#### 第五步：成品总结
**核心技术组合回顾**：

| 技术 | 在本案例中的角色 |
| 三重 sin 波 + 噪声偏移（来自案例 2） | 水面扭曲——打碎云的倒影 |
| 多层噪声混合（来自案例 3a） | 程序化生成天空中的云层图案 |
| smoothstep(0.4, 0.55, cloud) | 控制云的边界清晰度 |
| mix(sky, cloud, density) | 蓝天和白云的混合 |
| mix(deep, shallow, wave_height) + 高光 | 水深着色（同案例 2） |

**案例 2 vs 案例 3b 对比**：

| 对比维度 | 案例 2 | 案例 3b |
| 反射来源 | 节点自身的纹理（镜像精灵，flip_v = true） | get_sky_background() → 程序化天空 |
| 反射内容 | 上方景物的垂直镜像 | shader 内部生成的云层 |
| 适用视角 | 侧向（景物在水面上方有可见纹理） | Top-down（天空在画面外，需要程序化生成） |
| 依赖 | 需要一张可镜像的精灵纹理 | 完全自包含，不依赖场景内容 |
| 技术要点 | 纹理采样 + 波浪扭曲 | 程序化纹理生成 + 波浪扭曲 |

**两个案例可以组合**——如果你在做一个"侧向视角但天空不可见"的场景，可以把案例 3b 的 get_sky_background() 和案例 2 的镜像精灵叠加：靠近岸边的水面镜像景物纹理，远处水面反射程序化生成的天空。

## 4. 本章小结：方法论验证
下面的表格把本章三个案例按五步分析法拆解后的对比列在一起。观察一种模式：**越复杂的案例，拆出的"运动模块"越多，"混合层级"越深——但每一步的拆解逻辑完全一致**。

| 步骤 | 案例 1（top-down 水面） | 案例 2（侧向反射） | 案例 3a（云层） | 案例 3b（云反射水面） |
| 1. 运动 | UV 滚动 + 噪声扰动 | 三重 sin 波 + 噪声扰动 | 多频 UV 漂移 | 三重 sin 波 + 噪声扰动（水面）+ 多频 UV 漂移（云层） |
| 2. 颜色 | mix(水色, 白, pattern) | mix(深水, 水色, wave) + 纯白高光 | mix(蓝天, 云色, density) | mix(深水, 水色, wave) + 程序化天空的颜色信息 |
| 3. 形状 | 图案纹理 | 镜像精灵的纹理 | 噪声纹理团块 | 程序化天空的形状 + 水面扭曲 |
| 4. 混合 | 单层 mix | 反射 × 水色 + 高光 | 多层噪声加权 + smoothstep + mix | 天空采样 × 水色 + 高光 |
| 5. 动画 | TIME 驱动流动 | TIME 驱动波浪 | TIME 驱动云漂移 | TIME 同时驱动波浪和云漂移 |

**核心洞察**：如果一个效果拆不出五步中某一步的答案，说明你对这个效果的理解还不够"数据化"。回去多看几眼参考效果，把"它在做什么"转化为"它能拆成哪些数学操作"。

### 当你在游戏中需要一个新特效时
不要问"有没有现成的 shader 能实现 X 效果"。问这五个问题：

- **它在怎么动？** → 选运动函数（sin / fract / atan / 噪声）
- **颜色怎么变？** → 选颜色操作（mix / hsv / pow 亮度）
- **形状是什么？** → 选形状来源（纹理 / SDF / 噪声本身）
- **各层怎么叠？** → 选混合算子（mix / max / *）
- **谁驱动变化？** → 选动画源（TIME / uniform + GDScript）
回答完这五个问题，你的 shader 骨架就已经有了。剩下的只是代码——而代码你已经在前 16 章学过了。

### 
细心的读者可能注意到：本章的反射案例**没有使用** SCREEN_TEXTURE和BackBufferCopy 。主要为简化场景安排。在游戏中，"反射"有多种实现路径，各有适用场景：

| 技术 | 原理 | 适用场景 | 本章是否使用 |
| 镜像精灵（flip_v） | 复制节点 + 垂直翻转 + shader 扭曲 | 静态背景反射（河面倒影、湖面倒影），内容是一张已知纹理 | ✅ 案例 2 |
| 程序化生成 | shader 内部用噪声/数学函数生成反射内容 | 反射对象在画面外（天空、云层），或者需要完全程序化控制 | ✅ 案例 3b |
| SCREEN_TEXTURE + BackBufferCopy | 采样已渲染的屏幕内容 | 反射对象是场景中动态变化的节点（移动的角色和敌人），且内容无法用程序化方式描述 | ❌ 未使用 |
| Viewport → ViewportTexture | 将子视口渲染为纹理 | 需要反射一整个独立的 3D 场景、或需要多角度反射 | ❌ 未使用 |

选择哪条路径的决策原则：**反射内容是"已知的静态纹理"还是"动态变化的屏幕内容"？** 前者用镜像精灵（零额外开销），后者才考虑屏幕空间技术。这是一个典型的工程权衡——能用更简单的方案解决问题时，就不要引入更复杂的技术。

如果你需要为一个包含动态角色的场景做实时反射，ch10 的 SCREEN_TEXTURE + BackBufferCopy 就是正确的工具。详见第 10 章的屏幕空间技术一节。
