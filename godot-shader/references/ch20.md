# 第 20 章：Light 函数与自定义光照

### 第 20 章：Light 函数与自定义光照 —— 让光听你的话
**学习目标**：掌握 light() 函数的工作原理，能从头写出 Lambert 漫反射、Blinn-Phong 高光、Fresnel 边缘光和二段式 Toon Shader，理解 Godot 如何把"每光源×每像素"的光照计算交给 shader 控制。

**场景搭建**：创建一个 Node3D 根节点，添加 MeshInstance3D 子节点并挂载 SphereMesh（或任何带法线的模型）。在场景中添加一个光源，然后关闭环境光（将preview environment中的sky energy设置为0）。为 MeshInstance3D 新建 ShaderMaterial，shader_type 设为 spatial。本章所有 shader 代码直接在 light() 函数中编写，无需 GDScript 辅助。

**内容要点**：

- light() 的执行上下文：每光源×每像素运行；输入变量 LIGHT / ATTENUATION / VIEW / NORMAL / LIGHT_COLOR；输出变量 DIFFUSE_LIGHT / SPECULAR_LIGHT
- Lambert 漫反射的 5 步渐进：dot(N,L) → max(0, dot) → 乘 ATTENUATION → 乘 ALBEDO → 乘 LIGHT_COLOR
- Blinn-Phong 高光：half vector = normalize(LIGHT + VIEW)，pow(dot(N, half), m) 控制高光集中度
- Fresnel 效应：pow(1.0 - abs(dot(NORMAL, VIEW)), 5.0) 实现边缘亮、正面暗
- Toon Shading 三件套：色阶量化（ceil 分段）→ 卡通高光（step 阈值）→ 卡通边缘光（Fresnel + step）
- render_mode ambient_light_disabled：关闭引擎默认环境光，实现纯 toon 风格
- 数据流理解：fragment() 和 light() 的分工——前者准备材质属性，后者计算每个光源的贡献

---

## 0. 为什么需要 light()？
第 4 章讲过，spatial shader 有三条处理链：vertex() → fragment() → light()。到本章之前，你一直在用 Godot 的**默认光照**：在 fragment() 中写好 ALBEDO、ROUGHNESS、METALLIC，引擎自动帮你完成光照计算，最后把颜色显示在屏幕上。

这很好，如果你想要特定的效果呢？比如：

- 一个动漫角色的 skin shading，暗部不是"变暗"，而是"换成另一种颜色"
- 一个卡通风格的场景，光照明暗之间没有渐变，而是锐利的二分
- 一个技术感的全息投影，边缘亮、中间暗——和菲涅尔默认输出相反
这些问题都有一个共同的答案：**接管光照计算**。light() 函数就是你接管控制权的地方。它让你逐个光源、逐个像素地决定"这个光对我照了多少"和"我该怎么回应这个光"。

### 为什么不能在 fragment() 里算光照？
很多初学者学到这里会困惑：fragment() 里明明已经有 NORMAL，为什么还要多一个 light() 函数？直接在 fragment() 里做 dot(NORMAL, LIGHT) 不行吗？

答案是：**fragment() 里根本没有 LIGHT。**

fragment() 的职责是回答"**我是什么材质**"——设置 ALBEDO、ROUGHNESS、METALLIC，从纹理采样颜色。它不知道自己会被哪些光源照亮，也不知道每个光源在什么方向、有多远。光源信息只有在 light() 里才有（LIGHT、LIGHT_COLOR、ATTENUATION）。

更深一层：场景通常有多个光源，每个光源对同一个像素的贡献需要独立计算然后累加。如果在 fragment() 里写一个循环遍历所有光源，你不仅需要自己管理光源列表，还要处理不同类型光源（定向光、点光源、聚光灯）的计算差异，以及阴影贴图采样——这相当于把引擎的光照管线重写一遍。

Godot 的做法是：**引擎帮你遍历光源，你只需写一次 light() 来定义"一个光源如何影响一个像素"**。引擎在背后调用 light()，每光源每像素一次，然后把所有结果累加。

记住这个口诀：

fragment() = 我是什么材质。

light() = 光怎么照我。

在进入具体技术之前，先理解 light() 的执行模型，因为它和 fragment() 的运行方式有本质区别。

---

## 1. light() 怎么被调用的
fragment() 对每个可见像素执行一次。但 light() 不同——它对**每个可见像素、每个影响该像素的光源**各执行一次。

假设你的场景有一个 DirectionalLight3D 和一个 OmniLight3D，球体上有 5000 个像素被这两个光源共同照到。那么：
- fragment() 执行 5000 次
- light() 执行 5000 × 2 = 10000 次

每次 light() 调用只处理**一个光源**对**一个像素**的贡献。多光源的结果会被引擎自动累加。你不需要（也不应该）在 light() 里写循环遍历所有光源——Godot 已经帮你做了。

### 输入变量（只读）
light() 内部有一组**只读**的内置变量，描述"当前正在处理的这个光源"和"当前像素的表面信息"：

| 变量 | 类型 | 含义 | 坐标空间 |
| LIGHT | vec3 | 从当前像素指向光源的方向向量 | 视图空间 |
| ATTENUATION | float | 光源到达当前像素的衰减系数（0.0=无光，1.0=满） | — |
| NORMAL | vec3 | 当前像素的表面法线方向 | 视图空间 |
| VIEW | vec3 | 从当前像素指向摄像机的方向向量 | 视图空间 |
| LIGHT_COLOR | vec3 | 当前光源的颜色（已乘以光源 energy） | — |
| ALBEDO | vec3 | fragment() 中设置的材质基础色（可在 light() 中读取） | — |

注意：**所有方向向量都在视图空间**（view space）。这意味着 VIEW 方向总是大致指向 (0, 0, 1) 方向——摄像机前方。你不用手动做坐标变换，直接拿这些向量做点积、归一化即可。

ATTENUATION 解决了一个关键问题：**光不会照到所有地方都一样亮**。对于点光源，距离越远衰减越多；对于聚光灯，角度偏离中心越多衰减越多。Godot 计算好这些衰减后打包成一个 float 交给你——你只需在光照公式里乘上它。

### 输出变量（你写入）
light() 不返回任何值。你通过写入两个内置变量来告诉引擎"这个光源对这个像素贡献了多少光"：

| 变量 | 类型 | 含义 |
| DIFFUSE_LIGHT | vec3 | 漫反射分量——光打在粗糙表面上向各个方向均匀散射的部分。引擎会在 light() 全部执行完后自动乘以 ALBEDO |
| SPECULAR_LIGHT | vec3 | 高光反射分量——光打在光滑表面上朝特定方向集中反射的部分 |

引擎会把所有光源的 DIFFUSE_LIGHT 和 SPECULAR_LIGHT 分别累加。处理完所有光源后，引擎用 ALBEDO × DIFFUSE_LIGHT + SPECULAR_LIGHT 合成最终颜色。这是 Godot 的默认行为——当你**不写** light() 函数时，引擎内部就用 PBR 公式自动填充这两个变量。

**关键点：** DIFFUSE_LIGHT 应该只包含"光本身的贡献"（方向、衰减、颜色），**不要手动乘 ALBEDO**——引擎会自动完成这步乘法。。

### 最简单的 light() 实验
下面创建一个简单的三维场景，使用球形mesh，不用修改vertex或fragment，直接修改light函数，来编写三组不同的实验代码，它们是最直接理解输入/输出变量含义的方式：

```
// 实验 1：直接输出 NdotL，观察明暗分布
void light() {
    float ndl = dot(NORMAL, LIGHT);
    DIFFUSE_LIGHT = vec3(ndl);
}
```
运行效果：球体朝向光源的面是白色（ndl ≈ 1.0），背向光源的面是黑色（ndl ≤ 0.0）。侧面是灰色渐变。这就是漫反射的原始形态——dot(NORMAL, LIGHT) 返回的是法线和光线方向夹角的余弦值。

```
// 实验 2：输出 Fresnel，观察"边缘亮中间暗"
void light() {
    float fresnel = pow(1.0 - dot(NORMAL, VIEW), 3.0);
    DIFFUSE_LIGHT = vec3(fresnel);
}
```
运行效果：球体边缘发亮，正对摄像机的中心区域变暗。dot(NORMAL, VIEW) 是法线和视线夹角的余弦——在正前方趋近 1.0，1.0 - 1.0 = 0；在边缘趋近 0.0，1.0 - 0.0 = 1.0。

```
// 实验 3：输出 Blinn-Phong 高光
void light() {
    vec3 half_vec = normalize(LIGHT + VIEW);
    float spec = pow(max(dot(NORMAL, half_vec), 0.0), 32.0);
    SPECULAR_LIGHT = vec3(spec);
}
```
运行效果：球体上出现一个小而亮的白色光斑。改变指数 32.0 为 8.0 或 128.0，观察光斑大小的变化。

这三个实验展示了 light() 的核心工作方式：**输入五个变量，你决定怎么算，写入两个输出变量**。接下来我们从最基础的 Lambert 漫反射开始，一步步构建完整的自定义光照系统。

## 2. Lambert 漫反射 —— 5 步渐进

### 2.0 法线从哪来
在写 Lambert 公式之前，先理解 NORMAL 变量里装的是什么。

每个三角面有自己的面法线，它垂直于三角平面。如果渲染时所有像素共用一个面法线做光照，三角面之间亮度会跳变——这就是 Flat Shading。现代游戏不用它。

Smooth Shading 的做法：3D 模型的每个顶点储存自己的顶点法线。在光栅化阶段，三角形内部所有像素的法线由三个顶点法线**插值**得到。所以即使三角面是平的，像素级法线也是平滑变化的——GPU 在顶点之间"补充"了法线，让低面模型看起来像高面模型。

在 light() 中，你拿到的 NORMAL 就是这个插值后的结果——它已经是每个像素独一无二的法线方向。你不需要手动计算它。Godot 通常会提供已经归一化的法线，但在经过插值、法线贴图或自定义修改后，为了保证点积计算稳定，在关键公式中再次 normalize() 是一种良好的编程习惯。

Lambert 漫反射是最基础的光照模型，也是所有自定义光照的起点。它的物理直觉是：**一个完全粗糙的表面接收到光线后，向所有方向均匀散射。你看到的亮度只取决于光线"打得多正"——法线和光线方向越一致，越亮。**

我们不一次贴出完整公式，而是走 5 步渐进——每一步只加一个乘法因子，跑起来看效果，理解它解决了什么问题。

### Step 1：dot(NORMAL, LIGHT) —— 角度决定亮度

```
void light() {
    float NdotL = dot(NORMAL, LIGHT);
    DIFFUSE_LIGHT = vec3(NdotL);
}
```
把 DIFFUSE_LIGHT 设为一个标量，RGB 三通道相同，所以输出的是灰度图。

**为什么**：dot(NORMAL, LIGHT) 是两个向量的点积，也是两个单位向量的夹角的余弦值。为什么点积能衡量亮度？想象一束手电筒光照在墙上：光束正对墙面时，所有光能集中在最小的面积上，单位面积的亮度最高；斜照时，同样的光能散布到更大的椭圆形面积上，单位面积的亮度降低。这个"扩散因子"正好是光束方向与墙面法线夹角的余弦——也就是 dot(N, L)。

当光线正对表面（NORMAL 和 LIGHT 方向一致），cos(0°) = 1.0，最亮；当光线斜射（夹角 60°），cos(60°) = 0.5，一半亮；当光线从背面照来（夹角 > 90°），cos 为负。

### Step 2：max(0.0, NdotL) —— 消灭负值

```
void light() {
    float NdotL = max(dot(NORMAL, LIGHT), 0.0);
    DIFFUSE_LIGHT = vec3(NdotL);
}
```
**为什么**：背光面（夹角 > 90°）的 dot 结果是负数。在渲染中，负的光照值会导致"负的亮度"——黑色本该为零，负值却可能让颜色通道溢出、产生奇怪的颜色反转。max(x, 0.0) 把一切负面转为 0，表示"背面就是纯黑"。

物理上这也合理：光线不可能从物体背面照到正面（不考虑次表面散射的话）。最多就是照不到——0。

### Step 3：乘 ATTENUATION —— 距离/角度衰减

```
void light() {
    float NdotL = max(dot(NORMAL, LIGHT), 0.0);
    DIFFUSE_LIGHT = vec3(NdotL * ATTENUATION);
}
```
**为什么**：在 Step 2 中，SpotLight（聚光灯）照到球体上的边缘区域和中心区域一样亮——这不合理。ATTENUATION 是 Godot 帮你算好的衰减值：

- 对于 **OmniLight3D**（点光源）：距离越远，ATTENUATION 越小（平方反比衰减）
- 对于 **SpotLight3D**（聚光灯）：偏离中心角度越大，ATTENUATION 越小（角度衰减）
- 对于 **DirectionalLight3D**（定向光）：所有像素 ATTENUATION ≈ 1.0（无距离衰减，因为定向光模拟无限远的光源）
把 ATTENUATION 乘上去，点光源照到近处亮、远处暗；聚光灯中心亮、边缘暗；定向光照到的所有位置均匀亮。

### Step 4：设置 ALBEDO —— 引擎帮你乘

```
// fragment() 中设置材质颜色
void fragment() {
    ALBEDO = vec3(1.0, 0.2, 0.2); // 红色材质
}

// light() 保持不变——不需要手动乘 ALBEDO
void light() {
    float NdotL = max(dot(NORMAL, LIGHT), 0.0);
    DIFFUSE_LIGHT = vec3(NdotL * ATTENUATION);
}
```
**为什么**：到 Step 3 为止，光照结果还是灰度的——光本身没有颜色信息。但这里你**不要在 light() 里乘 ALBEDO**。

原因是 Godot 的渲染管线会自动完成这步乘法：light() 全部执行完后，引擎会把所有光源的 DIFFUSE_LIGHT 累加起来，然后乘以 ALBEDO（fragment() 中设置的材质基础色），得到最终颜色。你也可以是从纹理采样的。

所以 fragment() 和 light() 的分工是：

```
void fragment() {
    ALBEDO = vec3(1.0, 0.2, 0.2);          // 我是什么颜色
}

void light() {
    float NdotL = max(dot(NORMAL, LIGHT), 0.0);
    DIFFUSE_LIGHT = vec3(NdotL * ATTENUATION); // 光怎么照我
}
```
引擎的最终合成逻辑等于：最终颜色 = ALBEDO × DIFFUSE_LIGHT + SPECULAR_LIGHT。

**如果在 light() 里手动乘了 ALBEDO，引擎会再乘一次，导致 ALBEDO²——颜色会变暗失真。** 记住：DIFFUSE_LIGHT 是光本身的贡献，材质颜色留给 fragment() 和引擎处理。

### Step 5：乘 LIGHT_COLOR —— 光源颜色

```
void light() {
    float NdotL = max(dot(NORMAL, LIGHT), 0.0);
    DIFFUSE_LIGHT = LIGHT_COLOR * NdotL * ATTENUATION;
}
```
**为什么**：LIGHT_COLOR 是当前光源的颜色（已乘以你在编辑器中设置的光源 energy）。没有这一步，暖黄光和冷蓝光照在同一个球体上看起来一样——这显然不对。LIGHT_COLOR 赋予每个光源自己的"色彩身份"。

**注意各因子的含义**：LIGHT_COLOR × NdotL × ATTENUATION——"光源颜色 × 角度亮度 × 距离衰减"。材质颜色（ALBEDO）由引擎在 light() 之后统一处理，不写在这个公式里。

这就是完整的 Lambert 漫反射。五步走完，你写出的代码就是 Godot 默认 PBR 光照中漫反射部分的手工版本——和官方文档示例一致。把这个公式记在脑海里——它就是所有自定义光照的"地基"。

特别注意：在本例场景中我们只有一个光源，所以我们使用DIFFUSE_LIGHT =来定义光照，如果是多光源场景，你需要使用DIFFUSE_LIGHT +=。

**Lambert 漫反射公式总结**：

```
DIFFUSE_LIGHT = LIGHT_COLOR × max(dot(NORMAL, LIGHT), 0.0) × ATTENUATION
                   ①                   ②                           ③
```
引擎合成：最终颜色 = ALBEDO × DIFFUSE_LIGHT + ...

| 因子 | 来源 | 作用 | 缺了会怎样 |
| ① LIGHT_COLOR | light() 中乘 | 光源的颜色和强度 | 所有光源看起来一样 |
| ② max(dot(N, L), 0) | light() 中乘 | 光线角度对亮度的衰减 | 球体不会"鼓起来" |
| ③ ATTENUATION | light() 中乘 | 距离/角度衰减 | 点光源远近一样亮 |
| ALBEDO | fragment() 中设置，引擎自动乘 | 材质本身的颜色 | 所有材质都变白色 |

## 3. Blinn-Phong 高光 —— 光滑表面的"亮点"
Lambert 模型假设表面完全粗糙——光均匀散射到各个方向。但真实世界中大部分表面都有一定程度的光滑性：你不仅看到"漫反射的颜色"，还能看到"光源本身被表面反射形成的亮点"——这就是高光（specular highlight）。

计算高光的核心问题是：**光线从光源打到表面，然后反射进入眼睛。反射方向和视线方向越一致，看到的亮度越集中。**

直接算反射方向（Phong 反射模型）需要做一次向量反射运算，计算量大。1977 年 Jim Blinn 发现了一个更高效的等价方法：

**找到 LIGHT 和 VIEW 的"平均方向"——half vector H。如果 NORMAL 和 H 方向一致，说明表面正好把光反射进了眼睛。**

之所以叫 "Half"，是因为它就是字面意义上的"一半"——把两个方向向量加起来再归一化，得到的就是它们之间的中间方向（halfway direction）。想象两根筷子 L 和 V 摆成一个 V 形，normalize(L + V) 就是 V 形中间的那根角平分线。

### Blinn-Phong 公式

```
float blinn_phong(vec3 v, vec3 l, vec3 n, float m) {
    vec3 h = normalize(l + v);              // half vector
    float s = pow(max(0.0, dot(n, h)), m); // 高光强度
    s *= step(0.0, dot(n, l));              // 防止背面高光
    return s;
}
```
三个关键点：

- 
**dot(n, h)**：法线 n 和 half vector h 的夹角余弦。越一致（夹角越小），值越接近于 1.0。

- 
**pow(..., m)**：指数 m 控制高光的"集中度"——m 越大，高光斑越小、越亮、越锐利。这是 Blinn-Phong 模型的"材质光滑度"参数：

- m = 2：很大的柔和光斑（像橡胶）
- m = 32：中等光斑（像塑料）
- m = 128：很小的锐利光斑（像抛光金属）
- 
m = 256+：几乎是一个亮点（像镜子）

- 
**step(0.0, dot(n, l))**：这是一个防错保护。当光线来自背面（dot(n, l) < 0），高光应该不存在——但 half vector 的计算可能仍然给出正值，让背面也出现虚假高光。step(0.0, x) 在 x ≥ 0 时返回 1.0（保留高光），x < 0 时返回 0.0（消灭高光）。

### 在 light() 中使用 Blinn-Phong

```
void light() {
    // Lambert 漫反射
    float NdotL = max(dot(NORMAL, LIGHT), 0.0);
    DIFFUSE_LIGHT = LIGHT_COLOR * NdotL * ATTENUATION;

    // Blinn-Phong 高光
    float spec = blinn_phong(VIEW, LIGHT, NORMAL, 32.0);
    SPECULAR_LIGHT = spec * LIGHT_COLOR * ATTENUATION;
}
```
漫反射写入 DIFFUSE_LIGHT，高光写入 SPECULAR_LIGHT。两者的输出通道分离，引擎会分别处理——这意味着你可以通过修改两个通道来独立控制漫反射和高光的效果，后面的 Toon Shader 会充分利用这一点。

### 增加环境光
到这一步，我们已经能让物体在光源下有立体感。但场景中的背光面仍然是**纯黑色**。因为我们场景中将环境光设置为0，光线完全照不到背面，DIFFUSE_LIGHT 和 SPECULAR_LIGHT 都是 (0,0,0)。

真实世界中，几乎没有绝对的黑色阴影。即使被物体遮住直射光，周围环境的散射光（天空、墙壁、地面反射）也会照亮阴影区域。这就是**环境光（Ambient Light）**要解决的问题。

**最简单的环境光实现**

环境光不来自任何特定光源——它是对"周围散射光"的全局近似。在 light() 中直接叠加一个基础值：

```
uniform vec3 ambient_color : source_color = vec3(0.1, 0.1, 0.15);

void light() {
    float NdotL = max(dot(NORMAL, LIGHT), 0.0);
    DIFFUSE_LIGHT = LIGHT_COLOR * NdotL * ATTENUATION;
    DIFFUSE_LIGHT += ambient_color; // ← 环境光：不受光源方向/距离影响

    float spec = blinn_phong(VIEW, LIGHT, NORMAL, 32.0);
    SPECULAR_LIGHT = spec * LIGHT_COLOR * ATTENUATION;
}
```
注意： ambient_color 不与 LIGHT_COLOR、NdotL、ATTENUATION 相乘——环境光"无视"当前光源的位置和颜色，对每个像素均等贡献。本代码是一个特别示例，在一般情况下不需要代码中手动增加环境光，而且在多光源下会出错，通常只需要使用WorldEnvironment节点来定义环境光即可。

**Phong 光照模型 = Ambient + Diffuse + Specular**

这个三段式结构就是经典的 **Phong 光照模型**（1975，Bui Tuong Phong）：

```
引擎最终合成 = ALBEDO × (ambient_color + LIGHT_COLOR × NdotL × ATTENUATION)  // 漫反射 + 环境光
              + spec × LIGHT_COLOR × ATTENUATION                              // 高光
```
你在不知不觉中已经实现了 Phong 模型的全部三个组件——Lambert（漫反射）、Blinn-Phong（高光替代了 Phong 的原始反射向量计算）、常量环境光。这就是从 1975 年沿用至今的基础光照框架——几乎所有现代光照模型都是它的变体。

[IMAGE: phong](../ch20-diagrams/phong.webp)

Godot 的默认 PBR、Unity 的 Standard Shader、Unreal 的默认光照，本质上都是 Phong 模型的物理精确版或扩展版。你在本章写的 Lambert（漫反射项）和 Blinn-Phong（高光项），加上本节的环境光，凑齐了这个框架的全部三块拼图。

还有一类更高级的环境光，Hemisphere Shading 是一种比纯常量更自然的环境光方案。它的思路是：**上方来自天空的散射光偏蓝，下方来自地面的反射光偏暗**。它会用世界空间法线的 Y 分量作为"上下权重"。这在户外场景中尤其自然——角色的头顶偏蓝（天空），下巴偏暗（地面）。

**Godot 中的环境光**：如果不写 light() 函数，Godot 的默认 PBR 会自动加入环境光贡献。一旦你手写了 light()，引擎默认的环境光就失效了——你必须手动加回环境光，否则暗部就是纯黑的。也可以用 render_mode ambient_light_disabled 显式关闭引擎环境光（toon shader 用的就是这个）。

## 4. Fresnel 效应 —— 边缘发光原理

### 为什么边缘会更亮？
Fresnel（菲涅尔）效应描述了一个物理事实：**表面法线和视线方向夹角越大，反射率越高；夹角越小（越正对着看），反射率越低。**

直觉验证：
- 低头看脚下水面 → 水是透明的，能看到水底（低反射）
- 抬头看远方水面 → 水面像镜子，只看到天空倒影（高反射）

在渲染中，Fresnel 不用于精确物理模拟，而用于一个视觉效果：**让物体边缘发光**——边缘处 NORMAL 和 VIEW 几乎垂直，dot 近似 0.0，1.0 - dot 近似 1.0。

### 标准 Fresnel 近似（Schlick）

```
float fresnel = pow(1.0 - abs(dot(NORMAL, VIEW)), 5.0);
```

- dot(NORMAL, VIEW)：正前方 ≈ 1.0，边缘 ≈ 0.0
- 1.0 - dot：正前方 ≈ 0.0（暗），边缘 ≈ 1.0（亮）
- pow(..., 5.0)：指数控制从暗到亮的过渡有多"陡"。5.0 是经验值（Schlick 近似），调大（如 8.0）会让边缘光带变窄，调小（如 2.0）会让光晕更宽

### 把 Fresnel 用作边缘光
边缘光（rim light）是 Fresnel 最常见的应用——让角色的轮廓从暗背景中"跳出来"：

```
void light() {
    float NdotL = max(dot(NORMAL, LIGHT), 0.0);
    DIFFUSE_LIGHT = LIGHT_COLOR * NdotL * ATTENUATION;

    float fresnel = pow(1.0 - abs(dot(normalize(NORMAL), normalize(VIEW))), _RimPower);
    vec3 rim_light = fresnel * _RimColor.rgb * _RimStrength * LIGHT_COLOR;
    SPECULAR_LIGHT = rim_light * ATTENUATION;
}
```
注意这里把边缘光塞进了 SPECULAR_LIGHT 通道。虽然在物理上这不准确（Fresnel 不是高光），但在 Godot 的 light() 函数中，SPECULAR_LIGHT 是第二个可用的输出通道——它是给“非漫反射的光照贡献”用的。边缘光刚好符合这个定位。

**完整的 Fresnel 边缘光 shader 见**：rim.gdshader

[IMAGE: rim](../ch20-diagrams/rim.webp)

标准 Blinn-Phong 的高光斑是圆形的，即所有方向的粗糙度一致。但现实中有大量材质在不同方向有不同的微表面结构：例如头发，它的高光不是圆斑，而是沿发丝方向的"光带"。这称之为各向异性高光（Anisotropic Shading），它描述的是反射在不同方向上"拉长"的现象。各向异性的核心改动是：不再用 dot(N, H) 统一计算高光宽度，而是在切线方向和副切线方向分别控制粗糙度。Godot 的默认 PBR 渲染器使用各向同性模型。各向异性需要自定义 light() 函数实现。第 21 章的水面 shader 将用各向异性模拟水波的定向反射——那是它最经典的应用场景之一。

## 5. Toon Shading —— 二段式卡通渲染
Toon Shading（也叫 Cel Shading）是所有非写实渲染中应用最广的技术。它的核心思想是：**把连续渐变的光照量化成离散的色阶，模拟手绘/动画的风格。**我们以 5 步渐进，从 Lambert 出发最终实现一个完整的二段式 Toon Shader。

### Step 1：基础 Lambert
第一步和第 2 节完全相同——这是起点。

```
void light() {
    float NdotL = max(dot(NORMAL, LIGHT), 0.0);
    float base_light = NdotL * ATTENUATION;
    // 暂不写 DIFFUSE_LIGHT，后面每一步都会改这里
}
```
用 base_light 保存 Lambert 的连续亮度值。后面所有 toon 操作都在这个值上做文章。

### Step 2：ceil 量化 —— 把连续变成离散
色阶量化的本质是反锯齿的"舍入"——不是四舍五入，而是**向上对到最近的离散档位**：

```
float band_count = 4.0; // 4 段色阶
float band = ceil(base_light * band_count) / band_count;
```
**为什么 ceil + 除法能实现量化？** 逐步骤看：

| base_light 范围 | × 4.0 后 | ceil(...) | ÷ 4.0 后 |
| 0.00 – 0.25 | 0.00 – 1.00 | 1.0 | 0.25 |
| 0.25 – 0.50 | 1.00 – 2.00 | 2.0 | 0.50 |
| 0.50 – 0.75 | 2.00 – 3.00 | 3.0 | 0.75 |
| 0.75 – 1.00 | 3.00 – 4.00 | 4.0 | 1.00 |

原来连续渐变的值（0.0 → 0.1 → 0.2 → ...），经过 ceil 量化后只能取四个值（0.25 / 0.50 / 0.75 / 1.00）。这就是色阶分段的本质。

band_count 越大，分段越密，越接近连续渐变；越小，分段越疏，风格越卡通。典型的 toon shader 用 2-4 段。

### Step 3：二段色阶 —— step() 替代 ceil
ceil 方案简单，但有一个局限：每一段的颜色完全由 base_light 的数值决定——暗段永远是 band_count 分之一。如果你想精确控制"暗部到亮部的分界线在哪个亮度值"，ceil 就不够灵活了。

CODE-09 的方案是用**两个 step + 两个阈值**来定义"暗→中"和"中→亮"的分界：

```
uniform float _Step1 : hint_range(0.0, 1.0) = 0.3; // 暗→中 分界线
uniform float _Step2 : hint_range(0.0, 1.0) = 0.7; // 中→亮 分界线

void light() {
    float base_light = max(dot(NORMAL, LIGHT), 0.0) * ATTENUATION;

    float band1 = step(_Step1, base_light); // base_light ≥ 0.3 → 1.0
    float band2 = step(_Step2, base_light); // base_light ≥ 0.7 → 1.0
}
```
band1 和 band2 是两个"亮度档位检测器"：

| base_light 范围 | band1 | band2 | 对应的光照区域 |
| 0.00 – 0.30 | 0 | 0 | 暗部（shadow） |
| 0.30 – 0.70 | 1 | 0 | 中间调（mid-tone） |
| 0.70 – 1.00 | 1 | 1 | 亮部（highlight） |

两个 step 函数的输出只有 0 和 1。用它们作为"开关"选择颜色。

### Step 4：mix 着色 —— 给每个色阶指定颜色
有了档位检测器，下一步是用 mix() 在三种预定义颜色之间切换：

```
uniform vec4 _Shadow : source_color;    // 暗部颜色
uniform vec4 _Mid : source_color;       // 中间调颜色
uniform vec4 _Highlight : source_color; // 亮部颜色

void light() {
    float base_light = max(dot(NORMAL, LIGHT), 0.0) * ATTENUATION;

    float band1 = step(_Step1, base_light);
    float band2 = step(_Step2, base_light);

    vec3 toon = mix(_Shadow.rgb, _Mid.rgb, band1);
    toon      = mix(toon, _Highlight.rgb, band2);
}
```
两次 mix 的逻辑：
1. mix(暗, 中, band1)：band1 = 0（暗部）→ 取暗色；band1 = 1（非暗部）→ 取中间色
2. mix(上一步结果, 亮, band2)：band2 = 0（非亮部）→ 保持上一步结果；band2 = 1（亮部）→ 替换为亮色

效果是：暗部 → 纯 _Shadow 色，中间调 → 纯 _Mid 色，亮部 → 纯 _Highlight 色。颜色之间没有渐变过渡，这就是 toon 风格的视觉特征。

### Step 5：加上高光 + 边缘光
漫反射解决了，但 toon 风格的完整性还需要两个元素：

**卡通高光**（toon specular）：

普通 Blinn-Phong 的高光是连续渐变的（光斑中心亮、边缘淡）。卡通高光相反——**用 step 把高光切成"有"或"没有"**：

```
uniform float _SpecularSize : hint_range(0.0, 1.0) = 0.5;
uniform float _SpecularStrength : hint_range(0.0, 1.0) = 0.3;
uniform float _SpecularPower = 32.0;

// 在 light() 中：
float spec_raw = blinn_phong(VIEW, LIGHT, NORMAL, _SpecularPower);
float spec = step(_SpecularSize, spec_raw); // ← 关键：二值化高光
vec3 spec_light = spec * _SpecularStrength * LIGHT_COLOR;
```
step(_SpecularSize, spec_raw) 的含义：spec_raw 是 Blinn-Phong 的连续值（0.0 ~ 1.0）。只有当高光"足够亮"（大于阈值 _SpecularSize）时，step 才输出 1.0；否则输出 0.0。结果是：没有"半亮半暗"的高光，只有"有高光"和"没高光"两个状态。

**卡通边缘光**（toon rim）

和卡通高光同样的思路——Fresnel 的连续值经过 step 二值化：

```
uniform float _RimThreshold : hint_range(0.0, 1.0) = 0.7;
uniform float _RimStrength : hint_range(0.0, 1.0) = 0.25;

// 在 light() 中：
float rim = 1.0 - clamp(dot(normalize(NORMAL), normalize(VIEW)), 0.0, 1.0);
rim = step(_RimThreshold, rim);      // ← 二值化边缘光
rim *= base_light;                    // ← 背光面不显示边缘光（保护）
vec3 rim_light = rim * _RimStrength * LIGHT_COLOR;
```
两处值得注意的细节：
1. **rim *= base_light**——这个乘法很关键。如果没有它，物体背光面（全黑）也会有边缘光，导致暗部出现一圈发光的轮廓——这破坏了 toon 的"暗部纯黑"原则。乘上 base_light 后，背光面（base_light = 0）的 rim 也被归零。
2. **normalize(NORMAL) 和 normalize(VIEW)**——虽然 Godot 的内置变量已经接近单位向量（对于规则几何体确实如此），但插值后的 NORMAL 在曲面边缘可能长度不为 1。归一化消除这个误差。

将以上五步串联，加上顶部的 render_mode ambient_light_disabled 和 fragment() 中的纹理准备，得到完整的成品。

完整的 Toon Shader 参见：toon.gdshader

[IMAGE: toon](../ch20-diagrams/toon.webp)

render_mode ambient_light_disabled 的作用在这时候体现出来：Godot 默认会给所有 spatial 材质加一层环境光（ambient light），让暗部不是纯黑，而是带一点“环境照明”。在写实场景中这是合理的——现实中没有绝对的黑。但在 toon 风格中，暗部应该就是纯的 _Shadow 色，不能被环境光"冲淡"。关闭环境光后，暗部的颜色完全由你的 _Shadow 变量控制。

## 6. 本章小结：数据流总结——fragment() 与 light() 的分工
回顾这一章的内容，一个关键的理解是 **fragment() 和 light() 之间的数据传递**。下面这张图展示了从纹理到最终颜色的完整数据流——这页图建议你记住，因为后面所有章节都会用到：

```
纹理（texture / uniform）
       │
       ↓
  fragment()
       │
       ├──→ ALBEDO ────────────────────────────┐
       │                                         │
       │    （通过 varying 可以把纹理颜色        │
       │     传到 light()，用于 toon 等效果）    │
       │                                         │
       ↓                                         │
    light()  ◀── Godot 为每个光源调用一次        │
       │                                         │
       ├──→ DIFFUSE_LIGHT（光本身的贡献，无 ALBEDO）
       │                                         │
       └──→ SPECULAR_LIGHT                       │
       │                                         │
       ↓                                         ↓
  Godot 累加所有光源 → 合成: ALBEDO × DIFFUSE_LIGHT + SPECULAR_LIGHT
       │
       ↓
  最终屏幕颜色
```
**分工口诀**：

****
| 阶段 | 谁在做 | 做什么 |
| 材质准备 | fragment() | 采样纹理、设置 ALBEDO、准备 ROUGHNESS / METALLIC |
| 光照计算 | light() | 每个光源独立计算光贡献，写入 DIFFUSE_LIGHT / SPECULAR_LIGHT（不乘 ALBEDO） |
| 结果合成 | Godot 引擎 | ALBEDO × DIFFUSE_LIGHT + SPECULAR_LIGHT，累加所有光源后输出最终颜色 |

如果你在 fragment() 中设置 ALBEDO = vec3(1.0)（白色），然后在 light() 中直接使用自定义颜色（比如 toon 的 _Shadow / _Highlight），ALBEDO × 1.0 = 不变，你就拥有了 100% 的光照控制权。
