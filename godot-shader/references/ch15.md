# 第 15 章：描边与轮廓

### 第 15 章：描边与轮廓 —— 让角色从背景中"跳"出来
**学习目标**：从零开始，一步步构建两个可实战的描边 shader。整章围绕同一条主线——"最简单的描边 → 更粗 → 更圆 → 会发光 → 会呼吸 → 游戏里的目标高亮"——每增加一个新知识点，就让效果升级一次。

**场景搭建**：新建 Sprite2D 节点，选择一张带透明背景的角色或物品纹理。为它新建 ShaderMaterial，选择 canvas_item 类型。不需要 GDScript 脚本，全部参数在 Godot 检查器中调节。

**内容要点**：

- 描边的本质是"找边缘"——alpha 突变的位置就是边缘
- 四方向偏移采样：max(邻居alpha) × (1−当前alpha) 检测外描边
- 宽度、颜色、保留原图——三步做出可调参数的基础描边
- 内描边与外描边的数学差异：max vs min，(1−col.a) vs col.a
- 八方向采样解决斜边锯齿问题
- 圆形采样（角度循环 + cos/sin）让描边任意方向均匀
- smoothstep 替代 step 做柔和边缘 → Glow 发光描边
- TIME 驱动呼吸动画 → 游戏级目标高亮效果

---

## 15.1 为什么需要描边？
想象一个场景：你的主角正站在一片深绿色的森林背景前。角色服装恰好也是深绿色——于是角色"溶"进了背景里，玩家找不到自己在哪里了。

这不是颜色选择的问题，这是**视觉分离**（Visual Separation）的缺失。在现实世界中，光照、阴影和立体感自然将物体从背景中分离出来。在 2D 游戏中，你缺少这些深度线索——描边就是最简单有效的补救手段。

描边在游戏中扮演三个关键角色：

************
| 角色 | 说明 | 典型场景 |
| 可见性保证 | 确保角色/物体在任何背景下都清晰可辨 | 平台游戏主角、UI 按钮 |
| 状态反馈 | 用描边颜色传达游戏状态 | 选中目标（红色边）、中毒（绿色边）、无敌（金色边） |
| 风格化 | 描边本身就是一种美术风格 | 卡通渲染（Cel Shading）、漫画风格游戏 |

从技术角度看，描边问题可以归结为一个简单的判定：**哪些像素位于"边缘"上？**

**描边，本质就是找边缘。**

---

## 15.2 什么是边缘？
在动手写代码之前，先想清楚"边缘"的数学定义。对于带透明通道的精灵纹理，边缘就是一个像素的 alpha 值和它邻居的 alpha 值之间**发生了突变**：

```
当前像素透明（alpha = 0）

    ↓ 如果邻居中有不透明的（alpha > 0）

这里就是边缘
```
用伪代码表达：

```
外边缘 = (当前alpha == 0) 且 (邻居中有alpha > 0的)
```
把这个逻辑倒过来，就是内边缘：

```
内边缘 = (当前alpha > 0) 且 (邻居中有alpha == 0的)
```
整个思路可以浓缩成一张流程图：

```
透明 → 不透明 → 发生突变 → 边缘
```
再提炼成一行公式：

```
当前透明 + 邻居不透明 → 就是外描边
```
下面开始写代码验证这个思路。

## 15.3 第一个描边（四方向）
目标：做出最简单的红色描边。先不管粗细，不管颜色——只验证"边缘检测"这个核心逻辑是否正确。

思路：每个像素"探头"看一下上下左右四个邻居的 alpha 值。如果邻居中有不透明的，而自己是透明的——那自己就是边缘像素，染成红色。

```
shader_type canvas_item;

void fragment() {
    vec2 ps = TEXTURE_PIXEL_SIZE;

    float a_up    = texture(TEXTURE, UV + vec2(0.0, -ps.y)).a;
    float a_down  = texture(TEXTURE, UV + vec2(0.0, ps.y)).a;
    float a_left  = texture(TEXTURE, UV + vec2(-ps.x, 0.0)).a;
    float a_right = texture(TEXTURE, UV + vec2(ps.x, 0.0)).a;

    float neighbor_max = max(max(a_up, a_down), max(a_left, a_right));
    vec4 col = texture(TEXTURE, UV);
    float is_edge = neighbor_max * (1.0 - col.a);

    COLOR = vec4(1.0, 0.0, 0.0, is_edge);
}
```
逐行解释：

- TEXTURE_PIXEL_SIZE：单个纹素对应的 UV 大小。用 UV + vec2(0.0, -ps.y) 就是"向上偏移一个像素"。
- max(max(a_up, a_down), max(a_left, a_right))：四方向邻居 alpha 的最大值。只要有一个邻居不透明，结果就约等于 1.0。
- (1.0 - col.a)：当前像素的"透明度"。精灵内部 α=1 → 结果为 0；精灵外部 α=0 → 结果为 1。
- neighbor_max * (1.0 - col.a)：两者相乘——只有"邻居不透明 **且** 我透明"时，结果才是 1.0。这就是外描边的定义。
**效果**：精灵轮廓外围出现一圈**单像素宽的红色细线**。

这里没有 mix，没有 uniform，没有浮夸的参数。就是验证一件事：**边缘检测成功了。** 红色的像素正好贴在精灵的形状外面。

## 15.4 可调宽度
单像素的线太细了，不够用。要让描边更粗，只需要把采样偏移量放大：

```
shader_type canvas_item;

uniform float outline_width : hint_range(0.5, 5.0) = 1.0;

void fragment() {
    vec2 ps = TEXTURE_PIXEL_SIZE * outline_width;

    float a_up    = texture(TEXTURE, UV + vec2(0.0, -ps.y)).a;
    float a_down  = texture(TEXTURE, UV + vec2(0.0, ps.y)).a;
    float a_left  = texture(TEXTURE, UV + vec2(-ps.x, 0.0)).a;
    float a_right = texture(TEXTURE, UV + vec2(ps.x, 0.0)).a;

    float neighbor_max = max(max(a_up, a_down), max(a_left, a_right));
    vec4 col = texture(TEXTURE, UV);
    float is_edge = neighbor_max * (1.0 - col.a);

    COLOR = vec4(1.0, 0.0, 0.0, is_edge);
}
```
变化只有一行：TEXTURE_PIXEL_SIZE * outline_width。

**为什么这样就变粗了？** 当 outline_width = 2.0 时，每个采样方向偏移 2 个像素。于是距离精灵边界 2 个像素以内的透明像素都会"看"到不透明邻居——从而被判定为边缘。采样半径越大，描边越粗。

hint_range(0.5, 5.0) 让这个参数在编辑器中显示为一个滑块。拖拽它，描边从细到粗连续变化。

## 15.5 描边颜色
硬编码红色只能用于调试。把颜色暴露为 uniform：

```
uniform vec4 outline_color : source_color = vec4(0.0, 0.0, 0.0, 1.0);
```
source_color hint 让 Godot 在编辑器中显示一个颜色选择器，而不是四个分开的浮点数。把输出从硬编码红色改成用这个 uniform：

```
COLOR = vec4(outline_color.rgb, is_edge * outline_color.a);
```
**效果**：描边颜色和透明度都可以在编辑器中自由调整。黑色描边（默认）适合卡通风格，金黄色适合选中提示，绿色适合中毒状态反馈。

---

## 15.6 保留原图
现在有一个问题：精灵本体没有被画出来——因为我们只输出了描边像素。在精灵内部，is_edge 是 0，所以那些像素被跳过了。

mix() 解决了一个问题：**根据第三个参数在两个值之间切换。** 当第三个参数是 0，返回第一个值；是 1，返回第二个值；中间值做线性插值。mix(a, b, t) 的效果等价于 a * (1-t) + b * t——在 shader 里，mix 的本质就是 GPU 版的 if。

用 mix 根据 is_edge 在原始精灵和描边之间选择：

```
shader_type canvas_item;

uniform float outline_width : hint_range(0.5, 5.0) = 1.0;
uniform vec4 outline_color : source_color = vec4(0.0, 0.0, 0.0, 1.0);

void fragment() {
    vec2 ps = TEXTURE_PIXEL_SIZE * outline_width;
    vec4 col = texture(TEXTURE, UV);

    float a_up    = texture(TEXTURE, UV + vec2(0.0, -ps.y)).a;
    float a_down  = texture(TEXTURE, UV + vec2(0.0, ps.y)).a;
    float a_left  = texture(TEXTURE, UV + vec2(-ps.x, 0.0)).a;
    float a_right = texture(TEXTURE, UV + vec2(ps.x, 0.0)).a;

    float neighbor_max = max(max(a_up, a_down), max(a_left, a_right));
    float is_edge = neighbor_max * (1.0 - col.a);

    COLOR = mix(col, outline_color, is_edge);
    COLOR.a = max(col.a, is_edge);
}
```
这里有两行新逻辑：

**mix(col, outline_color, is_edge)**：当 is_edge = 0.0（不是边缘），结果是原始精灵颜色 col；当 is_edge = 1.0（是边缘），结果是描边颜色 outline_color。边缘外的像素显示描边，内部显示原图。

**COLOR.a = max(col.a, is_edge)**：这行确保 alpha 不出问题。在边缘像素处，col.a = 0（精灵外），is_edge = 1。如果只用 mix 的结果 alpha，当 outline_color.a 设为小于 1 时描边会变淡。max() 保证描边永远不会意外透明——边缘像素的 alpha 至少等于 is_edge。

**效果**：精灵本体完整显示，外围加了一圈可调颜色和宽度的描边。这是第一个真正可用的描边效果。

## 15.7 内描边、外描边
上一节做的是外描边——描边出现在精灵外围。但有时你希望描边**向内部延伸**（常见于 UI 按钮边框、卡牌边框），或者内外都有。三种模式的数学差异只在一行：

| 模式 | 公式 | 含义 |
| 外描边 | neighbor_max * (1.0 - col.a) | 邻居不透明 + 我透明 |
| 内描边 | (1.0 - neighbor_min) * col.a | 邻居透明 + 我不透明 |
| 全描边 | 两者相加 | 任意方向上的 alpha 突变 |

**为什么外描边用 max，内描边用 min？**

- **外描边**：只要邻居中**有一个**不透明（neighbor_max ≈ 1），且我透明，就是外边缘。所以用 max。
- **内描边**：只要邻居中**有一个**透明（neighbor_min ≈ 0），且我不透明（col.a ≈ 1），就是内边缘。所以用 min——1.0 - neighbor_min 在邻居全不透明时为 0，存在透明邻居时为 1。
用 outline_type 参数控制三种模式：

```
shader_type canvas_item;

uniform vec4 outline_color : source_color = vec4(0.0, 0.0, 0.0, 1.0);
uniform float outline_width : hint_range(0.5, 5.0) = 1.0;
uniform int outline_type : hint_range(0, 2) = 0;

const int TYPE_OUTER = 0;
const int TYPE_INNER = 1;
const int TYPE_BOTH  = 2;

void fragment() {
    vec2 ps = TEXTURE_PIXEL_SIZE * outline_width;
    vec4 col = texture(TEXTURE, UV);

    float a_up    = texture(TEXTURE, UV + vec2(0.0, -ps.y)).a;
    float a_down  = texture(TEXTURE, UV + vec2(0.0, ps.y)).a;
    float a_left  = texture(TEXTURE, UV + vec2(-ps.x, 0.0)).a;
    float a_right = texture(TEXTURE, UV + vec2(ps.x, 0.0)).a;

    float neighbor_max = max(max(a_up, a_down), max(a_left, a_right));
    float neighbor_min = min(min(a_up, a_down), min(a_left, a_right));

    float outer_edge = neighbor_max * (1.0 - col.a);
    float inner_edge = (1.0 - neighbor_min) * col.a;

    float edge;
    if (outline_type == TYPE_OUTER) {
        edge = outer_edge;
    } else if (outline_type == TYPE_INNER) {
        edge = inner_edge;
    } else {
        edge = outer_edge + inner_edge;
    }

    COLOR = mix(col, outline_color, edge);
    COLOR.a = max(col.a, edge);
}
```

## 15.8 四方向 vs 八方向
四方向采样只检查上下左右。对水平和垂直边缘，这完全够用。但对 45° 斜边，四个方向之间存在"盲区"——某一排斜向像素可能没有被任何采样方向覆盖到，导致描边在斜边上出现轻微锯齿。

解决方法是再加上四个对角线方向，八个方向均匀覆盖了 360°，斜边上的锯齿明显减少。用数组管理八个偏移量，避免重复写八段相似代码：

```
const vec2 OFFSETS[8] = {
    vec2(0.0, -1.0),  // up
    vec2(0.0, 1.0),   // down
    vec2(-1.0, 0.0),  // left
    vec2(1.0, 0.0),   // right
    vec2(-1.0, -1.0), // top-left
    vec2(1.0, -1.0),  // top-right
    vec2(-1.0, 1.0),  // bottom-left
    vec2(1.0, 1.0)    // bottom-right
};
```
然后用在循环里：

```
float neighbor_max = 0.0;
float neighbor_min = 1.0;
for (int i = 0; i < 8; i++) {
    float a = texture(TEXTURE, UV + OFFSETS[i] * ps).a;
    neighbor_max = max(neighbor_max, a);
    neighbor_min = min(neighbor_min, a);
}
```
**效果**：斜边描边更圆润，角落不再有明显锯齿。本章的完整案例已包含八方向采样。

## 15.9 圆形采样（Glow 的基础）
八方向仍然不够平滑。真正均匀的描边需要在**环状的边界上**均匀采样，而不是在正方形的八个角上。

画一个圆，在圆周上均匀放置采样点：

```
   8 个点：有明显角度感
  16 个点：更圆了
  32 个点：接近完美圆形
```
实现方式：用一个角度循环，把角度转为方向向量：

```
float alpha_sum = 0.0;
float TWO_PI = 6.2831853;
vec2 radius = TEXTURE_PIXEL_SIZE * outline_width;

for (int i = 0; i < 64; i++) {
    if (i >= sample_count)
        break;
    float angle = float(i) / float(sample_count) * TWO_PI;
    vec2 offset = vec2(cos(angle), sin(angle)) * radius;
    alpha_sum += texture(TEXTURE, UV + offset).a;
}
```
**为什么 cos(angle) 和 sin(angle)？** 角度 θ 在圆周上的坐标就是 (cosθ, sinθ)。除以采样数量均匀分布在 0 到 2π，就得到了圆形排列的采样方向。采样数量越多，圆形越精确——但每次采样都是一次 texture() 调用，需要在质量和性能之间权衡。

cos 和 sin 给每个角度生成一个 **单位方向向量**（长度为 1），乘以 radius 得到实际的采样偏移量。这比八方向的固定数组更灵活——采样数量、半径、间距全部可以通过参数调节。

## 15.10 发光描边
圆形采样解决了"均匀"的问题。现在让描边"发光"。

在四方向和八方向描边中，我们关心的是**"有没有邻居属于精灵"，因此使用 max() 即可——只要有一个方向命中，就判定为边缘。而在圆形采样中，我们更关心**"有多少个方向属于精灵"**。这意味着需要统计所有采样结果，计算平均值 alpha_average = alpha_sum / float(sample_count)。

这样得到的 alpha_average 不再是一个简单的 0 或 1，而是一个 0~1 的连续值，可以表示"当前像素距离边缘有多近"：当所有方向都在精灵内部时，alpha_average 接近 1；当没有一个方向命中精灵时，alpha_average 接近 0；处于两者之间时，alpha_average 是一个中间值——越接近边缘，这个值越低。正是这个连续值的特性，让我们后续可以用 smoothstep 绘制出柔和、自然的发光过渡，而不是一刀切的硬边。

发光的关键思路：**颜色可以超过 1.0。** 正常的纹理颜色在 [0, 1] 范围内。但如果你把 outline_color * glow_intensity 且 glow_intensity > 1.0，输出颜色就会"过曝"——在视觉上产生发光的感觉。

完整代码：

```
shader_type canvas_item;

uniform vec4 outline_color : source_color = vec4(1.0, 0.9, 0.2, 1.0);
uniform float outline_width : hint_range(0.5, 8.0) = 2.0;
uniform int sample_count : hint_range(8, 64) = 24;
uniform float glow_intensity : hint_range(1.0, 10.0) = 5.0;
uniform float edge_softness : hint_range(0.01, 1.0) = 0.05;

void fragment() {
    vec4 col = texture(TEXTURE, UV);
    float alpha_sum = 0.0;
    vec2 radius = TEXTURE_PIXEL_SIZE * outline_width;

    for (int i = 0; i < 64; i++) {
        if (i >= sample_count)
            break;
        float angle = float(i) / float(sample_count) * TAU;
        vec2 offset = vec2(cos(angle), sin(angle)) * radius;
        alpha_sum += texture(TEXTURE, UV + offset).a;
    }

    float alpha_average = alpha_sum / float(sample_count);
    float edge = smoothstep(edge_softness, 1.0, alpha_average) * (1.0 - col.a);

    vec4 glow = outline_color * glow_intensity;
    COLOR = mix(col, glow, edge);
    COLOR.a = max(col.a, edge);
}
```
逐行解析新增内容：

- **alpha_average = alpha_sum / float(sample_count)**：把圆周上所有采样点的 alpha 值加起来取平均。如果精灵在某个方向很近，alpha_average 会偏高；如果所有方向都是空的，alpha_average ≈ 0。
- **smoothstep(edge_softness, 1.0, alpha_average)**：当 alpha_average 在 [edge_softness, 1.0] 之间时，smoothstep 产生 0→1 的平滑过渡。edge_softness 越小，过渡越硬（像 step）；越大，发光的渐变范围越宽。
- **glow = outline_color * glow_intensity**：glow_intensity > 1.0 让颜色"超亮"——比起正常颜色，它在屏幕上产生更亮的光晕。配合金黄色（vec4(1.0, 0.9, 0.2, 1.0)），效果就是外围暖光。
**让发光效果真正可见**：glow_intensity > 1.0 渲染出的"过曝"颜色本身只是比白色更亮的数值。要在屏幕上看到光晕扩散效果，需要在场景中添加一个 **WorldEnvironment** 节点，并启用其 **Glow** 属性。操作步骤：选中 WorldEnvironment 节点 → 检查器中点击 Environment → 勾选 Glow 的 Enabled。Glow 会检测画面中亮度超过 1.0 的像素，并为其添加光晕扩散——这正是过曝颜色产生发光视觉效果的原理。没有 WorldEnvironment 的 Glow，超过 1.0 的颜色值会被截断到 1.0（纯白），看不到光晕。

## 15.11 呼吸描边
发光是静态的。让描边"呼吸"——亮度周期性起伏——只需要一个 TIME 驱动的正弦波：

```
float pulse = 0.8 + 0.2 * sin(TIME * 4.0);
```
sin() 在 [-1, 1] 之间波动。0.2 * sin(...) 调振幅（波动在 [-0.2, 0.2]），0.8 + ... 把整个范围平移到 [0.6, 1.0]。结果：一个在 0.6 到 1.0 之间周期性起伏的系数。

把它乘进 glow：

```
glow *= pulse;
```
描边亮度就会时强时弱——像一个缓慢呼吸的生物。也可以把 pulse 乘进来，让描边粗细周期性变化：

```
float pulse = 1.0 + 0.3 * sin(TIME * 3.0);
vec2 radius = TEXTURE_PIXEL_SIZE * outline_width * pulse;
```
**效果**：描边不是静止的，它在"一呼一吸"。这个效果在游戏中非常抓眼球——玩家本能会注意到周期性变化的亮光。

---

## 15.12 实战案例：目标高亮
把呼吸描边做成游戏里的**目标高亮系统**。典型场景：玩家选中一个敌人 → 黄色描边出现 → 缓慢呼吸 → 发光。很有 Diablo 或 RTS 游戏的感觉。

在上一节基础上增加三个 uniform：

```
uniform float pulse_speed : hint_range(0.5, 10.0) = 4.0;
uniform float pulse_strength : hint_range(0.0, 0.5) = 0.25;
uniform bool enable_pulse = true;
```
然后在 fragment 中计算 pulse：

```
float pulse = 1.0;
if (enable_pulse) {
    pulse = 1.0 + pulse_strength * sin(TIME * pulse_speed);
}
vec4 glow = outline_color * glow_intensity * pulse;
```
enable_pulse 让呼吸可以开关——选中时打开，取消选中时关闭。其它部分完全不变。

完整功能一览：

| 参数 | 作用 | 推荐值 |
| outline_color | 描边颜色 | 金黄色 (1.0, 0.9, 0.2, 1.0) |
| outline_width | 描边粗细 | 1.5–3.0 |
| sample_count | 圆形采样点数 | 16–32（少则快，多则圆） |
| glow_intensity | 发光强度 | 2.0–3.0 |
| edge_softness | 边缘柔和度 | 0.2–0.4 |
| pulse_speed | 呼吸速度 | 2.0–5.0 |
| pulse_strength | 呼吸幅度 | 0.15–0.35 |
| enable_pulse | 呼吸开关 | true/false |

**完整代码**见 outline_glow.gdshader（包含呼吸动画）。

这个 shader 可以直接用于角色选中、敌人高亮、可交互物体提示——挂上就能用，通过 GDScript 控制 uniform 实现开关。
