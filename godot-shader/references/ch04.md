# 第 4 章：Godot Shader 骨架

### 第 4 章：Godot Shader 骨架 —— 五种类型、三种函数、数据的入口与出口
**学习目标**：掌握 Godot Shader 的完整骨架结构，理解 shader_type、三种处理器函数、数据传递通道和 render_mode 的角色。在章末能够独立编写并运行一个最简 shader，并知道每一行代码属于骨架的哪个部分。

**场景搭建**：创建一个 Sprite2D 节点（拖入一张任意贴图或保持纯色矩形均可），为其新建 ShaderMaterial 资源，再新建一个 canvas_item 类型的 shader 文件。本章不需要额外的 GDScript 脚本。

**内容要点**：

- 动手写第一个 shader：5 行代码让 Sprite2D 变紫色
- 从这 5 行代码回头拆解 Godot Shader 的三大骨架要素
- shader_type 五种类型的职责分工
- vertex() → fragment() → light() 执行顺序与职责
- uniform（GDScript → GPU）与 varying（vertex → fragment 插值）两条数据通道
- 内置变量速览：COLOR、VERTEX、NORMAL、UV、TIME
- Godot 4.7 内联预览与逐行变量查看

## 1. 动手时刻：你的第一个 Shader
本章要做的事情只一件——写出一个能运行的 shader，然后回头理解它的每一行。我们的目标不是炫技，而是建立骨架感。从现在开始，你就是 shader 的作者了。

### 1.1 创建你的第一个 Shader（5 步操作）
**Step 1**：在场景中选中一个 Sprite2D 节点。如果场景里没有，点击 Scene 面板上方的 + 按钮，搜索 "Sprite2D" 创建即可。将自带的icon.svg设置为Sprite2D的纹理。
**Step 2**：在右侧 Inspector 面板中，找到 CanvasItem → Material 属性。点击其下拉框，选择 **"New ShaderMaterial"**。
**Step 3**：点击刚创建的 ShaderMaterial 左侧的展开箭头，找到 Shader 属性。点击下拉框，选择 **"New Shader"**。
**Step 4**：在弹出的文件保存对话框中，输入文件名（如 hello_shader），点击 Save。Godot 的 Shader 编辑器会自动打开。
**Step 5**：编辑器里会有一段默认模板代码。不用管它——全部删掉，输入下面这 4 行：

```
shader_type canvas_item;

void fragment() {
    COLOR = vec4(1.0, 0.0, 1.0, 1.0);
}
```
保存（Ctrl+S / Cmd+S）。回到 2D 视口——你的 Sprite2D 已经变成了**纯紫色**。

[IMAGE: 第一个 shader 的效果](../ch04-diagrams/first-shader.webp)

### 1.2 这 4 行代码在说什么
你刚刚完成了一个 shader。它不是"伪代码"，不是"概念演示"——它就是一段运行在 GPU 上的、真实的着色器程序。现在逐行拆开：

**第 1 行**：shader_type canvas_item;

这是 shader 的"身份声明"。canvas_item 告诉 Godot："我是一个 2D shader，我只作用于 Sprite2D、TextureRect、ColorRect、Label 这些 CanvasItem 节点。" 如果把 canvas_item 改成 spatial，这个 shader 就只能挂在 3D 物体上。shader_type 必须在文件最开头，且一个 .gdshader 文件只能声明一种类型。

**第 2-4 行**：void fragment() { ... }

这是一个**处理器函数**（processor function）。Godot Shader 有三种处理器：vertex()、fragment() 和 light()。fragment() 是最核心的一个——它对屏幕上的每一个像素运行一次。你的 Sprite2D 在屏幕上占 200×200 个像素，这个函数就会被 GPU 并行执行 40,000 次。

**第 3 行**：COLOR = vec4(1.0, 0.0, 1.0, 1.0);

这是整个 shader 的"出口"。COLOR 是 fragment 处理器中最重要的**内置输出变量**——你给 COLOR 赋什么值，屏幕上就显示什么颜色。vec4(r, g, b, a) 是一个四分量向量，分别代表红、绿、蓝和透明度，取值范围 0.0 到 1.0。你写的是 (1.0, 0.0, 1.0, 1.0)，即满红 + 零绿 + 满蓝 = 紫色，alpha = 1.0 = 完全不透明。

**一个小实验**：把 COLOR = vec4(1.0, 0.0, 1.0, 1.0); 改写成 COLOR = vec4(0.0, 1.0, 0.0, 1.0); 保存。Sprite2D 变成绿色了吗？再把最后一个 1.0 改成 0.5 保存——半透明出现了吗？shader 的反馈回路就是这么快：改一行代码，点保存，效果立现。

这 4 行代码就是本章的"种子"。接下来我们要做的，是以它为起点，逐一填充 shader 的骨骼结构——就像给一个火柴人添上肌肉和皮肤。

## 2. 骨架拆解：数据类型、处理器函数、数据的入口与出口
你刚才写的就是一个 shader。让我们回头看看它的骨架。

一个完整的 Godot Shader 由几个典型的结构块组成。你的 4 行代码里用了其中两个（shader_type + fragment() 处理器），剩下的几个我们会逐步学习。

```
shader_type ...;           ← 身份声明
render_mode ...;           ← 渲染规则（可选）
uniform ...;               ← 外部输入       
void vertex()   { ... }    ← 顶点处理器     
void fragment() { ... }    ← 片元处理器     
void light()    { ... }    ← 光照处理器     
```

### 2.1 shader_type：五种身份的切换
shader_type 决定了你的 shader 将在什么上下文中运行、有哪些内置变量可用。Godot 支持五种类型：

| shader_type | 适用对象 | 典型用途 |
| canvas_item | 所有 CanvasItem 节点（Sprite2D、TextureRect、ColorRect、Label 等） | 2D 材质特效、2D 后处理、UI 效果 |
| spatial | 所有 3D 可视节点（MeshInstance3D、GPUParticles3D 等） | 3D 材质、顶点动画、自定义光照 |
| particles | GPUParticles2D / GPUParticles3D 的材质 | 粒子行为（力场、颜色渐变、生命周期） |
| sky | Sky 资源 | 自定义动态天空盒 |
| fog | FogVolume 节点 | 自定义体积雾密度场 |

每种类型对应一套不同的内置变量。canvas_item 能访问 COLOR、UV、TEXTURE、VERTEX 等 2D 变量；spatial 则能访问 ALBEDO、ROUGHNESS、NORMAL等 3D 变量。如果你在一个 canvas_item shader 里写了 ALBEDO = vec3(1.0);，编译立刻报错——因为 ALBEDO 是 spatial 的专属变量。

**本书重点分布**：第 3 部分（ch12–ch17）全面使用 canvas_item 做 2D 特效；第 4 部分（ch18–ch22）全面使用 spatial 做 3D 材质与光照；第 5 部分（ch25）专门处理 particles / sky / fog 三种"兄弟类型"。你目前只需要记住：2D 用 canvas_item，3D 用 spatial。

GDShader 是 GLSL 的方言：语法几乎一致，不同之处在于 GDShader 用 shader_type 声明类型、用固定命名的处理器函数代替 main() 入口、用大写无前缀的 COLOR/ALBEDO 代替 gl_FragColor，且不需要手动绑定 uniform location。

### 2.2 三种处理器：vertex() → fragment() → light()
这是整本书最重要的概念之一。Godot Shader 有三种处理器函数，它们在渲染一帧时不按先后执行，而是按"维度"展开：

**vertex() — 顶点处理器**

vertex() 对图形的每个顶点执行一次。一个 Sprite2D 有 4 个顶点（矩形的四个角），所以 vertex() 执行 4 次。它的职责是修改顶点数据——最常见的是修改 VERTEX 来移动顶点位置，实现形变动画。你在 ch12 的旗帜飘动、ch18 的地形波浪中会反复用到它。对于 2D shader 的简单场景，完全可以不写 vertex() 函数——Godot 会自动用默认的顶点处理逻辑。

**fragment() — 片元处理器**

fragment() 对每个像素执行一次。你的 Sprite2D 在屏幕上占多少像素，它就执行多少次。它的职责是计算这一像素的最终颜色，输出到 COLOR（2D）或 ALBEDO（3D）。这是你最频繁打交道的地方——本书 90% 的 shader 代码都写在 fragment() 里。

**light() — 光照处理器**

light() 在 fragment() 内部被调用——但它不是对每个像素调用一次，而是对**每个像素 × 每个影响该像素的光源**调用一次。2D 场景中如果你挂了 Light2D 节点且 shader 用了光照模式，light() 就会被触发。它提供了 LIGHT（光源颜色与距离衰减）变量，在3D场景中还提供了ATTENUATION（光源衰减系数）、 DIFFUSE_LIGHT（漫反射贡献）和 SPECULAR_LIGHT（高光贡献）。当你不写 light() 时 Godot 会自动使用默认光照。

**为什么需要三种处理器？**

"为什么"永远比"怎么做"重要。GPU 的渲染管线在顶点处理和像素处理之间有一个必然的步骤叫**光栅化**：它把顶点构成的三角形"切成"成千上万个像素。你在 vertex() 里做的修改会通过光栅化自动传递到 fragment()；你在 fragment() 里计算的颜色又可能被 light() 叠加光照。这三种函数的分离不是设计模式，而是 GPU 硬件的物理分工。

#### Godot 的着色管线全景
上面描述的是 GPU 通用渲染管线的核心。在 Godot 中，这整条管线被引擎封装成一套清晰的接口：

- **Mesh 数据准备**：节点（Sprite2D / MeshInstance3D）上传顶点属性到 GPU 缓冲区。
- **vertex() 执行**：你的 vertex 处理器运行在所有顶点上，修改 VERTEX、NORMAL、UV 等。
- **光栅化**：GPU 将三角形转换为像素网格，对所有 varying 变量做透视校正插值。
- **fragment() 执行**：你的 fragment 处理器在每个像素上运行，计算颜色并写入 COLOR（2D）或 ALBEDO/EMISSION（3D）。
- **可选 — light() 执行**：如果场景中存在光源且 render_mode 非 unshaded，Godot 对每个影响该像素的光源调用一次 light()。
- **后处理管线**：所有渲染结果经 Godot 的后处理栈（色调映射、泛光、环境光遮蔽等）处理后写入最终帧缓冲。
这条管线的存在意味着：你写的 shader 不是独立渲染的——它运行在 Godot 已经准备好的材质上下文和光照上下文中。理解这一点，你就知道为什么不同 shader_type 对应不同的内置变量集、为什么 render_mode 能影响光照行为。

### 2.3 数据的入口与出口：uniform、varying、内置变量
Shader 在 GPU 上运行，与 CPU 完全隔离——它不能读 GDScript 里的变量，也不能在两次执行间保留任何记忆。那么数据怎么进去、怎么出来？

#### uniform：从 CPU 到 GPU 的单向通道
uniform 是一个全局常量——它在 shader 运行期间不变，但可以在 GDScript 中修改。它的用途是把游戏逻辑层的参数传进 shader。

用 uniform 把我们的 5 行 shader 改造成可参数化的版本：

```
shader_type canvas_item;

uniform vec4 my_color : source_color = vec4(1.0, 0.0, 1.0, 1.0);

void fragment() {
    COLOR = my_color;
}
```
保存后，在 Inspector 面板中点击 ShaderMaterial，你会在 Shader Parameters 下看到一个名为 my_color 的颜色选择器。拖动它——Sprite2D 的颜色实时变化。这就是 uniform 的威力：你不用改代码、不用重新编译，就能从编辑器或 GDScript 控制 shader 的参数。

: source_color 是一个 **uniform hint**，它告诉 Godot："这个 vec4 是一个颜色，在编辑器中用颜色选择器显示。" 如果不加这个 hint，my_color 会显示为四个独立的浮点数——能用，但不如颜色选择器直观。

设置uniform 的另一个入口是 GDScript：

```
$Sprite2D.material.set_shader_parameter("my_color", Color(1.0, 0.0, 0.0, 1.0))
```
这行代码把 my_color 从紫色改成红色。你将在 ch14 的溶解效果中频繁使用这条通道——用 GDScript 的 tween 驱动 shader 的 threshold uniform，实现从 0 到 1 的渐变动画。

**GDScript 设置 uniform 的常用模式**

set_shader_parameter() 是 uniform 的主要入口。以下是实际开发中最常见的几种调用模式：

```
# 基本类型：float / int / bool
material.set_shader_parameter("speed", 2.5)
material.set_shader_parameter("enabled", true)

# 向量类型：Color → vec4, Vector2 → vec2, Vector3 → vec3
material.set_shader_parameter("tint_color", Color.RED)
material.set_shader_parameter("offset", Vector2(0.5, 0.0))

# 纹理：Texture2D 资源直接传入
material.set_shader_parameter("custom_texture", preload("res://icon.svg"))

# 在 _process() 中驱动连续变化 —— 最常用的动画模式
func _process(delta):
    material.set_shader_parameter("time_accumulated",
        material.get_shader_parameter("time_accumulated") + delta)
```
**与 TIME 内置变量的区别**：TIME 在 GPU 端自动递增，无法暂停或倒放。如果你的效果需要玩家控制播放速度、正向/反向播放、或按某个事件触发——用 GDScript 驱动的 uniform 而不是 TIME。

#### varying：从 vertex() 到 fragment() 的插值管道
vertex() 和 fragment() 之间没有共享内存。你在 vertex() 里算出来的值，fragment() 读不到——除非你用 varying 声明一个传递变量。

```
shader_type canvas_item;

varying vec2 my_uv;                // 声明一个传递变量：vec2 类型，名为 my_uv

void vertex() {
    my_uv = UV;                    // 把顶点的 UV 坐标"装进"传递变量
}

void fragment() {
    COLOR = vec4(my_uv, 0.0, 1.0); // my_uv.xy 映射到红绿通道 → 可视化 UV
}
```
**UV 是什么？** UV 是每个 Sprite2D 顶点自带的纹理坐标，它是一个 vec2 类型的值。每个顶点知道自己身上对应纹理贴图的哪个位置——用 U（水平）和 V（垂直）两个分量描述，取值范围始终是 (0.0, 0.0) 到 (1.0, 1.0)。(0,0) 是纹理的左上角，(1,0) 是右上角，(0,1) 是左下角，(1,1) 是右下角。对于一个方形 Sprite2D，4 个顶点的 UV 正好均匀分布在四角。

你不需要手动给顶点的 UV 赋值——每个 Sprite2D 节点在创建时，Godot 已经自动为它的 4 个顶点分配了正确的 UV 值。在 canvas_item shader 中，你也可以在 fragment() 中直接使用 UV，因为 Godot 内部已经帮你完成了从 vertex 到 fragment 的 UV 传递。本节写 vertex() 的目的不是让你自己传 UV——而是让你看到 "vertex → varying → fragment 插值" 这条管道是怎么工作的。

这个 shader 给 vertex 的 4 个角分别赋了各自的 UV 坐标 (0,0)、(1,0)、(0,1)、(1,1)。GPU 在光栅化阶段对这 4 个值进行**自动插值**：角落之间像素的 my_uv 值被平滑过渡。在 fragment 里，my_uv 的 R=U 和 G=V 通道形成了颜色渐变。

[IMAGE: UV 渐变效果](../ch04-diagrams/varying.webp)

varying 解决了一个根本问题：vertex() 只有 4 个数据点（4 个顶点），但 fragment() 需要 40,000 个数据点（每个像素）。插值是 GPU 硬件免费提供的——你只需要声明 varying，剩下的 GPU 替你完成。

#### 内置变量速览
除了你自己声明 uniform 和 varying 之外，Godot 还为每种 shader_type 提供了一套内置变量。它们已经在 GPU 里准备好了，你直接使用即可——不需要声明、不需要初始化。

**canvas_item 核心内置变量**：

| 变量 | 类型 | 位于 | 含义 |
| COLOR | vec4 | fragment 输出 | 像素的最终颜色（RGBA）。你在 fragment() 里给它赋值 |
| VERTEX | vec2 | vertex 输入/输出 | 顶点位置（2D 本地空间）。在 vertex() 中修改它来移动顶点 |
| UV | vec2 | vertex / fragment 输入 | 纹理坐标，范围 (0,0) 到 (1,1)。每个顶点的 UV 值在 fragment 中会被自动插值 |
| TEXTURE | sampler2D | fragment | 节点的纹理。用 texture(TEXTURE, UV) 采样原始像素颜色 |
| TIME | float | 全局 | 自引擎启动以来的秒数。所有 shader 共用同一个 TIME 值 |
| NORMAL | vec3 | fragment | 顶点的法线方向（2D） |

**spatial 核心内置变量**（此处速览，详述在 ch18–ch20）：

| 变量 | 类型 | 位于 | 含义 |
| VERTEX | vec3 | vertex 输入/输出 | 顶点位置（3D 模型空间） |
| NORMAL | vec3 | vertex / fragment | 法线方向 |
| ALBEDO | vec3 | fragment 输出 | 基础反射率（PBR 的核心颜色属性） |
| ROUGHNESS | float | fragment 输出 | 表面粗糙度（0.0=镜面 / 1.0=漫反射） |
| METALLIC | float | fragment 输出 | 金属度（0.0=非金属 / 1.0=金属） |
| EMISSION | vec3 | fragment 输出 | 自发光颜色（不受外部光照影响） |

这只是一个速览——你不必现在就记住全部 15 个。关键的理解是：**这些变量存在的原因**跟 uniform 和 varying 一样——它们都是数据进出 shader 的通道。TIME 是全局 uniform 的变体，UV 是内置的 varying（顶点间自动插值），COLOR 是 fragment 对帧缓冲的输出端口。

### 2.4 render_mode：渲染规则的开关
render_mode 不是处理器函数，但它决定了 GPU 在处理你的 shader 时遵循哪些规则。它写在 shader_type 之后、uniform 之前。

**2D（canvas_item）常用 render_mode**：

| 模式 | 作用 | 典型场景 |
| blend_mix（默认） | 标准 Alpha 混合：源颜色按 alpha 覆盖目标 | 普通 Sprite，大多数情况 |
| blend_add | 颜色相加：每个通道直接累加，必定变亮 | 火焰、魔法光效、能量护盾 |
| blend_sub | 颜色相减：暗化效果 | 阴影投射、遮罩 |
| blend_mul | 颜色相乘：必定变暗（各通道 0-1 相乘） | 暗化叠加、污渍效果 |
| blend_premul_alpha | 预乘 Alpha 混合：源 RGB 已预先乘以 Alpha | 粒子特效、半透明叠加更精确 |
| unshaded | 忽略场景中所有 Light2D 节点的影响 | UI 元素、自发光材质 |

**半透明渲染的关键理解**：blend_mix 的混合公式是 result = src.rgb * src.a + dst.rgb * (1 - src.a)——Alpha 同时控制源色的"强度"和背景色的"透过量"。这看起来很自然，但有一个陷阱：如果你的 COLOR.a 设为 0.5 但 COLOR.rgb 的值是 (1, 0, 0)，最终颜色不是"半透明的红色"——它是 红×0.5 + 背景×0.5，即红色被稀释了一半。这在大多数场景下符合直觉，但在做粒子叠加时你会发现边缘有暗晕——这时 blend_premul_alpha 更合适，因为它要求你在 shader 中直接把 rgb *= alpha 做好，混合公式简化为 result = src.rgb + dst.rgb * (1 - src.a)，避免双重 Alpha 稀释。

**加法混合与透气的视觉关系**：blend_add 永远不会产生比源色更暗的像素，因此叠加在深色背景上的发光粒子效果极佳。但如果背景本身已经是亮白色，加法混合的粒子就"消失"了——因为 (1,1,1) + (1,0,0) 依然被 clamp 在 (1,1,1)（白）。做发光特效时，先确定背景的亮度范围，再选择合适的混合模式。

在你的 4 行 shader 中，没有写 render_mode——这意味着 Godot 使用了默认值 blend_mix。如果加上 render_mode blend_add;，你的 Sprite2D 会以加法混合的方式叠加到背景上——适合做发光特效。

**3D（spatial）常用 render_mode**：

| 模式 | 作用 |
| cull_back（默认） | 剔除背面：只有朝向摄像机的面被渲染 |
| cull_disabled | 不剔除：正反面都渲染（树叶、布料、全息投影） |
| unshaded | 不受场景光照影响（卡通渲染、全息投影的第一步） |
| shadows_disabled | 不接收阴影（特效物体） |

在 CODE-01 的 shade3d_01.gdshader 里能看到 render_mode cull_disabled;——它让 3D 平面无论从哪个角度看都可见，是做树木叶片和布料的标准起始配置。

## 3. Godot 4.7 新特性：Shader 实时调试
本节仅适用于 Godot 4.7 及以上版本。在 4.7 的 Shader 编辑器中，将光标放在 fragment() 函数内任意一行赋值语句上，编辑器会在预览窗口中显示**该变量在当前像素点的实际数值**：

- 光标放在 COLOR = vec4(...) 行上 → 显示当前片元的 COLOR 值（vec4，四个分量全部可见）
- 光标放在 float brightness = ... 行上 → 显示当前片元的 brightness 值（float）
- 光标放在 vec3 normal = ... 行上 → 显示 normal 的 x、y、z 分量
支持的数据类型覆盖 float、vec2、vec3、vec4、int 和它们的数组。

shader 调试有一个根本的差异：**GPU 上的所有像素是同时运行的。** 没有"停在某个像素上等你看"的概念。当你把光标放在 COLOR = vec4(...) 行上时，编辑器并不是暂停了 GPU 执行——它只是在同一时刻的快照中，抓取了该变量在某个特定像素的值给你看。

这就是为什么"逐行预览"是比"逐行暂停"更准确的描述。4.7 的调试器本质上是一个变量监视器：它在屏幕坐标上映射了变量的值域，让你可以直观地看到哪些区域的值高、哪些区域的值低。

## 4. spatial shader 快速预览：边缘光
本书的主体在 2D（ch12–ch17），但在本章收尾前，先瞥一眼 3D shader 的最小形态。下面是一个完整的 spatial 边缘光 shader——仅用几行代码实现物体边缘发光的视觉效果：

```
shader_type spatial;                                          // 3D 身份声明
render_mode unshaded;                                         // 关闭引擎默认光照，我们手动控制颜色

uniform vec4 rim_color : source_color = vec4(0.0, 1.0, 1.0, 1.0);  // 编辑器中的颜色选择器
uniform float rim_power : hint_range(0.5, 8.0) = 3.0;          // 边缘发光的锐利程度

void fragment() {                                             // 片元处理器——名字不变，输出从 COLOR 变 ALBEDO
    float rim = 1.0 - abs(dot(normalize(VIEW), normalize(NORMAL)));  // 视线与法线夹角——角度越大（越靠近边缘），rim 越接近 1
    rim = pow(rim, rim_power);                                 // 用幂函数收紧边缘发光范围
    ALBEDO = rim_color.rgb * rim;                              // 输出基础色乘以边缘系数
}
```
**简短解读**：与 2D 的 canvas_item 相比——shader_type 从 canvas_item 变成 spatial，输出变量从 COLOR（vec4）变成 ALBEDO（vec3，只含颜色不含 alpha），内置变量从 2D 系（VERTEX 为 vec2）切换到 3D 系（VERTEX 为 vec3，多了 VIEW等空间变量）。其余结构——render_mode、uniform、fragment() 处理器——完全一致。

**2D 与 3D shader 的骨架对照**：

|  | canvas_item | spatial |
| 身份声明 | shader_type canvas_item; | shader_type spatial; |
| 主要输出 | COLOR (vec4) | ALBEDO (vec3) + 材质属性 |
| 顶点类型 | VERTEX (vec2) | VERTEX (vec3) |
| 可用矩阵 | MODEL / CANVAS / SCREEN | MODEL / VIEW / PROJECTION 全系列 |
| 光照 | 2D light() 或 unshaded | 3D light() 或标准 PBR 或 unshaded |

记住这张对照表——当你在第 3 部分写完 2D 特效、进入第 4 部分 3D 材质时，你只需在骨架不变的前提下切换"方言"。

## 本章小结
本章搭建了 Godot Shader 的完整骨架，它由五块结构组成：shader_type 声明身份（2D 用 canvas_item，3D 用 spatial），render_mode 控制渲染规则（混合模式、是否受光照影响），uniform 从外部注入参数，varying 打通 vertex 到 fragment 的插值管道，以及三种处理器函数——vertex() 操作顶点、fragment() 计算像素颜色、light() 处理光照叠加。2D 与 3D 的骨架完全对称：vertex() 通用，fragment() 通用，区别仅在于输出变量名（COLOR vs ALBEDO）和内置矩阵。骨架齐了——第 2 部分开始，我们将用数学函数、噪声、SDF 和纹理给这副骨架长上肌肉。
