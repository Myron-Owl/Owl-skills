# 游戏设计师实务：从玩家体验到可验证规格

本参考补充六透镜分析，将创意转为可实现、可调节、可验证的系统、机制、经济与成长方案。适用于 RPG、平台跳跃、射击、生存、策略等品类；按任务选用相关部分，不要求每次走完整流程。

## 1. 工作立场与交付边界

- 以资深系统与机制设计师的工作方式分析：共情玩家，围绕循环、玩家动机、调节杠杆和系统交互推导方案，清楚记录假设及证据。
- 从已有游戏案例、项目记录和测试结果提取经验，不声称拥有真实从业经历、亲历项目或未提供的记忆。每个设计判断都可能需要验证。
- 每个系统先回答：玩家此刻应该感到什么？正在做什么决策？为什么值得继续？将认知成本与新增选择、情感或表达空间比较，删减无贡献的复杂度。
- 先写玩家可观察行为与反馈，再写规则和交付接口。工程师决定实现方案，美术决定具体视觉设计；设计文档描述识别、时机、信息优先级和效果目标。
- 重大规则、数值或范围变更遵守用户及项目的确认边界；已授权的常规细节继续处理，不以模板要求重复索取确认。

## 2. 设计支柱与三层循环

新概念通常提炼 3–5 个设计支柱，描述不可妥协的玩家体验及可观察表现。已有项目沿用已确定的支柱；小修订无需重建。机制应说明支持哪个支柱，以及与其他支柱的取舍。

### 核心循环模板

时间段是示例尺度，按品类、平台和玩家场景调整，不据此推定实际会话长度。

```markdown
# 核心循环：[游戏名称]

## 即时体验（示例：0–30 秒）
- 动机与决策：[目标与权衡]
- 行为：[核心操作动词]
- 反馈：[视觉 / 音频 / 触觉或信息响应及其时机]
- 奖励：[资源 / 进度 / 掌握感 / 表达满足]
- 闭合点：[结果如何改变下一次行动]

## 单次会话循环（示例：5–30 分钟）
- 目标：[任务与阶段奖励]
- 紧张感：[风险 / 资源压力 / 信息不确定性]
- 结局：[胜败或退出状态及后果]
- 闭合点：[结算如何导向下一次会话]

## 长期循环（示例：数小时–数周）
- 成长：[技能精通 / 解锁 / 构筑 / 世界或关系变化]
- 继续游玩的理由：[探索 / 叙事 / 新挑战 / 创作 / 社交]
- 终点与节奏：[何时可以满意离开；重复是否仍产生新决策]
```

长期循环可通过掌握、探索、叙事或重玩成立。每日奖励、赛季和连续登录只在相应运营目标已确定时评估，不作为单机或买断游戏的默认要求。

## 3. 纸面原型与核心好玩假设

投入主要实现工作前，用纸笔、表格或最小可运行原型检验风险最高的好玩假设。输入延迟、镜头、移动和操作手感需要可运行原型，纸面模拟不能替代实际操作测试；已有实现不必退回纸面重做。

| 原型项目 | 需记录的内容 |
|---|---|
| 好玩假设 | 哪个核心行为、权衡或反馈必须成立，游戏才成立 |
| 最小循环 | 输入 → 决策 → 结果 → 反馈 → 再行动 |
| 范围 | 只保留验证该假设需要的规则与资源 |
| 测试问题 | 此轮要回答的关键问题 |
| 成败标准 | 测试前定义可观察结果、目标和否决条件 |
| 下一步 | 支持 / 调整 / 否定；进入下一阶段需要的证据 |

核心循环尚未成立时，优先改善操作、反馈、可读性和决策价值。经济硬锁、无限套利等会破坏测试的严重问题及时修复，不因“先手感后平衡”而推迟。

## 4. 机制规格与 GDD 交付

正式机制条目覆盖目的、玩家体验目标、输入、输出、边界情况和失败状态，让工程和美术能够判断预期表现。无需为填表补写未决定的规则；缺口在对话中转为具体待决策问题。

```markdown
## 机制：[名称]

**目的**：[为何存在；支持哪个设计支柱]
**玩家幻想与体验目标**：[力量感 / 情感 / 决策及可观察表现]
**输入与前置条件**：[操作 / 触发器 / 计时器 / 事件；权限与资源要求]
**处理规则**：[状态转换、判定顺序、成本与结算时机]
**输出**：[状态 / 资源 / 世界变化；提示、反馈及其时机]
**成功判定**：[正常运行的验收结果]
**失败状态与恢复**：[游戏内失败、无效输入或中断的结果；重试与退出]
**边界情况**：
- [同时事件的优先级]
- [最大 / 最小资源与阈值行为]
- [重复触发、目标失效或动作取消；仅列相关情况]
**调节杠杆**：[变量、单位、作用方向、耦合关系与适用范围]
**依赖与交付接口**：[涉及系统、所需数据与可观察表现]
**证据与状态**：[规则决策状态；数值验证状态；测试记录]
```

复杂流程按需要附有标注的流程图、状态图或线框图，表达规则与信息要求，不替代美术设计。保持 GDD 为活文档：重大机制修订更新版本与变更记录，说明规则变化、影响及验证依据。

CC战棋正式文档遵循入口 5.7 节、`gdd-writer` 与现行《策划文档规范.md》。本参考模板用于分析和交付准备，不覆盖项目结构，不允许把占位符、假数据或未经确认的候选方案直接写入正式文档。

## 5. 数值假设、调参表与成长曲线

影响平衡的成本、奖励、时长、概率和冷却应有依据：目标体验、预算、公式、案例或测试证据。早期可以选取可解释的初始估值，但说明为何这样选，不把任意数字包装成定论。

区分两种状态：

- **规则决策状态**：候选 / 已确定。用户已确定规则，无需再次确认。
- **数值验证状态**：新估值初始标记 `[待测试]`；在相应版本、样本和情境达到预定标准后标记 `[已验证：范围与记录]`。已确定采用的值仍可能未实测；既有实测值不重新标为未验证。

调参表与规则同时维护。变量 ID、单位和作用域稳定，公式引用共享参数，避免散落常量。查看现有项目配置后再引用真实字段；建议的变量名不能写成已有表列。

| 变量 / ID | 单位 | 基础值 | 最小值 | 最大值 | 公式或依据 | 目标表现与调参备注 | 验证状态 |
|---|---|---|---|---|---|---|---|
| 玩家生命值 | 点 | 按项目填写 | 按项目填写 | 按项目填写 | 目标存活时长与受击次数 | 检查不同等级的容错 | `[待测试]` |
| 敌人伤害 | 点 / 次 | 按项目填写 | 按项目填写 | 按项目填写 | 生命预算、命中率与攻击频率 | 检查玩家能否理解失败原因 | `[待测试]` |
| 资源掉落率 | 概率 | 按项目填写 | 按项目填写 | 按项目填写 | 目标获取速率与掉落量 | 检查尾部坏运气和断供 | `[待测试]` |
| 技能冷却 | 秒或回合 | 按项目填写 | 按项目填写 | 按项目填写 | 战斗节奏与使用频率 | 区分有意义等待与空转 | `[待测试]` |

这是待填模板，不能按原样写入正式文档。秒与回合按项目选一种，不将实时动作数值直接移植到回合制。

用数学关系定义目标曲线，如升级经验、伤害衰减、收益率和风险 / 收益；检查端点、突变、累积成本及敏感性。确定性规则优先用解析计算、枚举或表格模拟。随机成长、掉落或多条玩家路径确有尾部风险时用蒙特卡洛模拟，记录分布、随机种子、样本规模与假设；模拟不能替代真实玩家体验。

## 6. 经济建模与健康检查

- 绘制资源来源、消耗、兑换、存量和流速，明确兑换方向、费率、限制及恢复路径；供需和均衡分析用于实际存在市场或交易的系统。
- 对新手、普通、高效率、保守或高风险玩法等相关画像模拟路径：是否断供、失败能否恢复、最佳策略是否退化成重复劳动，是否出现死胡同、无限资源或套利环。
- 为货币净增量、每活跃玩家每日货币量、价格或购买力等指标注明口径、目标区间、触发阈值和调整手段。单机可用每战斗、每章节或每游戏日的口径，不强套在线日活指标。
- 项目已采用相应付费模式时，才分析高付费、中付费与零付费画像：荣誉或表达型消耗出口、价值明确的消耗出口、可触达的成长目标，以及付费优势与核心公平性的关系。不凭模板引入商业化。
- 调参建议说明影响链：改哪个变量 → 哪些行为与资源流改变 → 预期收益 → 可能代价 → 验证方法。

## 7. 玩家提示、反馈与新手引导

定义提示触发条件、优先级、反馈时机、下一步行动和理解检查。以实际行为验证掌握，不以阅读提示或点击“下一步”作为掌握证据。

- [ ] 获得控制后尽快尝试核心操作；“30 秒内”是初始目标，按节奏与可访问性调整。
- [ ] 默认保护教学第一步的首次成功，给明确正反馈；若安全失败是学习目标，明确低成本、恢复方式与教学收益。
- [ ] 新机制先在低压力、可恢复的环境引入，再组合应用。
- [ ] 至少一次通过观察或探索发现规则的机会，同时保留必要的无障碍提示。
- [ ] 首次会话以明确成果和后续目标收束，例如悬念、解锁或新挑战。
- [ ] 无需设计师在旁指导即可完成关键任务，并能复述或实际运用规则。

“首次引导完成率 > 90%”可作初始目标，需事先约定目标玩家、任务终点、样本规模、观察窗口、允许提示和完成率分母。报告实际人数和失败原因，不当成所有品类的上线门槛或已获结果。

## 8. 测试、迭代与完成条件

每轮测试前定义目标体验、成功指标、失败阈值和适用样本；测试后区分观察、解读与待验证解释。

| 观察 | 解读 / 假设 | 调节杠杆 | 预期变化 | 复测标准 |
|---|---|---|---|---|
| 实际操作、耗时、失败次数或玩家原话 | 可能原因与替代解释 | 本轮参数或规则改动 | 可观察行为或指标 | 如何判断改善与副作用 |

“感觉不对”拆成发生位置、频率、行为和玩家描述。例如“冷却期间连续出现无决策等待”比“8 秒像惩罚”更有用；缩短冷却的候选值也需依据，不能用措辞代替证据。

按任务范围检查完成条件：

- 实现或上线范围的机制有完整规格，关键规则无未决歧义。
- 调参表与文档一致，未验证数值及验证范围明确。
- 测试结论能转为具体规则或参数调整、复测条件或有依据的保留决定。
- 经济在已建模路径与边界中无已知无限循环或不可恢复的死胡同；注明未覆盖路径。
- 引导达到项目预定标准，无需设计师额外解释。
- 加入次要系统前，核心循环通过当前阶段的好玩假设验证。

## 9. 进阶能力：按问题调用

### 行为经济学

分析损失厌恶、可变奖励、禀赋效应、沉没成本和承诺机制如何影响判断，区分短期参与指标与长期体验。通过命名、定制和玩家投入建立物品意义；奖励节奏应有可理解的规则与适当保障。

连续登录、赛季排名等承诺机制匹配运营目标，评估错过后的恢复成本。避免用沉没成本、恐惧错失或不透明奖励迫使玩家继续投入，允许合理中断。Cialdini 的互惠、社会认同、承诺一致、权威、喜好、稀缺等原则用于分析真实互助、可信信息和成长反馈，并检查误导或压力风险；不制造虚假权威、稀缺或社交压力。这些是行为分析工具，不新增大师 Lens，也不代表项目必用机制。

### 跨品类机制移植与“机制活检”

提取相邻品类的核心操作动词与有效因果链，记录源机制的问题、可迁移核心、输入 / 时间节奏 / 镜头 / 资源结构依赖、应剥离的非迁移部分和目标品类需重做的环节。

原型前比较品类惯例预期与颠覆风险。混合机制说明满足两个源品类的哪些预期、有意放弃哪些预期；用最小原型压力测试操作成本、决策密度、节奏与反馈，不要求保留两个品类的全部惯例。

### 涌现式系统设计

配合 Tynan Lens，设计少量可交叉作用的规则，产生未预设但可理解的策略。对相关系统建立交互矩阵，逐对记录组合条件、结果、影响及状态：预期 / 非预期但可接受 / bug。无交互标为不适用，不虚构规则填表。

邀请测试者打破设计，检查级联效果、资源循环、支配策略和反馈可读性，不把所有非预期玩法判成 bug。保留有价值的涌现，移除不产生新决策、情感或表达价值的额外系统。
