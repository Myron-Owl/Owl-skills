# 策划文档撰写技能

## 规范来源

- 正文结构与内容以项目根目录的 `策划文档规范.md` 为准；图示格式与视觉默认值执行下方[默认绘图规则](#默认绘图规则)，这是用户对本技能的明确设定。
- 内置备用规范为 v2.7（2026-10-13，包含 SVG 默认绘图定制）：[策划文档规范](references/策划文档规范.md)。
- 开始任务前完整读取适用规范。项目文件存在时读取项目文件；项目文件不存在时读取内置备用规范。
- 项目与备用规范不同步时，以项目的正文规范为准并说明差异，不自行改写项目规范。旧规范中的 draw.io 默认条款不视为用户主动要求 draw.io，仍执行 SVG 默认绘图规则，不因此重复请求确认。
- 用户要求“同步规范到 skill”时，将项目规范完整复制到 `references/策划文档规范.md`，更新本页的备用规范版本，再验证两者逐字一致；本页的用户绘图默认设定仍然保留，除非用户明确要求改变。

## 输出格式

- 默认输出 Markdown；输出 DOC/DOCX 时按适用规范的附录 D 切换文件格式、前置顺序和排版，并使用 Word 对应的检查项。Word 写法已完整收录，使用时无需原始本地参考文件。
- 游戏表现的颜色设计分工按规范 5.7 节执行；此要求同时适用于 Markdown 和 Word。文档图示使用下方用户指定的语义配色，不作为游戏美术最终配色要求。

## 执行流程

1. 确认任务属于新建、修改、重构、检查、迁移或规范维护。
2. 完整读取目标文档及其 `ai_context`（Markdown 位于 YAML，Word 位于文末“AI 生成说明”附录）；在本次范围内，按 `dependencies` 或该附录中的依赖路径读取理解当前修改所需的依赖文档。用户明确排除依赖文档时遵守该范围；只有缺口会使当前文档的关键规则无法确定时才报告并提问，不自动修改依赖文档。
3. 从用户要求、目标文档和本轮已确认信息中确定文档类型、目标读者和本次修改范围；信息已明确时不重复询问。
4. 复用用户已提供或已确认的关键数值、方案和规则归属；只有仍无法确定且会改变实际规则的缺项，才在对应内容写入前向用户提问。不得把猜测、候选方案或待办标记写进文档。
5. 按规范完成内容与结构调整，只修改本次需求涉及的部分。
6. 按规范递增修订序号、更新日期并追加本次更新记录；不得改写历史记录或擅自变更主版本。
7. 完成后按规范附录 A 的检查单验证格式、目录、标题、链接、版本、内容去重；图示同时执行下方渲染与视觉检查。

## 正文与实现信息

- 将正文写给策划、程序、美术、UI、测试及后续接手者共同阅读，优先使用普通中文描述条件、行为、结果和玩家反馈。
- 不使用字段名、类名、接口名或程序执行过程代替玩法规则。影响玩法的技术限制仍在正文用人话说明。
- 仅供程序对接的字段、类型、接口、事件、存储和执行顺序集中放在文末程序说明附录；附录只解释如何实现正文规则，不得新增或改变玩法规则。
- 中文术语与英文变量映射、代码块、配置表等具体写法，严格执行规范正文和附录 A。

## 默认绘图规则

**默认输出可编辑 SVG；只有用户明确要求使用 draw.io 时，才采用 draw.io。** 不因旧规范、旧图源或工具可用性自动选择 draw.io。用户本次明确指定其他格式或视觉要求时，按该要求执行。

1. 采用现代、简洁、克制的卡片式 UI 信息图风格，参考 ChatGPT 对话中的现代技术图解；同时满足信息准确与专业产品设计文档的视觉质量。
2. 统一语义配色：主色 `#0D9488`、辅助色 `#64748B`、警告色 `#B45309`。以文字、形状与箭头共同表达含义，不只依赖颜色。
3. 涉及角色示意时，使用带白色描边的圆形标记；领队与普通队员通过主色、外环或文字标识明显区分。
4. 使用浅色背景、低透明度辅助网格、虚线路径与合理留白建立层次；流程连线的方向与线型仍按其实际语义表达。
5. 同类元素统一尺寸、间距、圆角和描边粗细。中文文字清晰、对齐，避免拥挤、重叠或压线。
6. 复杂内容拆成独立示意图，每张图解决一个核心理解问题，不把所有规则塞进同一张图。
7. 保留独立矢量图形与 SVG 文本元素，便于用户编辑文字、颜色、标记和路径；不要把文字全部转曲或用一张内嵌位图代替可编辑图示。
8. 保存 SVG 后用浏览器或 SVG 渲染器实际渲染并查看，检查文字溢出、中文字体、对齐、留白、线条穿字、画布裁切与视觉层次。发现问题时修改源文件并重新渲染检查；XML 校验不能替代视觉检查。无法渲染时说明限制，不宣称已通过。
9. 信息表达优先于美观：术语、数值、条件、箭头和状态关系必须与策划正文一致；位置、人数或距离仅作示意时明确标注，不能借绘图新增规则。

SVG 放在文档所在分类目录的公共 `img/`，Markdown 默认直接引用 `img/{文件名}.svg`。PNG 只用于明确要求的导出或兼容预览，不替代 SVG 源文件。draw.io 被明确要求时，维护 `.drawio` 源文件并重新导出同名 `.png`，两者保存在同一 `img/`。

## 硬性边界

- 不使用独立的“规则”小标题；规则直接跟在能说明具体内容的功能标题下。
- 不设置独立的“验收标准”模块；可验证条件与预期结果写入对应功能、流程或边界条件。
- 正文不散布 AI 命令；Markdown 的生成与维护约束写入 YAML `ai_context`，较长时按规范放入对应附录；Word 按规范附录 D 放入文末“AI 生成说明”。
- 同一事实只完整定义一次，其他位置使用链接或一句引用。
- 不删除或改写策划已确认内容；`已定稿`、`已废弃` 文档只按规范允许的范围修改。
- 改图时维护本次采用格式的可编辑源文件，并实际渲染检查；格式选择遵循[默认绘图规则](#默认绘图规则)。

## 交付

- 说明修改了哪些文档、当前版本和验证结果。
- 提供可点击的文件链接；SVG 图示同时提供可编辑源文件链接。
- 绘图默认与旧规范不同时，按用户已设定的 SVG 默认继续并说明差异；其他影响实际规则的规范冲突、依赖缺失或已定稿文档结构调整，停止相应写入并明确报告。
