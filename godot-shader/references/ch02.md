# 第 2 章：图形学与数学基础

### 第 2 章：图形学与数学基础 —— 向量、矩阵与变换
**学习目标**：理解向量和矩阵在图形学中的实际用途——normalize 定方向、dot 判夹角做光照、cross 建法线、matrix 做空间搬运、齐次坐标装平移。不推公式，只弄明白"这些数学在 shader 里解决了什么问题"。

**场景搭建**：本章是纯概念章，不需要搭建 Godot 场景。

**内容要点**：
- 向量在 shader 里的四种身份：方向、位置、颜色、UV（纹理坐标）
- normalize()：把任意向量变成纯方向（光照计算的前置步骤）
- length() / distance()：测量向量的长度或两点之间的距离
- 点积 dot() 解决的核心问题：判断两个方向有多接近（光照计算的基石）
- 叉积 cross() 解决的核心问题：从一个面造出一个垂直方向（法线的基础）
- 矩阵：空间搬运机——一次乘法完成旋转+缩放+平移
- 齐次坐标——让平移进入矩阵：为什么 3D 变换需要 4D 向量（平移装不进 3×3 矩阵）
- 线性变换 vs 仿射变换：旋转/缩放是线性的，平移必须进齐次坐标

---

## 2.1 向量是什么：shader 里的几种身份
在数学课本里，向量是"有方向有大小的量"，用箭头表示。但在 shader 里，向量有几种截然不同的身份。

**身份一：方向（direction）。** 这是最接近数学课本的用法。当你需要知道"光线从哪个方向来"、"表面朝哪个方向"、"摄像机从哪个方向看"时，你用的就是方向向量。方向向量的长度通常是 1（单位向量），因为方向本身不在乎"有多远"。在 shader 中，NORMAL 内置变量就是一个方向——它告诉你当前这个像素点的法线朝向哪里。

**身份二：位置（position）。** 当一个向量表示"某一个点在空间中的位置"时，它就成了位置向量。VERTEX（顶点坐标）、FRAGCOORD（像素坐标）都是位置向量。位置上可以做距离计算——两个位置相减得到一个方向向量，位置减去一个方向就移动到了新位置。

**身份三：颜色（color）。** 在 shader 里颜色就是向量。vec3(1.0, 0.0, 0.0) 是一个红色，也是一个三维向量 (1, 0, 0)。颜色向量的妙处在于：你可以对颜色做数学运算——两个颜色相加是混合，一个颜色乘以一个数（标量）是变亮或变暗。mix() 本质上就是两个颜色向量之间的线性插值。

**身份四：纹理坐标（texture coordinate / UV）。** UV 坐标是一种特殊的二维向量。它的两个分量 u 和 v 分别沿纹理的水平方向和垂直方向，但关键区别在于：UV 是**归一化坐标**——无论纹理图片的实际尺寸是 256×256 还是 4096×4096，UV 的取值范围始终是 0.0 到 1.0。在Godot中(0.0, 0.0) 是纹理图片的左上角，(1.0, 1.0) 是右下角。当你对 UV 做加减法时，实际上就是在纹理上"滑动"——比如 UV + vec2(time * 0.1, 0.0) 能让纹理沿水平方向缓缓滚动。这种简单的 UV 偏移是纹理动画（流水、跑马灯、滚动背景）的基础。mix() 函数同样可以用于纹理——mix(tex_a, tex_b, factor) 在两张贴图之间做平滑过渡。在 Godot 中，UV 是 canvas_item shader 的内置变量，texture() 函数内部自动把归一化 UV 映射到实际像素坐标。

这些身份共享同一套运算规则：你不需要区分"这是一个方向还是一个颜色"，+、-、* 对所有向量一视同仁。这种统一性是图形学中最优雅的设计之一。

**这在 shader 中的对应物**：Godot 的内置变量分属这几种身份——NORMAL 是方向（vec3）、VERTEX 是位置（vec3）、COLOR 是颜色（vec4）、UV 是纹理坐标（vec2）。Godot 里向量类型是 vec2（2 分量）、vec3（3 分量）、vec4（4 分量）。后续章节中你会频繁看到 vec3(some_float) 把标量"升维"成向量。

## 2.2 normalize()：只保留方向，去掉长度信息
normalize(v) 的作用很简单：把任意向量变成**纯方向**——长度变为 1，方向保持不变。

为什么要专门去掉长度信息？因为在 shader 里，方向向量只关心"指向哪里"，不关心"有多长"。NORMAL 内置变量在传入 fragment() 之前，GPU 已经帮你把它归一化了；但如果你自己构造了一个方向向量（比如两个位置相减得到的光线方向），它的长度取决于两点之间的距离，这时候做点积之前必须先 normalize()——否则 dot(N, L) 的结果会被长度歪曲，不再是纯净的"有多像"。

归一化最典型的应用场景是**光照计算**：float ndotl = dot(normalize(NORMAL), normalize(LIGHT_DIRECTION));。两个输入都是单位向量时，点积结果才精确反映夹角关系（-1 到 1）。如果忘了归一化，点积就不再是"有多像"，而是"有多像乘以长度"，光照就会出现难以调试的暗角或过曝。

**这在 shader 中的对应物**：Godot 内置 normalize(x)，接受 vec2 / vec3 / vec4，返回同类型。NORMAL 和 TANGENT 在传入 shader 前已归一化，但你自己构造的方向务必调用它。

## 2.3 length() / distance()：测量距离
length(v) 返回向量 v 的长度：sqrt(v.x² + v.y² + v.z²)——就是勾股定理在三维空间的推广。

distance(a, b) 等价于 length(a - b)，返回两点之间的直线距离。

这两个函数在 shader 里的主要用途：

- **半径判断**：if (length(uv - center) < radius) 判断一个像素是否在圆内，这是画圆形、圆角、进度环的基础。
- **衰减计算**：离光源越远越暗——float attenuation = 1.0 / length(light_pos - frag_pos); 是最简单的距离衰减。
- **SDF（有符号距离函数）**：第 8 章的核心概念，用 length() 描述几何形状到像素的距离，是程序化建模的基石。
一个实用技巧：如果仅仅比较距离大小（只想知道"谁更近"），可以用 dot(v, v)（即 length²）代替 length(v)，省去一次 sqrt 开方。GPU 做开方比做乘法费时，在大量像素循环中这个优化很实用。

**这在 shader 中的对应物**：Godot 内置 length(x) 和 distance(a, b)，都接受任意维度的向量（vec2/vec3/vec4），返回 float。

## 2.4 点积 dot()：判断两个方向"有多像"
点积是整本 shader 书里出现频率最高的数学运算，没有之一。它只做一件事：**判断两个方向有多少是重叠的**——用行话说，判断两个方向的夹角关系。

想象你用手电筒照向一堵墙。手电筒正对墙壁时（光线方向 = 墙面法线方向），墙面最亮。手电筒斜着照时，光线方向和法线方向不再重合，墙面变暗。手电筒完全侧着照（光线方向垂直于法线），墙面全黑。

点积就是**量化这种现象的数学工具**：

- 两个方向完全一致（夹角 0°） → 点积 = 1
- 两个方向垂直（夹角 90°） → 点积 = 0
- 两个方向完全相反（夹角 180°） → 点积 = -1
- 两个方向呈锐角（< 90°） → 点积 > 0（正面朝向，光照有效）
- 两个方向呈钝角（> 90°） → 点积 < 0（背向，光照无效）
这个简单到只有三个结果（1 / 0 / -1 为极端值）的运算，是**所有光照模型的基础**。Lambert 漫反射就是 max(dot(NORMAL, LIGHT), 0.0)；Blinn-Phong 高光进一步对"反射方向和视线方向"做点积；Fresnel 效应对"视线方向和法线方向"做点积。你会在第 20 章逐一见到它们。

点积还有一个重要用途：**投影**。一个向量投影到另一个方向上，剩余的长度就是 dot(vector, direction)。如果你想知道一个点离开某条直线的距离，点积配合简单的加减法就能算出来。这在 SDF（距离函数，第 8 章）中非常常用。

**这在 shader 中的对应物**：Godot 的内置函数就是 dot(a, b)，接受两个相同维度的向量，返回一个 float。后续章节你会无数次看到 dot(NORMAL, LIGHT)——这就是在做光照计算。不要因为它是"数学函数"就跳过它；它就是光照的开关。

## 2.5 叉积 cross()：制造垂直方向
如果说点积解决"有多像"的问题，叉积解决的是"给我一个垂直方向"。

**叉积的核心用途是构建法线。** 图形学中的"法线"就是垂直于一个表面的方向。如果你知道一个三角形三个顶点的位置，你可以用其中两条边的叉积算出这个三角形的面法线——不需要手动指出"这个面朝哪"，数学自动算出来。

叉积的三个特点：

- **结果是一个方向向量**，垂直于参与运算的两个向量构成的平面。
- **结果的方向由右手定则决定**：用右手的食指指向第一个向量，中指指向第二个向量，拇指就是叉积结果的方向。这意味着交换顺序会得到相反的方向——cross(a, b) = -cross(b, a)。
- **结果的长度等于两个向量构成的平行四边形的面积**。如果两个向量平行（夹角为 0° 或 180°），叉积结果是零向量。
在 shader 里，叉积最常见的使用场景是**从已知信息推导缺失的方向**。比如：

- 已知法线与切线方向 → cross(NORMAL, TANGENT) 得到副法线，构成 TBN 矩阵。
- 已知任意两个不平行方向 → 叉积可以构建一个垂直于二者的参考方向。
- 3D 顶点的 camera-facing 方向（Billboard）也需要叉积参与计算（第 18 章）。
**这在 shader 中的对应物**：Godot 的内置函数是 cross(a, b)，只接受 vec3（叉积定义在三维空间中）。典型用法是 vec3 bitangent = cross(normal, tangent)。你会在法线贴图相关的章节再次遇到它。

## 2.6 矩阵：空间搬运机
如果向量是"一句话"，矩阵就是"空间传送门"。矩阵解决的核心问题是：**把多次坐标变换打包成一次乘法，把顶点从一个空间"搬"到另一个空间**。

以三维场景为例，每个顶点从 3D 模型最终显示到屏幕，需要经历三级"搬运"：
- 局部空间 → 世界空间
- 世界空间 → 相机空间
- 相机空间 → 屏幕空间

每一级搬运背后都是一个矩阵。更妙的是，矩阵乘法有**结合律**——你可以先把三级的矩阵"预烤"成一个 MVP 矩阵，然后每个顶点只需要做一次乘法，就完成了全部搬运。

举个例子。假设你想对一个顶点先旋转、再缩放、再平移。如果一步步来，每个顶点都要经历三趟乘法。但利用结合律，你可以先把三个矩阵乘好：

mat4 combined = translate_matrix * scale_matrix * rotation_matrix;
（注意顺序：先旋转、再缩放、最后平移）

然后用这个"预烤"好的矩阵，一次乘法搬运到位：

vec4 result = combined * vec4(vertex, 1.0);

Godot 已经把最常用的空间搬运矩阵准备好了——你不需要手动构建它们：

| 内置矩阵 | 搬运动作 | 属于哪个 shader_type |
| MODEL_MATRIX | 局部空间 → 世界空间 | spatial |
| VIEW_MATRIX | 世界空间 → 相机空间 | spatial |
| PROJECTION_MATRIX | 相机空间 → 裁剪空间 | spatial |
| MODELVIEW_MATRIX | 局部空间 → 相机空间（两步打包） | spatial |

每一个矩阵都对应着一级"空间搬运"——MODEL_MATRIX 把顶点从局部搬到世界，VIEW_MATRIX 从世界搬到相机。第 3 章会把这些搬运步骤连成一条完整的流水线，逐个详细展开——每个矩阵对应坐标空间链中的一站，串联起来就是顶点从模型到屏幕的完整旅程。2D canvas_item 中也有对应的矩阵（CANVAS_MATRIX、SCREEN_MATRIX），在第 3 章详细展开。

矩阵的另一层用途是**存储多层变换的"历史记录"**。无论你有多少个顶点（一个模型可能有几万个顶点），你只需要把三个小矩阵乘成大矩阵的"预烤"工作做一次，然后每个顶点只做一次矩阵×向量乘法。最后这个三连乘积叫做 MVP 矩阵。Godot 在后台自动算好了这一步，但你理解它的存在后，才能读懂第 3 章"坐标空间"中各个内置变量到底是哪个空间的坐标。

**这在 shader 中的对应物**：Godot 的内置矩阵全部以 *_MATRIX 命名，类型是 mat4（4×4）。你在 vertex() 中写入 VERTEX（模型空间坐标），Godot 内部自动执行 PROJECTION_MATRIX * VIEW_MATRIX * MODEL_MATRIX * vec4(VERTEX, 1.0) 把它变到屏幕空间。你通常不需要手动做这个乘法——除非你要绕过默认管线。

## 2.7 齐次坐标：让平移进入矩阵
这是本章唯一需要稍微耐心一点的段落——但它解决了一个非常重要的"为什么"问题。

你注意到没有：Godot 里的顶点坐标是 vec3（3D），但矩阵是 mat4（4×4 的）。为什么用 4×4 矩阵去乘一个 3 分量向量？答案很简单：**3×3 矩阵无法处理平移**。

**旋转和缩放是线性的，它们完美适配 3×3 矩阵。** 把(x,y,z)乘以一个 3×3 矩阵，你可以绕着任意轴旋转它，或者在任意轴上缩放它。这些操作的性质是"原点不动，只改变坐标系的方向和刻度"。

**但平移不是线性的。** 平移是把整个物体从 A 位置挪到 B 位置，所有点都加上一个偏移向量。从数学上看，(x, y, z) + (tx, ty, tz) 不能写成"3×3 矩阵乘以 (x, y, z)"的形式——因为矩阵乘法本质上是 x、y、z 各分量之间的线性组合，永远变不出"加一个常数"的效果。

**齐次坐标的解决方案：在 3D 向量后面补一个 1，变成 4D 向量。**

在齐次坐标中，一个 3D 点 (x, y, z) 写作 (x, y, z, 1)——第四个分量 w = 1。一个 3D 方向 (dx, dy, dz) 写作 (dx, dy, dz, 0)——w = 0。这个区别很巧妙：点和方向在数学上终于有了不同的"身份"。w=0 和 w=1 不是随便规定的，而是人为设计出来的一套编码规则：w 分量在这里充当了一个"开关"，1 表示"我是位置，参与平移"，0 表示"我是方向，忽略平移"。这种设计使矩阵可以统一处理点和方向，而无需写两套不同的乘法逻辑。

[IMAGE: 齐次坐标直觉图](../ch02-diagrams/ch02-homogeneous.svg)
*齐次坐标一个 4×4 矩阵可以分成四个区域：3×3 区域承载旋转和缩放（线性变换），第 4 列承载平移（仿射变换)。w=1 表示"我是一个点，请对我施加平移"；w=0 表示"我是一个方向，忽略平移"。*

- **左上角 3×3**：旋转和缩放（线性变换）
- **右上角 3×1 列**：平移量（Tx, Ty, Tz）
- **左下角 1×3**：在标准变换中永远是 (0, 0, 0)
- **右下角 1×1**： 1或0
当你用这个 4×4 矩阵去乘向量 (x, y, z, 1) 时：线性部分作用于 x, y, z；平移部分直接加到结果上——因为 w=1 允许平移量"泄漏"进结果。而对方向向量 (dx, dy, dz, 0)，w=0 将平移量全部归零——方向不变，只受旋转/缩放影响。这正是你期望的行为：挪动一个物体时，它的朝向不应该改变。

**这在 shader 中的对应物**：Godot 的 mat4 矩阵和 vec4 向量天然处理齐次坐标。当你在 vertex() 中操作 VERTEX（vec3）时，Godot 内部自动补 w=1 再与各矩阵相乘。只有当你在 vertex() 中手动计算矩阵运算时（如 skip_vertex_transform 模式），才需要显式写成 vec4(VERTEX, 1.0)。方向向量（如 NORMAL）在数学上对应 w=0，Godot 在底层也做了自动化处理。

## 2.8 线性变换 vs 仿射变换：平移为什么特殊
上一节已经埋下了答案。这里做一个清晰的总结。

**线性变换**：原点不动，只改变坐标系的方向和刻度。包括：
- 旋转（rotate）
- 缩放（scale）
- 剪切（shear）
- 反射（reflect）

线性变换可以用 3×3 矩阵表示。GPU 对 3×3 矩阵乘法极度高效——只需要 9 次乘法和 6 次加法。

**仿射变换**：线性变换 + 平移。这是图形学中最通用的变换类型。你在 Godot 编辑器中对节点做的所有 Transform 操作——移动、旋转、缩放——在底层都是仿射变换。

**为什么必须区分？** 因为要保证"方向不受平移影响"。当你旋转一个 3D 模型时，它身上所有点的法线也跟着旋转；但当你平移这个模型时，法线不应该有任何变化。齐次坐标的 w=0 恰好让这件事自动发生——方向向量不受平移列的影响——不需要你写任何额外的保护代码。

在 shader 编程中，你 95% 的情况下不需要手动区分线性变换和仿射变换——Godot 的内置矩阵和自动化管线替你处理了。但当你开始写自定义的顶点变换（比如手动构建 MVP 矩阵做 Ray Marching，第 27 章），或者需要在 shader 里对法线做特殊处理时，这个知识会让你立刻理解"为什么法线变换要用逆转置矩阵"——那是第 18 章的内容了。

**这在 shader 中的对应物**：Godot 中 MODEL_MATRIX 是一个仿射变换矩阵（包含旋转 + 缩放 + 平移），VIEW_MATRIX 也是仿射变换。在 canvas_item shader 中，CANVAS_MATRIX 同样是 4×4 仿射矩阵——2D 的 Sprite 节点同样可以用这个矩阵描述旋转、缩放和平移。

## 本章小结：这些数学在 shader 里解决什么问题
让我们把整章串起来，用一句话回答"这个数学在 shader 里到底干嘛用"：

| 数学工具 | 解决的核心问题 | 出现章节 |
| 向量（vec2/vec3/vec4） | 统一表达方向、位置、颜色三种语义 | 全书 |
| 归一化 normalize() | 把任意向量变成纯方向（去掉长度信息） | 第 2/20 章 |
| 长度 length() / distance() | 算距离 → 衰减、半径判断、SDF | 第 2/8 章 |
| 点积 dot() | 判断两个方向有多接近 → 光照强度的开关 | 第 20 章 |
| 叉积 cross() | 从一个面推导出垂直方向 → 构建法线/副法线 | 第 9/19 章 |
| 4×4 矩阵 mat4 | 一次乘法完成旋转+缩放+平移 → 坐标空间转换 | 第 3 章 |
| 齐次坐标（w 分量） | 让平移能装进矩阵乘法 → 统一处理点和方向 | 第 3/18 章 |
| UV 坐标（vec2） | 归一化纹理查找 → 把图片"贴"到几何体上 | 第 7/8 章 |

你不是在学"数学"，你是在学"shader 里的工具"。点积不是公式，是光照开关；矩阵不是线性代数，是坐标空间的传送门。带着这个心态往下读，第 3 章（坐标空间）和第 5-6 章（数学函数与塑形函数）会变得异常清晰。

**章末练习**：

- 
**方向与光照的关系**：在脑海中想象一个球体放在一盏灯下。球体正对着灯的那一侧（NORMAL 与 LIGHT 方向一致）最亮，侧面越来越暗。用文字描述这个现象与 dot(NORMAL, LIGHT) 的关系——为什么 dot 值从 1 逐渐变小到 0，正好对应了从最亮到全暗？

- 
**齐次坐标实验**：取任意 3D 点，比如 (2, 3, 5)，写出它的齐次坐标形式。然后手动"应用"一个平移 (1, 0, -2)：如果不用齐次坐标（只用 3 分量），你需要写成 (2,3,5) + (1,0,-2)；如果用 4×4 矩阵（在纸上构造一个先旋转 90° 绕 Z 轴、再平移 (1,0,-2) 的矩阵），验证 w=1 是否确实让平移"泄漏"进了结果。不必算对，体会流程即可。

- 
**预览内置函数**：打开 Godot，在任意一个 shader 文件的 fragment() 函数中，输入 float d = dot(，稍等片刻，观察 Godot 编辑器的自动补全弹出窗口。它会显示 dot() 的参数类型和返回类型。同样试验 cross()、normalize()、length()。熟悉这些函数的签名，后续写 shader 时它们就是你的基本词汇。
