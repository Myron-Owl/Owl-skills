# 第 13 章：颜色处理与调色板

### 第 13 章：颜色处理与调色板 —— HSV 空间里的动态调色术
**学习目标**：掌握 rgb2hsv / hsv2rgb 转换算法，理解为什么 HSV 空间比 RGB 更适合调色，并能够实现受伤闪白、中毒变色、彩虹流光和调色板替换四种 2D 角色特效。

**场景搭建**：创建一个 Sprite2D 节点，拖入一张角色纹理（推荐有人物或物体的彩色贴图，分辨率 256×256 或以上），为其新建 ShaderMaterial，再新建本章各实战对应的 canvas_item 类型 shader 文件。

**内容要点**：

- RGB vs HSV：为什么在 RGB 空间里调色像"摸着石头过河"，而 HSV 空间像"给颜色装上了方向盘"
- rgb2hsv() / hsv2rgb() 实现：一套经典 GLSL 转换公式，写进 .gdshaderinc 共享库
- 实战 1：受伤闪白 —— 调高明度 (V)、调低饱和度 (S)、hit_intensity 随时间衰减
- 实战 2：中毒变色 —— 偏移 Hue 轴（h += 0.3），叠加墨绿色 tint
- 实战 3：彩虹流光 —— fract(TIME * speed) 驱动 Hue 从 0 滚到 1，循环变色
- 实战 4：调色板替换 —— 量化颜色后用调色板纹理映射新色，像素"换装"
- 额外参考：无敌闪烁 —— sin(TIME) * 0.5 + 0.5 驱动 alpha 在 min_alpha 和 1.0 之间交替

---

#### 13.1 RGB vs HSV：为什么你需要另一套颜色空间
前 12 章你处理的所有颜色都在 **RGB 空间** 里操作。RGB 是 GPU 的原生颜色语言：每个像素的三个通道直接驱动显示屏的红、绿、蓝子像素。这是最底层、最高效的颜色表示。

但当你需要"调色"时，RGB 立刻暴露出一个致命问题：**三个通道的视觉含义不是独立的**。

**RGB 的三个分量是"亮度 + 色相 + 饱和度"这三件事的搅在一起的结果。** 你不知道"把颜色变得更鲜艳"对应到 R、G、B 三个通道上各自该加减多少。你不知道"保持原有鲜艳度、只改色相"意味着 R、G、B 中哪些增哪些减。

举个例子：你要把一个角色的颜色从"正常"变成"受伤闪白"。在 RGB 里，这意味着在原有颜色的基础上叠加白色——但叠加多了，原有的色相消失了，角色变成一块白板。你真正想要的是：**提高明度，同时稍微降低饱和度**，而这两个操作在 RGB 中没有直接的通道对应。

这就是 **HSV 颜色空间** 要解决的问题。

##### 13.1.1 HSV 的三个分量：各管一件事
HSV 把颜色拆成三个**语义独立**的分量：

************
| 分量 | 全称 | 含义 | 范围 | 调色操作 |
| H (Hue) | 色相 | 颜色的"种类"——红/橙/黄/绿/青/蓝/紫 | [0, 1] 对应色环 0°→360° | 改颜色 = 偏移 H |
| S (Saturation) | 饱和度 | 颜色的"纯度"—— 0 = 无颜色，1 = 最鲜艳 | [0, 1] | 鲜艳度 = 乘 S |
| V (Value / Brightness) | 明度 | 颜色的"亮暗"—— 0 = 全黑，1 = 最亮 | [0, 1] | 明暗 = 调 V |

**S 和 V 都是 "0 = 没有，1 = 最大"**，但各自控制完全不同的维度。S=0, V=1 是纯白色；S=0, V=0.5 是纯灰色；S=0, V=0 是纯黑色；S=1, V=0 也是纯黑色；S=1, V=1 是色相 H 对应的最鲜艳颜色。

把这三个分量想象成一个"颜色遥控器"上的旋钮：
- 想换个颜色？（如红→绿）——转 H 旋钮
- 想更鲜艳？（灰扑扑的 → 鲜亮的）——转 S 旋钮
- 想更亮/更暗？（褪色→发白）——转 V 旋钮

[IMAGE: HSV空间](../ch13-diagrams/hsv.webp)

上图中底部的彩虹条带显示了颜色种类，也就是Hue色相空间，可以看到最左和最右端都是红色，所以色相空间是一个环。再看上部的矩形空间中，纵轴是明度，横轴是饱和度，越往右，色彩越鲜艳，反之则越灰，越往下，明度越暗，越往上，明度越亮。

RGB 没有这种"一个旋钮管一件事"的分工。你在 RGB 里想要"换个色相"，需要同时调三个通道，且调整量依当前颜色而定。这也是为什么直观的颜色调整操作都在 HSV 空间进行。

##### 13.1.2 RGB → HSV → RGB：本章的统一管线
本章所有四个实战遵循同一套流程：

```
纹理颜色 (RGB)  →  rgb2hsv()  →  修改 H / S / V  →  hsv2rgb()  →  输出颜色 (RGB)
```
变化发生在中间的"修改"步骤——受伤闪白改 V+S、中毒变色改 H、彩虹流光滚动 H、调色板替换读取另一个纹理的 RGB 映射。骨架是一样的，差异只在"对 HSV 做了什么"。

下面从这套骨架的地基开始——rgb2hsv() 和 hsv2rgb() 的实现。

#### 13.2 rgb2hsv() 与 hsv2rgb()：颜色空间的桥梁
rgb2hsv(vec3) 接收一个 RGB 颜色，返回一个 HSV 颜色（均为 vec3）。hsv2rgb(vec3) 做反向转换。两个函数是互逆的——hsv2rgb(rgb2hsv(color)) 应当返回原色。

Godot Shader 没有提供 rgb2hsv() 和 hsv2rgb()。需要自己实现一套转换函数——而且这套函数会在本章的四个 shader 中反复使用。按照第十一章学习的工程化原则，我们把它们写进一个 .gdshaderinc 共享库，四个 shader 各自 #include。

最常见的实现思路如下：

- **找出 RGB 中最大和最小的通道**：最大者决定明度 V，最小者参与计算饱和度 S
- **计算饱和度**：S = (V - min) / V（V=0 时分母为零，需防除零）
- **计算色相**：根据哪个通道是最大值，分 6 段计算 H。R 最大时 H 在红-黄区间，G 最大时在黄-青区间，B 最大时在青-品红区间
但逐段计算 if-else 分支在 GPU 上效率不佳。实际生产代码使用一段无分支的数学变换，借用一个 vec4 常量 K 来实现分段逻辑的向量化。这是广泛使用的经典实现：

```
// hsv_tools.gdshaderinc
#ifndef HSV_TOOLS
#define HSV_TOOLS

vec3 rgb2hsv(vec3 c) {
    vec4 K = vec4(0.0, -1.0 / 3.0, 2.0 / 3.0, -1.0);
    vec4 p = mix(vec4(c.bg, K.wz), vec4(c.gb, K.xy), step(c.b, c.g));
    vec4 q = mix(vec4(p.xyw, c.r), vec4(c.r, p.yzx), step(p.x, c.r));
    float d = q.x - min(q.w, q.y);
    float e = 1.0e-10;
    return vec3(abs(q.z + (q.w - q.y) / (6.0 * d + e)), d / (q.x + e), q.x);
}

vec3 hsv2rgb(vec3 c) {
    vec4 K = vec4(1.0, 2.0 / 3.0, 1.0 / 3.0, 3.0);
    vec3 p = abs(fract(c.xxx + K.xyz) * 6.0 - K.www);
    return c.z * mix(K.xxx, clamp(p - K.xxx, 0.0, 1.0), c.y);
}

#endif
```
**不要求逐行理解这些公式。** 它们是"拿来即用"的工具函数——你只需要知道输入和输出，以及为什么在 HSV 空间操作比在 RGB 空间更直观。如果非要类比：这就像你不需要理解 C 语言标准库中 sqrt() 的内部实现才能用它做开方计算。把 rgb2hsv 和 hsv2rgb 视为颜色空间的" sqrt() "即可。

在开始实战之前，先验证转换函数的正确性——写一个 shader，把 RGB 转成 HSV、不做任何修改、再转回 RGB。结果应该与原始纹理完全一致：

```
shader_type canvas_item;

#include "include/hsv_tools.gdshaderinc"

void fragment() {
    vec4 tex = texture(TEXTURE, UV);
    vec3 hsv = rgb2hsv(tex.rgb);
    vec3 rgb = hsv2rgb(hsv);
    COLOR = vec4(rgb, tex.a);
}
```
保存后，角色纹理应该与不使用 shader 时**肉眼无法区分**。如果出现偏色，检查 #include 路径是否正确。如果一切正常——颜色空间的桥梁已经搭好，下面开始在 HSV 空间里"拧旋钮"。

**完整共享库代码**见 hsv_tools.gdshaderinc

#### 13.3 实战 1：受伤闪白 —— 高明度 + 低饱和度 + TIME 衰减
受伤闪白（Hit Flash）是 2D 游戏中最常见的角色反馈效果之一：角色受击的瞬间，身体短暂变亮、褪色，然后逐渐恢复正常。我们分 5 步渐进构建。

##### 第 1 步：最简框架——引入 uniform，直接还原
先从最简 shader 开始：接收一个 hit_intensity uniform（0=正常，1=完全闪白），目前先不做任何实际变化。

```
shader_type canvas_item;

#include "include/hsv_tools.gdshaderinc"

uniform float hit_intensity : hint_range(0.0, 1.0) = 0.0;

void fragment() {
    vec4 tex = texture(TEXTURE, UV);
    vec3 hsv = rgb2hsv(tex.rgb);
    COLOR = vec4(hsv2rgb(hsv), tex.a);
}
```
此时 hit_intensity 还没有参与任何计算，shader 表现与原始纹理一致。在 Inspector 中拖动 hit_intensity 滑块——画面不变。这是地基。

##### 第 2 步：调高明度并降低饱和度
受伤闪白的核心操作是**调高明度 V**，同时**降低饱和度 S** 来实现角色的颜色应该向白色方向偏移：

```
// 明度向 1.0 混合，饱和度向 0.0 混合
hsv.z = mix(hsv.z, 1.0, hit_intensity* 0.8); 
hsv.y = mix(hsv.y, 0.0, hit_intensity* 0.8); 

COLOR = vec4(hsv2rgb(hsv), tex.a);
```
在 Inspector 中把 hit_intensity 从 0 拖到 1——角色从正常颜色的状态逐渐变成"亮度被拉到最大"，颜色信息丢失，几乎全白。这是闪白的本质。

##### 第 3 步：在GDScript中进行控制
之后，我们只需要用 GDScript 的 Tween 动画来动态修改 hit_intensity 这个参数即可。直接将这段代码挂载在你的 Sprite2D 节点上。

```
extends Sprite2D

var tween: Tween

# 外部调用此函数来触发受击闪白
func take_damage():
    # 1. 先停止并清除之前可能正在运行的 tween，防止多次受击时动画冲突
    if tween != null:
        tween.kill()

    # 2. 重新创建一个 Tween
    tween = create_tween()

    # 3. 瞬间将 hit_intensity 设为 1.0（触发最强闪白）
    tween.tween_property(material, "shader_parameter/hit_intensity", 1.0, 0.0)

    # 4. 在 0.2 秒内，将 hit_intensity 平滑地恢复到 0.0（淡出效果）
    # 使用 TRANS_SINE 或 TRANS_CUBIC 会让恢复过程看起来更自然
    tween.tween_property(material, "shader_parameter/hit_intensity", 0.0, 0.2).set_trans(Tween.TRANS_SINE)

func _input(event: InputEvent) -> void:
    if event.is_action_pressed("ui_accept"):
        take_damage()
```

最终效果：当玩家按下空格或回车键时，会调用 take_damage函数，此时角色就会瞬间闪白，然后在 0.2 秒内平滑地恢复原色了。

**完整代码**见 hit_flash.gdshader。

#### 替代方案
当然在 Godot 中实现“受击闪白”效果，其实可以不需要进行昂贵的 RGB 到 HSV 的来回转换。你可以直接在 RGB 空间内，将原始纹理颜色与纯白色进行线性混合。这不仅代码更简洁，而且 GPU 运算效率极高。但在HSV空间中转换可以有更强的灵活性和扩展能力。

```
uniform float hit_intensity : hint_range(0.0, 1.0) = 0.0;

void fragment() {
    vec4 tex = texture(TEXTURE, UV);
    // 直接在 RGB 空间混合：hit_intensity 为 0 时是原图，为 1 时是纯白
    // 注意：保留 tex.a 以确保透明背景依然透明
    COLOR = vec4(mix(tex.rgb, vec3(1.0), hit_intensity), tex.a);
}
```

#### 13.4 实战 2：中毒变色 —— 偏移 Hue 轴
受伤闪白改的是 S 和 V，中毒变色改的是 H。中毒效果的核心：让角色的色相向绿/紫色方向偏移，同时叠上一层薄暮般的墨绿色。

##### 为什么偏 H 就是"换颜色"？
HSV 空间中，H 轴是一个环——H=0 和 H=1 都对应红色，中间依次经过黄、绿、青、蓝、品红。把 H 偏移 0.3（约 108°），红色变绿色，蓝色变品红——这相当于在色环上顺时针旋转了大约 108°。

##### 完整实现：H 偏移 + tint 叠加

```
shader_type canvas_item;

#include "include/hsv_tools.gdshaderinc"

uniform float poison_intensity : hint_range(0.0, 1.0) = 0.0;
uniform float hue_shift : hint_range(0.0, 0.5) = 0.3;
uniform vec3 tint_color : source_color = vec3(0.3, 0.9, 0.2);

void fragment() {
    vec4 tex = texture(TEXTURE, UV);

    vec3 hsv = rgb2hsv(tex.rgb);
    hsv.x = fract(hsv.x + hue_shift);

    vec3 shifted = hsv2rgb(hsv);
    vec3 tinted = mix(shifted, tint_color, poison_intensity * 0.5);

    COLOR = vec4(mix(tex.rgb, tinted, poison_intensity), tex.a);
}
```
两个控制轴协同工作：

- **hue_shift**：控制色相偏移量。fract(hsv.x + hue_shift) 中的 fract() 确保 H 值在 [0, 1] 范围循环——H=0.8 + 0.3 = 1.1 → fract 取 0.1，即色环绕回红色区
- **tint_color**：叠加的墨绿色色调。mix(shifted, tint_color, ...) 在偏移后的颜色与纯墨绿色之间插值，让中毒不是"换个颜色"而是"被中毒色调污染"
poison_intensity 既控制 H 偏移的生效程度，也控制 tint 的强度——0=正常，1=完全中毒。

**完整代码**见 poison.gdshader。

#### 13.5 实战 3：彩虹流光
彩虹流光（Rainbow Flow）是另一个 H 轴操作——但不是固定偏移，而是**让 H 随时间持续滚动**。效果：角色颜色不断循环——红→橙→黄→绿→青→蓝→紫→红，类似 RGB 键盘灯光或彩虹渐变的流动效果。

##### 核心公式：fract(h + fract(TIME * speed))

```
shader_type canvas_item;

#include "include/hsv_tools.gdshaderinc"

uniform float flow_speed : hint_range(0.0, 2.0) = 0.5;
uniform float saturation_boost : hint_range(0.0, 2.0) = 1.2;

void fragment() {
    vec4 tex = texture(TEXTURE, UV);

    vec3 hsv = rgb2hsv(tex.rgb);
    hsv.x = fract(hsv.x + fract(TIME * flow_speed));
    hsv.y = min(1.0, hsv.y * saturation_boost);

    COLOR = vec4(hsv2rgb(hsv), tex.a);
}
```
三层 fract 各司其职：

- **内层 fract(TIME * flow_speed)**：产生一个从 0 到 1 不断循环的时间驱动值。一秒钟转 flow_speed 圈——若 flow_speed=0.5，每 2 秒完成一个 H 循环
- **外层 fract(hsv.x + ...)**：把时间偏移加到原始色相上，fract 保证结果在 [0, 1] 范围内循环。这是色环上的"连续滚动"——H 永远不会"卡在" 0 或 1 处
- **saturation_boost**：彩虹效果需要鲜艳的颜色，将饱和度微微提高（默认 1.2），用 min(1.0, ...) 防溢出
flow_speed 控制变色速度。设为 0.1 → 慢速渐变，适合 UI 边框。设为 2.0 → 快速旋转，适合技能蓄力光环。saturation_boost 控制颜色的冲击力——降低到 0.5 会产生柔和的淡彩流光。

**升级版本**：上面这种方式虽然能够实现彩虹效果，但整个角色始终保持同一种颜色，视觉表现略显单调。更常见的做法是**让颜色沿着角色表面缓慢流动**。实现的方法也非常简单——让 **UV 坐标参与 Hue 的计算**。

```
    shader_type canvas_item;

    #include "include/hsv_tools.gdshaderinc"

    uniform float flow_speed : hint_range(0.0,5.0) = 1.0;
    uniform float flow_width : hint_range(0.0,5.0) = 1.5;
    uniform float saturation_boost : hint_range(0.5,2.0) = 1.2;

    void fragment() {

        vec4 tex = texture(TEXTURE, UV);

        vec3 hsv = rgb2hsv(tex.rgb);

        // TIME 控制整体移动
        // UV.x 控制颜色分布
        float hue_offset = TIME * flow_speed + UV.x * flow_width;

        hsv.x = fract(hsv.x + hue_offset);
        hsv.y = min(hsv.y * saturation_boost,1.0);

        COLOR = vec4(hsv2rgb(hsv), tex.a);
    }
```

hue_offset由两部分组成，前者控制整个颜色不断向前移动，后者让不同位置拥有不同的 Hue。于是颜色便产生了**流动**。flow_width控制颜色跨度。目前颜色是横向流动，如果改成 UV.y，颜色就会从上向下流动。如果使用 length(UV-0.5)，颜色将围绕中心形成彩虹光环。如果使用噪声纹理，则可以实现更加自然的不规则能量流动效果。

**完整代码**见 rainbow.gdshader。

#### 13.6 实战 4：调色板替换 —— 量化颜色 + 预定义调色板映射
前三个实战都在 HSV 空间修改颜色——本质是**"把颜色往某个方向推"**。调色板替换（Palette Swap）则完全不同：它的目标不是修改颜色，而是**"把颜色完全变成另一个颜色"**——像给角色换了一套衣服。

本示例是要实现将原图颜色替换为 Game Boy 的四色（灰度/绿屏）效果，核心思路是**色彩量化（Color Quantization）**。下图就是四种颜色的调色板图片文件。

[IMAGE: 颜色替换](../ch13-diagrams/gameboy.webp)

具体来说，我们需要将原图每个像素的 RGB 颜色先转换为灰度亮度（Luminance），然后根据亮度将其映射到 0~3 这四个离散区间，最后用这个区间作为 UV 坐标去采样你准备好的调色板 PNG。在Sprite2D上挂一个shader如下：

```
    shader_type canvas_item;

    // 绑定你的 128x32 Game Boy 调色板图片
    uniform sampler2D gameboy_palette;

    void fragment() {
        // 1. 采样原始纹理颜色
        vec4 original_color = texture(TEXTURE, UV);

        // 2. 计算原图的灰度亮度（Luminance）
        // 使用标准的 Rec.709 亮度公式，能更真实地还原人眼对颜色的感知
        float luminance = dot(original_color.rgb, vec3(0.2126, 0.7152, 0.0722));

        // 3. 色彩量化：将连续的亮度映射为 4 个离散档位 (0.0, 0.33, 0.66, 1.0)
        // luminance * 3.99 将 0~1 映射到 0~3.99，floor 取整后得到 0, 1, 2, 3
        // 除以 3.0 后，得到 0.0, 0.333, 0.666, 1.0
        float quantized_level = floor(luminance * 3.99) / 3.0;

        // 4. 从调色板中提取颜色
        // 你的调色板是 128x32，从左到右四个颜色。
        // 我们只需要在 X 轴上采样，Y 轴固定取中间值（如 0.5）即可
        vec3 final_color = texture(gameboy_palette, vec2(quantized_level, 0.5)).rgb;

        // 5. 输出最终颜色（保留原图的 Alpha 透明通道）
        COLOR = vec4(final_color, original_color.a);
    }
```

**核心逻辑解析：**

- 亮度提取：dot(original_color.rgb, vec3(0.2126, 0.7152, 0.0722)) 是图形学中标准的灰度化公式。它考虑了人眼对绿色最敏感、对蓝色最不敏感的特性，比简单的 (R+G+B)/3 效果要好得多。
- 四档量化：Game Boy 原始硬件仅支持 4 级灰度。floor(luminance * 3.99) / 3.0 这行代码是色彩量化的精髓，它强行把千变万化的颜色“压缩”进 4 个亮度区间里。
- 调色板采样：通过量化后的 quantized_level 作为 X 轴坐标去采样你的 PNG。因为我们准备的 PNG 四个颜色是均匀从左到右排列的，所以 0.0 对应最左边（最深），1.0 对应最右边（最浅）。
前面这种方法简单直观，但存在一个问题：不同颜色可能拥有相同亮度。最终都会映射到同一个颜色。因此，更常见的是**Index Texture（索引贴图）**。它不是保存颜色，而是保存每一个像素属于第几个调色板颜色。Shader 再根据编号去调色板查找真正颜色，这样无论颜色多接近，都不会发生误映射。

完整代码见 palette_swap.gdshader。

#### 13.7 无敌闪烁 —— alpha 交替的经典模式
本章最后一个参考效果是**无敌闪烁**（Invincibility Blink）。与前面四个实战不同，闪烁不改颜色，只改透明度 alpha。它的核心是一个经典的 shader 动画模式：

```
shader_type canvas_item;

uniform float blink_speed : hint_range(0.0, 20.0) = 10.0;
uniform float min_alpha : hint_range(0.0, 1.0) = 0.3;

void fragment() {
    vec4 tex = texture(TEXTURE, UV);
    float blink = sin(TIME * blink_speed) * 0.5 + 0.5;
    blink = mix(min_alpha, 1.0, blink);
    COLOR = tex;
    COLOR.a *= blink;
}
```
两行核心代码拆解：

- **sin(TIME * blink_speed) * 0.5 + 0.5**：用标准周期运动公式，把 sin 的 [-1, 1] 输出映射到 [0, 1]，变成一个在完全不透明和完全透明之间来回振荡的 alpha 信号
- **mix(min_alpha, 1.0, blink)**：把 [0, 1] 的 alpha 信号限制在 [min_alpha, 1.0] 范围内——角色永远不会完全消失（因为 min_alpha = 0.3，最透明时仍有 30% 不透明），闪烁变成"半透明→不透明→半透明"的循环

#### 13.8 本章小结：HSV 空间里的四种"旋钮操作"
****************
| 实战案例 | 修改内容 | 核心公式 | 数据来源 | 常见应用 |
| 受伤闪白（Hit Flash） | V↑、S↓ | mix(hsv.z,1.0,t)、mix(hsv.y,0.0,t) | GDScript 控制 | RPG、ACT、射击游戏受击反馈 |
