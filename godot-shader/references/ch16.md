# 第 16 章：复古与故障艺术

### 第 16 章：复古与故障艺术 —— CRT / VHS / Glitch 全栈后处理
**学习目标**：掌握像素化、色差、CRT 扫描线、VHS 磁带效果和 Glitch 故障艺术五种后处理 shader 的实现原理，能独立搭建完整效果并组合应用到游戏场景中。

---

## 16.1 为什么复古效果都属于后处理
你可能会问：为什么像素化、CRT、VHS 这些效果都要用"后处理"来实现？答案很简单——它们处理的不是某一个物体的外观，而是**整个画面**的视觉效果。

后处理（Post-Processing）是在场景渲染完成后，对最终画面施加的一层滤镜。它不关心画面里有什么——无论是 3D 场景、2D 精灵还是 UI——全部一视同仁地被同一个 shader 处理。

在 Godot 中，后处理的标准搭建方式如下：

- 在场景中新建一个 CanvasLayer 节点（确保它位于所有游戏内容之上）
- 在 CanvasLayer 下新建一个 ColorRect 节点，将其锚定设为 Full Rect（覆盖全屏）
- 在 ColorRect 的 material 属性中新建 ShaderMaterial
- 在 ShaderMaterial 中新建 .gdshader 文件，shader 类型设为 canvas_item
shader 中访问画面内容的关键是 SCREEN_TEXTURE——这是一个由 Godot 自动提供的纹理，包含了**当前 ColorRect 渲染之前**的所有画面内容。在 shader 中声明 uniform sampler2D screen_texture : hint_screen_texture，你就能在 fragment() 中像读普通纹理一样读取屏幕画面，然后对它做任何处理。

本章后续的每一个效果——像素化、色差、CRT、VHS、Glitch——都建立在这套东西之上。它们之间的唯一区别，就是 fragment() 里对 SCREEN_TEXTURE 采样结果做了什么修改。

多效果串联时，每个效果放在独立的 CanvasLayer + ColorRect 上，通过 BackBufferCopy 节点在它们之间传递中间画面（详见 16.8 节）。

## 16.2 像素化：最简单的后处理
像素化是所有复古效果中最简单、也最能立刻看到结果的。它的核心思想只有一个：**把连续屏幕坐标变成离散的阶梯值**，让相邻的一整块像素全部采样到同一个颜色。

FRAGCOORD 是当前的像素坐标。floor() 的作用是"丢弃小数部分"。floor(uv / pixel_scale) 把整个块内的 UV 值压缩到同一个整数坐标，再乘以 pixel_scale 还原到 UV 空间——这一除一乘看起来绕了一圈，实际 floor() 在中间截断了精度，让整个块内的坐标完全一致。

```
"像素化"本质：
  连续坐标 ——> 除以 pixel_scale ——> floor() 取整 ——> 乘回 pixel_scale ——> 阶梯状 UV
```
完整 shader 代码（pixel.gdshader）：

```
shader_type canvas_item;

uniform sampler2D screen_texture : hint_screen_texture;

// 1.0 = 原始像素大小, 10.0 = 每个马赛克包含 10x10 个屏幕像素
uniform float pixel_scale : hint_range(1.0, 20.0, 1.0) = 1.0;

void fragment() {
    // 基于屏幕像素的坐标系
    vec2 virtual_coord = FRAGCOORD.xy;

    // 进行取整操作
    vec2 stepped_coord = floor(virtual_coord / pixel_scale) * pixel_scale;

    // 将坐标转回 UV 空间用于采样
    vec2 screen_uv = stepped_coord * SCREEN_PIXEL_SIZE;

    // 采样
    COLOR = texture(screen_texture, screen_uv);
}
```
**效果**：pixel_scale 从 1 调到 20，可以看到画面从清晰到"积木块"的完整渐变过程。

## 16.3 色差：引入多次采样
像素化只用了一次 texture() 调用——对 SCREEN_TEXTURE 采样一次，输出。色差（Chromatic Aberration）往前推了一步：**对 R、G、B 三个通道分别从略微偏移的 UV 坐标采样 SCREEN_TEXTURE，再合并输出。**

这是老相机镜头和 CRT 显示器最显著的特征之一——物体边缘出现红蓝偏移。GPU 沿用了 CRT 时代的 RGB 三色荧光粉思路：在真正的物理 CRT 里，R/G/B 三束电子束打在荧光屏上的位置本身就不完全重合，shader 里用三次 texture() 调用、每次给 UV 加不同偏移量来模拟这个物理现象。

```
shader_type canvas_item;

uniform sampler2D screen_texture : hint_screen_texture;
// 色差偏移量：正值 = R 右移 B 左移
uniform float chromatic_offset : hint_range(0.0, 0.02, 0.001) = 0.005;

void fragment() {
    vec2 uv = SCREEN_UV;
    // 对 R/G/B 三个通道从不同 UV 坐标分别采样
    float r = texture(screen_texture, uv + vec2(chromatic_offset, 0.0)).r;
    float g = texture(screen_texture, uv).g;
    float b = texture(screen_texture, uv - vec2(chromatic_offset, 0.0)).b;
    // 三通道合并输出
    COLOR = vec4(r, g, b, 1.0);
}
```
R 通道向右偏移，B 通道向左偏移，G 通道保持原位。这是最基础的横向色差。理解"多次采样 + 通道重组"这个模式非常重要——它是后续 CRT 和 Glitch 效果的基础。

## 16.4 CRT 显示器：五步构建
CRT 显示器的视觉特征不是单一效果，而是色差、扫描线、噪点、暗角和闪烁五个效果的叠加。我们从零开始，一步一步搭出完整的 CRT shader。

### 第 1 步：色差 —— 三通道分离
先把 16.3 的色差作为起点。对 R、G、B 三个通道从略微偏移的 UV 坐标分别采样 SCREEN_TEXTURE，然后合并为一个 vec3。R 通道向右偏移、B 通道向左偏移、G 通道保持原位，模拟 CRT 三束电子打在荧光屏上的微小位置偏差：

```
vec2 uv = SCREEN_UV;

float r = texture(screen_texture, uv + vec2(chromatic_offset, 0.0)).r;
float g = texture(screen_texture, uv).g;
float b = texture(screen_texture, uv - vec2(chromatic_offset, 0.0)).b;
vec3 color = vec3(r, g, b);
```
此时画面已经有了一层"老相机镜头"的质感——物体边缘出现微弱的红蓝错位。但这还不够，真正的 CRT 特征还没出现。

### 第 2 步：扫描线 —— 逐行明暗
扫描线是 CRT 最核心的视觉特征。电子束从屏幕顶部逐行扫描到底部，当前被击中的那一行最亮，两行扫描线之间有一条暗带。用 sin() 生成亮度波，调制上一步的 color：

```
vec3 color = vec3(r, g, b);

float scanline = sin(uv.y * scanline_density * PI);
scanline = (scanline + 1.0) / 2.0;
scanline = mix(1.0, scanline, scanline_intensity);

vec3 final_color = color * scanline;
```
sin(uv.y * N * PI) 每 uv.y 走完 1/N 就完成一个周期——scanline_density 越大，扫描线越密集。(sin + 1) / 2 把输出范围从 [-1, 1] 映射到 [0, 1]，让它可以用作亮度系数乘在原色上。mix(1.0, scanline, intensity) 控制效果的强弱：intensity = 0 时等于没加扫描线，intensity = 1 时扫描线最明显。

到这一步，画面已经有了横条纹。但老电视的"脏感"还没出来。

### 第 3 步：颗粒噪点 —— 模拟信号噪声
老 CRT 接收的是模拟信号，总有随机噪点在闪烁。shader 中用 hash 函数为每个像素每一帧生成一个伪随机值，叠加到画面上：

```
float hash(vec2 p) {
    return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

// ... 色差 + 扫描线同上 ...

float noise = hash(FRAGCOORD.xy + TIME * 10.0);
vec3 grain = vec3(noise);

vec3 final_color = color * scanline;
final_color = mix(final_color, grain, grain_intensity);
```
hash 函数的本质是把输入坐标"打散"成一个看起来完全随机、但对每个输入确定的值。FRAGCOORD.xy 保证不同像素的噪点不同，+ TIME * 10.0 让噪点每帧重新随机，视觉上就是持续闪烁的雪花。mix() 让噪点强度在 Inspector 中从 0 到 0.15 可调——0 就是干净画面，0.15 就是严重的信号干扰。

### 第 4 步：暗角 —— 边缘压暗
老 CRT 的屏幕四角有明显的亮度衰减——这是阴极射线管边缘磁场不均匀导致的结果。用"到画面中心的距离"驱动 smoothstep() 来模拟：

```
float dist = length((uv - 0.5) * 2.0);
float vignette = 1.0 - smoothstep(1.0- vignette_smoothness, 1.0 , dist);
vignette = mix(1.0, vignette, vignette_intensity);
final_color *= vignette;
```
(uv - 0.5) * 2.0 把 UV 坐标原点移到画面中心，范围从 [0, 1] 变为 [-1, 1]，length() 计算当前像素到中心的距离。smoothstep 的效果是：中心区域（dist 小）返回 1.0（全亮），边缘区域（dist 接近 1）被压暗，过渡区域的平滑度由 vignette_smoothness 控制。mix(1.0, vignette, intensity) 同样是"总开关"——开 0 就是正常画面，开 1 就是明显的四角暗影。

### 第 5 步：闪烁 —— 微弱的全局亮度波动
最后加一个全局亮度波动。老电视的荧光屏受 60Hz 交流电影响，全屏亮度有微弱的周期性明暗变化：

```
float flicker = 1.0+ 0.02*sin(TIME*80.0);
final_color *= flicker;
```
sin(TIME * 80.0) 以约 13Hz 的频率做正弦波动（TIME 单位是秒），振幅只有 2%，非常微弱——它不应该被"看见"，但如果少了它，画面会感觉少了那么一点"活气"。这就是好的效果和"神似"的效果之间的区别：往往是最后一个最微小的细节补上了最后一环。

### 完整代码
五步走完，完整 shader（ch16_crt.gdshader）如下：

```
shader_type canvas_item;

uniform sampler2D screen_texture : hint_screen_texture;

uniform float scanline_density : hint_range(100.0, 800.0, 1.0) = 300.0;
uniform float scanline_intensity : hint_range(0.0, 1.0, 0.01) = 0.5;

uniform float chromatic_offset : hint_range(0.0, 0.01, 0.0005) = 0.003;

uniform float grain_intensity : hint_range(0.0, 0.15, 0.005) = 0.1;

uniform float vignette_intensity : hint_range(0.0, 1.0, 0.01) = 0.4;
uniform float vignette_smoothness : hint_range(0.1, 0.9, 0.01) = 0.4;

float hash(vec2 p) {
    return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

void fragment() {
    vec2 uv = SCREEN_UV;

    float r = texture(screen_texture, uv + vec2(chromatic_offset, 0.0)).r;
    float g = texture(screen_texture, uv).g;
    float b = texture(screen_texture, uv - vec2(chromatic_offset, 0.0)).b;
    vec3 color = vec3(r, g, b);

    float scanline = sin(uv.y * scanline_density * PI);
    scanline = (scanline + 1.0) / 2.0;
    scanline = mix(1.0, scanline, scanline_intensity);

    float noise = hash(FRAGCOORD.xy + TIME * 10.0);
    vec3 grain = vec3(noise);

    vec3 final_color = color * scanline;
    final_color = mix(final_color, grain, grain_intensity);

    float dist = length((uv - 0.5) * 2.0);
    float vignette = smoothstep(1.0, 1.0 - vignette_smoothness, dist);
    vignette = mix(1.0, vignette, vignette_intensity);
    final_color *= vignette;

    float flicker = 1.0+ 0.02*sin(TIME*80.0);
    final_color *= flicker;
    COLOR = vec4(final_color, 1.0);
}
```

### 处理流水线总结

```
采样链：
1. 色差偏移 → 三通道分别采样 → 合并为 vec3 color
2. sin(uv.y * density) → 扫描线调制 → color *= scanline
3. hash(FRAGCOORD + TIME) → 噪点混合 → mix(color, grain, intensity)
4. smoothstep(中心距离) → 暗角衰减 → color *= vignette
5. sin(TIME) → 全局闪烁 → color *= flicker
6. 输出 COLOR
```
每一步在前一步的输出上做进一步修饰，形成一条完整的处理流水线。mix() 的"总开关"模式贯穿始终——每个效果都可以通过 uniform 独立控制强度，让读者在 Inspector 中调节出自己想要的"复古程度"。

更精确的 CRT 模拟会使用 YIQ 色彩空间做色差（NTSC 电视信号使用的编码），对 Y/I/Q 三通道以不同带宽衰减后再转回 RGB。视觉效果与 RGB 色差差异不大但成本更高，教学阶段用 RGB 空间完全够用。

## 16.5 VHS 录像带效果
VHS 模拟的不是一瞬间的故障，而是磁带播放的持续退化：画面波纹、磁带折痕、信号切换噪点、亮度拍频和颗粒噪点。vhs.gdshader 覆盖了这五个方面：

```
shader_type canvas_item;
uniform sampler2D screen_texture : hint_screen_texture;

uniform float wave_amount : hint_range(0.0, 0.02) = 0.003;
uniform float crease_amount : hint_range(0.0, 2.0) = 0.5;
uniform float noise_intensity : hint_range(0.0, 1.0) = 0.1;

float hash(vec2 p) {
    return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

void fragment() {
    vec2 uv = SCREEN_UV;

    // 1. 磁带波纹：Y 坐标驱动水平波浪
    uv.x += (hash(vec2(uv.y * 100.0, TIME * 10.0)) - 0.5) * wave_amount;

    // 2. 磁带折痕：sin() 产生暗纹
    float crease = sin(uv.y * 8.0 - TIME * PI * 1.2);
    crease = smoothstep(0.92, 1.0, crease);

    // 3. 信号切换噪点：只影响画面上半部的水平偏移
    float switch_noise = smoothstep(0.03, 0.0, uv.y);
    uv.x += switch_noise * (hash(vec2(uv.y * 100.0, TIME * 10.0)) - 0.5) * 0.2;

    vec3 color = texture(screen_texture, uv).rgb;
    color *= 1.0 - crease * crease_amount;

    // 4. 亮度拍频：AC 电源产生的亮度波动
    float beat = hash(vec2(0.0, uv.y + TIME * 0.1)) * 0.6 - 0.25;
    color *= 1.0 + clamp(beat, 0.0, 0.1);

    // 5. 颗粒噪点
    float noise = hash(FRAGCOORD.xy + TIME * 100.0);
    color = mix(color, vec3(noise), noise_intensity);

    COLOR = vec4(color, 1.0);
}
```
VHS 的难点不在单一技巧，而在**五个效果的协同**——波纹让画面"软"，折痕让画面"旧"，切换噪点让画面"不稳定"，拍频让画面"有电气感"，颗粒让画面"脏"。少一个就不像 VHS。建议从单独的波纹开始，逐个叠加，感受每一步加入后画面"老化程度"的递增。

## 16.6 Glitch 故障艺术
Glitch 和 CRT 是不同的审美方向。CRT 是"怀旧的温暖"，Glitch 是"数字错误的暴力美"。如果希望画面看起来"被破坏了"，用 Glitch。glitch.gdshader 实现了三种核心故障：

```
shader_type canvas_item;

uniform sampler2D screen_texture : hint_screen_texture;

uniform float scan_line_jitter : hint_range(0.0, 0.5) = 0.1;
uniform float vertical_jump : hint_range(0.0, 0.15) = 0.02;
uniform float horizontal_shake : hint_range(0.0, 0.3) = 0.01;
uniform float color_drift : hint_range(0.0, 0.05) = 0.01;

float nrand(float x, float y) {
    return fract(sin(dot(vec2(x, y), vec2(12.9898, 78.233))) * 43758.5453);
}

void fragment() {
    vec2 uv = SCREEN_UV;

    //==================================================
    // 1. Scan Line Jitter（按扫描线分组）
    //==================================================

    // 将屏幕划分成约 300 条扫描线，同一条扫描线共享一个随机值
    float line = floor(uv.y * 300.0);

    float jitter = nrand(line, TIME) * 2.0 - 1.0;

    float jitter_threshold = 1.0 - scan_line_jitter * 1.2;
    float jitter_disp = 0.002 + pow(scan_line_jitter, 3.0) * 0.05;

    jitter *= step(jitter_threshold, abs(jitter)) * jitter_disp;

    //==================================================
    // 2. Vertical Jump
    //==================================================

    float jump_time = TIME * vertical_jump * 11.3;
    float jump = mix(uv.y, fract(uv.y + jump_time), vertical_jump);

    //==================================================
    // 3. Horizontal Shake（降低随机刷新频率）
    //==================================================

    float shake =
        (nrand(floor(TIME * 20.0), 2.0) - 0.5)
        * horizontal_shake
        * 0.2;

    //==================================================
    // 4. Color Drift
    //==================================================

    float drift = sin(jump + TIME * 606.11) * color_drift * 0.04;

    vec4 final1 = texture(
        screen_texture,
        fract(vec2(uv.x + jitter + shake, jump))
    );

    vec4 final2 = texture(
        screen_texture,
        fract(vec2(uv.x + jitter + shake + drift, jump))
    );

    COLOR = vec4(final1.r, final2.g, final1.b, 1.0);
}
```
三种故障的核心机制：

- **扫描线抖动**：step(jitter_threshold, abs(jitter)) 是关键——只有当随机值超过阈值时，这条扫描线才被选中做水平位移。阈值越高，被抖动的线越少，画面看起来像是"偶尔跳一下"而非"全部在抖"。
- **水平撕裂**：垂直跳动（fract(uv.y + jump_time) 产生整帧位移）与水平晃动（基于 TIME 的全局偏移）配合，产生"画面被撕开又弹回去"的效果。
- **RGB 漂移**：两次采样 fract() 截断后的 UV——一次带漂移、一次不带——然后跨采样通道合并（R/B 取采样 1，G 取采样 2），产生单通道撕裂的色彩错位。
将所有参数暴露为 uniform，读者可以通过调节 scan_line_jitter / vertical_jump / horizontal_shake / color_drift 来微调效果从"微妙故障"到"画面崩溃"的整个频谱。

## 16.7 游戏中的组合应用
写了这么多效果，最终目的是在游戏里用起来。以下是四个常见的组合场景。

### 受击效果
玩家受到伤害时触发瞬间画面故障，增强打击感。用 Glitch shader，在 GDScript 中用 tween 短暂提升 vertical_jump 和 horizontal_shake：

```
func apply_hit_glitch():
    var mat = $CanvasLayer/ColorRect.material
    var tween = create_tween()
    tween.tween_method(
        func(v): mat.set_shader_parameter("vertical_jump", v),
        0.0, 0.08, 0.05
    )
    tween.tween_method(
        func(v): mat.set_shader_parameter("vertical_jump", v),
        0.08, 0.0, 0.15
    )
```
0.05 秒内跳跃到峰值，0.15 秒内平滑恢复——整个效果不到 0.2 秒，给人"屏幕被砸了一下"的感觉。

### 回忆闪回
闪回 / 回忆场景用 CRT + 去色处理。在 CRT shader 的最终输出前加一行：

```
float gray = dot(final_color.rgb, vec3(0.299, 0.587, 0.114));
final_color.rgb = mix(final_color.rgb, vec3(gray), 0.7);
```
或者直接把 CRT shader 改造为支持 uniform float desaturation 参数。配合略增的暗角强度，画面立刻染上"过去的事"的氛围。

### 监控摄像头
CCTV 画面 = 像素化 + 颗粒噪点 + 轻微色差。不需要 BackBufferCopy——直接在单个 shader 里组合 pixel + grain + chromatic：

```
// 像素化
vec2 block = TEXTURE_PIXEL_SIZE * pixel_size;
vec2 stepped_uv = floor(uv / block) * block;
// 色差采样
float r = texture(screen_texture, stepped_uv + chromatic_off).r;
float g = texture(screen_texture, stepped_uv).g;
float b = texture(screen_texture, stepped_uv - chromatic_off).b;
vec3 color = vec3(r, g, b);
// 噪点叠加
color = mix(color, vec3(hash(FRAGCOORD.xy + TIME * 50.0)), 0.08);
```
上面一组参数很容易调出"便利店的廉价监控画面"。如果再加一个 Label 节点显示时间戳文字，代入感更强。

### 老电视
最完整的复古体验——CRT 扫描线 + VHS 磁带退化。用 BackBufferCopy 串联（详见 16.8 节）：

```
[原始场景] → BackBufferCopy → CRT shader → BackBufferCopy → VHS shader → 屏幕
```
每一层独立可调：CRT 决定"电视机型"，VHS 决定"磁带老化程度"。运行时还可以通过 GDScript 动态调节某一层的 uniform——比如让 VHS 的 wave_amount 随"信号质量"游戏变量缓慢波动。

## 16.8 BackBufferCopy：多效果串联
前面的效果都是"一个 shader 搞定"。但如果想给同一个画面同时加像素化和 CRT 扫描线和 VHS 抖动呢？

你不能把三套代码全部塞进一个 fragment()——那样 shader 会变成不可维护的巨型函数。正确做法是**拆成三个独立的 shader，用 BackBufferCopy 把它们串成流水线**。

### BackBufferCopy 做了什么？
BackBufferCopy 是 Godot 的 CanvasItem 节点，它在每一帧复制**当前渲染缓冲区中的画面区域**到一个内部纹理。之后，同层的 ColorRect 可以通过 SCREEN_TEXTURE 读取这个被复制的画面。

**没有 BackBufferCopy 时**，SCREEN_TEXTURE 读到的是当前 ColorRect 渲染之前的所有内容——但不包括同层其他后处理效果。而 BackBufferCopy 把一个"快照"截取下来，让下一个 ColorRect（绑在下一个 CanvasLayer 上）可以从这个快照出发继续处理。

### 串联模型

```
[原始场景渲染]
    ↓
BackBufferCopy（截取全屏）
    ↓
CanvasLayer_1 → ColorRect（像素化 shader，SCREEN_TEXTURE = BackBufferCopy 的副本）
    ↓
BackBufferCopy_2（截取像素化后的画面）
    ↓
CanvasLayer_2 → ColorRect（CRT shader，SCREEN_TEXTURE = BackBufferCopy_2 的副本）
    ↓
BackBufferCopy_3（截取 CRT 处理后的画面）
    ↓
CanvasLayer_3 → ColorRect（VHS shader，SCREEN_TEXTURE = BackBufferCopy_3 的副本）
    ↓
最终屏幕输出
```
每个 CanvasLayer 层高一级（layer 值递增），确保渲染顺序正确：底层先渲染，上层后渲染，后渲染的读取前一层已经处理完的画面。

### 场景搭建步骤

- 建第一个 BackBufferCopy，设为 Full Rect，Cut Mode 选 Copy Mode
- 建 CanvasLayer，layer 设为 1；挂 ColorRect（Full Rect）；挂像素化 shader
- 建第二个 BackBufferCopy，Full Rect，Copy Mode
- 建 CanvasLayer，layer 设为 2；挂 ColorRect；挂 CRT shader
- 建第三个 BackBufferCopy，Full Rect，Copy Mode
- 建 CanvasLayer，layer 设为 3；挂 ColorRect；挂 VHS shader
每一层级的效果都独立可控——你可以在运行时通过 GDScript 动态调节某一层的 uniform（比如只在"受击"时打开 Glitch）。

**注意**：BackBufferCopy 的 Copy Mode 会全量复制缓冲区，在大分辨率（4K）下有性能开销。如果只处理局部区域，改用 Rect Mode 并按需设置拷贝区域大小。

## 本章小结
本章从零搭建了五种复古后处理效果，它们遵循同一个技术范式——CanvasLayer + ColorRect + SCREEN_TEXTURE：

| 效果 | 核心技术 | 典型场景 |
| 像素化 | floor(UV / block) * block | 复古像素画面、遮挡隐私 |
| 色差 | R/B 通道向不同方向偏移采样 | 老相机、镜头模拟 |
| CRT | 扫描线 + 色差 + 噪点 + 暗角 + 闪烁 | 老式电视机、回忆场景 |
| VHS | 波纹 + 折痕 + 切换噪点 + 拍频 + 颗粒 | 录像带画质、恐怖游戏 |
| Glitch | 扫描线抖动 + 垂直/水平撕裂 + RGB 漂移 | 受击反馈、赛博朋克 UI |

关键设计模式值得带走：

- **mix(1.0, effect, intensity)** 控制效果强度的简洁模式，让每个效果都可以在 Inspector 中从 0 到 1 渐变调节。
- **BackBufferCopy 串联**让多个效果像管道一样组合，每个 shader 只做一件事，避免巨型函数。
- **效果协同**不是简单堆叠——VHS 少了任何一个维度都不像，CRT 少了暗角就少了"时代感"。学会感受每个效果对整体氛围的贡献，比记住代码更重要。
