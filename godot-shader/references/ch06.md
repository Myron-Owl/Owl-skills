# 第 6 章：塑形函数

### 第 6 章：塑形函数 —— 平滑、过渡与混合
**学习目标**：掌握 step()、smoothstep()、mix()、clamp() 四种核心塑形函数，理解 smoothstep 的 Hermite 插值为什么比线性插值更适合做视觉过渡，并能够用这些函数组合出魔法圆环和圆形淡入淡出效果。

**场景搭建**：创建一个 Sprite2D 节点（使用默认纹理即可），为其新建 ShaderMaterial，再新建一个 canvas_item 类型的 shader 文件。本章所有代码均写在 fragment() 函数中，不需要额外场景节点或 GDScript 脚本。

**内容要点**：

- step(edge, x)：二值选择（硬边界）—— 遮罩、切换、硬边缘
- smoothstep(a, b, x)：平滑过渡 —— Hermite 3t² − 2t³ 的直觉解释（慢→快→慢），配线性 vs smoothstep 视觉对比
- mix(a, b, t)：插值混合 —— 颜色渐变、纹理混合、值域映射
- clamp(x, lo, hi)：约束范围 —— 防溢出、安全限幅
- 函数组合：distance() + smoothstep() 画圆环
- 实战 1：扩散魔法圆环（5 步渐进构建）
- 实战 2：任意点圆形淡入淡出

## 1. 形状从何而来：塑形函数的总览
第 5 章你学会了用 sin()、fract()、mod() 让画面动起来。但那些函数产出的值是**连续波动**的——它们擅长制造周期和节奏，却不擅长制造"边界"。如果你想让一个圆环的边缘锐利，或者让一个颜色从一个区域平滑过渡到另一个区域，你需要的是**塑形函数**。

塑形函数的作用只有一个：重映射数值。输入通常是连续变化的量（距离、时间、坐标），输出则是用于控制颜色与透明度的信号。它们不是"数学函数"，而是"视觉控制器"。

本章介绍的四种塑形函数构成了 shader 编程的"控制层"。你在后续章节中会反复看到它们的身影：ch8 用 smoothstep 做 SDF 图形的抗锯齿边缘；ch10 用 mix 混合屏幕纹理；ch14 用 step 做溶解阈值；ch20 用 smoothstep 做卡通渲染的色阶分段。理解这四个函数，就是理解了 shader 的"开关逻辑"。

四种函数按"硬度"排列：step 最硬——输出只有 0 或 1，像一堵墙。smoothstep 最软——在 0 和 1 之间有一条优美的 S 曲线。mix 和 clamp 居中，提供线性控制。本章不是按函数逐个讲，而是按"视觉控制的硬度谱"展开——从最硬的二值开关，到最软的平滑过渡，再到中间的线性控制和边界保护。下面我们从最硬的开始，逐一拆解。

---

## 2. 硬开关 —— step()

### 2.1 它是什么？
step(edge, x) 是一个**阶梯函数**。它比较两个值，返回 0.0 或 1.0：

```
step(edge, x)  →  0.0   (当 x < edge)
                   1.0   (当 x >= edge)
```
用一句话描述：**x 跨过门槛 edge 的那一刻，输出从 0 跳到 1**。没有中间值，没有渐变——它就是一条硬边界。

### 2.2 为什么需要它？
想象你要在屏幕上画一个圆。用数学语言描述这个需求：**距离圆心小于半径的像素是一种颜色，大于半径的是另一种颜色**。这正是 step 做的事情——它把连续的距离值变成"内/外"的二元判断。

更一般地，任何"是/否"的判断在 shader 中都应优先考虑 step。你需要一个遮罩来隔离某个区域？step。你需要根据某个值是否超过阈值来切换两种颜色？step。你需要做一个硬边缘的进度条分割线？step。

### 2.3 怎么用：画一个硬边圆
先算出每个像素到中心的距离，再用 step 做内/外判断：

```
shader_type canvas_item;

void fragment() {
    // 将 UV 中心化：把 (0,1) 映射到 (-1,1)
    vec2 uv = UV * 2.0 - 1.0;

    // 计算当前像素到中心 (0,0) 的距离
    float d = length(uv);

    // 距离 < 0.5 的像素为白色，其余为黑色
    float mask = step(d, 0.5);

    COLOR = vec4(vec3(mask), 1.0);
}
```
**效果**：Sprite2D 中央出现一个白色圆，边缘锐利如刀切。圆心到 d = 0.5 处 mask 保持 1.0，一过 0.5 立刻跌落为 0.0。

step 第二个参数大于第一个参数时也可以反过来用：step(0.5, d) 会在 d >= 0.5 时返回 1.0，换句话说——画出的不是实心圆，而是一个**中心黑色、外围白色**的图案。

**length(uv) 是 ch8 SDF 章的前奏。** 现在你只需要知道：length(vec2) 返回向量的长度，等价于 sqrt(x*x + y*y)。对中心化后的 UV 坐标来说，它就是"到中心的距离"。

## 3. 软开关 —— smoothstep()

### 3.1 它是什么？
smoothstep(edge0, edge1, x) 是 step 的**平滑版本**。它在两个边界之间不是跳变，而是生成一条 S 形曲线：

```
smoothstep(a, b, x)  →  0.0                         (当 x <= a)
                         0.0 到 1.0 之间的平滑过渡     (当 a < x < b)
                         1.0                         (当 x >= b)
```
当 x <= a 时输出 0，x >= b 时输出 1。在 a 和 b 之间，它使用 **Hermite 插值** 生成一条从 0 到 1 的平滑曲线。

### 3.2 为什么 Hermite 比线性好？
这是本章最重要的概念。让我们对比两种过渡方式：

**线性插值（如果 smoothstep 用线性做）**：

```
t = (x - a) / (b - a)    // 线性比例
result = t                // 匀速变化
```
线性过渡的问题是：它在起点和终点处**有尖角**。从视觉上看，这意味着过渡区域的起点和终点会出现肉眼可见的"折痕"——因为变化率在边界处发生了突变（从"不变"突然变成"匀速变化"）。

**Hermite 插值（smoothstep 实际使用的）**：

```
t = (x - a) / (b - a)
result = t * t * (3.0 - 2.0 * t)
```
它的关键不是公式，而是两个约束：**起点速度 = 0**（从静止慢慢开始），**终点速度 = 0**（到终点前缓缓停下）。这两个约束恰好对应自然界中大多数平滑运动的特征——物体从静止开始加速，到达终点前减速。这就是它比线性"看起来更自然"的原因。

在 shader 中，这条 S 曲线直接转化为视觉上的"柔和"。它消除了硬边界处的人工痕迹，让发光、阴影、混合过渡看起来自然。

### 3.3 怎么用：从硬边圆到软边圆
把上一节的 step 替换为 smoothstep：

```
// 之前：硬边
float mask = step(d, 0.5);

// 之后：软边 (边缘跨度 0.1)
float mask = 1.0 - smoothstep(0.4, 0.5, d);
```
1.0 - smoothstep(...) 做了一个反转——原来是 d < 0.4 时为 0、d > 0.5 时为 1 的渐变，反转后变成圆心 = 1.0、圆外 = 0.0、圆边缘 = 平滑过渡。

**关键参数理解**：smoothstep(0.4, 0.5, d) 中的 0.4 和 0.5 定义了过渡带的宽度——0.5 - 0.4 = 0.1。这个宽度越小，边缘越锐利；宽度越大，边缘越模糊。当宽度趋近于 0 时，smoothstep 的表现趋近于 step。

**smoothstep 是全书最重要的 shader 函数之一。** ch8 用它给 SDF 图形做抗锯齿；ch10 用它做屏幕特效的混合遮罩；ch14 用它做溶解效果的边缘发光；ch20 用它做卡通渲染的色阶分段。本章是它的大本营——现在讲透，后面各章只需引用。

## 4. 线性控制 —— mix()

### 4.1 它是什么？
mix(a, b, t) 执行**线性插值**：

```
mix(a, b, t)  →  a * (1.0 - t) + b * t
```
当 t = 0.0 时返回 a，t = 1.0 时返回 b，t = 0.5 时返回 a 和 b 的中点。

mix 与普通数学函数有一个根本区别：**它的参数 a 和 b 可以是任意类型**——float、vec2、vec3、vec4，甚至 mat3。当你 mix(vec3, vec3, float) 时，GPU 对向量的每个分量分别执行插值——这是一条指令完成的并行操作。

**一个常见的误区纠正**：mix 不是叠加（a + b * t 会把 a 和 b 都带进来造成过曝），而是**选择权重**——t 决定你更偏向 a 还是 b。正确理解是 a ←→ b 的连续选择，而非 a + b。

### 4.2 为什么需要它？
在 shader 中，"混合两样东西"是最常见的操作之一：

- 两种颜色之间渐变（天空的蓝色到橙色）
- 两层纹理之间切换（草地纹理到泥土纹理）
- 噪声值与固定颜色之间插值（随机色块）
- 把 smoothstep 的 0/1 输出映射为任意两种颜色的过渡
如果没有 mix，你需要手写 a * (1.0 - t) + b * t。mix 不仅省了 8 个字符，更重要的是它**表达了意图**：这行代码是在做"混合"，不是在"做算术"。

### 4.3 怎么用：用 mix 给世界着色
最简单的用法——用 UV 坐标驱动颜色渐变：

```
shader_type canvas_item;

void fragment() {
    // UV.x 从 0 到 1，驱动蓝色到橙色的渐变
    vec3 blue = vec3(0.1, 0.3, 0.8);
    vec3 orange = vec3(0.9, 0.4, 0.1);
    vec3 color = mix(blue, orange, UV.x);

    COLOR = vec4(color, 1.0);
}
```
**效果**：Sprite2D 从左边的深蓝平滑过渡到右边的橙色。UV.x 充当了 t 的角色——自然地把水平坐标映射为颜色插值因子。

mix 的真正威力在于与 smoothstep 的组合——smoothstep 负责生成 0 到 1 的控制信号，mix 负责把控制信号翻译成颜色。这就是后续"实战 1：魔法圆环"的核心。

## 5. 安全边界 —— clamp()

### 5.1 它是什么？
clamp(x, lo, hi) 把 x 夹在 lo 和 hi 之间：

```
clamp(x, lo, hi)  →  lo   (当 x < lo)
                      x    (当 lo <= x <= hi)
                      hi   (当 x > hi)
```
它是 min(max(x, lo), hi) 的语法糖，但更可读。

### 5.2 为什么需要它？
在 shader 中，很多运算会产生超出预期范围的值：

- 两个颜色的加法可能让通道超过 1.0（过曝）
- 多次噪声叠加（FBM）可能超过 1.0 或低于 0.0
- 距离计算可能产生巨大值，除以小除数可能产生 inf
clamp 是安全网。它不改变中间值，但保证输出不会失控。在 chapter 7 的 FBM 噪声叠加中你会频繁用它。

### 5.3 怎么用：简洁示例

```
float brightness = sin(TIME) * 2.0;   // 范围 [-2, 2]
brightness = clamp(brightness, 0.0, 1.0);  // 现在范围 [0, 1]
```
sin() 天然输出 [-1, 1]，乘以 2 后变成 [-2, 2]——而颜色通道必须保持在 [0, 1]。clamp 一刀切掉违规值：低于 0 的部分变成 0，高于 1 的部分变成 1。

**shader 排查技巧**：大多数"画面发白/溢色"问题，本质都是某个值没有被 clamp 或 normalize 约束。当你看到不正常的全白或全黑区域——第一反应检查是否有运算产生了超出 [0,1] 的值。

**clamp 与 smoothstep 的区别**：clamp 对输入值做硬裁剪——超限部分被直接截断；smoothstep 则是做平滑重映射。当你需要"限制范围"用 clamp；当你需要"过渡效果"用 smoothstep。

## 6. 函数组合：distance() + smoothstep() 画圆环
单个塑形函数是字母，组合才是句子。这一节展示 shader 编程的核心技巧：**把函数串联成链**。

### 6.1 从实心圆到圆环
一个圆是 smoothstep(r1, r2, distance_to_center)。一个圆环是"大圆减去小圆"——在 shader 中，"减去"意味着**用两个 smoothstep 的差**：

```
float inner_radius = 0.3;
float outer_radius = 0.5;
float edge_width = 0.05;

float d = length(UV * 2.0 - 1.0);

float inner = 1.0 - smoothstep(inner_radius - edge_width, inner_radius, d);
float outer = 1.0 - smoothstep(outer_radius, outer_radius + edge_width, d);
float ring = outer - inner;
```
**另一种更直观的写法**：

```
float r = smoothstep(inner_r, outer_r, d); 
float ring = 1.0 - r;
```

只用一个 smoothstep 完成从内到外的渐变。本书采用"双 smoothstep 差分法"，是为了训练你理解"函数叠加思维"——用两个独立信号做差来定义一个区间，这个模式在 ch7 的噪声叠加和 ch14 的溶解边缘发光中会反复出现。

思路分解：
- inner：在圆心方向（半径 < 0.3）返回 1，在超出内半径后平滑过渡到 0
- outer：在圆外方向（半径 < 0.5）返回 1，在超出外半径后平滑过渡到 0
- ring = outer - inner：只有既在outer之内又在inner之外的区域才为正值——正是圆环！

### 6.2 用 mix 给圆环上色
有了 ring 这个 0→1 的遮罩信号，就可以用 mix 把圆环"翻译"成颜色：

```
vec3 bg_color = vec3(0.0, 0.0, 0.0);
vec3 ring_color = vec3(0.2, 0.8, 1.0);
vec3 final_color = mix(bg_color, ring_color, ring);
```
ring = 0 的区域 → 黑色背景；ring = 1 的区域 → 青蓝色圆环；ring 在边缘处 = 0.3 → 两种颜色的中间色。

## 7. 实战 1：扩散魔法圆环（5 步渐进构建）
以下是我们将构建的完整效果——一个从中心向外扩散、逐渐变色的发光圆环。我们分 5 步渐进完成，每一步都在上一步的基础上加一个概念。

### 第 1 步：distance 算距离
最底层的地基：计算每个像素到中心的距离。

```
shader_type canvas_item;

void fragment() {
    vec2 uv = UV * 2.0 - 1.0;
    float d = length(uv);

    // 用距离值直接做灰度输出，验证距离场是否正确
    COLOR = vec4(vec3(d), 1.0);
}
```
保存后你会看到：Sprite2D 中心是黑色（d≈0），向四角逐渐变白（d≈1.4）。这就是距离场——它是一切圆环效果的地基。

### 第 2 步：step 做硬环
用 step 在距离场上切出一个硬边圆环。

```
float inner = step(0.3, d);           // d > 0.3 的区域 = 1
float outer = 1.0 - step(0.5, d);     // d < 0.5 的区域 = 1（反转 step 方向）
float ring = inner * outer;           // 两区交集 = 圆环带

COLOR = vec4(vec3(ring), 1.0);
```
inner 在圆心内部为 0（我们不要那个区域），外部为 1。outer 在圆外部之前为 1（我们只要这个范围内的区域），外部为 0。相乘得到交集：只有 0.3 < d < 0.5 的环带区域为 1。

**效果**：屏幕上出现一个白色硬边圆环。边缘像刀切一样锐利。

### 第 3 步：smoothstep 做软环
把 step 替换为 smoothstep，让圆环边缘柔和。

```
float edge = 0.03;

float inner = 1.0 - smoothstep(0.3 - edge, 0.3, d);
float outer = 1.0 - smoothstep(0.5, 0.5 + edge, d);
float ring = outer - inner;

COLOR = vec4(vec3(ring), 1.0);
```
1.0 - smoothstep(...) 反转了方向：圆心方向 = 1，圆外方向 = 0，过渡带 = 平滑渐变。outer - inner 得到了边缘柔和、内圈明亮、外圈渐隐的圆环。

### 第 4 步：mix 着色
用 mix 把灰度环翻译成颜色。同时把参数提升为 uniform，方便后续调节。

```
uniform vec3 ring_color : source_color = vec3(0.2, 0.8, 1.0);
uniform vec3 bg_color : source_color = vec3(0.02, 0.02, 0.05);
uniform float ring_radius = 0.4;
uniform float ring_thickness = 0.06;
uniform float edge_softness : hint_range(0.0, 0.1) = 0.03;

void fragment() {
    vec2 uv = UV * 2.0 - 1.0;
    float d = length(uv);

    float inner_r = ring_radius - ring_thickness;
    float outer_r = ring_radius + ring_thickness;

    float inner = 1.0 - smoothstep(inner_r - edge_softness, inner_r, d);
    float outer = 1.0 - smoothstep(outer_r, outer_r + edge_softness, d);
    float ring = outer - inner;

    vec3 color = mix(bg_color, ring_color, ring);
    COLOR = vec4(color, 1.0);
}
```
在 Inspector 中拖动 ring_color 颜色选择器——圆环颜色实时变化。这就是 uniform 的威力：塑形逻辑不变，参数从外部注入。

### 第 5 步：加上 TIME 动画
最终一步——让圆环动起来。用 sin(TIME) 驱动圆环半径上下脉动：

```
void fragment() {
    vec2 uv = UV * 2.0 - 1.0;
    float d = length(uv);

    // 半径随时间脉动：在 0.3 和 0.5 之间来回振荡
    float pulse = sin(TIME * 2.0) * 0.1 + 0.4;

    float inner_r = pulse - ring_thickness;
    float outer_r = pulse + ring_thickness;

    float inner = 1.0 - smoothstep(inner_r - edge_softness, inner_r, d);
    float outer = 1.0 - smoothstep(outer_r, outer_r + edge_softness, d);
    float ring = outer - inner;

    vec3 color = mix(bg_color, ring_color, ring);
    COLOR = vec4(color, 1.0);
}
```
这里 sin() 的作用不是"震动"，而是提供一个**天然归一化的周期控制器**——sin 的输出始终在 [-1,1] 之间，乘以振幅再偏移后恰好映射到一个安全的半径区间。你不需要写 if 判断边界、不需要手动循环——sin 的周期性让一切自动完成。

**效果**：青蓝色圆环从中心向外扩散，到达最大半径后收缩回去，循环往复。这就是魔法圆环——只用 length + smoothstep + mix + sin(TIME)，零贴图、纯代码。

**完整代码**见 ring.gdshader。它比这里多了一个可调节的 pulse_speed uniform 和一个 inner_glow（内圈发光），作为读者可以自行实验的扩展。

### 5 步回顾

| 步骤 | 新增概念 | 效果 |
| 1 | length(uv) 距离场 | 灰度渐变 |
| 2 | step 硬边界 | 白色硬环 |
| 3 | smoothstep 软过渡 | 柔和光环 |
| 4 | mix 颜色映射 | 彩色光环 |
| 5 | sin(TIME) 动画 | 呼吸扩散 |

每一层都是在前一层基础上"加一块砖"——这是 shader 编程的核心思维模式。你不需要一次性写出完整效果，而是先做最简版本、让它跑起来，再逐步叠加复杂性。

## 8. 实战 2：任意点圆形淡入淡出
魔法圆环是从中心扩散，而圆形淡入淡出解决的是另一个问题：**从屏幕上的任意一点开始，逐渐显示或隐藏画面**。这在游戏开场/转场/技能特效中是极常用的模式。

```
shader_type canvas_item;

uniform float fade_progress : hint_range(0.0, 1.0) = 0.3;  // 已显示的比例（0=全隐，1=全显）
uniform vec2 center = vec2(0.5, 0.5);                       // 淡入中心点（默认屏幕中心）
uniform float softness : hint_range(0.0, 0.5) = 0.1;       // 边缘柔和度

void fragment() {
    float dist = distance(UV, center);                      // 当前像素到中心点的距离
    float mask = 1.0 - smoothstep(fade_progress,            // 用 smoothstep 在 fade_progress 处做过渡
                                   fade_progress + softness, dist);

    vec4 raw = texture(TEXTURE, UV);                        // 采样原始贴图
    COLOR = vec4(raw.rgb, raw.a * mask);                    // 用 mask 控制透明度
}
```

这个 shader 的运作原理：dist 算每个像素到中心的距离。smoothstep(fade_progress, fade_progress+softness, dist) 在距离超过 fade_progress 的地方返回 1（不可见），在距离小于 fade_progress 的地方返回 0（可见），过渡带由 softness 控制。1.0 - smoothstep(...) 翻转方向，使得圆心处 mask=1（完全可见）、圆外 mask=0（不可见）。这个模式在 UI 转场（radial wipe）、技能指示器和视觉特效中极常用——通常由 GDScript 的 tween 驱动 fade_progress 从 0 到 1，视觉上就是从一点扩散到全屏的圆形的淡入。

**完整代码**见 circular_fade.gdshader

## 本章小结：塑形函数的"思维地图"
**本章的核心公式链**（会在全书反复出现）：

```
distance(pixel, target)  →  smoothstep(a, b, dist)  →  mix(color_a, color_b, t)
     距离场                    控制信号                     视觉输出
```

这三个环节是 shader 编程最基础的"三段论"：先算距离，再生成控制信号，最后映射为颜色。记住它——ch8（SDF）、ch10（热浪混合）、ch14（溶解边缘发光）、ch20（卡通色阶）都在复现这个模式。

四种函数按使用场景分类：

| 场景 | 函数 | 为什么用它 |
| 需要是/否判断 | step(edge, x) | 最简洁的二值开关，零开销 |
| 需要平滑过渡 | smoothstep(a, b, x) | Hermite 的 S 曲线自然柔和，无人工痕迹 |
| 需要在两色/两纹理间渐变 | mix(a, b, t) | 单指令完成多分量插值，表达意图清晰 |
| 需要防溢出 | clamp(x, lo, hi) | 安全网，保证值不失控 |

组合模式：

```
distance(pixel, target)  →  0 到 max 的连续值
         ↓
smoothstep(a, b, dist)   →  0→1 的控制信号
         ↓
mix(color_a, color_b, t)  →  具体颜色
```
这个三连环是全书出现频率最高的 shader 编码模式。记下它——你会在 ch8 的 SDF 画图形、ch10 的热浪混合、ch14 的溶解边缘发光、ch20 的卡通色阶中反复看到它的身影。
