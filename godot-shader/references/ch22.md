# 第 22 章：3D 描边

### 第 22 章：3D 描边 —— 从倒壳法到屏幕空间边缘检测
**学习目标**：掌握 Godot 4 中 3D 描边的三条主要技术路线——倒壳法（Inverted Hull）、Stencil 模板缓冲、屏幕空间边缘检测——理解各自的原理、代价与适用场景，能为自己的游戏选择并落地合适的描边方案。

**场景搭建**：创建 Node3D 根节点，添加 DirectionalLight3D 与 WorldEnvironment；放入若干测试模型——SphereMesh（圆润表面）、BoxMesh（硬边）、CapsuleMesh（充当主角）。倒壳法部分给模型挂 ShaderMaterial 并通过 Next Pass 叠加描边材质；屏幕空间部分额外添加一个 2×2 的全屏 QuadMesh。所有 shader 均为 spatial 类型；Stencil 部分不写 shader，在 StandardMaterial3D 面板中操作。

**内容要点**：

- 3D 描边的两类边缘——轮廓边随相机移动、折痕边与相机无关，第 15 章的 alpha 检测在 3D 全面失效
- 倒壳法：render_mode cull_front + VERTEX += NORMAL * outline_width，八行代码实现 3D 描边
- 三种挂载方式：next_pass、复制 MeshInstance3D、material_overlay + GDScript 动态开关
- 屏幕等宽修正：用 MODELVIEW_MATRIX 取视空间距离，补偿透视造成的"远细近粗"
- Stencil 模板缓冲：原理 + Godot 4.4 材质面板 stencil_mode 实战（实验特性，仅 Forward+/Mobile）
- 屏幕空间描边：hint_depth_texture 线性化 → Roberts Cross 边缘检测 → hint_normal_roughness_texture 折痕检测，做出全场景漫画线稿
- 七种方案的对比表与按游戏类型的选型指南

## 0. 为什么 3D 描边比 2D 难？
第 15 章里，2D 描边被归结为一句话：**当前像素透明、邻居像素不透明，这里就是边缘**。Sprite 的 alpha 通道天然标注了"哪里是图、哪里是空"，边缘检测只是顺着这个标注找突变。

3D 世界里没有这个标注。一个 3D 模型渲染到屏幕上是不透明的实心色块——立方体边缘的像素和它旁边的像素一样不透明，alpha 检测无从下手。**3D 的"边缘"不存在于纹理里，而存在于几何和视角的关系里。**

具体来说，3D 描边要处理的是两类完全不同的边缘：

- **轮廓边**：物体在屏幕上投影的边界。球体的轮廓是一个圆，但这个圆对应的表面位置会随着相机移动而滑动——轮廓边是"看"出来的。
- **折痕边**：表面上两个面的法线方向发生突变的位置，比如立方体的十二条棱。它长在几何体上，与相机无关。
一个完整的 3D 描边方案，本质上就是回答一个问题：**你打算用哪种数据把这两类边缘找出来？** 围绕这个问题，社区发展出了七种主流方案，但它们并非七条平行路——真正的区别只有一个：**是在几何体上找，还是在屏幕上找。**

在几何体上找，核心就是倒壳法——把模型膨胀一圈，露出壳的边界。在此之上，遮盖壳内部的策略可以升级：初代方案用深度测试（壳内壁比本体远，自动被挡住），升级方案用 Stencil 模板缓冲做像素标签（"这个像素刚才画过没"），遮盖更精确。编辑器 Create Outline Mesh 只是把位移烤进网格，省掉 shader。变异虽多，根都是同一个膨出来的壳。

在屏幕上找，是不碰模型、渲染完再在画面上搜突变——用深度抓轮廓边，加法线抓折痕边，最终汇入全屏后处理的管线。

本章按这条认知主线组织：先做出几何路线的核心（第 1 节）→ 把遮盖策略从深度测试升级到模板掩码（第 2 节）→ 切换到完全不同的屏幕空间路线，实现不依赖模型的漫画线稿（第 3 节）。第 4 节速览剩余方案，第 5 节给出完整的对比表和选型指南。

## 1. 倒壳法（Inverted Hull）—— 最快上手的 3D 描边

### 1.1 原理：把模型"吹"大一圈，只画它的内表面
倒壳法解决了一个问题：如何不改任何渲染管线，仅凭材质和顶点操作就让模型周围出现一圈轮廓。

它由三个零件组成，每个都是你已经认识的：

**零件一：面剔除。** 每个三角形都有正反面（由顶点环绕方向决定）。Godot 默认 render_mode cull_back——背面不画，因为实心模型的背面永远被正面挡住，画了也是浪费。cull_front 则反其道而行：**只画背面**。

**零件二：顶点沿法线膨胀。** 第 18 章的冲击波案例用过这个操作——VERTEX += NORMAL * width，每个顶点沿自己的法线方向向外挪一点，模型整体"吹"大一圈。

**零件三：纯色无光照。** unshaded 跳过光照计算，ALBEDO 直接给纯色。

三个零件拼起来：一个**比本体大一圈、只画内表面、纯黑色**的"壳"套在模型外面。从相机看过去，壳的中心区域被本体挡住（深度测试），只有壳超出本体轮廓的那一圈边缘露出来——这就是描边。

**为什么要 cull_front 而不是直接画一个放大的模型？** 如果壳画正面，它会像一个更大的实心模型一样把本体整个盖住。剔除正面后，我们看到的其实是壳的"内壁"——而内壁在深度上位于本体后方，只有在壳比本体多出来的那一圈区域里才不被遮挡。露出来的内壁，就是轮廓线。

### 1.2 第一个倒壳 shader
先写最简版本，验证原理。新建 ShaderMaterial，输入：

```
shader_type spatial;

render_mode cull_front, unshaded;

void vertex() {
    VERTEX += NORMAL * 0.02;
}

void fragment() {
    ALBEDO = vec3(0.0);
}
```
八行代码，对应上一节的三个零件：cull_front 只画背面、VERTEX += NORMAL * 0.02 膨胀 0.02 米、unshaded + 纯黑输出。NORMAL 在 vertex() 中是模型空间法线，与第 18 章做顶点位移时用的是同一个变量。

把材质挂到 SphereMesh 上——球变成了一个**纯黑的剪影**。这不是我们要的描边：壳确实画出来了，但它现在是模型唯一的材质，把**本体替换掉了**。倒壳的正确用法是让壳和本体**叠加渲染**，这就是下一节的挂载问题。

先把 shader 完善一下，把宽度和颜色提取成可调参数：

```
shader_type spatial;

render_mode cull_front, unshaded;

uniform vec4 outline_color : source_color = vec4(0.0, 0.0, 0.0, 1.0);
uniform float outline_width : hint_range(0.0, 0.1) = 0.02;

void vertex() {
    VERTEX += NORMAL * outline_width;
}

void fragment() {
    ALBEDO = outline_color.rgb;
}
```
source_color 提示让检查器弹出取色器，hint_range 把宽度限制在合理滑杆范围内。现在在检查器里就能实时调整描边的粗细和颜色了。

### 1.3 挂载方式 A：Next Pass —— 一个节点画两遍
next_pass 解决了一个问题：如何让同一个模型先后用两个材质各画一遍。

它是 **Material 资源自带的属性**，含义直白："画完我之后，用下一个材质把同一个 mesh 再画一遍"。操作步骤：

- 选中 MeshInstance3D，在 Inspector 中找到 Surface Material Override，新建一个 StandardMaterial3D 作为本体材质（给个浅色，方便观察黑色轮廓）。
- 点击这个材质进入编辑界面，找到最下方的 Next Pass 属性，新建一个 ShaderMaterial。
- 给这个 ShaderMaterial 指定上一节的倒壳 shader。
运行——球体外面出现了一圈干净的黑色轮廓。本体和描边在同一个节点上，移动、旋转、缩放都天然同步。

**为什么壳在本体之后画，却不会盖住本体？** 两个材质画的都是不透明几何，深度缓冲说了算：壳的内壁比本体表面离相机更远，深度测试失败，只有溢出本体轮廓的那一圈通过测试。所以渲染顺序在这里不重要，深度测试保证了正确结果。

### 1.4 挂载方式 B：复制 MeshInstance3D —— 商业游戏的做法
next_pass 很方便，但它把描边**焊死**在材质里：所有用这个本体材质的对象都会带描边，想单独开关某一个对象的描边就得动材质。商业项目更常用第二种方式——直接复制一个节点：

```
Player
├── MeshInstance3D        ← 本体材质
└── OutlineMesh           ← 同一个 Mesh 资源 + 倒壳材质
    （MeshInstance3D）
```
关键操作：在 OutlineMesh 的 Mesh 属性上，把本体节点的 **Mesh 资源**直接拖进去（或复制粘贴资源引用）——两个节点共享同一份网格数据，不要重新建模。对骨骼动画角色同样适用：复制的 MeshInstance3D 挂在同一个 Skeleton3D 下，两套网格跟随同一套骨骼，描边不会和动画脱节。

#### 编辑器捷径：Create Outline Mesh
Godot 编辑器还提供了一个更偷懒的办法。选中 MeshInstance3D，点击 3D 视口顶部的 **Mesh** 菜单 → **Create Outline Mesh…**，输入膨胀宽度（margin），点确定。编辑器会生成一个**新的 Mesh 资源**并自动创建子节点挂好，你只需要手动给这个子节点挂一个纯色材质。

这个功能本质上就是给手动复制做了自动化。但它生成的不是原 Mesh 的引用，而是一个**预处理过的新网格**——和手动方案有两个关键差异：

- **顶点位移烤进了网格数据**。手动方案是 vertex() 里每帧算出 VERTEX += NORMAL * width；编辑器生成的 Outline Mesh 顶点已经沿法线膨胀完毕、直接就是"大一圈"的样子，顶点着色器里不需要再做位移运算。
- **三角形缠绕顺序被翻转了**。官方文档写明这条方法 *"returns the vertices in reverse order (e.g. clockwise to counterclockwise)"*。这意味着生成的网格各面是朝里的，配合默认 cull_back（或 cull_disabled + unshaded）就能显示倒壳，**不需要在材质里写 cull_front**。直接用最简单的碎片着色器输出 ALBEDO = vec3(0.0) 就行，连 render_mode 都可以省掉。
使用时注意两个限制：

- **宽度是静态的**：margin 烤死在网格数据里，运行时没法用 uniform 调粗细，也没法像 1.5 节那样做 screen_constant_width 透视补偿——远距离的描边会变细。
- **硬边裂缝依然存在**：这个功能使用原模型的顶点法线做膨胀方向，和手动方案一样，遇到 BoxMesh、CylinderMesh 等硬边模型棱边处仍然裂开（GitHub issue [#55385](https://github.com/godotengine/godot/issues/55385)）。开发者的 workaround 正是退回到本节的"手动复制 + 等比缩放"而不是用这个功能。
两种复制方案怎么选：**编辑器捷径**最快，适合做一次性原型或宽度固定的静态道具；**手动复制 + 倒壳 shader** 保留了调参数和屏幕等宽补偿的能力，适合运行时换粗细/颜色的角色。两者的硬边缺陷相同，都是平滑法线模型的最佳拍档。

### 1.5 挂载方式 C：material_overlay + GDScript —— 选中才显示的高亮
RTS 点选单位、RPG 锁定目标，需要的是"平时没有、选中才有"的描边。next_pass 和复制节点都做不到按对象动态开关（前者改材质影响全局，后者切 visible 要多维护一个节点）。

material_overlay 解决了一个问题：它是 GeometryInstance3D 的属性，效果是"在本体材质画完之后，整体再叠画一层材质"——正好用来叠倒壳，而且随时可以从 GDScript 设置或清空，完全不用碰模型原来的材质。

配套代码见 ch22-shaders/outline_highlight.gd，核心逻辑只有两行：

```
func set_highlighted(enabled: bool) -> void:
    highlighted = enabled
    material_overlay = outline_material if highlighted else null
```
把脚本挂到 MeshInstance3D 上，把倒壳 shader 做成的 ShaderMaterial 拖到脚本的 Outline Material 槽里。运行后按空格，描边随按随显。

三种方式怎么选：

|  | next_pass | 复制 MeshInstance3D | material_overlay |
| 开关粒度 | 按材质（影响所有使用者） | 按节点（切 visible） | 按对象（代码随时切） |
| 节点数量 | 1 | 2 | 1 |
| 与本体材质耦合 | 是 | 否 | 否 |
| 典型场景 | 角色/道具的标配描边 | 需要独立控制描边节点 | RTS 选中、交互高亮 |

### 1.6 屏幕等宽：让远处的描边和近处一样粗
到这里描边已经能用，但有一个明显的瑕疵：把相机拉远，描边会变得越来越细，最后几乎消失。

原因在透视投影：outline_width = 0.02 是**模型空间**的固定宽度，0.02 米在近处占 20 个像素，在 50 米外可能只占半个像素。屏幕上的线宽和距离成反比。

修正思路：既然屏幕宽度 ≈ 模型宽度 ÷ 距离，那就让模型宽度随距离同步放大——宽度乘以"顶点到相机的距离"，屏幕线宽就近似恒定了。取距离要用到第 3 章的坐标空间知识：视空间中相机位于原点、看向 -Z 方向，所以顶点在视空间中的 -z 分量就是它到相机的距离。用 MODELVIEW_MATRIX 把顶点从模型空间变换到视空间：

```
uniform bool screen_constant_width = true;

void vertex() {
    float width = outline_width;
    if (screen_constant_width) {
        float dist = -(MODELVIEW_MATRIX * vec4(VERTEX, 1.0)).z;
        width *= max(dist, 0.05);
    }
    VERTEX += NORMAL * width;
}
```
max(dist, 0.05) 防止相机贴脸时距离趋近于零、描边缩没。开启 screen_constant_width 后，outline_width 的含义从"固定米数"变成"随距离的比例系数"——0.02 大约对应屏幕上恒定的一线宽度。近处的球和远处的球，描边在屏幕上一样粗。完整代码参考 outline_hull.gdshader

**注意**：宽度计算发生在模型空间，如果节点带了非均匀缩放（比如 scale 设为 (2, 1, 1)），膨胀量也会被缩放扭曲。对绝大多数等比缩放的角色模型没有影响；遇到硬表面缩放道具时，把宽度补偿关掉、手动调 outline_width 更稳妥。

### 1.7 倒壳法的问题：什么时候别用它
把 BoxMesh（立方体）挂上倒壳材质，宽度调大——棱边处会出现一道道**裂缝**，壳像一件被撑破的衣服。

裂缝的根源是**硬边处的法线分裂**。GPU 中每个顶点只携带一条法线；球面上一个顶点的法线是周围面的平均，方向唯一，膨胀时所有相邻三角形把顶点往同一个方向推，壳保持密闭。但立方体的一个角顶点同时属于三个互相垂直的面——为了让棱边光照锐利，建模时这个顶点会被拆成**三个位置相同、法线各不相同的顶点**。膨胀时三个顶点各沿各的法线走，原本重合的位置被撕开，壳在棱边处裂开。

**这就是倒壳法的根本约束：它要求模型的法线是平滑的。** 球体、胶囊、圆润的角色模型没有问题；硬表面建筑、机械件、带锐利棱边的低模道具都会裂缝。（工程上的解法是烘焙一份"平均法线"存进 UV2 或顶点色，膨胀时读平均法线而不是面法线——这属于进阶话题，了解原理即可。）

第二个约束是**复杂模型的穿插**：角色张开的手指之间、腋下、裙摆褶皱，这些部位的表面间距可能小于描边宽度，膨胀后的壳会把相邻部位的本体也盖住，描边糊成一团。

第三个约束是**纯几何判定**：倒壳只认自己的壳，不知道屏幕上还有什么。两个模型重叠摆放时，交界线处没有描边——因为那里不是任何一个模型的轮廓溢出区。

记住这三个约束，后面的方案就是在逐个拆除它们。

## 2. Stencil 模板缓冲

### 2.1 原理：给像素贴上"已占用"标签
Stencil（模板缓冲）解决了一个问题：如何在**屏幕像素级别**精确区分"这个像素属于目标物体"和"这个像素不属于"。

除了颜色缓冲和深度缓冲，GPU 还有第三块缓冲：**模板缓冲**。它为屏幕上每个像素存一个整数标记，渲染时可以按标记决定"画"或"不画"。用模板做描边是一场两步的配合：

```
第一步：画本体。
        每个通过深度测试的像素，在模板缓冲里写入标记 1。

第二步：画放大的壳。
        只为"模板 != 1"的像素着色——
        本体盖住的区域被跳过，壳只在轮廓外圈显形。
```
因为遮盖判定发生在像素级别，轮廓边界比深度测试更精确——不会出现"壳离本体太近、深度差太小、描边消失"的问题。骨骼动画、Morph 形变天然支持（只要有本体像素覆盖的地方，模板标记就在那里）。

但有一个核心事实需要讲清楚：**模板缓冲只负责遮盖，不负责膨胀**。第二步"画放大的壳"，用的还是第 1 节那套几何操作——倒壳法。Godot 的 stencil_mode = Outline 预设内部做的事情，拆开来看就是：

```
stencil 描边 = 倒壳法（cull_front + grow 沿法线膨胀 + unshaded 纯色）
            +
         模板掩码（只在"第一步没画过"的像素上显形）
```
BaseMaterial3D 的 grow 属性定义为 *"expands object vertices along their normal directions"*，和倒壳 shader 的 VERTEX += NORMAL * width 在几何层面**完全等价**。官方文档用 grow 做描边的标准配方也一字不差：*"second material pass, making it black and unshaded, reversing culling, and then applying some grow"*——这就是 1.1 节拆过的三个零件。

这意味着 stencil 没有创造新的几何方案，它只是把倒壳法的遮盖策略从**"比深度"**升级成了**"查标签"**。两者的边界对比：

******
|  | 倒壳法（纯几何） | Stencil 预设（几何 + 标签） |
| 膨胀方式 | VERTEX += NORMAL * width | grow（引擎内置，等价） |
| 遮盖策略 | 深度测试——壳内壁比本体远，自动被挡住 | Stencil 掩码——像素级"禁止画在标记过的区域" |
| 硬边裂缝 | 有（顶点法线分裂，壳撕开） | 一样有（grow 文档明确写 "cannot create new vertices, leading to visible gaps in sharp corners"） |
| 叠件穿插 | 有（间距小于宽度时壳互相吞没） | 有（同上） |
| 优势 | 零额外开销、全渲染器 | 边界 pixel-perfect、不受深度精度影响、动画/Morph 天然对齐 |

换一个角度更好记：倒壳法管"长出来"（几何），stencil 管"别画过界"（像素标签）。后者让遮盖更干净，但膨出来的壳长什么样——有没有裂缝、厚度均不均匀——不归它管。

### 2.2 Godot 4 实战：材质面板里的 stencil_mode
早期的 Godot 完全不暴露模板缓冲，**Godot 4.4 后的新版本改变了这一点**：BaseMaterial3D 新增了一组 Stencil 属性，直接在材质面板里就能配置模板描边。操作步骤：

- 选中 MeshInstance3D，给 Surface Material Override 新建一个 StandardMaterial3D。
- 进入材质编辑，展开下方的 **Stencil** 区块。
- Stencil Mode 选择 **Outline**。
- 调整 Outline Thickness（默认 0.01）和 Stencil Color（默认黑色）。
描边立刻出现——零行 shader 代码。同一个下拉框里还有一个 **XRay** 预设：它让物体的剪影穿透遮挡物显示（隔墙看到敌人的轮廓），FPS 和潜行游戏的标配效果。

使用时要注意四点：

- **实验特性**：官方文档明确标注 stencil 属性组为 Experimental，未来渲染管线调整可能影响它。
- **渲染器限制**：仅 Forward+ 和 Mobile 渲染器生效，Compatibility 渲染器下无效。
- **预设会接管 next_pass**：Outline/XRay 预设内部是通过自动管理材质的 next_pass 实现的（壳层使用 grow 膨胀）。如果你手动改过该材质的 next_pass，修改 stencil 属性或重载场景后手动改动会丢失；想自己再叠一层材质，请改用 GeometryInstance3D 的 material_overlay。
- **自定义模式**：Stencil Mode = Custom 时可以通过 Stencil Flags、Stencil Compare、Stencil Reference 手动配置模板读写规则，做更复杂的遮罩效果。
需要讲清楚一个边界：Godot 是把模板缓冲做成了**引擎内建功能**，而不是把它暴露给 .gdshader——你没法在自己的 shader 代码里读写 stencil 标记。所以 stencil 在本书的定位是"编辑器方案"：理解原理、会用预设、知道限制，就够了。想完全掌控描边的每一行代码，回到第 1 节的倒壳法；想要像素级的精确又想全场景生效，继续往下看屏幕空间方案。

## 3. 屏幕空间描边 —— 全场景漫画线稿

### 3.1 原理：不碰模型，在渲染完的画面上"找茬"
倒壳法和 stencil 都是"按对象"的描边——每个要描边的模型都得配置一遍。如果你要做的是《塞尔达传说》式的**全场景卡通勾线**：地形、建筑、树木、角色、道具，画面上所有东西都带轮廓线——按对象配置就是一场灾难。

屏幕空间描边解决了一个问题：如何把描边从模型身上彻底解耦——**不改任何模型，渲染完成后，在整张画面上找边缘**。

思路与第 15 章的 2D 描边一脉相承，只是"找边缘"用的数据换了：2D 用 alpha 通道，3D 屏幕空间用两张引擎渲染时顺手生成的纹理：

- **深度纹理**：每个像素离相机有多远。物体与背景的交界处，深度必然突变——这抓的是**轮廓边**。
- **法线纹理**：每个像素的表面朝向。立方体的棱上，两个面的朝向突变——这抓的是**折痕边**。
整个流程：

```
场景渲染
   ↓
深度纹理 ──────┐
              ├─→ 边缘检测（Roberts Cross）─→ 边缘遮罩
法线纹理 ──────┘                                ↓
原画面 ────────────────→ 混合：边缘处染上描边色 ─→ 输出
```

### 3.2 全屏四边形：把后处理 shader 铺到屏幕上
后处理的代码需要一个几何载体来承载：它必须是某种能被 GPU 光栅化的网格，但不能是场景中任何模型——因为我们不要它在 3D 世界里占位，只要它平铺在屏幕上、让每像素运行一次片段着色器。

Godot 的标准答案是 **QuadMesh**（四边形网格）。选它不是因为随便，而是因为它是数学意义上的最小全屏载体——只有两个三角形、四个顶点。POSITION 把顶点直接写入裁剪空间后，形状本身不再重要，但 QuadMesh 的 XY 范围 [-1, 1] 天然对齐裁剪空间，2×2 的尺寸恰好铺满。

**作为开关**：既然是 MeshInstance3D 节点，visible 属性就是最简单的 toggle。把节点的 visible 设为 false，后处理立刻关闭；切回 true 即刻恢复。不需要动 shader、不需要重建材质。如果有多个后处理效果串联，每个挂在自己的 QuadMesh 上，独立开关互不干扰。

搭建步骤：

- 在 3D 场景根节点下新建 MeshInstance3D，命名为 PostQuad。
- Mesh → 新建 QuadMesh，Size 设为 (2, 2)。
- GeometryInstance3D 区块：Cast Shadow 设为 **Off**——全屏四边形占据了整个屏幕，如果不关阴影投射，整个场景会被它投下的巨大影子覆盖。
- Extra Cull Margin 设为 **16384**——这个值防止相机移动或旋转时节点被视锥剔除（frustum culling）。视锥剔除的计算基于节点的世界空间包围盒，发生在**顶点着色器之前**，还没轮到 POSITION 旁路变换管线。如果包围盒离开了相机视野，GPU 连 vertex shader 都不会跑。
- Surface Material Override → 新建 ShaderMaterial，指定本节的 shader。
shader 骨架：

```
shader_type spatial;

render_mode unshaded, fog_disabled, cull_disabled;

void vertex() {
    POSITION = vec4(VERTEX.xy, 1.0, 1.0);
}
```
骨架中三个 render_mode 和一个 POSITION，各解决一个独立的问题：

- 
**POSITION = vec4(VERTEX.xy, 1.0, 1.0)**：把顶点**直接写入裁剪空间**（clip space），旁路模型→世界→视空间→投影的整条变换管线。裁剪空间的可见范围是 X 和 Y 均在 [-1, 1]，所以 2×2 的 QuadMesh 恰好铺满屏幕——不需要把四边形摆到相机前面，它与 3D 世界无关。

- 
**unshaded**：关闭 PBR 光照计算。这个 shader 不需要被环境光照亮——它的颜色来自 screen_texture 采样 + 边缘计算结果。开着光照不仅浪费，光的颜色还会污染 ALBEDO。

- 
**fog_disabled**：关闭雾效。如果场景开了雾，雾会在片段着色器结束后按距离在后处理结果上叠一层灰白——全屏四边形在最远距离，整张画面会变成雾色。

- 
**cull_disabled**：关闭背面剔除。这是一个容易被踩的坑：POSITION 把顶点从模型空间钉到了裁剪空间，但 GPU 的**背面剔除发生在片段着色器之前、POSITION 写入之后**——它用裁剪空间里三角形的方向来判定正反面。QuadMesh 只有两个三角形，如果判定为背面，整片都被丢掉，片段着色器一行都不跑。加 cull_disabled 强制两个三角形都参与光栅化。

**视锥剔除 vs 背面剔除，别搞混。** 视锥剔除是 CPU 侧判断包围盒是否在相机视野内，由 extra_cull_margin 兜底；背面剔除是 GPU 侧用三角形缠绕方向丢面，由 cull_disabled 兜底。两个缺一不可。

### 3.3 读懂深度纹理：先线性化，再谈比较
引擎的深度缓冲可以通过一个带提示的 uniform 直接读到：

```
uniform sampler2D depth_texture : hint_depth_texture, repeat_disable, filter_nearest;
```
hint_depth_texture 解决了一个问题：声明后，Godot 会把当前帧的深度缓冲绑定到这个采样器上（原理同第 21 章）。

但读到的原始值**不是距离**。深度缓冲采用非线性分布：靠近相机的区域占据绝大部分精度，远处挤在极小的一段数值区间里——这是为了在视觉上更重要的近处获得更高的深度分辨力。直接比较两个原始深度值，会出现"近处过度敏感、远处完全失灵"的畸形检测。所以第一步永远是**线性化**：把原始深度还原成视空间中的真实距离。

还原过程是投影变换的逆运算：用屏幕 UV 和深度值重建 NDC 坐标，再乘 INV_PROJECTION_MATRIX（逆投影矩阵）回到视图空间：

```
float get_linear_depth(vec2 screen_uv, mat4 inv_proj) {
    float depth = texture(depth_texture, screen_uv).r;
    vec3 ndc = vec3(screen_uv * 2.0 - 1.0, depth);
    vec4 view_pos = inv_proj * vec4(ndc, 1.0);
    view_pos.xyz /= view_pos.w;
    return -view_pos.z;
}
```
这里的代码和第21章的逻辑是一致的，注意三个细节：

- **NDC 重建的渲染器差异**：Forward+/Mobile 的深度 z 范围是 [0, 1]，只需把 UV 映射到 [-1, 1]。
- **view.xyz /= view.w**：逆投影出来的是齐次坐标，必须除以 w 分量才是真正的视空间坐标。
- **取负**：视空间中相机看向 -Z，所以 -view.z 才是正的距离值（单位：米）。
写代码之前先验证数据对不对。把 fragment 写成可视化：

```
void fragment() {
    float d = get_linear_depth(SCREEN_UV,INV_PROJECTION_MATRIX);
    ALBEDO = vec3(fract(d * 0.1));
}
```
fract() 把距离折回 [0, 1)，画面上会出现一圈圈以相机为中心的等距色带——色带贴着物体表面弯曲，说明线性化成功了。

### 3.4 Roberts Cross：用四个像素找边缘
有了逐像素的距离图，"找边缘"就变成了熟悉的邻居比较。第 15 章用的是 3×3 的 Sobel 算子（9 次采样）；深度图只需要轻量得多的 **Roberts Cross** 算子——沿两条对角线各取一对像素，比较对角线两端的差：

```
    A ······· B
    ·         ·
    ·    P    ·        边缘强度 =
    ·         ·        max(|d(A) − d(D)|, |d(B) − d(C)|)
    C ······· D
```
为什么对角线差分有效：无论边缘是横的、竖的还是斜的，它总会切开两条对角线中的至少一条，造成对角线两端的深度差。max 取两条对角线中的较强响应，保证任何方向的边缘都被抓到。采样偏移量 px 控制描边粗细——偏移几个像素，线就粗几个像素。

第一版检测代码：

```
void fragment() {
    vec2 px = outline_thickness / vec2(textureSize(screen_texture, 0));

    float d00 = get_linear_depth(SCREEN_UV + vec2(-px.x, -px.y),INV_PROJECTION_MATRIX);
    float d11 = get_linear_depth(SCREEN_UV + vec2( px.x,  px.y),INV_PROJECTION_MATRIX);
    float d10 = get_linear_depth(SCREEN_UV + vec2( px.x, -px.y),INV_PROJECTION_MATRIX);
    float d01 = get_linear_depth(SCREEN_UV + vec2(-px.x,  px.y),INV_PROJECTION_MATRIX);

    float edge = max(abs(d00 - d11), abs(d10 - d01));
    float outline = step(depth_threshold, edge);

    vec4 scene = texture(screen_texture, SCREEN_UV);
    ALBEDO = mix(scene.rgb, outline_color.rgb, outline);
}
```
hint_screen_texture 提供渲染完成的原画面，mix() 在边缘处替换成描边色。近处的物体描边干净利落——但把视线移向远处，问题暴露了：**远景被整片涂成了描边色**。

原因：线性化之后，深度差和距离成正比。同样是"前景物体贴着背景"的遮挡关系，在 2 米外产生的深度差可能是 0.1 米，在 50 米外就是 5 米——固定阈值对远处来说约等于零，于是远处所有像素都被误判为边缘。

修正方法：让阈值随距离同步放大，把"绝对深度差"变成"相对深度差"：

```
    float center_depth = get_linear_depth(SCREEN_UV);
    float threshold = depth_threshold * max(center_depth, 0.05);
    float outline = smoothstep(threshold * 0.5, threshold, edge);
```
顺带把 step 换成了 smoothstep：边缘强度在阈值半宽内平滑过渡，描边线有了抗锯齿般的柔和感，不再是一刀切的两值突变。至此，outline_post.gdshader 完成——一个全场景生效的深度描边后处理。场景里任何不透明物体，无论地形还是建筑，自动获得轮廓线。

[IMAGE: 屏幕空间描边效果](../ch22-diagrams/outline_post.webp)

### 3.5 加法线：检测深度"看不见"的折痕
深度描边有一个结构性盲区：**深度连续的地方，它一律认为没有边缘**。两个典型反例：

- 桌面上平放一张纸——纸和桌面的交界处深度几乎连续，纸的边缘描不出来。
- 立方体的棱——棱两侧的面在棱上深度无缝衔接，但表面朝向突变 90°。立方体只会被描出外轮廓，十二条棱一条都没有。
折痕的信息不在深度里，在**法线**里。Godot 在深度预渲染阶段会把每个像素的视空间法线和粗糙度存进一张缓冲，通过提示符读取：

```
uniform sampler2D normal_roughness_texture : hint_normal_roughness_texture, repeat_disable, filter_nearest;
```
法线存在纹理的 xyz 通道、编码到 [0, 1] 区间（粗糙度在 w 通道），解码方式和第 9 章的法线贴图完全相同——乘 2 减 1：

```
vec3 get_normal(vec2 uv) {
    return texture(normal_roughness_texture, uv).xyz * 2.0 - 1.0;
}
```
法线边缘的度量用点积：两个法线方向一致时 dot 为 1，垂直时为 0，相反时为 -1。1.0 - dot(n1, n2) 就是"朝向差"，同样套 Roberts Cross 的对角结构：

```
    vec3 n00 = get_normal(SCREEN_UV + vec2(-px.x, -px.y));
    vec3 n11 = get_normal(SCREEN_UV + vec2( px.x,  px.y));
    vec3 n10 = get_normal(SCREEN_UV + vec2( px.x, -px.y));
    vec3 n01 = get_normal(SCREEN_UV + vec2(-px.x,  px.y));

    float normal_edge = max(1.0 - dot(n00, n11), 1.0 - dot(n10, n01));
    float normal_outline = smoothstep(normal_threshold * 0.5, normal_threshold, normal_edge);
    normal_outline *= normal_edge_strength;
```
最后把两类边缘合成一张遮罩：

```
    float outline = clamp(depth_outline + normal_outline, 0.0, 1.0);
    vec4 scene = texture(screen_texture, SCREEN_UV);
    ALBEDO = mix(scene.rgb, outline_color.rgb, outline);
```
深度抓轮廓、法线抓折痕——立方体的十二条棱全部显现，整张画面变成了漫画线稿。完整代码见 outline_post_normal.gdshader。

[IMAGE: 屏幕空间描边效果](../ch22-diagrams/outline_post_normal.webp)

### 3.6 屏幕空间方案的局限

- **成本按像素计**：每个像素 6~10 次纹理采样加若干矩阵运算，全屏执行。中端开销。
- **半透明物体缺席**：透明材质不写深度缓冲，玻璃、水面上的物体描不到边。
- **一视同仁**：全场景所有东西都描边。想"只给选中的敌人描边"需要分层渲染——把目标渲到独立 SubViewport 再做后处理合成，或者干脆回到按对象的倒壳法。

## 4. 七种方案对比与选型
还有两种方案没有展开。它们不是不重要，而是与前文同源——理解了一处，另一处就是顺水推舟。

**Silhouette 轮廓渲染 Pass**：把倒壳法的思路推到极简——不膨胀、不剔除，而是分两个 Pass：第一遍只画背面（cull_front）输出剪影色，第二遍正常画正面。配合模板或偏移量让背面比正面"大"出一线，就能得到电影级的干净剪影。它本质上是倒壳家族的一员，代价是多一次完整渲染。

**全屏后处理描边**：第 3 节做的是"检测 + 叠加"的最小闭环，它的完全体还包括——对边缘遮罩做高斯模糊得到发光描边、按 SubViewport 分层做选择性高亮、用边缘遮罩驱动颜色脉冲做交互反馈。它是七种方案里最灵活、也最贵的，属于后处理管线的综合应用。

所有常见的七种方案对比表如下：

| 方法 | 效果 | 性能 | 实现难度 | Godot 4 支持现状 | 适合场景 |
| ① 复制 Mesh 膨胀 | ★★★ | ★★★★★ | ★ | ✅ 全渲染器 | RTS 单位选择、RPG 角色高亮 |
| ② 顶点 Shader 膨胀（倒壳） | ★★★ | ★★★★★ | ★ | ✅ 全渲染器 | 圆润角色的标配描边 |
| ③ Stencil 模板缓冲 | ★★★★★ | ★★★★ | ★（编辑器操作） | ⚠️ 实验特性，仅 Forward+/Mobile | 不写代码的精确角色描边 |
| ④ 屏幕空间深度描边 | ★★★★ | ★★★ | ★★★ | ✅ 全渲染器 | 通用全场景描边 |
| ⑤ 屏幕空间法线描边 | ★★★★ | ★★★ | ★★★ | ⚠️ 仅 Forward+ | 卡通渲染、漫画线稿 |
| ⑥ Silhouette Pass | ★★★★★ | ★★★ | ★★★★ | ✅ 可用（需多 Pass） | 高质量剪影、影视级 |
| ⑦ 全屏后处理描边 | ★★★★ | ★★ | ★★★ | ✅ 可用 | 全局风格化、发光描边 |

按需求对号入座：

- **给角色/道具加描边** → 方案 ②（倒壳 + next_pass）。简单、教学价值高、性能最好，是本章推荐的第一选择。
- **商业项目的角色高亮** → 方案 ①（复制 Mesh）。可独立开关、不占材质耦合，商业游戏最常用。
- **不想写代码的精确描边** → 方案 ③（stencil_mode 预设）。像素级精确，代价是实验特性和渲染器限制。
- **全场景卡通勾线** → 方案 ④ + ⑤（深度 + 法线屏幕空间）。一次配置、全场生效，《塞尔达》式 NPR 的标配。
- **要发光、要选中反馈、要风格化** → 方案 ⑦。

## 本章小结
3D 描边比 2D（ch15）难，本质原因只有一条：**3D 物体有真正的"背面"——你在前面描线，背面挡着前看不到，需要靠几何手段让它露出来**。本章的所有方案，都是在回答"怎么让这条线被看见"。

把七种方案压缩到一个二维坐标轴上记忆：

- **横轴：在哪儿算边缘？**
- 几何上（管顶点）：方案 ① 复制 Mesh、方案 ② 倒壳、方案 ⑥ Silhouette Pass
- 缓冲里（管像素）：方案 ③ Stencil（模板）、方案 ④ 深度检测、方案 ⑤ 法线检测、方案 ⑦ 屏幕后处理
- **纵轴：贵不贵？**
- 顶点方案：每物体多一次 draw call，但全场景成本低
- 屏幕方案：全场景一次 draw call，但每次都全屏采样
带走两条选型口诀：

- **想要"按选中物体描边"** → 选顶点方案（倒壳或复制 Mesh），按物体独立可控。
- **想要"全场景统一风格"** → 选屏幕方案（深度 + 法线），一次配置、全场生效——但记得它不能区分物体。
至此，本书 22 章的核心技法地图已经完整：从 ch03 的坐标空间到 ch20 的 light()，从 ch15 的 2D 描边到本章的 3D 描边，整套"vertex → fragment → light → 后处理"的渲染管线你已经全栈走过一遍。接下来你可以按本书最后给出的综合项目，把这些技法拼成自己的第一个完整 shader 工程。
